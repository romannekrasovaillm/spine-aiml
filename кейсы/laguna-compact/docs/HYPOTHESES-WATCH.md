## 3. Отклонено и почему (не возвращать без нового ADR)

- **MoE и архитектура** (`moe-routing-effrank-monitor`, `moe-sparsity-scaling-law`,
  `t1-routing-replay`, `frozen-router-mopd`, `kda-kalman-write-rule`,
  `qwen-hybrid-3-1-threshold`, `mxfp4-kappa-qat-guard`, `per-head-qk-norm-muon`,
  `router-prior-anchor`): адресованы претрейну собственной архитектуры — у ревизии
  dense Qwen2.5-0.5B, ни MoE, ни KDA в ней нет.
- **Оркестрация и платформа** (`arcticswarm-fleet-isolation`,
  `single-agent-beats-multiagent`, `harness-ab-selection`, `harness-token-economics`,
  `skill-*`, `selective-revalidation`, `agent-federation-governance`,
  `memory-lifecycle-governance`, `synapse-typed-skill-exchange`): про контур агентов
  и скиллов, не про обучение модели.
- Отдельно: `handoff-package-no-stale-contracts` — реальный дефект **платформы**
  (пакет не перезатирает `SPEC.md`/`ROLLBACK.yaml`), к Лагуне не относится, но
  терять его нельзя.

## 4. Как карточка технически поднимается

1. **Реестр — это диспетчер, а не карточка.** Файл `docs/HYPOTHESES-WATCH.md` живёт в
   кейсе и **не участвует в роутинге** (`card_match.py` читает только
   `<id>/HYPOTHESIS.md`). Он нужен человеку и агенту как таблица решений.
2. **Смена состояния — действием человека:** `card_review.py --dir ~/hypotheses
   --promote <id> --to active --apply --yes` (так 14.09 переведены 7 карточек).
   Переход предлагают скрипты, выполняет человек — это правило схемы карточек.
3. **Автоматический подъём по фактам проекта** работает для триггеров-файлов и слов
   (`card_match.py --project <кейс>`); для наших событий (вырождение награды, сигнал
   хак-а) он **не сработает** — поэтому и нужен этот реестр.
4. **Обслуживание реестра — по событию, а не по календарю:** при наступлении события
   из таблицы §2 — сначала действие, потом отметка в реестре (что подняли, что нет,
   почему). При добавлении новой отложенной карточки в ADR-006 — строка в §2.

## 5. Известное ограничение роутера (наблюдение, чужой контур)

Матчинг по фактам проекта поднимает карточки по файлам, и **файлы-«универсалии»
(`CONSTRAINTS.yaml`, `README.md`) совпадают у всех кейсов платформы**. На нашем кейсе
это даёт ложные срабатывания с высоким баллом: `arcticswarm-fleet-isolation` (7),
`single-agent-beats-multiagent` (7) — про оркестрацию флота, к обучению модели
отношения не имеющие, при том что релевантные карточки стоят ниже.

Следствие для нас: **балл роутера нельзя использовать как отбор** — отбор делается
предметно (ADR-006). Исправление — на стороне плагина
`hypothesis-router` (исключить универсальные имена из весового матчинга), это
отдельная работа в чужой зоне, а не дельта этого кейса.

**Сделано 16.09.2026 (по решению владельца):** триггеры **7 наших активных карточек
переписаны под факты этого кейса** — убраны ссылки на файлы чужого контура
(`verifier.py`, `reward.py`, `calibrate.py`, `PASS_RATE_RANGE`, `hidden_constraints_sha256`)

## 6. Что этот реестр НЕ делает

- Не заменяет ADR: решение о внедрении карточки оформляется ADR, реестр лишь
  указывает, когда о нём вспомнить.
- Не поднимает карточки автоматически: событие должен кто-то заметить (человек или
  агент на гейте) — реестр снижает шанс, что это заметят «потом», но не убирает
  необходимость смотреть.
- Не содержит карточек, отклонённых без права возврата (§3): для них нужен новый ADR.

## 7. Журнал подъёмов по триггерам

### 2026-09-20 — агентный граундинг и подготовка RL (7 карточек)

Переход выполнен агентом по поручению владельца; инструмент — `card_review.py
--promote <id> --to active --apply --yes` (правило схемы карточек: переход
предлагает скрипт, выполняет человек — здесь человек поручил, факт зафиксирован).

**Событие 1 — ось RL переведена на граундинг.** Факт: пул v2 (9 162 задачи) на
100 % текстовый (`multi_slug_match` 8 768 / `keyword_match` 394), `tool_call` в
задачах — 0, «среды E1–E8» — файлы задач-текстов, пороги верификаторов `null`,
7/7 unsafe, награда за слаги в тексте ответа. Решение — **ADR-049** (Proposed).
Подняты: `execution-grounded-benchmark-gen`, `environment-as-scaffold`,
`proof-carrying-reward`, `verify-by-separate-role`, `judge-credit-limits`
(latent → active). Действие по существу: G1–G4, walking skeleton 50 задач ×
3 инструмента, страж «успех без `tool_call` > 0 → красное».

**Событие 2 — расширение RL-пула / подготовка фазы 2.** Факт: собраны свежие
`ox`-датасеты; пересечение с SFT-набором v13 — 59.8 % (8 581 задача из 14 339),
карточки AD-2 нет. Подняты: `task-difficulty-curriculum`,
`learnability-frontier-task-synth` (latent → active).

**Не трогались, потому что уже были active:** `laguna-rl-passrate-curriculum`,
`laguna-rl-homogeneous-filter`, `laguna-sft-antiforget-replay`,
`laguna-memorization-metric` (подняты 16.09 по триггерам пересборки наборов и
прибора GEN-EVAL).

**Не сработали (ждём события):** вырождение награды и «reward растёт, judge
падает» (RL не начат), точка решения S4, «чекпойнт принят по оси», собственный
претрейн, пересмотр eval-протокола (фаза 2).

**Перенос выполнен 20.09.2026.** Сверка попарно показала **байт-в-байт идентичность**
теплицы и яруса, при этом ярусные копии свежее (mtime 2026-08-07 против июля — то есть
перенос фактически состоялся раньше, в теплице оставались дубликаты). Дубликаты
перемещены в `plugins/_archive/greenhouse-dedup-20260920/` (библиотека без git — поэтому
перенос, а не удаление; там же таблица «скилл → тема теплицы → ярусный дом»). Итог:
**13 скиллов семи карточек в доменном ярусе, второго источника в теплице не осталось.**
