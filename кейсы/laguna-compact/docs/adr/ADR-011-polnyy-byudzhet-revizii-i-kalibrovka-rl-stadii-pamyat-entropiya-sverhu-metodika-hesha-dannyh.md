# ADR-011. Полный бюджет и калибровка RL-стадии

- Date: 2026-09-14
- Status: Proposed
- Основание: RL-разведка завершена, `evidence/s3-rl-probe.json`, ветка `arch/laguna-s2`, коммит `af40623`

## Context

**Измерено (RL-разведка):** 99 закрытых шагов из 100 начатых, стена **12 590.04 с
(3.50 ч)**, `error: null`; цена закрытого шага **123.87 с** (медиана 123.61,
σ 1.40, диапазон 121.83–130.43). Фазы шага: генерация роллаутов **71.4 %**,
обучение 27.7 %, чекпойнт 0.9 %, GEN-EVAL/ресник ≈ 0 %. Генерация: **361.7 tok/s**,
3 166 233 токена за 396 вызовов. Ресники: **9 hot-sync, 0 пересозданий движка**,
одна инициализация 159.73 с (старт, не ресник). Память: пик **81.77 ГБ** занято,
свободных опускалось до **39.92 ГБ** (прирост **+42.78 ГБ**). Инцидентов 0.
Фон: `reward_mean` 0.3782, `pass_rate` 0.3887, 800 траекторий, `hit_timeout` 0,
`zero_reward` 405, энтропия политики **2.1517** (91 шаг из 100 выше 2.0, ниже 1.0 — ни одного).

**Экстраполяция (обе границы, без усреднения):** 500 шагов = **12.27 ч**
(нижняя: прямой замер исторического лога 88.1 с/шаг) … **17.26 ч** (верхняя: 123.87 с/шаг
+ старт 186.19 с); три сида = **36.8 … 51.66 ч**. Полный цикл с календарём ADR-008
(CPT+SFT ≈ 8.5 суток) — **≈ 10.0 … 10.7 суток** стенда, без eval.

**Три поправки к методике, найденные при сверке (важно: первые две — исправление
моих же выводов из отчёта разведки):**

1. **`t_probe` 14.975 с — не «10–12 % шага».** Это однократный хвостовой вызов проб
   (`run_probes`, `laguna_pipeline_v8.py:1547`) после цикла шагов; он попал в
   незакрытый блок, а у того нет следующего старта, чтобы считаться шагом. Реальная
   цена инструментации — **≈ 0.04 с за весь прогон** (0.122 % стены амортизированно).
   Удешевлять мониторинг нечего — мой вывод был неверен.
2. **«Упор в потолок хода» считался не по тем токенам.** Признак опирался на
   `n_assistant_tokens`, а это `len(tokenizer.encode(responses[g]))` — включает prefill
   и текст `<tool_response>` (`pipeline:1261,1283-1284`), отсюда максимум 4623 при
   потолке 4096. Точная проверка по `gen_tokens`: **3997.8 из 4096 = 97.6 %** —
   генерация действительно идёт до потолка, но доля «88.6 %» остаётся верхней границей,
   а «92 из 96 траекторий» по финальным артефактам **не воспроизводится** (финал: 709/800).
3. **Два манифеста дали разные sha256 одного и того же пула** — whole-file `06b95b2f`
   против head-1-MiB `7ba116ae`. Прогон шёл по пулу ревизии (проверено), но без оговорки
   такая сверка выглядит как подмена датасета.

## Decision

1. **Полный бюджет фиксируется:** на сид — CPT 7.0 ч + SFT 20.3 ч/эпоху +
   RL 12.3 … 17.3 ч; на три сида — **≈ 10.0 … 10.7 суток** стенда плюс eval. Разброс
   RL (41 %) — следствие «болтливости» чекпойнта: чекпойнт, умеющий завершать ход,
   экономит около трети времени RL.
2. **Порог RL-памяти: ≥ 49 ГБ свободно** (замена 40 ГБ из ADR-010 п.4): измеренный
   прирост +42.78 ГБ плюс запас ~15 %, по той же формуле, что ADR-008 п.2 для
   CPT (35 ГБ) и SFT (50 ГБ). Факт: свободных опускалось до 39.92 ГБ — при пороге 40 ГБ
   прогон стоял бы на грани.
3. **Энтропия политики: выход сверху — не дегенерация.** Коридор `1.0–2.0` — эвристика
   другого режима (иной `group_size`, иной харнесс); в ревизии (`G=2`) 91 шаг из 100
   лежит выше 2.0 при полном отсутствии коллапса. Для ревизии действуют пороги:
   **< 1.0 — внимание, < 0.5 × 2 шага — стоп** (mode collapse). Выход сверху не
   является нарушением критерия и не требует «лечения».
4. **Методика хеша данных называется явно** (уточнение AD-2): манифест обязан
   указывать метод — `sha256` по файлу целиком (предпочтительно) либо по первым 1 МиБ
   с явной пометкой `_sha256_head`. Сверка двух манифестов с разными методами не
   является расхождением, но и не является доказательством совпадения данных.
5. **Выбор протокола (A/B/C из ADR-008 п.4) — за владельцем**, теперь на полных числах.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. Калибровать порог памяти и снять коридор энтропии (принято)** | Пороги стоят на замере; ложные тревоги по энтропии исчезают | Порог 49 ГБ сужает окно (на стенде сегодня свободно ровно ~49) |
| **B. Оставить порог 40 ГБ** | Не трогаем ADR-010 | Факт: свободных падало до 39.92 ГБ — прогон на грани OOM; в unified это не «предупреждение», а падение |
| **C. Считать коридор 1.0–2.0 обязательным для RL ревизии** | Единое правило | 91 из 100 шагов объявляются отклонением при отсутствии деградации; правило, которое врёт, перестают читать |
| **D. Взять 127 с/шаг как цену шага** | Совпадает с «сырым» делением стены на шаги | Завышает на 2.5 %: включает старт стадии (186 с) и хвост; экстраполяция обязана идти по 123.87 |

## Consequences

### Positive

- Бюджет полный: любое планирование теперь опирается на замер всех трёх стадий.
- Пороги памяти выстроены по одной формуле (прирост + 15 %), а не по интуиции.
- Коридор энтропии перестаёт быть источником ложных «дегенераций» на RL ревизии.
- Методика хеша названа — сверка манифестов перестаёт выглядеть как подмена данных.

### Negative

- **Разброс RL 41 % (12.3 против 17.3 ч)** — это не шум замера, а зависимость от
  качества SFT-чекпойнта; планировать «по нижней границе» рискованно, «по верхней» —
  закладывает лишние сутки.
- **Окно памяти в 49 ГБ стало узким**: на стенде при работающей платформе (28 ГБ) и ОС
  свободно ровно ~49 ГБ. Любой чужой процесс сдвигает окно.
- **Отказ от коридора 1.0–2.0 ослабляет привычный сигнал**: «энтропия выросла» больше
  не значит «что-то не так» — нужен новый признак для противоположной аномалии
  (рост энтропии к максимуму тоже бывает симптомом), и он пока не определён.
- **Оценка «92/96 упоров» была неверной** — вывод о «болтливости» чекпойнта остаётся
  (доказан по `gen_tokens`, 97.6 %), но его количественная доля уточнена задним числом.

## Reversibility

**reversible.** Пороги, определение энтропии и методика хеша — правки правил и
документов; данные и веса не мигрируют. Уже посчитанные прогоны не пересчитываются:
изменение порога памяти не влияет на валидность состоявшихся замеров (они сделаны при
иной конфигурации), изменение определения энтропии — влияет на интерпретацию, что и
зафиксировано здесь.
