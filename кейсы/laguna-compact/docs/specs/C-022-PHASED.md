# C-022-PHASED.md — правило агентного критерия с фазой + реестр номеров разделов тестов

- Date: 2026-09-25
- Status: Proposed (дельта; решение фиксируется до кода)
- Основание: ADR-059 (база агентного критерия — переснятая), ADR-053 (у правила есть фаза: «ещё не может быть» ≠ «провалено»), ADR-023 п.12 (ложный красный запрещён), `docs/specs/AGENTIC-GUARD.md` §3, `docs/specs/WORK-BACKLOG.md` §7
- Предусловие выполнено: ветки `arch/agentic-base-gate` (`dd698b0`) и `arch/probe-success` (`87f1793`) приняты в канон

## 1. Задача

Внести правило `C-022` (агентный критерий под ADR-059) в `CONSTRAINTS.yaml` так, чтобы оно
**не краснело по построению** там, где артефактов ещё нет, и добавить механическую защиту от
дублей номеров разделов в наборе тестов.

## 2. Правило C-022: почему нужна обёртка

Стражу `tools/check_sft_agentic_share.py` обязательны аргументы `--report` и `--base-report`.
Правило `command_succeeds` передаёт только командную строку, поэтому:

- **прямой вызов** стража в правиле даст красное на любом дереве без артефактов — это ровно тот
  «красный по построению», который ADR-053 запрещает (правило требовало бы артефакт, появление
  которого само же и ограничено моментом замера);
- нужна **обёртка-фаза**: она решает, в каком состоянии находится предмет правила.

**Контракт обёртки** `tools/check_agentic_criterion.py`:

| Состояние | Условие | Код | Смысл |
|---|---|---|---|
| Предмета ещё нет | нет ни одного из двух артефактов (report/base) | **2** | `NOT-VERIFIED` — фаза «ещё не может быть» |
| Предмет есть | оба артефакта на месте | **0 / 1** | проброс вердикта стража (0 — сопоставимо, 1 — нарушение) |
| Частичный предмет | есть только один из двух | **1** | неполнота — нарушение, а не «ещё не может быть» |

- Пути по умолчанию: `evidence/s3aa-agentic-sft.json` и `evidence/s3aa-agentic-cpt-nogram4.json`;
  переопределяются флагами `--report` / `--base-report` (для будущих стадий и сидов).
- Обёртка **ничего не решает по существу**: она не считает метрику и не подменяет вердикт; при
  наличии предмета она вызывает страж и **пробрасывает его код как есть**.
- Печатает состояние одной строкой (`state: absent|partial|present`, `verdict: …`).

**Правило в `CONSTRAINTS.yaml`** — `C-022`, `command_succeeds`,
`command: "python3 tools/check_agentic_criterion.py"`, severity — как у прочих механических
правил кейса; комментарий в правиле называет ADR-059 и §2 настоящей дельты.

## 3. Номера разделов тестов: что делаем и чего не делаем

**Не делаем перенумерацию.** В файле исторически два блока 20–24 (разные стеки дельт), набор
стража идёт под 51, на ветви `laguna-eval-set` тот же набор — под 25. Массовая перенумерация
сломала бы цитаты в спеках и отчётах — это переписывание истории, запрещённое ADR-028 п.4.

**Делаем механический страж дублей:** проверка в наборе тестов, что каждый номер раздела
либо уникален, либо его повтор **назван в реестре** шапки файла («номер → набор»); повтор сверх
реестра и расхождение реестра с телом — красное с поимённым списком. Формулировка «номера
уникальны» **невыполнима буквально** (в файле исторически повторяются 15–24 и 31, а перенумерация
запрещена там же), поэтому принято чтение **«уникальность сверх реестра»**: история ветвления
называется явно и проверяется, а не переписывается.

## 4. Критерии приёмки

| # | Проверка |
|---|---|
| 1 | `python3 tools/check_agentic_criterion.py` без артефактов → exit 2 и строка `state: absent` |
| 2 | с одним артефактом → exit 1 и `state: partial` |
| 3 | с обоими (боевая пара) → код стража, `state: present` |
| 4 | код стража не подменяется: на фикстуре с нарушением сопоставимости обёртка даёт 1 |
| 5 | страж номеров: на текущем файле — зелёный (повторы, названные в реестре, — история); на подсунутом дубле сверх реестра и на расхождении реестра с телом — красный с поимённым списком |
| 6 | таблица «номер → набор» в шапке согласована с телом (число разделов и их номера совпадают) |
| 7 | `arch-ml control check .` — без новых красных (warn'ы чужих плагинов не в счёт) |

## 5. Границы

- Дельта не меняет критерий (в1)/(в2) и не присваивает обёртке решающий голос: вердикт по
  критерию остаётся у сводки (ADR-059 п.5).
- Дельта не расширяет предмет стража; она лишь вводит **фазу** для правила гейта.
- Перенумерация разделов тестов остаётся долгом (WORK-BACKLOG §7) — здесь она сознательно не делается.

## 6. Долги, названные этой дельтой (не входят в неё)

| Долг | Почему не здесь | Условие возврата |
|---|---|---|
| Генератор реестра «номер → набор» вместо ручной таблицы | Таблица растёт вручную на каждый новый раздел; генерация — отдельная правка тестового каркаса | при следующем добавлении раздела тестов |
| Дефолты обёртки по стадии (пара «SFT → RL»: базой становится SFT-финал) | Сейчас стадии RL нет; флаги `--report/--base-report` покрывают ручной запуск | старт RL-стадии ревизии (S4-точка) |
| Перенумерация разделов тестов | Запрещена (переписывание истории, ADR-028 п.4) — страж номеров лишь называет повторы | снимается только отдельным решением владельца о смене схемы нумерации |
