## 4. Ограничения (нарушение = отказ, а не «предупреждение»)

1. **Стенд — одна нагрузка** (AD-5): замеры на GB10 идут последовательно; агентную пробу и PPL можно снять на локальной 4080 (вне стенда), если так дешевле; параллелить два GPU-замера нельзя.
2. **Живой прогон `sft-v13-2e6-20260921-2054` не править** (ни `stages.tsv`, ни манифест): цепочка замеров живёт в новом каталоге. Приборы читают копию чекпойнта.
3. **Эвристика вместо судьи — не результат**: артефакт с `judge != GLM-API` в приёмку не идёт.
4. **Никаких выводов по точкам n < 100** о языке и формате: `n` печатать рядом с долей.
5. **Правило задним числом не менять**: пороги берутся из ADR/S4, а не подбираются под полученные числа.
6. **Длинные пробы разбиваются по состояниям** (при обрыве перемеряется только недостающее), но сравнение допускается только между прогонами с идентичным полем `protocol` (бюджет, режим, набор, версия прибора). Состояние `base` из форматной пробы **не выбрасывать**: оно — точка отсчёта (у базы обрывы 4,8 %), и без него «стало лучше/хуже» не читается.
7. **Проба на живом прогоне запрещена** (ADR-058): все замеры читают бронированную копию; проба обязана верифицировать предмет в начале, а не на финальном пересчёте.
6. `evidence/result-report.json` **не создавать** — точка решения не пройдена (нет RL).

## 5. Результат дельты

Артефакты замеров 1–7 + короткий отчёт `runs/sft-point-chain-<ts>/REPORT.md`: что снято, какие вердикты по критериям (язык / домен / агентность / формат), что **не** снято и почему, где отказ прибора. Отчёт — по числам, не по впечатлению.

## 6. Стоп-условия

- брендированный предмет отсутствует или хеш копии не совпал → стоп, разбор (не «мерить живое»);
- eval вернул `judge: slug-verifier` → замер не засчитан, причина в отчёт;
- манифест/проба указывают на другой чекпойнт, чем бронь → стоп (класс дефекта ADR-051);
- доступ к стенду/ключу потерян → фиксируем частичный результат и остаток, не выдаём за полный.
