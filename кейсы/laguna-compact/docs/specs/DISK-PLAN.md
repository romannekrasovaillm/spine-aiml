## Главный вывод: нехватка диска НЕ тормозит контур

Тяжёлые артефакты контура Laguna физически лежат на **NFS** `~/gb10-shared`
(смонтирован с `10.55.0.2`), а не на локальном `/`. Это проверено, а не подразумевается:

| Что | Куда ведёт |
|---|---|
| HF-кэш весов | `~/.cache/huggingface -> gb10-shared/models-store/home-roman/huggingface-cache` |
| Датасеты кейса | `кейсы/laguna-compact/datasets -> gb10-shared/datasets` |
| CPT-корпус | `кейсы/laguna-compact/cpt_corpus_v12r.txt -> gb10-shared/cpt_corpus_v12r.txt` |
| Пайплайн | `кейсы/laguna-compact/laguna_pipeline_v8.py -> gb10-shared/laguna_pipeline_v8.py` |

Следствие: полный CPT пишет ~59 ГБ чекпойнтов **на NFS** (там свободно 1,2 ТБ из 3,7 ТБ)
и **≈0 ГБ на локальный `/`**. Локальные 24 ГБ стадии CPT/SFT/RL не ограничивают.

Ограничивают они другое: новые worktree, git-клоны, pip/conda-установки, docker build,
запись локальных чекпойнтов, apt. Один всплеск `/tmp` (уже 25 ГБ) или сборка образа
доводят `/` до 100 % и валят хост.

**Поэтому цель освобождения — не «расчистить под CPT», а вернуть хосту рабочий запас.**

## Оценка потребности на полный цикл

Опорный факт — измеренный чекпойнт: `calib_checkpoint_3000.pt` = **2 963 146 899 Б (2,96 ГБ)**,
запись каждые **500 шагов** (подтверждено 6 записями `CKPT` в `logs/cpt.log`).

| Стадия | Объём | Куда ложится | Локальный `/` |
|---|---|---|---|
| **Полный CPT** (9776 шагов) | 19 промежуточных + final ≈ 20 × 2,96 = **59,2 ГБ** | NFS `full-cpt-<ts>/checkpoints` | **≈ 0 ГБ** |
| Уже на NFS | 17,8 ГБ (6 чекпойнтов прогона 1933) | NFS | — |
| **SFT** | вход 486 МБ (на NFS); чекпойнты класса CPT ≈ 3 ГБ × 3–5 = **9–15 ГБ** | NFS | **≈ 0 ГБ** |
| **RL** (500 шагов, `resync_every` 25) | локальный scratch **1–3 ГБ**; чекпойнты на NFS | NFS + scratch | малый |

Измерено локально по RL: каталог `кейс/runs/` = 21 МБ, крупнейший файл
`rollouts_log.jsonl` = 16 МБ — то есть RL-стадия локально почти ничего не стоит.

Запас NFS: свободно 1,2 ТБ из 3,7 ТБ (67 % занято) → влезает ~20 полных CPT.

**Итог по потребности:** суммарно локальному `/` под весь цикл нужно **≈2–3 ГБ**
(scratch, worktree, кэши компиляции). Текущих 24 ГБ **достаточно** для прохождения
стадий. Но как рабочий запас хоста 24 ГБ **недостаточно**: они ниже порога 33 ГБ и
съедаются одним `/tmp`-всплеском (уже 25 ГБ), `docker build` или pip/conda-установкой
(venv-класс — 5–16 ГБ каждый).

**Рекомендуемая цель: освободить 60–90 ГБ** → 84–114 ГБ свободно (≈82–76 % занято).
