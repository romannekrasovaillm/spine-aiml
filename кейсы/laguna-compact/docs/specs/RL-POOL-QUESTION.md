## 1. Что решается

**Какие наборы подаются в RL-стадию** — и в какой роли: как **ось** (на чём меряется
награда) или как **курикулум** (warm-start формата и ранняя диагностика).

Роль разделяет ADR-049: осью объявлен **заземлённый** пул (награда по состоянию, G1–G4),
текстовый пул переведён в курикулум (п.2). Значит вопрос не «текстовый или заземлённый» —
это уже решено, — а **какие именно текстовые наборы берём в курикулум** и что делаем с
наборами `ox`, у которых 59.84 % задач дословно совпадают с обучающим набором.

## 3. Что здесь **не** решается

- Не решается, нужен ли граундинг: решён владельцем 20.09.2026 (ADR-049, Accepted).
- Не решается число сидов и переход к фазе 2: фаза 1 — один сид (ADR-013 п.1), фаза 2 —
  по числам точки решения S4 (`S4-PROTOCOL.md` §4).
- Не решается план Б по вырожденной награде: ADR-017 п.4.
- **Не правится ни один существующий файл** (AD-7): любой отбор оформляется **новым**
  набором с собственной карточкой, а не правкой текущего.

## 4. Варианты

Цена указана в единицах работы и в ресурсе стенда (AD-9: одна нагрузка за раз).

### Вариант A — курикулум: **v2**; `ox`-наборы не берём

| | |
|---|---|
| Что берём | `rl_tasks_revpool_v2.jsonl` (9 162) как курикулум; ось — заземлённый пул стадии |
| Цена | **0** сверх плана: файл готов, карточка есть, пересечения с обучением нет |
| Что закрывает | чистый курикулум по построению; курикулум и ось разделены по данным и по шкале |
| Что ломает/чего лишает | теряется тёплый старт на `ox`-распределении (промпты ox-серии — то, что учитель размечал 24–26.08); наборы `ox` остаются неиспользованными |
| Риск | нет риска смешения памяти и решения: 0.00 % пересечения |

### Вариант B — курикулум: **v2 + `ox`-merged с фильтром** (8581 совпадающих задач исключены), отбор оформлен **новым** набором `ox_cur_*` с карточкой

| | |
|---|---|
| Что берём | 9 162 + 5 758 (14 339 − 8 581) |
| Цена | ≈1 день: сборка нового набора + карточка AD-2 (база/набор/токенизатор/sha256) + прогон C-017 по новому файлу; **правка существующих файлов запрещена (AD-7)** |
| Что закрывает | тёплый старт формата на `ox`-распределении без задач, где ответ был в обучении |
| Что ломает/чего лишает | появляется третий набор со своим носителем и своей карточкой — состав данных растёт, а вместе с ним и объём сверки |
| Риск | фильтр по дословному совпадению **не ловит перефраз**: задача с переписанным промптом остаётся «несовпавшей» (прибор измерения смыслового совпадения — другой, `check_eval_leakage`-линия) |

### Вариант C — курикулум: **`ox`-merged целиком** (включая 8 581 совпадающую задачу)

| | |
|---|---|
| Что берём | 14 339 как курикулум |
| Цена | **0** (файл готов, карточка есть) |
| Что закрывает | максимальный тёплый старт формата; ничего не фильтруем — состав не меняется вовсе |
| Что ломает | **59.84 % курикулума дословно знакомы модели**: в курикулуме это допустимо по роли, но любая метрика, снятая на этих задачах, измеряет память, а не наученное. Отчёт обязан нести оговорку, а выводы по таким задачам запрещены |
| Риск | главный: граница «курикулум» и «ось» проходит **внутри одного файла**, и её придётся удерживать дисциплиной отчёта, а не свойством данных. Плюс сборщик неизвестен и лицензия не урегулирована |

### Вариант D — только заземлённый пул, без текстового курикулума

| | |
|---|---|
| Что берём | заземлённый пул стадии |
| Цена | сборка пула стадии (обязательна во **всех** вариантах — это ось) + больше шагов до первого ненулевого градиента |
| Что закрывает | максимально чистый предмет: награда только по состоянию, текст вообще не участвует |
| Что ломает | теряется дешёвый warm-start формата; ADR-049 прямо называет разреженность награды риском и предлагает снимать её **средой** (`environment-as-scaffold`), а не прогревочной стадией — то есть вариант упирается в качество сред, которых пока 5 задач |
| Риск | длинный участок стадии без сигнала → время стенда уходит на шаги, где учиться нечему (ADR-017 Context) |

## 5. Рекомендация исполнителя (не решение)

**A** — как вариант с наименьшей ценой и без смешения ролей: курикулум `v2` (0.00 %
пересечения, карточка есть) плюс заземлённый пул как ось. Если владельцу важен тёплый старт
именно на `ox`-распределении, то **B**, а не C: разница между B и C — ровно в том, попадают
ли 8 581 дословно знакомая задача внутрь обучающего сигнала, и это единственное, что их
различает. **C** не рекомендуется при любом раскладе: смешение ролей внутри одного файла
удерживается только дисциплиной отчёта, а цена ошибки — вывод «RL помог», который на 60 %
задач означает «модель вспомнила».

Рекомендация **не является решением**: выбор — за владельцем (AD-2/AD-8). До решения
пункт 1 чек-листа старта (`RL-STAGE-PLAN.md` §7) остаётся крестом, и стадия не стартует.

> **Итог (22.09.2026).** Рекомендация совпала с решением: владелец выбрал **A** — ADR-054
> п.1. Пункт 1 чек-листа (`RL-STAGE-PLAN.md` §7) переведён из креста в галочку, а шаг 1
> реализации (переключение раннеров v1→v2, 8 вхождений в 3 файлах) исполнен дельтой S3be:
> вхождений `v1` в раннерах — **0**. Текст выше не правился.

## 6. Форма ответа владельца

Достаточно одной строки в любом из принятых в кейсе носителей (ADR-дельта или решение в
`WORK-BACKLOG.md` §4), отвечающей на три вопроса:

1. **Пул курикулума:** A (v2) / B (v2 + `ox`-фильтр новым набором) / C (`ox`-merged целиком) / D (без курикулума).
2. Если B — кто и когда собирает новый набор (и принимает карточку AD-2).
3. Если C — согласована ли оговорка отчёта «8 581 задача курикулума дословно совпадает с
   обучением; выводы по ним не делаются» как обязательная часть `evidence/result-report.json`.

Ответ фиксируется в `evidence/result-report.json` не как вердикт, а как **основание**
(поле `limits`): «пул выбран решением от <дата>`.
