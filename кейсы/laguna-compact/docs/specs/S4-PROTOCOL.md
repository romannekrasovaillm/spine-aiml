# S4-PROTOCOL.md — протокол точки решения пилота (фаза 1)

- Date: 2026-09-14
- Статус: подготовлено заранее (до финиша SFT/RL), ADR-013 п.3 + ADR-015
- Назначение: принять решение о фазе 2 **по числам**, а не по впечатлению от логов

## 1. Что читается на входе (артефакты прогона)

| Артефакт | Где | Что берём |
|---|---|---|
| `eval_results_sft.json` | `runs/pilot-compact-s42-*/logs/` | `judge_mean` **SFT-базовой** (на том же чекпойнте) |
| `eval_results.json` | там же | `judge_mean` после RL |
| `eval_results_base.json` | там же | база до SFT (ориентир) |
| GEN-EVAL история | `general_eval_history.jsonl` стадии | `ppl_general` / `ppl_domain` (тренд) |
| RL-метрики | лог RL-стадии, `rl_metrics` | `reward_mean`, `pass_rate`, `entropy` политики, `zero_reward`, `hit_timeout` |
| Манифесты | `run_manifest.json` стадий | пиннинг данных/пайплайна/сида (AD-2) |

**Важно:** eval обязан быть от судьи (`judge` в артефакте; цепочка иначе отказывает —
`pilot_chain.sh:596-605`). Артефакт с эвристикой вместо судьи **не является** осью AD-1.

## 2. Ось AD-1 при одном сиде — что считается, а что нет

| Величина | При 1 сиде | Комментарий |
|---|---|---|
| `judge_mean` (RL) vs `judge_mean` (SFT) | **считается** — направление | это и есть «направление оси» |
| std по сидам, k-из-k | **не считаются** | статистики нет: 1 точка. В отчёте — `null` + пометка `single_seed: true` |
| n попыток на задачу | 1 | pass@k **не экстраполируется** (ADR-015, `passk-identifiability`) |
| Оценка шума | SE ≈ 3.6 % при p≈0.5, n=192 | разница меньше шума — **неразличима**, а не «победа» |

## 3. Критерии решения (все четыре — обязательны)

**Бюджет проб — 8192** (ADR-045 п.4): решение по критерию формата вступает в силу
по факту различающего замера на бюджете 8192 (S3aq); до его завершения выводы о
формате читаются с оговоркой об усечении (ADR-045 п.2/п.3).

1. **Направление:** `judge_mean(RL) > judge_mean(SFT)` на этом сиде.
   Если разница **< SE (≈3.6 %)** — фиксируется «неразличимо на одном сиде», а не «есть эффект».
2. **Нет дегенерации:** энтропия политики не ниже 1.0 (стоп-порог 0.5),
   `clip_frac < 0.2`, доля timeout-деградаций не растёт монотонно.
3. **Общий язык (K1 ∧ K2) и домен (v3):**
   - **K1 — в жанре реплея** (`general_eval_v3`, 200 док): `ppl` ≤ 2× своей базы — **15.009373** (база 7.504686);
   - **K2 — вне обучающего распределения** (`general_eval_k2`, 200 док): `ppl` ≤ 2× своей базы — **12.319871** (база 6.159936);
   - вердикт по общему языку — **конъюнкция**: проход одной компоненты и провал другой — не проход (ADR-027 п.1/п.2; ADR-029);
   - **Домен** (`domain_eval_v3`, 200 док): отношение к базе **< 1** = домен выучен (ADR-044 п.1/п.6; правило чтения — ADR-031 п.4).
4. **Полнота доказательств:** манифесты всех стадий, оба eval-артефакта, отсутствие
   необъяснённых инцидентов (NVRM/OOM/рестарты).

## 4. Ветвление

| Итог | Действие |
|---|---|
| Все четыре выполнены, **разница > SE (≈3.6 %)** | **Фаза 2** (ADR-013 п.4): ещё два сида → полная ось со статистикой. *Решение владельца 16.09.2026: порог — SE, затем фаза 2* |
| Все выполнены, разница < SE | Эскалация владельцу: «неразличимо на 1 сиде» — либо фаза 2 ради статистики, либо стоп |
| Критерий 2 или 3 нарушен | Стоп, разбор: причина в режиме (LR), в данных (микс) или в RL (награда) |
| Критерий 4 не выполнен | Продолжать нельзя: сначала полный манифест, иначе результат недоказуем |

## 5. Формат отчёта

Файл `evidence/result-report.json` создаётся **только по факту** замера
(не заранее — иначе правило C-014 станет ложно зелёным). Обязательные поля:

```json
{
  "axis": {"metric": "judge_mean", "rl": 0.0, "sft": 0.0, "delta": 0.0, "exceeds_noise": false},
  "single_seed": true,
  "n_attempts": 1,
  "k_of_k": null,
  "std": null,
  "generation": {
    "k1": {"ppl": 0.0, "baseline": 7.504686, "ceiling": 15.009373},
    "k2": {"ppl": 0.0, "baseline": 6.159936, "ceiling": 12.319871},
    "domain_v3": {"ppl": 0.0, "baseline": 13.559193, "relation": 0.0}
  },
  "rl_health": {"entropy": 0.0, "clip_frac": 0.0, "zero_reward_share": 0.0, "hit_timeout": 0},
  "verdict": "phase2 | stop | escalate | insufficient_evidence",
  "limits": ["single seed: no std/k-of-k", "pass@k not extrapolated", "GEN-EVAL sets 200/200 docs (v3)"]
}
```

Схема — `docs/specs/result-report.schema.json`. Правило C-014 требует наличия
`evidence/result-report.json`; отсутствие отчёта = «точка решения не пройдена», а не «гейт сломан».

## 6. Что протокол **не** делает

- Не пересчитывает задним числом прошлые прогоны (в т.ч. `qwen25-05b` с `accuracy 0.0`).
- Не выдаёт заключений о семействах и размерах — протокол узкий (AD-1).
- Не заменяет собой фазу 2: один сид даёт направление, не воспроизводимость.
