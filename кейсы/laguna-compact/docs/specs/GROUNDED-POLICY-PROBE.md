# GROUNDED-POLICY-PROBE.md — прибор измерения действия политики по состоянию среды

- Date: 2026-09-25
- Status: Proposed (дельта к `ADR-061` шаг 1; решение зафиксировано до кода)
- Основание: `ADR-061` (предмет, метрика, порядок), `ADR-049` (награда по состоянию среды, G1–G4), `AD-11` (кредит бинарный), `ADR-058` (бронь предмета), `ADR-051` (идентичность входа), `AD-5` (одна нагрузка)
- Что уже есть: контракт среды доказан (`tools/grounded_runner.py`, `evidence/grounded-skeleton.json`, G1–G4, no-action = 0, лимит шагов из задачи); скелет 5 задач (`data/grounded-skeleton`)

## 1. Зачем прибор

В контуре нет инструмента, который прогоняет **политику** (чекпойнт модели) по заземлённым задачам
и считает кредит по **состоянию среды**. `grounded_runner.py` прогоняет контракт среды
(положительный контроль, no-action, лимит шагов) и модель не загружает вовсе; `passrate_probe.py`
измеряет текстовый пул через `search_concepts`. Без этого прибора вопрос «научилась ли модель
действовать умнее» неизмерим — ни до RL, ни после.

## 2. Контракт прибора

**Вход:** `--checkpoint <бронь>` (ADR-058: только копия/хардлинк, sha256 снимается с копии),
`--set-dir <набор заземлённых задач>`, `--state <тег состояния>` (например `base|cpt|sft`),
`--out <evidence.json>`, `--run-dir <каталог прогона>`.

**Что делает на задачу:** поднимает среду задачи (как в скелете: контейнер + sidecar-мок, сеть
закрыта), подаёт политике наблюдение, даёт ей до `max_steps` действий, каждое действие исполняет
в среде, затем прогоняет **верификатор задачи по состоянию** и получает бинарный кредит (AD-11).
Успех без действия невозможен по построению и проверяется отдельно.

**Выход (evidence JSON):** `protocol` (чекпойнт + sha, набор + sha, seed, `max_steps`, лимит ходов,
режим декодирования, версия прибора и её sha), метрики `n`, `pass_rate`, `no_action_share`,
`tool_error_share`, `mean_steps`, `median_steps`, `by_task` (по одной записи на задачу: id, исход,
класс отказа), `limits` (n = 5 — сигнал, не вердикт).

**Классы отказа** (объявлены заранее, разбор как в агентной пробе): `a_no_action` — политика не
сделала ни одного действия; `b_action_no_effect` — действия были, состояние не изменилось;
`c_wrong_state` — состояние изменилось, но не к цели; `d_cutoff_effect` — упёрлась в лимит шагов,
**но состояние менялось** (действия были полезны); `d_cutoff_plain` — упёрлась в лимит шагов без
изменения состояния. Разделение обязательно: иначе лимит шагов скрывает полезные действия.

**Мощность и пометки:** `signal_only` печатается при **n < 30**; при 30 ≤ n < 50 — `limited_power`
(числа печатаются, вердикт не выносится); вердикт по оси возможен при **n ≥ 50** (пул стадии,
шаг 3 ADR-061). Порог назван до прогонов и не пересматривается задним числом.

**Интерфейс замера** (ADR-062): прибор измеряет политику **в том интерфейсе, которому она
обучена**. Если набор, на котором училась политика, и мир задачи дают разные инструменты, прибор
обязан напечатать `interface_mismatch: true` и причину — и такой прогон вердиктом не является.

## 3. Правила

1. **Бронь** (ADR-058): предмет — копия, хеш с копии; прибор верифицирует предмет **в начале**.
2. **Кредит бинарный** (AD-11): верификатор возвращает 0/1 по состоянию; градуированный кредит
   в этом приборе не допускается.
3. **Метка площадки признаками** (как в скелете): `in_container` подтверждается маркерами образа,
   а не флагом вызова.
4. **Один GPU-замер за раз** (AD-5); прогон допустим на локальной 4080 (вес 0.5B).
5. **Никаких выводов по n = 5**: прибор обязан печатать `n` рядом с каждой долей и помечать
   результат как `signal_only`.
6. **Утечка gold**: если эталон достижим из промпта/seed/id — красное, замер не принимается.

## 4. Критерии приёмки

| # | Проверка |
|---|---|
| 1 | Положительный контроль: gold-решение задачи даёт кредит 1 на каждой задаче набора |
| 2 | Проба no-action: текстовый ответ без действий даёт 0; доля успехов без действия = 0 |
| 3 | Пустая среда (нет docker) → `NOT-VERIFIED` (exit 2), а не красное и не выдуманные числа |
| 4 | В отчёте есть `protocol` с sha чекпойнта (с копии), sha набора и версией прибора |
| 5 | Классы отказа покрывают все провалы (сумма долей = 1 по провалам), `by_task` полон |
| 6 | Повторный прогон на том же входе даёт те же числа при фиксированном seed (детерминизм проверяется на фикстуре) |

## 5. Границы шага

- Скелет 5 задач — **сигнал**, не вердикт; расширение до пула стадии (≥50 задач) — шаг 3 ADR-061.
- Прибор не обучает: он измеряет. RL-стадия — шаг 5, и только после замера «до» на пуле.
- Текстовый пул не измеряется этим прибором: другая ось (ADR-061 п. 6).
