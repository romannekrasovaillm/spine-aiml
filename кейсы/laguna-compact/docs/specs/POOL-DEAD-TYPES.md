# POOL-DEAD-TYPES — почему мёртвы типы пула (диагностика для фазы 2)

> Узел `pool-dead-types` плана `.arch-fleet/laguna-analysis.plan.toml`.
> Полная таблица и машинный контракт: `evidence/pool-dead-types.json`.
> Диагностика, а не правка: пулы, верификатор, пайплайн и ADR не менялись.

## Вопрос

Сравнение пулов на одном SFT-чекпойнте (`sft_checkpoint_final.pt`, sha `5bc15f708111`)
дало: v1 pass 0.17 / v2 pass 0.108, и сигнал держится почти целиком на одном типе
`explain_relation` (v1 0.5, v2 0.43). Мертвы: `chain_reasoning` 0.0, `formula_chain` 0.0,
`find_concept` 0.0, `multi_hop_search` 0.0, `compare_concepts` 0.01.

Отказ типа — это свойство **задачи**, **проекции** или **формата**?

## Метод

Детерминированная выборка 20 задач на тип (seed 42) из исполненных 100/тип в прогоне
`runs/passrate-sft-20260916-1200/{v1,v2}/` (worktree `laguna-passrate-probe`, только чтение).
Классификация отказа пересчитана заново: `diag_class` в прогоне зашумлён багом порядка
вычисления `dict.update` в `passrate_probe.py` (`classify_failure` читает `rec['tool_calls']`
до применения `r.update(...)` → у всех фейлов всегда `a_no_tool_call`). Здесь классы честные
по фактическим `tool_calls`/`coverage`/`hit_timeout`.

## Ключевой факт (объясняет всё)

**SFT-чекпойнт ни разу сам не испускает `<tool_call>`** — на 700 задач прогона
`tool_calls` строго `1` у `compare_concepts`/`explain_relation` (это единственный
forced-вызов) и строго `0` у остальных типов; `turns=1` везде. Единственный источник
вызова инструмента — `toolcall_force`: блок бутстрапа в `passrate_probe.py` форсит первый
вызов **только для `compare_concepts` и `explain_relation`** (query выводится из промпта),
у остальных типов query пустой → бутстрапа нет, а модель самовызовом его не компенсирует.

Поэтому раскол «живой/мёртвый» — это в первую очередь **проекция** (асимметрия бутстрапа
+ семантика верификатора), а не суть модели 0.5B.

## Разбор по типам

### `explain_relation` — живой, но артефактный
- Верификатор (`keyword_match`): порог ≥3 терминов определения каждого концепта
  (парафраз-дружелюбный, не точные slug-и).
- Forced-вызов вкладывает оба определения в контекст; модель пересказывает → попадает в порог
  в ~0.43–0.50 случаев. Фейлы — класс `c`: термины частично есть (coverage 0.25–0.42), порог не добит.
- **Вывод**: сигнал реален, но это «retrieval-augmented paraphrase», а не agentic-поиск.

### `find_concept` — мёртв проекцией
- Промпт «Запиши формулу Implicit Q-Learning (IQL) в LaTeX…», верификатор `multi_slug_match`
  требует точный slug `implicit_q_learning`, которого **нет в промпте**.
- Нет бутстрапа (query не выводится), 0 самовызовов → slug не появляется ни разу (coverage=0/20).
- **Пример**: требуемое `["implicit_q_learning"]`; ответ модели — галлюцинация про `f(q_1,…,q_10)`,
  slug отсутствует.
- **Вердикт**: чинится сменой проекции (вывести query из title и форсить вызов; проверять термины
  определения/title, а не точный slug). Не мёртв по существу модели.

### `chain_reasoning` / `formula_chain` — мёртвы проекцией
- `expected_slugs` — **русские термины определений** (`"метрика","совместного","сохранения"`),
  это анти-лейк-проекция ADR-021: проверяются промежуточные определения, а не концы цепочки.
- Верификатор `multi_slug_match` требует **ВСЕ** термины точной подстрокой (словоформы с падежом:
  «совместного», «сохранения»), threshold-механики нет — строже, чем у `explain_relation`.
- Нет бутстрапа (n_min_steps=2/3), 0 самовызовов → определения не достаются; модель генерирует
  часть русских терминов из приора (coverage до 0.83), но полный набор не добирает.
- **Пример** (`formula_chain`): требуемое `["парадигма","видео","этапа","компонент","отображает","каждый"]`;
  ответ — галлюцинация с частичным совпадением (coverage 0.33), полный матч не достигнут.
- **Вердикт**: чинится сменой проекции — бутстрап вызова + threshold-проверка по терминам
  определений (как `explain_relation`) или канонические словоформы. Задачи не переписывать.

### `multi_hop_search` — проекция + суть
- Требует найти промежуточный концепт C (не в промпте) и выдать 3 точных slug-а; n_min_steps=2.
- Нет бутстрапа, 0 самовызовов → coverage=0/20.
- **Пример**: требуемое `["feedback_asymmetry_hypothesis","llm_based_recsys…","evidence_verification"]`;
  ответ — галлюцинация, промежуточный slug не найден.
- **Вердикт**: проекция доминирует в замере, но сам 3-hop поиск выше потолка 0.5B.
  Для фазы 2 деприоритизировать; не брать без отдельного пилота.

### `compare_concepts` — мёртв проекцией (порог + источник keywords)
- Forced-вызов есть (share 1.0), модель выдаёт часть keywords (coverage до 0.6),
  но верификатор требует 67% из ~15 gold-summary keywords, **не выводимых** из вложенного
  определения (это отпечаток gold-саммари, а не определения).
- **Пример**: требуемое ~15 keywords (`"метод","пост-тренировочного","квантования","весов",…`);
  ответ покрывает 0.13 → порог 0.67 недостижим по конструкции.
- **Вердикт**: чинится сменой проекции — проверять термины определения (как `explain_relation`)
  или снизить порог; заменить gold-keywords на определение-термины.

## Рекомендация для фазы 2

Если оставить пул как есть, фаза 2 выучит **ровно один навык** — пересказ вложенного
определения с попаданием в 3 термина (`explain_relation`). Остальные типы — мёртвый балласт:
их награда = `-0.1` (штраф `min_steps`, т.к. 0 вызовов) и обучающего градиента не даёт.

1. **Не делать вывод** «модель 0.5B не решает эти типы» — 0.0 измеряет отсутствие бутстрапа
   и самовызова, а не глубину рассуждения.
2. **Выбор A (минимальный)**: фаза 2 только на `explain_relation`, остальные типы убрать
   из обучающего пула. Честно зафиксировать: учится парафраз-навык.
3. **Выбор B (предпочтительный — выравнивание проекции)**: (i) форсить вызов для всех типов
   (query из title/start-end slug); (ii) перевести `find_concept`/`multi_hop`/`chain`/`formula`
   на термины определений (как `explain_relation`), а не точные slug-и; (iii) `compare_concepts` —
   термины определений или ниже порог. Тогда пул даёт несколько живых парафраз-типов.
4. **Выбор C (учить самовызов)**: отдельная SFT/бутстрап-строка на испускание `<tool_call>`
   до того, как полагаться на agentic-типы в RL. Дороже, вне этого узла.
5. **`multi_hop_search` не смешивать** с остальными: 3-hop выше потолка 0.5B даже после
   смены проекции.

## Открытые вопросы

- Точен ли вывод «0 самовызовов» — нужен замер с `--hint` (prefill `<think>\n<tool_call>`),
  чтобы отделить «не умеет формат» от «не знает когда звать».
- Сколько даёт сам бутстрап без forced: повторить пробу с `--no-toolcall-force` на
  `explain_relation`/`compare_concepts`.
- `chain_reasoning`/`formula_chain`: русские термины в `expected_slugs` — задуманная
  анти-лейк-проекция (ADR-021), но threshold-механика отсутствует; переводить ли на threshold?
- Достаточно ли для фазы 2 перевести все типы на парафраз-проекцию, или цель фазы 2 —
  именно agentic-поиск (тогда нужен Выбор C)?
