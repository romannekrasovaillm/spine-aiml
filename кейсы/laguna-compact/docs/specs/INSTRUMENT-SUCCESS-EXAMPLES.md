# INSTRUMENT-SUCCESS-EXAMPLES.md — прибор агентной пробы обязан сохранять успешные траектории

- Date: 2026-09-25
- Status: Proposed (дельта к прибору; решение фиксируется **до** правки кода)
- Основание: разбор агентности после SFT (`docs/reports/AGENTIC-TRACES-INTERNAL.md`), ADR-023 п.10 (у числа один носитель), ADR-028 п.4 (история не переписывается), ADR-051 (артефакт обязан называть свой предмет), ADR-053 (у правки есть момент вступления в силу)
- Прибор: `tools/passrate_probe.py` (агентная проба: pass-rate, доля самостоятельных вызовов, классы отказа)

## 1. Дыра (наблюдённый факт, не предположение)

Разбор «где хорошо, где плохо» по итогам агентной пробы SFT-финала упёрся в то, что
прибор сохраняет **только отказы**:

| Что | Где | Факт |
|---|---|---|
| Классы отказа | `probe_meta.json → diagnosis.examples` | `{c: v[:3]}` — только классы отказов (`passrate_probe.py:1255`) |
| Признак успеха | `tasks.jsonl` | есть (`"pass": int(passed)`, `passrate_probe.py:1006`) |
| Признак успеха в `answers.jsonl` | `answers.jsonl` | **нет**: `{task_index, task_type, prompt, answer, answer_truncated}` (`passrate_probe.py:2160-2165`) |

Следствие: «что сработало» описывается **только агрегатом** (8–12 % на одношаговых типах),
а показать форму успешной траектории по артефакту нельзя — без GPU и без повторного прогона.
Для приборов класса «обучение с проверкой» это асимметрия разбора: отказ разбирается по примеру,
успех — нет, хотя именно успех отвечает на вопрос «какой режим закреплять».

## 2. Решение

1. **`answers.jsonl` несёт признак исхода и разборные поля.** К существующим полям
   **аддитивно** добавляются: `pass` (0/1), `coverage`, `turns`, `tool_calls`, `diag_class`
   (null для успешных). Существующие поля и их порядок не меняются; ответ по-прежнему обрезается
   `ANSWER_CAP`.
2. **`diagnosis.examples` получает ветвь `pass`.** До 3 успешных траекторий, отбор — по одному
   примеру на тип задачи (до 3 типов), структура записи — та же, что у примеров отказов
   (task_index, task_type, source_env, prompt, required/found, answer_excerpt).
3. **Измеряющая часть не меняется.** `pass` (из `verify_task`), `tool_call_share`, `coverage`,
   классы отказа, пороги и вся арифметика вердикта остаются прежними байт-в-байт по смыслу:
   новая редакция **добавляет носитель для разбора**, а не меняет число.
4. **Редакция и её вступление в силу.** Правка прибора меняет `tool_sha256`, который отчёт
   объявляет сам (прибор не входит в реестр `INSTRUMENT-VERSIONS.md`, носителем хеша служит
   артефакт). В отчётах и цитатах новая редакция называется с датой; на артефакты прогона
   `20260925-1000` (снятые прежней редакцией) она **не распространяется задним числом** (ADR-028 п.4).
5. **Живая цепочка не трогается** (ADR-016): правка выполняется в изолированном дереве;
   работающие прогоны дочитывают прежнюю редакцию.

## 3. Критерии приёмки (проверяются механически)

| # | Проверка | Где |
|---|---|---|
| 1 | `answers.jsonl` каждой задачи несёт `pass` и `coverage`; число строк равно числу задач | раздел 16 `tools/tests/run_tool_tests.sh` |
| 2 | `diagnosis.examples.pass` непуст при наличии успешных и содержит не более 3 записей; типы не повторяются, пока есть непокрытые | там же |
| 3 | при нуле успешных ветвь `pass` — пустой список, а не ошибка и не выдуманный пример | там же (фикстура «все провалены») |
| 4 | метрики на фикстуре тождественны прежней редакции (`pass_rate`, `tool_call_share`, `class_counts`) | там же (регресс-контроль: числа не поехали) |
| 5 | отчёт по-прежнему объявляет `tool_sha256` и он равен хешу новой редакции | там же |
| 6 | полный набор тестов зелёный (`bash tools/tests/run_tool_tests.sh`) | прогон |

## 4. Что делается после (вне этой дельты)

- Разбор успешных траекторий по типам — отдельная задача; эта дельта даёт носитель, а не вывод.
- Если по итогам разбора окажется, что успех достигается одним устойчивым паттерном (или что
  успешных траекторий в пуле почти нет), это отдельный факт для развилки RL, а не правка прибора.

## 5. Границы

- Дельта не расширяет предмет прибора (по-прежнему: pass-rate и агентность на одном чекпойнте).
- Дельта не меняет протокол декодирования и не снимает требований ADR-041 (штатный режим).
- Публикация чего-либо из новых примеров — не автоматическая: действует ADR-048 п.6 (реальные
  промпты и генерации в публичный контур не выходят).
