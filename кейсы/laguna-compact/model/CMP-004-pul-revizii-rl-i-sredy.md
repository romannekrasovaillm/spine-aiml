- **Назначение**: источник задач RL-стадии — пул ревизии v1 (27 992 задачи, 8 исключённых `explain_relation`) и пул v2 (9162 задачи, фильтр по верифицируемости сред E1–E8 + лейк-правило); карточка `data/rev-envs-v2-card.json` фиксирует состав, `data/verifier-thresholds.json` — пороги верификаторов.
- **Где живёт**: файлы пулов — `/home/user/gb10-shared/datasets/rl_tasks_revpool_{v1,v2}.jsonl` (на сетевом диске — AD-4); в кейсе — отфильтрованные копии с причинами исключений (`runs/rev-pool/rl_pool_filtered.jsonl`, `runs/rev-pool/exclusions.json`, `runs/rev-pool-v2/*`) и карточка.
- **Чем проверяется**: C-017 (пересечение пула с SFT по нормализованному тексту = 0; на 20.09.2026 правило смотрит на пул v1 — это названо в ADR-021). Механически **не** проверяется (держится приборами-пробами, правила гейта нет): фильтр по `verifiable_weight`, проекция задач на замороженный `verify_task`, лейк-фильтр самого пула — приборы `tools/probe_pool_v2_leak.py`, `tools/probe_pool_v2_reachability.py`, `tools/validate_verifiers.py`.
- **Связь**: AD-11 (среды принимаются в пул только с бинарно проверяемым ответом; кредит не градуируется), AD-6 (судья не участвует в награде — среды с `judge_weight > 0.2` в награду не идут), AD-4 (пулы читаются из `gb10-shared`). Решения: ADR-021 (среда ревизии v2), ADR-007 (сборка пула), ADR-006 (курирование по полосе pass-rate), ADR-017 (наблюдаемость вырождения награды).
- **Границы**: контура награды RL (функция кредита, верификатор в шаге обучения) в модели пока нет — он появится с RL-стадией; здесь описан источник задач, а не награда.
