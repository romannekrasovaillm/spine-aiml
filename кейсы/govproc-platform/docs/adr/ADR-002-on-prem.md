# ADR-002. On-prem размещение и стек из реестра отечественного ПО

- Date: 2026-08-15
- Status: Proposed

## Context

Заказчик — госсектор: данные закупок и персональные данные участников (152-ФЗ), возможная принадлежность к КИИ (187-ФЗ) и требования импортозамещения (реестр отечественного ПО, постановления о запрете/ограничении иностранного ПО для госорганов). Решение о размещении принято человеком: **on-premise в собственном ЦОД заказчика**. Это фиксирует trust zone, требования к аттестации (ФСТЭК), криптографии (ФСБ) и операционную модель на годы вперёд.

## Decision

Размещение — собственный ЦОД заказчика, два контура: продуктивный и стендовый (для аттестационных испытаний и приёмки). Технологический стек — только ПО из реестра российского ПО или открытое ПО, допустимое для госорганов:

- ОС: Astra Linux Special Edition (режим замкнутой программной среды — по решению СЗИ-гейта).
- СУБД: PostgreSQL (сертифицированная сборка Postgres Pro Certified) — пин версии в spine.
- Очередь/шина: RabbitMQ (не входит в ограничения; альтернатива — при наличии лицензии на отечественную шину).
- Криптография: КриптоПро CSP / КриптоПро DSS (сертификаты ФСБ) — см. ADR-004.
- Контейнеризация: Kubernetes-совместимый кластер внутри контура (дистрибутив — по итогам обследования ЦОД; `[ТРЕБУЕТ ПРОВЕРКИ]` наличие у заказчика кластера и его дистрибутива).

Внешние зависимости (ЕИС, СМЭВ, ЕСИА) — через выделенный сегмент интеграции (DMZ) с TLS по сертификатам Минцифры.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Гособлако | Готовая аттестация инфраструктуры; быстрее запуск | Зависимость от оператора; лимиты кастомизации; отклонено заказчиком |
| Коммерческое аттестованное облако (УЗ-1/К1) | Баланс скорости и соответствия | Допустимость для конкретных классов данных заказчика не подтверждена; отклонено заказчиком |
| Гибрид (ядро on-prem, витрина в облаке) | Дешёвое масштабирование витрины | Сложная граница доверия; витрина закупок содержит данные, чувствительные до момента публикации; отклонено |
| Статус-кво | — | Не применимо: платформа создаётся с нуля |

## Consequences

### Positive

- Полный контроль над данными и trust zone; предсказуемая позиция при проверках ФСТЭК/ФСБ.
- Нет зависимости от облачного оператора и его ценовой политики.
- Стек из реестра снимает риск санкционного отзыва лицензий.

### Negative

- Капекс и сроки: закупка железа, монтаж, аттестация контура — месяцы до первого развёртывания. Митигация: разработка ведётся на стендовом мини-контуре; требования к железу фиксируются в NFR до закупки.
- Своя эксплуатация 24/7 (дежурства, резервирование, DR). Митигация: RTO/RPO зафиксированы в NFR; план DR — обязательный артефакт эпика.
- Аттестация ИСПДн/ГИС — отдельный проект с неопределённым сроком. Митигация: модель угроз и класс защищённости — на гейт A1, до массовой разработки.

## Reversibility

**costly.** Миграция on-prem → облако возможна (контейнеры, стандартный PostgreSQL), но повлечёт повторную аттестацию и простой. Решение считается долгоживущим.
