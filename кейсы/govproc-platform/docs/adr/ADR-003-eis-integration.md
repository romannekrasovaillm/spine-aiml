# ADR-003. Интеграция с ЕИС через асинхронный антикоррупционный адаптер

- Date: 2026-08-15
- Status: Proposed

## Context

Публикация извещений, протоколов и контрактов в ЕИС (zakupki.gov.ru) обязательна для 44-ФЗ и частично для 223-ФЗ. Проверённая фактура: с 01.01.2025 FTP-выгрузки закрыты, взаимодействие — только через сервисы отдачи данных и интеграционные сервисы ЕИС (раздел V ПП РФ №803); до 04.07.2026 для TLS-соединений с ЕИС обязателен корневой сертификат Минцифры России. ЕИС — внешняя система с собственным графиком регламентных работ, пиковыми нагрузками и эволюционирующими схемами документов (XML-схемы версионируются Казначейством). Связывать ядро платформы с ЕИС синхронно — значит импортировать её доступность и модель данных в наш SLA.

## Decision

Интеграция с ЕИС — только через выделенный модуль-адаптер (антикоррупционный слой) с асинхронным обменом:

1. Ядро ничего не знает о схемах ЕИС. Отправка документа — доменное событие + запись в outbox (той же транзакцией, что и изменение состояния).
2. Адаптер читает outbox, транслирует доменный документ в актуальную XML-схему ЕИС, подписывает (ADR-004), отправляет, опрашивает статус, транслирует ответ/ошибки ЕИС обратно в доменные события.
3. Версии XML-схем ЕИС — конфигурация адаптера с явными пинами; смена версии схемы — релиз адаптера с контрольными прогонами, не трогающий ядро.
4. Недоступность ЕИС не блокирует работу платформы: документы накапливаются в outbox, соблюдаются контрольные сроки публикации через мониторинг «документ в очереди > X часов» (X — из регламента контура).
5. TLS к ЕИС — с корневым сертификатом Минцифры; обновление сертификатов — эксплуатационная процедура с дедлайном 04.07.2026.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Синхронные вызовы ЕИС из ядра | Проще код; мгновенная обратная связь | SLA ядра = SLA ЕИС; схемы ЕИС протекают в домен; сбой ЕИС блокирует подписание протоколов |
| Готовое интеграционное решение (вендор) | Быстрый старт; вендор следит за схемами | Зависимость от вендора в критичном контуре; стоимость лицензий на арендатора; не снимает необходимость outbox |
| Ручная публикация операторами | Нулевая разработка интеграции | Нарушает сроки публикации при масштабе; человеческий фактор в юридически значимом действии — неприемлемо |

## Consequences

### Positive

- Доступность платформы не зависит от доступности ЕИС; регламентные работы ЕИС переживаются штатно.
- Смена XML-схем ЕИС локализована в одном модуле с контрольными прогонами.
- Outbox даёт полный след «что и когда отправлялось» — опора для аудита и разбора расхождений с ЕИС.

### Negative

- Итоговая консистентность: статус «опубликовано в ЕИС» приходит с задержкой; UI и регламенты обязаны честно показывать состояние «отправлено, ожидает подтверждения». Митигация: явная машина состояний публикации, запрет переходов процедуры, требующих подтверждённой публикации, до её получения.
- Дубли отправки при сбоях: ЕИС должна корректно обработать повтор. Митигация: идемпотентные ключи (GUID документа из ядра), дедупликация на адаптере.
- Мониторинг сроков публикации становится критичным компонентом (штрафные риски заказчика). Митигация: алерты в NFR, эскалация при приближении к регламентному дедлайну.

## Reversibility

**reversible** для ядра (адаптер заменяем без его изменения); **costly** по операционным данным — история обмена с ЕИС должна сохраняться при замене адаптера.
