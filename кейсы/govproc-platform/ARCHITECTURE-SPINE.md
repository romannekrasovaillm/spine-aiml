# ARCHITECTURE-SPINE — Платформа B2G-закупок (44-ФЗ / 223-ФЗ)

Инварианты уровня платформы. Обязательны для всех модулей и параллельных исполнителей. Локальное переопределение запрещено; конфликт эскалируется архитектору. ID стабильны, без переиспользования.

**Принятые решения человеком (маршрут Critical, 2026-08-15):** сценарий — B2G-портал госзакупок; правовой контур — оба закона (44-ФЗ + 223-ФЗ); размещение — on-premise в ЦОД заказчика.

---

## AD-1. Границы модулей и workflow-конфигурации

- **Binds:** все модули ядра (извещения, заявки, протоколы, контракты, НСИ, пользователи)
- **Prevents:** эрозию модульного монолита; рассинхрон процедур 44-ФЗ/223-ФЗ между исполнителями
- **Rule:** кросс-модульные импорты только через публичный API модуля или доменные события; прямые запросы к чужой схеме БД запрещены (проверяется fitness function в CI). Процедурная логика правовых контуров — только в версионируемых workflow-конфигурациях; продуктивная версия конфигурации неизменяема (новая правка = новая версия).
- **Ref:** ADR-001, ADR-005

## AD-2. Стек и пины версий

- **Binds:** все деплой-юниты и CI
- **Prevents:** «зоопарк» версий и ПО вне реестра в госконтуре
- **Rule:** ОС — Astra Linux SE; СУБД — Postgres Pro Certified 16.x (точный минор пинуется в манифесте развёртывания); брокер — RabbitMQ 3.13.x; JDK — Liberica JDK 21 LTS `[стек приложения — ТРЕБУЕТ ПРОВЕРКИ: финальный выбор языка на гейте A1]`. Любая новая зависимость — проверка по реестру отечественного ПО и лицензионной чистоте, фиксация в манифесте. Непиннутые версии запрещены.
- **Ref:** ADR-002

## AD-3. События, outbox и идемпотентность

- **Binds:** ядро, eis-adapter, notification, любые будущие интеграции
- **Prevents:** потерю/дубли юридически значимых сообщений; рассинхрон состояний с ЕИС
- **Rule:** любое внешнее взаимодействие инициируется записью в outbox в той же БД-транзакции, что и изменение состояния. Все внешние вызовы идемпотентны по ключу (GUID доменного документа). Ретраи — только в слое адаптера, с экспоненциальной паузой и circuit breaker; таймауты явные, настроены по p99.9 внешней системы. Fallback-«тихих» веток нет: неустранимая ошибка — явное состояние `integration_failed` + алерт.
- **Ref:** ADR-003

## AD-4. Аудит и неизменяемость юридических фактов

- **Binds:** все модули, совершающие юридически значимые действия
- **Prevents:** оспаривание процедур; невозможность реконструировать ход закупки для ФАС/суда
- **Rule:** аудит-лог append-only (запрет UPDATE/DELETE на уровне БД-ролей), каждая запись: кто (subject_id), что (action, object_ref), когда (UTC), хеш ГОСТ Р 34.11-2012 канонической формы документа, ссылка на предыдущую запись (hash-chain). Протоколы и подписанные документы неизменяемы: исправление = новый документ со ссылкой на отменённый. Время хранится в UTC, отображается в зоне заказчика.
- **Ref:** ADR-001, ADR-004

## AD-5. Внешние схемы и API-контракты

- **Binds:** eis-adapter, публичное API платформы, потребители API
- **Prevents:** протекание чужих моделей данных в домен; ломающие изменения API
- **Rule:** схемы ЕИС (XML) и прочих внешних ГИС существуют только на границе адаптера, версии схем пинуются конфигурацией. Публичное API — OpenAPI 3.1, версионирование `/vN`, обратно-несовместимые изменения только новой версией; контрактные тесты в CI. Канонические справочники (ОКПД2, КТРУ, ОКЕИ) — единый модуль НСИ, импорт из официальных источников с фиксацией версии справочника.
- **Ref:** ADR-003

## AD-6. Trust zone и данные

- **Binds:** все компоненты, эксплуатация, CI/CD
- **Prevents:** утечку ПДн/закупочных данных за контур; нарушение 152-ФЗ
- **Rule:** один продуктивный контур (ЦОД заказчика), внешние соединения — только из DMZ-сегмента интеграции; TLS с ГОСТ/сертификатом Минцифры для гос-систем. ПДн участников — шифрование at-rest, маскирование в логах, доступ по ролевой модели с обязательным аудитом чтения чувствительных полей. В CI/CD и тестовых данных — только синтетика; копия продуктивных данных на стенд запрещена без обезличивания.
- **Ref:** ADR-002, ADR-004

## AD-7. Криптография — только модуль signing

- **Binds:** все модули
- **Prevents:** размазывание СКЗИ по коду; несертифицированную криптографию в контуре
- **Rule:** операции с ЭП и ГОСТ-криптографией выполняет только модуль `signing` через сертифицированные СКЗИ (КриптоПро CSP/DSS). Остальному коду запрещено подключать крипто-библиотеки (проверяется fitness function по зависимостям). Подписывается каноническая форма; хеш фиксируется в аудите (AD-4).
- **Ref:** ADR-004
