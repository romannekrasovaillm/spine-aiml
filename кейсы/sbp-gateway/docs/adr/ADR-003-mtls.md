# ADR-003. Транспорт к ОПКЦ СБП: изолированный адаптер с mTLS/ГОСТ и сертификатами УЦ НСПК

- Date: 2026-08-15
- Status: Proposed
- Owner: solution-architect (платёжный контур) + ИБ
- Related: ADR-001, ADR-006, AD-004, AD-005

## Context

Шлюз обменивается с ОПКЦ СБП (НСПК) по протоколу участника. Точные требования к транспортному уровню (версии TLS, алгоритмы, форматы, сертификаты УЦ НСПК, ключи) определяются документацией НСПК на Портале поддержки и выдаются участнику после присоединения к Правилам ОПКЦ СБП — публично полный контракт не раскрыт. Известно из публичных источников: подключение требует СКЗИ (выдаёт Банк России на шаге 1 порядка подключения), сертификаты, тестовые испытания; применяются российские криптоалгоритмы (ГОСТ).

Силы: канал к внешнему оператору — граница доверия (trust zone change), канал финансово значимый, ключевой материал должен храниться в сертифицированном СКЗИ/HSM, требования КИИ (187-ФЗ, приказы ФСТЭК) и НПС.

## Decision

1. **Единственный адаптер ОПКЦ** внутри СБП-шлюза (см. ADR-001) — только он знает протокол НСПК. Для остальных компонентов — внутренний контракт шлюза.
2. **Транспорт — по требованиям НСПК на дату контракта**: взаимная TLS-аутентификация (mTLS), сертификаты УЦ НСПК для клиентской стороны, российские криптоалгоритмы. Детали (версии протокола, профили cipher suites, форматы сообщений, поля, схемы URL) фиксируются в `docs/contracts/nspk-contract.md` **после получения документации НСПК** — до этого контракт помечен `[ТРЕБУЕТ ПРОВЕРКИ]` и не реализуется.
3. **Ключевой материал** — в сертифицированном СКЗИ (HSM/аппаратный или сертифицированный программный контур по требованиям НСПК/ЦБ); ключи не покидают СКЗИ; ротация — по политике НСПК.
4. **Сетевой контур адаптера изолирован** (см. ADR-006): выделенный сегмент «контур НСПК», доступ только из DMZ-адаптера, без сквозного доступа к внутренней сети; файрвол-правила по белому списку адресов/портов НСПК.
5. **Таймауты и ретраи**: таймаут на синхронный вызов — по регламенту НСПК; ретраи только на транзиентные сбои, с экспоненциальной задержкой и джиттером, в одном слое (адаптер), с circuit breaker (размыкание — не молча, а переход на режим «только чтение/очередь» + алерт). Повторная отправка идемпотентна (ADR-002).
6. Тестовый контур НСПК (test ОПКЦ) подключается до боевого; конфигурация окружений (test/prod) — параметризована, секреты — из секрет-менеджера, не в коде.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Говорить с НСПК напрямую из каждого сервиса | Меньше прослоек | Дублирование протокольной логики, шире поверхность атаки, сложнее сертификация и обновление крипто-профилей |
| Использовать несертифицированное СКЗИ / обычный TLS | Проще интеграция | Нарушение требований НСПК/ЦБ — банк не пройдёт тестовые испытания; риск для КИИ |
| Синхронный вызов НСПК без очереди и circuit breaker | Проще модель | Каскадный отказ при деградации НСПК, потеря операций при таймауте |

## Consequences

### Positive

- Одна точка знания протокола НСПК: обновления протокола — только в адаптере.
- Соответствие требованиям НСПК/ЦБ по криптографии и СКЗИ — проходимость тестовых испытаний.
- Изоляция границы доверия: компрометация DMZ-адаптера не даёт доступа во внутренний контур.

### Negative

- Зависимость от документации НСПК: точный контракт — внешний вход, задержка до его получения (gap).
- СКЗИ/HSM — дорогой и медленный компонент (операции подписи/проверки), нужен запас производительности.
- Адаптер — потенциальное узкое место: требуется горизонтальное масштабирование и резервирование.
- Ретраи и circuit breaker усложняют поведение (нужны тесты на отказы).

## Reversibility

**reversible.** Транспортный адаптер можно заменить (другой вендор, другой стек) без смены статусной машины — внутренний контракт остаётся. Необратимой миграции нет.
