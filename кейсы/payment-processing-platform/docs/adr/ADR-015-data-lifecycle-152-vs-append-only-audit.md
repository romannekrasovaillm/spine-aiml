# ADR-015. Data lifecycle — 152-ФЗ vs append-only audit

- Date: 2026-08-15
- Status: Accepted

## Context

152-ФЗ (ПДн) даёт субъекту право на забвение — удаление персональных данных. 115-ФЗ (ПОД/ФТ) требует хранения данных о транзакциях 5 лет. AD-7 требует append-only audit log (запрет на UPDATE/DELETE). Эти требования напрямую конфликтуют: клиент просит удалить данные, но закон требует хранить. Без явной политики — юридический и технический тупик.

## Decision

**Классификация данных + псевдонимизация вместо удаления.**

### Классы данных

| Класс | Примеры | Retention | Право на забвение |
|-------|---------|-----------|-------------------|
| Финансовые транзакции | payment, payment_events, ledger entries | 5 лет (115-ФЗ) | НЕТ — удаление запрещено |
| Персональные данные в metadata | ФИО, телефон, email в payment.metadata | 5 лет, псевдонимизация | Частично — маскирование |
| Карточные данные | PAN, CVV, expiry | Не хранятся (токенизация, AD-6) | N/A |
| Технические данные | логи, traces, metrics | 90 дней | ДА — удаление |
| Операторский аудит | operator_audit | 5 лет | НЕТ |

### Псевдонимизация (при запросе на забвение)
- ФИО, телефон, email в `payment.metadata` → замена на token (`PERSONAL_DATA_REDACTED_<hash>`).
- Связь token → реальные данные — в отдельном secure mapping (Vault-encrypted, доступ только DPO).
- Финансовая суть транзакции (amount, status, accounts) — сохраняется.
- Результат: данные обезличены, финансовый след — целостен.

### Data minimization
- В событиях Kafka: только payment_id, status, amount, rail. Никаких ПДн.
- В логах: маскирование (phone: `+7-XXX-XXX-12-34`, email: `a***@b.com`).
- В API-ответах: каналу возвращается только необходимый минимум.

### Процедура запроса на забвение
1. Запрос от клиента (через DPO).
2. DPO верифицирует запрос.
3. Технический скрипт: псевдонимизация ПДн в payment.metadata по client_id.
4. Запись в operator_audit (кто, когда, какой клиент).
5. Уведомление клиента.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Удаление ПДн по запросу** | Полное соответствие 152-ФЗ. | Нарушение 115-ФЗ. Удаление из append-only (AD-7) — невозможно. |
| **Игнорировать 152-ФЗ** | Просто. | Нарушение закона. Штрафы. |
| **Полная анонимизация всех ПДн сразу** | Нет конфликта. | Потеря бизнес-данных (клиентская аналитика, fraud patterns). |

## Consequences

### Positive

- Разрешение конфликта 152-ФЗ ↔ 115-ФЗ через псевдонимизацию.
- Append-only audit log не нарушается.
- Data minimization — снижение риска компрометации ПДн.

### Negative

- Псевдонимизация — не полное удаление (DPO должен обосновать).
- Secure mapping — дополнительная точка хранения ПДн (митигация: Vault-encrypted, строгий доступ).
- Процедура — не автоматическая (DPO approval).

## Reversibility

**Reversible.** Изменение классификации — обновление policy. Техническая реализация (псевдонимизация) — обратима (restore из backup, если mapping сохранён).
