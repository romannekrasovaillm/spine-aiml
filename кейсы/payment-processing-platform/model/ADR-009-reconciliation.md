## Context

Платформа отправляет платежи на внешние рельсы (NSPK, CBR, SWIFT) и получает подтверждения. Между внутренним состоянием платформы и состоянием рельса возможны расхождения: платформа считает платёж завершённым, но рельс его отклонил; рельс провёл платёж, но callback не дошёл; двойное списание из-за дублирующего вызова. Без систематической сверки — расхождения накапливаются и обнаруживаются при клиентском запросе или аудите ЦБ.

## Decision

**Отдельный bounded context Reconciliation: end-of-day двусторонняя сверка.**

### Процесс
1. **Сбор реестров**: каждый рельс предоставляет end-of-day файл/отчёт (MT940/MT942 для SWIFT, реестр НСПК, выписка ЦБ).
2. **Auto-match**: сопоставление по payment_id (или reference) + amount + status. Точный матч → `MATCHED`.
3. **Unmatched — платформа → рельс**: платформа считает COMPLETED, но в реестре рельса нет. Причины: потерянный callback, задержка клиринга.
4. **Unmatched — рельс → платформа**: рельс провёл платёж, но в платформе нет. Причины: прямой входящий платёж (не через платформу), дубль.
5. **Exception queue**: unmatched → ручная разборка оператором (AD-26 operator audit).
6. **Reconciliation report**: `reconciliation_report(date, rail, matched_count, unmatched_platform_count, unmatched_rail_count, exceptions[])`.

### Расписание
- End-of-day (23:00 МСК): сбор реестров.
- 01:00 МСК: auto-match.
- 09:00 МСК: операторская разборка exceptions.
- Алерт при unmatched > 0 после auto-match.

### Связь с Clearing & Settlement
- Сверка — предусловие для settlement: нельзя settle unmatched платёж.
- После сверки → settlement (проводка по корр. счетам).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Real-time сверка** | Мгновенное обнаружение. | Нагрузка на рельсы (запросы статуса). Рельсы не поддерживают real-time. |
| **Ручная сверка в Excel** | Просто. | Не масштабируется. Ошибки. Нет аудита. |
| **Без сверки** | Нет работы. | Финансовый риск. Нарушение требований ЦБ. |

## Consequences

### Positive

- Своевременное обнаружение расхождений (до клиентских жалоб).
- Аудиторский след сверки для ЦБ.
- Предусловие для корректного settlement.

### Negative

- Зависимость от формата реестров рельсов (разные форматы: MT940, XML, CSV).
- Окно обработки: 23:00–09:00 (ночью) — операторская разборка утром.
- Exception queue может накапливаться при систематических проблемах.

## Reversibility

**Reversible.** Переход на real-time сверку — добавление polling-запросов статуса. Архитектура не меняется.
