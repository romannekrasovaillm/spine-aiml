Унаследованный монолит биллинга: приём платежей по HTTP, запись в общую
таблицу `payments`, уведомления через RabbitMQ, csv-импорт из drop-каталога.
Источник истины о текущем состоянии — карта обследования
`docs/reverse/survey.md` (33 находки [confirmed], 2 [gap]), собранная
`arch-be survey`. Документации до обследования не было («в чатах и головах»).

Скрытые связи (карта, секция 5): таблица `payments` используется из пяти
мест одновременно (billing, importer, migrations, notifier, scripts) —
изменение схемы бьёт по всем сторонам; обмен с внешней системой идёт через
drop-каталог csv, а не через API.
