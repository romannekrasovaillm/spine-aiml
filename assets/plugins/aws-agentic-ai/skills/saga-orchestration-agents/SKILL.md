# Saga-оркестрация агентов (AWS PG, 2026)

## Две оркестрации

**Event orchestration (классика)**: центральный координатор ведёт workflow явно (Step Functions + Lambda + SQS/EventBridge): ретраи, параллельные ветви, таймауты, сбои — под контролем. Пример: create order → update inventory → make payment.

**Role-based agent orchestrator (supervisor)**: LLM-оркестратор интерпретирует цель, декомпозирует в подзадачи, делегирует worker-агентам (у каждого ролевой промпт/тулчейн), собирает и синтезирует. Пример из гайда (Bedrock supervisor): «проектный бриф + топ-5 конкурентов» → research agent → summarization agent → brief-writer → компиляция.

## Что общее (переносится)

Оркестратор в обоих мирах: держит контекст и поток исполнения; ветвления/последовательности/обработка ошибок; единый результат из распределённых компонентов.

## Что добавляет агентность

Семантическая делегация (подзадача формулируется смыслом, не сигнатурой); адаптивность (worker выбирает инструменты); интроспекция (оркестратор оценивает промежуточные результаты и меняет план). Пригодно для открытых, неоднозначных, эволюционирующих задач — и дорого/менее предсказуемо для детерминированных.

## Правила выбора (банк)

- Процесс детерминирован и регулируем (проводки, клиринг) → Step Functions-подобная оркестрация; LLM — в отдельных шагах (классификация, извлечение).
- Процесс исследовательский (подготовка архитектурного решения, анализ инцидента) → supervisor-оркестратор.
- Гибрид: детерминированный skeleton + агентные шаги; компенсации саги — детерминированные всегда (навык `saga-transactions`).
- У оркестратора-агента: явный бюджет шагов/токенов, лог делегирований (аудит), выход по таймауту с partial-результатом (headless-контракт complete/partial/blocked).
