# Multi-agent collaboration (AWS PG, 2026)

## Отличие от workflow-оркестрации (таблица гайда)

| Аспект | Workflow-агенты | Multi-agent collaboration |
|---|---|---|
| Контроль | Централизованный координатор | Децентрализованные пиры по ролям |
| Взаимодействие | Один делегирует и трекает | Многие договариваются, делятся, адаптируются |
| Дизайн | Предопределённая последовательность | Эмерджентное, гибкое распределение задач |
| Координация | Процедурная оркестрация | Кооперативные/соревновательные взаимодействия |
| Применение | Автоматизация процессов предприятия | Сложные рассуждения, исследования, эмерджентные стратегии |

## Когда collaboration оправдана

- Задача без предопределённой декомпозиции (исследование, разведка вариантов, red/blue).
- Нужны параллельные «персоналии» с разными целями (переговоры, торг, состязательное ревью — наш `adversarial-review` по сути двухагентная коллаборация).
- Эмерджентность — фича, а не баг.

## Цена (для регулируемого контура)

- Стоимость и latency: N агентов × диалоги; бюджетируй (токен-лимиты на дискуссию).
- Предсказуемость: эмерджентный путь трудно аттестовать; гейты и рубрики — на выходе, не на пути.
- Аудит: протокол переговоров логируй целиком (кто что предложил, почему приняли) — в Evidence Bundle.
- Управление: у каждого агента — роль, инструменты, R-уровень; kill switch общий.

## Банковские примеры

- Инвест-анализ: bull vs bear агенты + синтезатор.
- Архитектурный комитет-симуляция: автор + состязательный ревьюер + председатель (вердикт).
- НЕ для транзакционных потоков (платежи — оркестрация, не коллаборация).
