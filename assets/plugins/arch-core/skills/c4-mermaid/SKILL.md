# C4 + mermaid в харнессе

## Уровни (C4, Саймон Браун)

1. **System Context** — система среди пользователей и внешних систем (для комитета).
2. **Container** — приложения, БД, очереди, шлюзы (рабочий уровень solution-архитектора).
3. **Component** — внутри контейнера (только для нетривиальных).
4. Code — не рисуем (выводимо из кода).

Правило: один уровень абстракции на диаграмму; 5–9 узлов максимум; каждая стрелка подписана протоколом/смыслом.

## Mermaid-подмножество харнесса (инструмент `mermaid_render`)

- `graph TD|LR`: узлы `A[прямоугольник]`, `B(скругление)`, `C{ромб}`, `D((круг))`; рёбра `-->`, `---`, `-- метка -->`, цепочки `A --> B --> C`; quoted-метки `A["текст с --> внутри"]`.
- `sequenceDiagram`: `participant A as Клиент`, стрелки `->>` (синхр), `-->>` (асинхр/ответ), `Note left of|right of X: текст`.
- Не поддерживаются (пропускаются с предупреждением): subgraph, classDef, style, click.

## Приём

```
graph LR
  mb[Мобильный банк] -->|REST JSON| gw[API Gateway]
  gw -->|маршрутизация| po[Платёжный оркестратор]
  po -->|ISO 20022| hub[Платёжный хаб]
  po -->|команда списания| core[Ядро: счета]
```

- Кириллица в метках — ОК; id — латиница.
- Поток денег/данных — направление стрелки; вызов — подпись протокола, событие — подпись топика.
- Проверяй читаемость: `mermaid_render` в сессии или `arch-ml mermaid file.mmd`.

## Чек-лист диаграммы

- [ ] Один уровень C4, ≤9 узлов
- [ ] Все стрелки подписаны (протокол/событие)
- [ ] Граница доверия (trust zone) читается отдельно — комментарием `%% trust boundary` + отдельный узел-шлюз
- [ ] Рендерится без предупреждений

## Антипаттерны

- «Паутина» на 20 узлов — делить по уровням.
- Стрелки без подписей («магия между коробками»).
- Диаграмма не совпадает с кодом (drift) — пересобирать при изменениях, living-spec подход.
