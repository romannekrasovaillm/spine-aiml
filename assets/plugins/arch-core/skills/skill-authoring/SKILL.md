# Создание архитектурных скиллов

Скилл — методическое пособие для агента: когда применять + процедура + чек-лист + антипаттерны. НЕ промпт (роль) и НЕ справка (факты): скилл меняет поведение исполнителя.

## Анатомия (стандарт agent-plugins.org)

```
my-plugin/
├── plugin.json          # $schema, name, version, description, keywords
├── skills/<name>/
│   ├── SKILL.md         # frontmatter (name, description) + тело
│   └── references/      # шаблоны, чек-листы, примеры (подгружаются по требованию)
├── mcp.json             # MCP-серверы плагина (stdio/http)
├── agents/              # субагенты (md с frontmatter) — клиентское расширение
└── hooks/hooks.json     # хуки событий — клиентское расширение
```

## Правила хорошего SKILL.md

1. **description — фильтр срабатывания**: формула «<суть в одно предложение>. Используй этот навык ВСЕГДА, когда <триггеры через запятую>». Модель выбирает скилл по description — пиши триггеры языком задач пользователя.
2. **Имя** — kebab-case глагол/сущность (`adr-authoring`, `saga-transactions`); уникально в библиотеке (дедуп по имени при discover).
3. **Тело 40–90 строк**: назначение → железные правила → процедура по шагам → чек-лист → антипаттерны. Код/форматы — в блоках; длинные шаблоны — в `references/`.
4. **Связь с инструментами**: где применимо — имя инструмента в бэктиках (`spine_lint`, `fitness_check`), CLI и слэши.
5. **Без воды**: каждая строка должна менять решение читателя. Общие места («тестируйте код») удалить.

## Процедура создания

1. Источник: постмортем/решение комитета/паттерн с авторитетного сайта (укажи URL внизу скилла) — скилл без происхождения не принимается.
2. Черновик по структуре выше; шаблоны → references/.
3. Валидация: `arch-ml skills list` (виден?), frontmatter парсится, линтеры проекта проходят.
4. Проверка срабатывания: `arch-ml skills search <типичный запрос>` — скилл в топ-3? Нет — усиль description ключевыми словами.
5. Упаковка: плагин в `~/.arch-ml/plugins/` или в общую библиотеку; версия по semver; changelog в plugin.json не храним — в git.

## Антипаттерны

- Скилл-конспект (факты без процедуры) — это reference, не скилл.
- Description «полезный навык про архитектуру» — никогда не сработает.
- Дубли имени в разных плагинах (молчаливая подмена — первый wins).
- Скилл на 300 строк — разбить; тело ≠ энциклопедия (детали в references/).
