# Spine-инварианты

Позвоночник — минимальный набор решений, без которых независимые исполнители (агенты, команды) выберут несовместимые API, модели данных, retries и протоколы. Это НЕ полное описание системы.

## Тест принадлежности (главный фильтр)

«Могут ли две единицы уровнем ниже, построенные независимо, выбрать несовместимо?»
- Да → в spine. Нет → в Deferred (с причиной и условием возврата).
- Выводимо из кода/репозитория → в spine НЕ дублируется (seed vs spine: стек и дерево каталогов — «посев», владелец дальше — код).

## Формат блока

```
## AD-3. Единый формат идентификаторов платежа
Binds: все сервисы платёжного контура
Prevents: рассинхрон форматов id при интеграции (UUIDv7, не serial)
Rule: `grep -rE "payment_id.*serial" services/` пуст; контракт tests/contracts/payment-id
Status: Accepted  (Proposed|Accepted|Deprecated|Superseded; [ADOPTED] — ратифицированная реальность)
```

- ID стабильны: без перенумерации и переиспользования.
- Binds/Prevents/Rule непустые — линтер `spine_lint` ловит дубли ID, пустые поля, заглушки, непиннутые версии.

## Наследование по высоте

initiative → feature → epic: родительский spine — read-only связывающее ограничение; секция Inherited Invariants ссылается на оригинальные ID; локальное переопределение запрещено — конфликт эскалируется наверх (человек-архитектор, гейт A3).

## Чек-лист

- [ ] Каждый блок проходит тест принадлежности
- [ ] Rule — машинно-проверяемое (regex/команда/контракт-тест), не «должно быть хорошо»
- [ ] Deferred содержит причину и условие возврата
- [ ] `spine_lint` чист
- [ ] Состязательная линза: «построй две единицы, соблюдающие все AD, но несовместимые» — не должно получиться

## Антипаттерны

- Spine на 40 блоков: никто не держит в голове → не работает (норма 5–15).
- Дублирование очевидного из кода (структура пакетов, версии библиотек).
- Rule без проверяемого критерия.
