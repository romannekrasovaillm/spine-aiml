# Паттерны DeepSeek Harness

DeepSeek Harness (`dsh`) — открытый агентный харнесс DeepSeek AI на vendored-фреймворке Cordis: **всё является плагином**, включая адаптер модели, реестр инструментов, журнал сессии и сам агентный цикл. Привилегированного ядра нет — расширение = монтирование плагина рядом с остальными, а его регистрации отматываются при выгрузке.

## Иерархия цикла: turn / step / round

Единый словарь для архитектурных разборов агентных систем:

- **step** — один запрос к модели плюс инструменты, которые она вызвала.
- **turn** — ноль или более step: открывается, когда принят вход, закрывается, когда ничего не осталось должны (модель и инструменты остановились или вмешалась терминальная политика).
- **round** — внешняя политико-итерация поверх turn: раунд цели, раунд Ralph-цикла. Счётчики раундов принадлежат своей политике и НЕ считают каждый turn сессии.

Типовой скелет хода: `turn/start → agent/pre-step (waterfall) → step/start → agent/request → llm/stream → assistant/chunk* → tool/call → tools/pre-execute → tools/execute → tools/post-execute → tool/result → step/end → … → agent/turn-stopping → turn/end`.

## Инвариант: model-visible ⟺ logged

Всё, что достигает запроса к модели, должно быть восстановимо из append-only журнала сессии; новый вид model-visible входа требует нового события журнала. Журнал — источник истины для `deriveMessages()`: fork, resume, транскрипты, телеметрия и персистентность — все проекции одного потока. Для банка это готовый паттерн аудита агента: сырьё (`assistant/chunk`) хранится отдельно от проекции, реплей воспроизводит диалог дословно.

## Capability seam: Definition / Provider / Consumer

**Seam** — заменяемая способность из трёх ролей: *Service Definition* (владеет интерфейсом и словарём типов), один или несколько *Service Providers*, один или несколько *Consumers* (обычно инструмент, обращённый к модели). Одна роль сама по себе — НЕ seam. Канонический пример dsh: `dsh-shell` (Definition) + `dsh-bash-local` / `dsh-bash-sandbox` (провайдеры) + `dsh-tool-bash` (потребитель). Провайдеры fs и subprocess делят один execution world, поэтому переключение на удалённый sandbox переносит Bash, PTY и LSP разом, без форков провайдеров. Роли разносятся по пакетам, только когда эволюционируют независимо.

Применение в solution-архитектуре: любую платформенную способность (шина, identity, журналирование, LLM-гейт) описывай тремя ролями — тогда замена провайдера (вендор A → вендор B, on-prem → cloud) меняет продукт целиком, а не точечно.

## Режимы диспетча событий

Режим — часть публичного контракта события, а не деталь реализации:

| Режим | Ждут? | Порядок | Возврат |
|---|---|---|---|
| `emit` | нет | в порядке регистрации, наблюдение | нет |
| `waterfall` | нет | around-middleware, `next()` делегирует | да |
| `parallel` | да | все слушатели параллельно | нет |
| `serial` | да | в порядке регистрации | да |

Waterfall-семантика: слушатель получает `(...args, next)`; вызов `next()` делегирует, возврат без `next()` — короткое замыкание (для событий единственного решения это дизайн, а не хак). Слушатель, который лишь аннотирует, обязан делегировать.

## Defensive patterns (классы дефектов, а не советы)

1. **Ортогональные исходы сообщаются независимо.** Процесс может истечь по таймауту И выйти с кодом 0 (поймал сигнал). `timedOut`, `signal`, `exitCode` — отдельные факты; никогда не вкладывай отчёт одного флага в ветку другого.
2. **Публичные контракты соблюдаются с ОБЕИХ сторон.** Несколько представлений одного исхода нормализуются на границе API (у dsh: ошибки запроса к модели выходят наружу только как терминальные finish-chunks; брошенные исключения — только дефекты middleware/потребителя).
3. **Асинхронное состояние ≠ синхронное.** Статус «running» не является результатом одного сообщения: несколько follow-up делят один интервал. Кто владеет прогоном — определяет интервал явно (от дurable-квитанции до whole-agent idle) и обрабатывает ветку «ждать нечего».
4. **Dispose доходит до квиэссенции, а не до запроса.** Teardown: kill → await done; реестры слушателей закрываются ДО убийства, чтобы поздние завершения молчали.
5. **Исключения колбэков содержатся в диспетчере.** Падающий слушатель не должен ронять обещание, в котором исполняется, и голодать слушателей после себя.
6. **Недоверенному выводу — не ambient-окружение и не предсказуемые пути.** Порождённые команды получают scrubbed env (выброшены `*KEY*`/`*SECRET*`/`*TOKEN*`/`*PASSWORD*`); temp/spill-файлы — каталог 0700, случайные имена, эксклюзивные owner-only открытия. В этом харнессе правило реализовано: инструмент `bash`, `[bash] env_scrub/env_allow`.
7. **Unlink путей-ссылок.** Путь, который может быть symlink/junction, удаляется как ссылка (lstat → unlink), а не рекурсивным rm — рекурсия может уйти по ссылке в цель.

## Ralph-цикл

**Ralph loop** — foreground-прогон к НЕИЗМЕННОЙ цели свежими агентами. Раунд = свежая дочерняя сессия без родительского и предшественного контекста; междураундное состояние несут общий workspace (файлы) и один ограниченный **handoff**: `{status, summary, evidence[], next_steps[], blockers[]}`. Handoff дополняет workspace, а не подменяет его как источник истины. В этом харнессе реализовано инструментом `ralph_run` (до 6 раундов, артефакты в `reports/ralph/<id>/`).

Когда применять в банковском PDLC: поэтапная миграция, серия ADR, ревизия доменной документации, наращивание architecture-rules по модулям — всё, что один контекст деградирует тянуть.

## Профили и бандлы

Запущенный харнесс — дерево плагинов, собранное при загрузке из упорядоченных слоёв: **профиль** (именованная композиция в home: список бандлов + свои патчи) → **бандлы** (формат распространения конфиг-строк и кода) → патч-оверлеи пользователя. Каждый слой остаётся патчабельным слоями выше. Урок для корпоративных платформ: состав среды воспроизводим из декларативных слоёв, а любую строку можно заменить патчем без форка.
