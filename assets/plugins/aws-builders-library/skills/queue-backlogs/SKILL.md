# Бэклоги очередей (David Yanacek, AWS)

## Бимодальность

Очередная система имеет два режима: быстрый (пустая очередь) и зловещий (бэклог): часовая остановка консьюмера = час восстановления при ДВОЙНОМ запасе мощности. Асинхронность покупает надёжность ценой latency при бэклоге — и это часто забывают («асинхронщине latency не важна» — неверно).

## Метрики

- Producer-side availability ≈ доступность очереди (малоинформативно). DLQ-rate — поздний сигнал (алармить, но не только).
- **Возраст сообщения при снятии с очереди** — главная метрика отставания.
- **AgeOfFirstAttempt** (возраст при ПЕРВОЙ попытке доставки) — отфильтровывает шум медленных/офлайн-получателей; ранний индикатор системной проблемы. В pub/sub: AgeOfFirstSubscriberFirstAttempt.
- Trace id в сообщениях; X-Ray для трассировки.

## Техники против бэклогов

- **Защита на каждом слое**: front-door throttling недостаточно для асинхронных — каждый компонент защищает себя (belt + suspenders).
- **Shuffle-sharding** (Lambda): фиксированный пул очередей, клиент хэшируется на подмножество; сообщение — в самую пустую из «своих». Шумный сосед топит свои очереди, остальные уходят в сторону. Не нужно много очередей для магии изоляции.
- **Sidelining**: избыточный трафик (сверх rate) → в spillover-очередь (аппроксимация приоритетной); старый трафик → в backlog-очередь, живые сообщения обрабатываются первыми (аппроксимация LIFO).
- **TTL сообщений**: если есть anti-entropy sweeper (периодическая полная синхронизация) — старые дельты дёшево выбрасывать.
- **Лимиты на workload**: отдельные пулы потоков + AtomicInteger-семафоры конкурентности + rate-лимиты (Little's Law: concurrency = rate × latency; всплеск latency ×10 = ×10 потоков).
- **Backpressure вверх**: producer притормаживает пропорционально глубине бэклога (в общих очередях — аккуратно: невинные workload'ы страдают).
- **In-flight лимиты**: сообщение, не удалённое после обработки (исключение!), висит in-flight до VisibilityTimeout — форк-бомба при перегрузке: latency пересекает visibility timeout → дубликаты → ещё перегрузка. Лечение: heartbeat продления или остановка работы по истечении.
- **DLQ**: автоматическое отведение необрабатываемых; алерт на ЛЮБОЕ сообщение в DLQ (= баг); повторная обработка после фикса.

## Банковский маппинг

Зарплатные реестры: sidelining фоновых выписок; AgeOfFirstAttempt на топике payments.status; visibility timeout > p99 обработки + heartbeat в длинных проводках.
