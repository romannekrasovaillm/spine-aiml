# Control plane / data plane: меньший флот у руля (Joe Magerramov, AWS)

Типовая асимметрия AWS: data plane (исполняет работу) больше control plane (раздаёт конфигурацию) в 100–1000×. Проблема: если большой флот дёргает маленький — любая корреляция вызовов (баг, восстановление после аварии, ретрай-шторм) валит control plane: goodput падает в ноль.

## Три архитектуры (от простой к сильной)

1. **Data plane дёргает control plane API** (pull за LB). Просто, но хрупко при ×100+ — требует тонкой настройки (load shedding на control plane, backoff+jitter на data plane).
2. **Конфигурация через объектное хранилище (S3-файлы)**: control plane периодически выгружает конфиг в S3; data plane поллит файл и кэширует. Плюсы: S3 масштабируется бесконечно, control plane крошечный, **статическая стабильность** — при падении control plane data plane живёт на последней конфигурации. Так работает AWS Hyperplane (NLB/NAT Gateway/PrivateLink). Минусы: не для высокодинамичной конфигурации и не для доставки за секунды.
3. **Меньший флот у руля (push)**: control plane сам пушит конфигурацию — темп запросов диктует тот, у кого ресурсов меньше; при перегрузке он просто работает медленнее, а не падает. Тонкости: инвентаризация data plane, consistent hashing зон ответственности между control-plane серверами (heartbeat в общую БД), либо разворот направления: data plane открывает long-lived соединение, а control plane по нему вызывает API (решения по локальному состоянию, без распределённых алгоритмов). При ×1000+: лёгкий UDP-«стук» перед установкой соединения (EC2 → Nitro).

## Правила

- Разделяй плоскости всегда: data plane проще и доступнее control plane (у неё больше движущихся частей).
- Темп системы должен контролировать тот, кто слабее.
- Восстановление после аварии не должно требовать control plane (static stability, навык `static-stability`).

## Банковский маппинг

Флот банкоматов/пос-терминалов: конфиги и ключи — push из управляющего контура или файловая доставка; не давать 40 тыс. терминалов опрашивать центральный API напрямую; при недоступности центра терминал работает на последней конфигурации (офлайн-лимиты).
