# Таймауты, ретраи, бэкофф с джиттером (Marc Brooker, AWS)

## Таймауты

- Таймаут — на ЛЮБОЙ вызов через процессы (даже на одной машине): и connect, и request.
- Выбор значения: по метрикам latency зависимости. Допустимая доля ложных таймаутов (напр. 0.1%) → соответствующий перцентиль (p99.9). Не работает: интернет-клиенты (учитывай worst-case сеть) и сервисы с p99.9≈p50 (добавь паддинг).
- Тонкости: таймаут обязан покрывать DNS и TLS-handshake; Linux SO_RCVTIMEO — не end-to-end таймаут. Предпочитай таймауты проверенных клиентов.
- Кейс Amazon: таймаут 20 мс «горел» на установлении TLS-соединения после деплоев → лечение: устанавливать соединения на старте процесса, до приёма трафика.

## Ретраи — «эгоистичны»

- Ретрай тратит время сервера ради шанса клиента. При перегрузке ретраи УСИЛИВАЮТ аварию и отсрочивают восстановление.
- **Амплификация слоёв**: 5 уровней вызовов × 3 ретрая = 243× нагрузки на БД. Правило: ретрай в ОДНОЙ точке стека (для дешёвых control/data-plane операций).
- **Token bucket для ретраев** (AWS SDK, 2016): пока есть токены — ретраим, исчерпаны — ретрай на фиксированной ставке. Альтернатива circuit breaker'у, у которого модальное поведение и дорогое восстановление.
- Ретраим: server errors, транзиентные, таймауты. Не ретраим: client errors (кроме 429), неидемпотентные side effects. Соблюдай eventual consistency: «client error» может стать успехом после распространения состояния.

## Джиттер

- Рандомизация момента ретрая — размазывает коррелированные волны. Capped exponential backoff + jitter обязательны вместе.
- Джиттер не только для ретраев: периодические джобы, cron, таймеры — иначе все хосты стреляют в первую секунду минуты.
- Тонкость Amazon: для периодических работ джиттер выбирается НЕ случайно, а консистентно для хоста — повторяемость паттерна упрощает поиск root cause.

## Банковский маппинг

Платёжный оркестратор → ядро: таймаут из p99.9 ядра; ретрай только в оркестраторе (не в каждом фильтре); 500 мс сквозного бюджета включает ретрай-дедлайн; ночные реестры — джиттер по окну банковского дня.
