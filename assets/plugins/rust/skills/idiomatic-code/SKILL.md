# Идиоматичный Rust

Навык для написания кода, который выглядит так, будто его писал опытный расточник: компилируется без предупреждений, проходит `clippy -D warnings`, следует Rust API Guidelines и не борется с borrow checker'ом, а использует его как инструмент дизайна.

## Базовые установки

- **Edition 2024** — текущая редакция языка (стабильна с Rust 1.85). Новые проекты создавай на ней. Ключевые отличия от 2021: `unsafe_op_in_unsafe_fn` включён по умолчанию, изменены правила захвата лайфтаймов в RPIT (`impl Trait`), атрибуты вроде `no_mangle` требуют `#[unsafe(...)]`.
- Rust выпускает стабильный релиз каждые 6 недель. Если задача зависит от конкретной версии/фичи — проверь актуальный статус через https://releases.rs/ или блог https://blog.rust-lang.org/, а не по памяти.
- Код всегда должен проходить: `cargo fmt`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test`.

## Методология: порядок работы над задачей

1. **Сначала типы, потом код.** Смоделируй домен так, чтобы некорректные состояния были непредставимы (*make invalid states unrepresentable*): enum вместо флагов + Option-полей, newtype вместо голых `String`/`u64`, typestate для протоколов с фазами. Компилятор — твой главный тест.
2. **Реши вопросы владения на уровне сигнатур.** По умолчанию принимай заимствования (`&str`, `&[T]`, `&T`), забирай владение (`String`, `Vec<T>`, `T`) только когда функция реально потребляет или сохраняет значение. Возвращай владеемые значения или `impl Iterator`/`impl Trait`.
3. **Ошибки — часть API.** Спроектируй тип ошибки до реализации (см. `references/error-handling.md`).
4. **Пиши код, читая подсказки компилятора полностью.** rustc даёт точные объяснения и часто готовый фикс (`rustc --explain E0502`). Не «затыкай» borrow checker клонированием — сначала попробуй реструктурировать (сузить область заимствования, разбить структуру на части, вынести вычисление до мутации).
5. **Прогони clippy и осмысленно отработай каждый линт.** Подавление `#[allow]` — только с комментарием-обоснованием.
6. **Документируй публичное API** rustdoc-комментариями с работающими примерами (они выполняются как doctests) и секциями `# Errors`, `# Panics`, `# Safety` где применимо.

## Ownership: рабочие правила

- Заимствуй по умолчанию; `clone()` — осознанное решение, а не способ утихомирить компилятор. Если клонирование напрашивается — это сигнал пересмотреть структуру данных (например, разделить структуру на независимые поля, использовать индексы вместо ссылок, `std::mem::take`/`replace` для перемещения из `&mut`).
- Для дешёвого разделяемого владения — `Rc<T>` (однопоточно) / `Arc<T>` (многопоточно). Внутренняя изменяемость: `Cell<T>` (Copy-типы) → `RefCell<T>` (однопоточно) → `Mutex<T>`/`RwLock<T>` (потоки) → `OnceLock`/`LazyLock` (ленивая инициализация статики). Выбирай минимально мощный инструмент.
- `Cow<'_, str>` — когда функция иногда модифицирует вход, а чаще нет.
- Лайфтаймы аннотируй только когда elision не справляется; если аннотации расползаются по всему API — вероятно, где-то стоит владение вместо ссылки.
- Самоссылочных структур избегай (реструктурируй, используй индексы/арены); это не тот случай, где нужен `unsafe`.

## API-дизайн (сжатая выжимка Rust API Guidelines)

Полный чеклист и примеры — в `references/api-design.md`. Читай его при проектировании любого публичного API (библиотеки, общего модуля). Минимум, который применяй всегда:

- Именование: `snake_case` функции, `UpperCamelCase` типы, конверсии `as_` (дёшево, ссылка→ссылка), `to_` (дорого), `into_` (с передачей владения); геттеры без префикса `get_`; итераторы `iter()`/`iter_mut()`/`into_iter()`.
- Выводи стандартные трейты где осмысленно: `Debug` — почти всегда, плюс `Clone, PartialEq, Eq, Hash, Default`, для публичных enum — подумай про `#[non_exhaustive]`.
- Принимай `impl Into<T>`/`AsRef<str>`/`IntoIterator` для эргономики на входе; **не** возвращай абстракции сложнее необходимого.
- Конструкторы: `new()` для простых случаев, builder — когда полей много/опциональны.
- Никаких паник в библиотечном коде на ожидаемых ошибках — только `Result`. Паника допустима лишь при нарушении внутреннего инварианта (и это документируется в `# Panics`).

## Паттерны и антипаттерны

Каталог с примерами кода — `references/patterns.md`. Читай при рефакторинге и ревью. Ключевое:

- **Newtype** для доменных типов и обхода orphan rule; **Builder** для сложной конструкции; **RAII-guard** для ресурсов; **typestate** для конечных автоматов в типах.
- Итераторные цепочки (`map/filter/collect`) вместо ручных циклов с аккумулятором — но без фанатизма: если цепочка нечитаема, обычный `for` лучше.
- `match` — исчерпывающий; `if let`/`let else` для одного варианта; `let else` идиоматичен для ранних выходов.
- Антипаттерны: `Deref` для эмуляции наследования; `clone()` ради borrow checker; `unwrap()` в неигрушечном коде (вместо него `expect("описание нарушенного инварианта")` и только для доказуемых инвариантов); булевы параметры-флаги (замени на enum); `Vec<Box<dyn Trait>>` там, где хватит enum-диспетчеризации.
- Generics (`impl Trait`/`<T: Trait>`) — статическая диспетчеризация по умолчанию; `dyn Trait` — когда нужна гетерогенная коллекция, плагинность или важен размер бинарника/время компиляции.

## Обработка ошибок — кратко

Подробно — `references/error-handling.md` (читай при проектировании ошибок). Резюме:

- **Библиотека**: свой тип ошибки (enum) с `std::error::Error`, обычно через `thiserror`; сохраняй `#[source]`; не навязывай `anyhow` пользователям.
- **Приложение**: `anyhow::Result<T>` (или `eyre`) + `.context("что делали")` на каждом fallible-вызове; `main() -> anyhow::Result<()>`.
- `?` — основной механизм проброса; `From`-конверсии между ошибками; `Option`→`Result` через `ok_or_else`.
- Различай **ошибки** (ожидаемые, восстановимые → `Result`) и **баги** (нарушенные инварианты → `panic!`/`assert!`/`debug_assert!`).

## Инструменты качества

```toml
# Cargo.toml — базовая конфигурация линтов (workspace или пакет)
[lints.rust]
unsafe_code = "forbid"        # для кода без FFI
missing_docs = "warn"          # для библиотек

[lints.clippy]
all = { level = "warn", priority = -1 }
pedantic = { level = "warn", priority = -1 }  # включай осознанно, глуши точечно
unwrap_used = "warn"
```

- `cargo fmt` — не обсуждается, стиль задаёт официальный Rust Style Guide.
- `cargo clippy --all-targets --all-features -- -D warnings` — в CI обязателен.
- `cargo doc --no-deps` — проверяй, что документация собирается и intra-doc-ссылки не битые.
