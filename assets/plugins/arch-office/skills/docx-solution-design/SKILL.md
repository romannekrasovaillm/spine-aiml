# Документ архитектурного решения (docx)

SAD отвечает на вопрос «что строим и почему именно так». Читатели: архкомитет,
команды реализации, эксплуатация. Родственные навыки: `adr-authoring`
(точечные решения), `nfr-design` (требования), `c4-mermaid` (диаграммы).

## Железные правила

- Раздел «Варианты» обязателен и честен: минимум 2 альтернативы + «не делать
  ничего»; у каждой — следствия. Решение без альтернатив — не обосновано.
- Каждое ключевое утверждение решения трассируется к драйверу или требованию
  (ссылка на ID требования, напр. NFR-3).
- Диаграммы — через `mermaid_render` (C4-контекст и контейнеры), в документ
  вставляются как текст-арт или перегенерируются в PNG внешним рендерером;
  ASCII-арт в docx — только моноширинным шрифтом (скелет это делает).
- NFR — измеримые (цель + метод проверки), не «быстро и надёжно».
- План внедрения содержит критерии выхода и план отката — без них документ
  не уходит на комитет.
- Статусы решения фиксируются (Проект/На ревью/Утверждено) — документ
  версионируется, старые версии не затираются.

## Структура (фиксированная)

1. О документе (статус, версия, авторы, ссылки на ADR).
2. Контекст и драйверы (бизнес-цель, ограничения, заинтересованные стороны).
3. Требования: функциональные (кратко) + NFR с целями и проверкой.
4. Варианты решения (≥2 + «нулевой вариант») и оценка.
5. Выбранное решение: C4-контекст, контейнеры, ключевые потоки (sequence).
6. Стыки и контракты (ссылки на интеграционные спецификации).
7. Риски и митигации (связь с реестром рисков, `xlsx-risk-register`).
8. План внедрения: этапы, критерии выхода, план отката.

## Процедура

1. Собери драйверы и требования из исходников (`kb_search`, чтение спек).
2. Диаграммы: `mermaid_render` → проверка компоновки → вставка в раздел 5.
3. Скелет `references/docx_solution_design_gen.py` (python-docx): заполни
   структуры, запусти `python3 docx_solution_design_gen.py sad.docx`.
4. Прочитай назад (заголовки + таблицы), сверь с чек-листом.

## Чек-лист приёмки

- ≥2 альтернативы с честными минусами; выбор обоснован драйверами.
- Каждый NFR измерим (число + как проверить).
- Диаграммы читаются (моноширинный блок, без разрывов узлов).
- Есть критерии выхода и план отката.
