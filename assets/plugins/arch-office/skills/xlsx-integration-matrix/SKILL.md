# Матрица интеграций (xlsx)

Матрица отвечает «кто с кем связан и что будет, если этот стык умрёт».
Два вида: реестр стыков (строка = стык, основной) и квадратная матрица
N×N (для наглядности на комитете). Скелет строит реестр + сводку по системам.

## Железные правила

- Стык направленный: A→B и B→A — две строки; «двусторонне» запрещено
  (скрывает, кто инициатор и кто отвечает за контракт).
- Каждый стык ссылается на контракт (интеграционную спецификацию,
  `docx-integration-spec`) или помечается «контракта нет» — это находка.
- Протокол и формат из словаря (REST/JSON, AMQP/proto, файлы CSV/SFTP…) —
  свободный текст ломает сводки.
- Критичность стыка ≠ критичности систем: стык витального потока важнее
  вспомогательной системы; оценивается по потоку.
- Частота/объём — числами (RPS, соб/сут, размер пакета), не «часто».
- Сводка по системам (сколько стыков наружу/внутрь, сколько без контракта)
  — обязательный лист: на ней видны «осьминоги».

## Колонки (лист «Стыки»)

ID стыка · Источник · Приёмник · Поток (что передаётся) · Протокол/формат ·
Частота/объём · SLA · Критичность · Контракт (ссылка/«нет») · Владелец ·
Комментарий.

Лист «Сводка по системам»: система · исходящих · входящих · без контракта ·
критичных стыков — считается формулами (`COUNTIF`) по реестру.

## Процедура

1. Собери стыки из кода (клиенты/продюсеры/консьюмеры), схем, каталогов;
   каждый стык проверяем.
2. Скелет `references/xlsx_integration_matrix_gen.py` (openpyxl): заполни
   `LINKS`, `python3 xlsx_integration_matrix_gen.py matrix.xlsx`.
3. Прочитай назад, сверь с чек-листом.

## Чек-лист приёмки

- Нет «двусторонних» записей; каждый стык имеет владельца и SLA.
- Сводка сходится с реестром (формулы, не ручные числа).
- Стыки без контракта явно видны (фильтр «нет»).
