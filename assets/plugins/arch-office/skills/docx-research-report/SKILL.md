# Аналитический отчёт для МД (docx)

Отчёт для управляющей дирекции читают по диагонали: сначала «Резюме», потом
матрицы и «Рекомендации». Тело — доказательная база, а не эссе.

## Железные правила

- **«Резюме» — на первой странице и самодостаточно**: 5–8 предложений, из него
  понятны предмет, главный вывод и рекомендация. Пишется ПОСЛЕДНИМ.
- Каждая оценка — из матрицы: сравнение альтернатив только таблицей
  (критерии × объекты, шкала зафиксирована легендой, напр. 1–5).
- Утверждения о версиях/статусе/ценах — только с источником (URL, дата
  обращения). Не проверено — пометка `[ТРЕБУЕТ ПРОВЕРКИ]`, не выдумывать.
- Тон: управленческий русский, без жаргона и без «мы думаем»; позиция —
  от организации («целесообразно», «риск состоит в…»).
- Структура фиксирована (домовый стиль отчётов для МД): О документе → Резюме →
  Предмет и метод → Ландшафт/разделы → Сравнительная оценка (матрица) →
  Рекомендации → Выводы → Приложения (глоссарий, источники).
- Один документ — один вопрос. Смежные вопросы — в «Приложения» или
  в отдельный отчёт серии.

## Процедура

1. Собери фактуру инструментами (`kb_search`, `web_fetch` по первоисточникам);
   зафиксируй источники с датами.
2. Заполни структуру разделов; сравнения оформи как списки строк матрицы.
3. Сгенерируй документ скриптом-скелетом `references/docx_research_report_gen.py`
   (python-docx): скопируй его рядом с рабочим файлом, заполни структуры
   `SECTIONS`/`MATRIX`/`SOURCES`, запусти `python3 docx_research_report_gen.py out.docx`.
4. Прочитай результат назад (python-docx: заголовки, число таблиц) и сверь
   с чек-листом ниже, прежде чем отдавать пользователю.

## Чек-лист приёмки

- «Резюме» помещается на первой странице и содержит рекомендацию.
- Есть хотя бы одна сравнительная матрица с легендой шкалы.
- Все внешние факты имеют источники в разделе «Источники» (URL + дата).
- Заголовки нумеруются, стили консистентны (скелет даёт это из коробки).
