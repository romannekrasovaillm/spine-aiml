# Каталог систем (xlsx)

Каталог систем — опорный регистр: на него ссылаются аудит
(`docx-current-state-assessment`), матрица интеграций, дорожные карты.
Он живёт постоянно, а не под задачу — поэтому колонки минимальны и устойчивы.

## Железные правила

- Одна строка — одна система; идентификатор стабилен (код системы),
  переименование не меняет ID.
- Колонки — только поддерживаемые: если за «владельцем» никто не следит,
  колонка пустует и обесценивает каталог; лучше меньше колонок, но живых.
- Критичность — по шкале банка (критичная/важная/стандартная или C1–C3) —
  зафиксировать легенду на листе «Легенда».
- Статус жизненного цикла — из закрытого списка: pilot / active / sunset /
  retired; свободный текст запрещён (ломает фильтры и сводки).
- Каталог не дублирует CMDB: он архитектурный (критичность, домен,
  жизненный цикл, инициативы), а не инвентарный (серверы, IP).
- Лист «Легенда» со словарями значений обязателен.

## Колонки (лист «Системы»)

ID · Название · Домен · Назначение (1 строка) · Владелец (команда) ·
Критичность · Стек (язык/БД/платформа) · Жизненный цикл ·
Связанные инициативы/ADR · Комментарий.

## Процедура

1. Собери системы из репозиториев/реестров/интервью; каждая строка — из
   проверяемого источника.
2. Скелет `references/xlsx_system_catalog_gen.py` (openpyxl): заполни
   `SYSTEMS` и словари `LEGENDS`, `python3 xlsx_system_catalog_gen.py catalog.xlsx`.
3. Прочитай назад (openpyxl: листы, число строк), сверь с чек-листом.

## Чек-лист приёмки

- Фильтры и закреплённая шапка работают; ширины колонок по содержимому.
- Жизненный цикл и критичность — только из словарей легенды.
- Нет дублей ID; назначение умещается в одну строку.
