# Интеграционная спецификация (docx)

Спецификация стыка — единственный источник истины для двух команд, которые
больше не разговаривают друг с другом. Всё, что не записано, будет реализовано
по-разному.

## Железные правила

- Каждая операция: семантика + пример сообщения (валидный JSON/XML) +
  коды ошибок с поведением вызывающей стороны.
- Идемпотентность — явно: ключ дедупликации, окно хранения, поведение
  при повторе. Без этого стык денег/статусов не проектируется.
- Ретраи и таймауты — с числами (таймаут, число попыток, backoff, дедлайн);
  «retry при сбое» без чисел не считается.
- Версионирование контракта: правила совместимости (только добавление
  необязательных полей и т.п.), политика sunset для старых версий.
- SLA — измеримый (p95/p99, окно измерения, источник метрик), а не «быстро».
- Тестовые сценарии — обязательный раздел: позитив, дубль, таймаут,
  частичный сбой, некорректное сообщение.

## Структура (фиксированная)

1. О документе (участники, роли Поставщик/Потребитель, статус версии).
2. Общая схема взаимодействия (диаграмма последовательности).
3. Транспорт и безопасность (протокол, аутентификация, каналы).
4. Операции (на каждую: семантика, запрос/ответ с примерами, ошибки).
5. Идемпотентность и дедупликация.
6. Таймауты, ретраи, дедлайны.
7. SLA и лимиты нагрузки.
8. Версионирование и совместимость.
9. Тестовые сценарии и точка подключения стенда.

## Процедура

1. Выпиши операции и их семантику из кода/контрактов (инструменты чтения,
   `grep` по схемам); не проектируй по памяти.
2. Диаграмму потока проверь `mermaid_render` (sequenceDiagram).
3. Скелет `references/docx_integration_spec_gen.py` (python-docx):
   заполни структуры, `python3 docx_integration_spec_gen.py spec.docx`.
4. Прочитай назад, сверь с чек-листом.

## Чек-лист приёмки

- У каждой операции есть пример сообщения и таблица ошибок.
- Идемпотентность, ретраи и SLA — с числами.
- Есть раздел тестовых сценариев с ожидаемыми результатами.
