# Реестр архитектурных рисков (xlsx)

Реестр рисков — рабочий инструмент, а не отчёт «для галочки»: у каждого
риска есть владелец митигации и дата пересмотра, иначе реестр мёртв.

## Железные правила

- Риск формулируется как событие с причиной и следствием: «из-за X может
  случиться Y, что приведёт к Z». «Риск: микросервисы» — не риск.
- Вероятность и влияние — по шкале 1–5 с определениями на листе «Легенда»
  (влияние — в деньгах/простое/регуляторике, не «высокое»).
- Оценка дважды: исходная (до мер) и остаточная (после мер). Митигация без
  изменения оценки — не митигация.
- У каждой меры: владелец (роль/команда) и срок. «Команда разберётся» —
  не владелец.
- Статусы из закрытого списка: open / mitigating / accepted / closed;
  accepted-риск требует подписи руководителя уровня, который может
  принять потерю.
- Связи: находка аудита (F-N), ADR, волна миграции — риск без привязки
  теряется.

## Листы

1. «Реестр»: ID · Риск (причина→событие→следствие) · Категория ·
   Вероятность (1–5) · Влияние (1–5) · Балл (=П×В) · Митигация · Владелец ·
   Срок · Остаточная В/В/балл · Статус · Связи · Дата пересмотра.
2. «Карта 5×5»: распределение рисков по клеткам вероятность×влияние
   (формулы COUNTIFS + цветовые зоны).
3. «Легенда»: шкалы влияния и вероятности, словарь статусов.

## Процедура

1. Собери риски из находок аудита/SAD/интервью; переформулируй в
   причина→событие→следствие.
2. Скелет `references/xlsx_risk_register_gen.py` (openpyxl): заполни
   `RISKS`/`SCALES`, `python3 xlsx_risk_register_gen.py risks.xlsx`.
3. Прочитай назад, сверь с чек-листом.

## Чек-лист приёмки

- У каждого риска: владелец меры, срок, остаточная оценка, дата пересмотра.
- Карта 5×5 заполнена формулами и сходится с реестром.
- Accepted-риски имеют ссылку на решение о принятии.
