# Здоровье RL-контура

RL в лесенке — GRPO: группы задач × роллаутов на шаг (v12: 4×2 = 8),
reward функциональный (релевантный вызов инструмента + попадание slug'ов),
плюс встроенный GEN-EVAL раз в N шагов — perplexity на общем тексте как
датчик забывания. Ключевой урок v12: **RL после хорошего SFT — полировка,
а не рост**. Ждать от 500 шагов с группой 4×2 скачка попаданий не стоит;
ждать стоит роста качества (PARTIAL, балл судьи) при сохранении базы.

## 1. Считать, а не смотреть на глаз

```bash
python3 scripts/rl_health.py ~/experiments/<run>/rollouts_log.jsonl \
    [--agg rl_steps_agg.csv] [--total-steps 500] [--json]
```

Скрипт агрегирует по шагам и четвертям: reward mean/std, pass-rate
(доля роллаутов с reward ≥ 1), энтропию (min и доля шагов ниже порога),
KL, clip-fraction, длину ответа, tool-calls/роллаут, ppl_general
(тренд и отклонение от первого замера), и печатает диагноз по
`references/thresholds.md`. Поля угадываются; при иной схеме — `--inspect`
и `--field ключ=имя`.

## 2. Эталон здорового контура (v12, 1.5B, 500 шагов)

| Метрика | Значение | Как читать |
|---|---|---|
| reward mean | 0.428 (Q1 0.429 → Q4 0.383) | без роста, но и не деградация |
| pass-rate | 44%, колебания 0–75% по шагам | высокая дисперсия — норма для группы 8 |
| энтропия | 0.9–1.5, ни разу ниже 0.9 | нет коллапса |
| KL | ≤ 0.001 | почти не уехала от SFT — консервативно |
| clip-fraction | 0.000 | апдейты не срезались |
| длина ответа | 2.5–4k токенов, стабильна | нет раздувания/схлопывания |
| tool-calls/роллаут | ≈ 1.1 | компактный «поиск → ответ» |
| ppl_general | 50.8 ± 0.1% (шаги 200–475) | забывания нет |
| ppl_domain | 3.6 | домен выучен ещё на CPT |

Результат такого профиля: +2 попадания (в шуме), judge 0.045→0.104,
PARTIAL 1→9. Это «регуляризованная полировка».

## 3. Диагнозы

| Картина | Диагноз | Действие |
|---|---|---|
| энтропия падает < 0.5 и не возвращается | коллапс политики | остановить, откатить на чекпоинт до падения, уменьшить lr / усилить KL-штраф |
| KL растёт > 0.01 при падении ppl_general на > 2% | уехали от базы, забывание | снизить lr, добавить replay/KL-штраф |
| reward растёт, pass-rate растёт, ppl_general стабилен | здоровый рост | продолжать; можно увеличивать группу |
| reward плоский, KL≈0, clip=0 | полировка (v12) | норма при малом бюджете; для роста — §4 |
| длина ответа растёт монотонно | reward hacking на длине | штраф за длину / проверить reward |
| tool-calls/роллаут ≫ 2 или → 0 | сломан формат вызова | смотреть роллауты, чинить парсер/промпт |
| ошибок парсинга роллаутов > 5% | обрыв на max_len или формате | проверить `<|im_end|>`-артефакты после SFT |
| pass-rate 0 на серии шагов подряд | сложность задач/поломка инструмента | проверить search_concepts, лог tool_response |

## 4. Бюджет: когда «полировки» мало

Если цель — рост попаданий, а не регуляризация:
1. Сначала закрыть вопрос судьи (иначе рост не измерить) — `ood-stage-eval`.
2. Группа 4×2 → 8×4 (дисперсия advantage падает вчетверо); на GB10
   считать память под vLLM-роллауты (длина 4k × 32 роллаута).
3. Шаги 500 → 1500 при том же lr; следить за KL и ppl_general каждые 25.
4. Reward: добавить градацию за частичное попадание (один slug из двух)
   вместо бинарного — иначе сигнал слишком редкий при pass-rate 44%.
5. Не менять всё сразу: одна ось на прогон, иначе результат не
   атрибутируется.

## 5. Отчёт

Одна таблица (как в §2) + один график (reward/pass-rate/энтропия/длина
по шагам) + фраза-диагноз из §3 + число рестартов RL (v12: 4, rc=1,
NVRM) со ссылкой на `laguna-ladder-run`.
