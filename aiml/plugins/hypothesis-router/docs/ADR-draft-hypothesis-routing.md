# ADR-draft: Роутинг гипотез по фактам проекта (плагин hypothesis-router)

Статус: PROPOSED (через evolve propose; аппрувер — владелец Spine)

## Контекст
Библиотека — ~1000 скиллов и ~170 плагинов. Отбор по description работает
для активных доменных наборов и не работает для латентных личных наборов:
им не с чего конкурировать. Контекстная инженерия решает, что положить в
окно; она не решает, из чего выбирать и когда вспомнить. Не хватает двух
вещей: памяти о намерении с жизненным циклом и роутинга по фактам проекта.

## Решение
1. Ввести карточку гипотезы `HYPOTHESIS.md` (скилл `hypothesis-card`) как
   обязательный артефакт при помещении набора скиллов в библиотеку.
   Состояния: fleeting / latent / active / project / archived; переходы —
   по касаниям и по времени, предлагаются скриптом, утверждаются человеком.
2. Ввести ярус «теплица»: скиллы карточек в состояниях fleeting/latent не
   участвуют в общем отборе по description; поднимаются только триггером
   или явной командой.
3. Три точки вызова в ядре, все — через существующий механизм плагин-хуков
   (без зависимости ядра от плагина, AD-1; без LLM, AD-2):
   - `intent`: на входе первого контура, до сбора REQ/NFR — одна строка
     «пересекающиеся гипотезы — поднять?».
   - `pre_handoff`: при `handoff_create`, до записи MANIFEST — по файлам,
     ключам конфигов, зависимостям и тексту TASK.md; пишет HYPOTHESES.json,
     объединяет `skills` в MANIFEST.
   - `post_accept`: при принятии worktree — касание карточек из
     HYPOTHESES.json.
   Плюс `library_changed` → пересборка `routing.json` (плоская таблица
   триггеров для детерминированного слоя).
4. Fitness-правила плагина (`fitness/hypothesis-routing.yaml`) гейтят
   наличие HYPOTHESES.json в пакете и свежесть routing.json.

## Что нужно от ядра (единственная правка)
`harness.rs::handoff_create` и точка принятия worktree должны вызывать
хуки плагинов с событиями `pre_handoff(project_dir, handoff_dir)` и
`post_accept(handoff_dir, project_name)`, если таковых ещё нет; вход
намерения — событие `intent(text, project_dir)`. Контракт: хук — процесс,
stdout ≤ 1 строка для TUI, exit 0/2/3. Пока правки нет — правила
`command_succeeds` вызывают хук сами (см. docs/spine-integration.md).

## Последствия
+ Латентные наборы всплывают по свидетельствам в репо, не по памяти модели.
+ Теплица не разбавляет корпоративный поиск.
+ Жизненный цикл даёт основание архивировать, а не копить.
− Ещё один артефакт при дистилляции (мал; скрипт с интервью).
− Триггеры нужно выверять; шумные словесные триггеры дают ложные подъёмы
  (смягчено весами и порогом).

## Альтернативы
- Семантический поиск по description с эмбеддингами — не решает «когда
  вспомнить» и не различает латентное/активное.
- Теги проектов вручную — не поддерживаются без дисциплины; факты в репо
  уже есть.
