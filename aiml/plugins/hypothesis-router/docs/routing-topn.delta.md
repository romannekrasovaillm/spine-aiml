# DELTA: нормированный балл, ограничение числа и диверсификация подъёма гипотез

- Дата: 2026-09-14 · Маршрут: Standard (score 3: api_contract_change, data_contract_change, significant_nfr)
- Затрагивает: `aiml/plugins/hypothesis-router/skills/hypothesis-card/scripts/card_match.py`,
  `aiml/plugins/hypothesis-router/hooks/hypothesis_hook.py`,
  поведение `intent` / `pre-handoff` (то есть содержимое `.arch-handoff/HYPOTHESES.json` и `MANIFEST.json`)

## 1. Контекст и проблема (измерено 14.09.2026)

Реестр вырос за сутки с 1 карточки до 43 (417 триггеров в `routing.json`).
Симптомы, подтверждённые прогонами:

1. **В проекте поднимаются все карточки.** `card_match --project кейсы/kimi-killer`
   при пороге `min_score=2` возвращает 43 из 43: порог абсолютный, а число
   триггеров на карточку выросло до 8–12, поэтому любого совпадения файла
   (вес 3) достаточно.
2. **Словесный слой почти не работает.** Фразы намерения дают 1 совпадение
   (вес 1 < порога 2): из 6 проверенных фраз карточку подняла одна.
3. **Handoff-пакет зашумлён.** `pre-handoff` пишет в `HYPOTHESES.json` все
   совпадения и объединяет скиллы всех карточек: на 14.09 — 16 hits и 32
   скилла в `MANIFEST.json` при 43 карточках в реестре.
4. **Дубли по триггерам.** Jaccard-анализ (14.09) дал 10 пар с перекрытием
   ≥ 0.35, максимум 0.67 (`learnability-frontier-task-synth` ↔
   `task-difficulty-curriculum`), 0.57 (`frozen-router-mopd` ↔
   `router-prior-anchor`). Истинных дублей нет (≥ 0.8 нет ни одной пары), но
   в одну задачу приходят почти одинаковые наборы карточек.

## 2. Решение

1. **Нормированный балл.** Для каждой карточки считать
   `max_possible = 3*|files| + 3*|keys| + 2*|deps| + 1*|words|` и
   `norm = score / max_possible` (округление 4 знака). `norm` выводится в
   отчёте и в JSON (`--json`), в `routing.json` **не добавляется**
   (сохраняем совместимость HYP-02).
2. **Ограничение числа поднятых.** Новый флаг `--max-cards N`
   (0 = без ограничения, **значение по умолчанию — 0**, поведение CLI без
   флага не меняется). Сортировка: `score` убыв., при равенстве — `id`
   возр. (детерминизм).

   **Решение архитектора 14.09 (после прогона харнесса, коммит 512c4ef):**
   норм-тайбрейк (§2.2 в первой редакции — «при равенстве score сортировать
   по `norm` убыв.») **отклонён**. Причины: (а) он ломает K2 (детерминизм
   при равных баллах) и K6 (неизменность вывода CLI без новых флагов) —
   проверено на реальных данных: в группах score 20 и 17 значения `norm`
   различаются (0.9091 / 0.8333 / 0.7727), порядок менялся бы; (б) вариант
   «тайбрейк только при `max-cards > 0`» создал бы два разных порядка
   вывода — источник путаницы; (в) `norm` остаётся **информационным полем**
   (печатается в строке карточки и в JSON) и материалом для будущих решений.
   Замена отклонённому тайбрейку — диверсификация по перекрытию (п. 3):
   именно она защищает набор от почти одинаковых карточек.
3. **Диверсификация по перекрытию.** Новый флаг `--dedupe J` (по умолчанию
   0.0 = выключено). Если множества **совпавших** триггеров двух карточек
   дают Jaccard ≥ J, остаётся карточка с большим `score` (при равенстве —
   с меньшим `id`); вторая попадает в список `suppressed` с причиной
   «перекрытие с <id> = <jaccard>» и в набор не входит.
4. **Хук.** `hypothesis_hook.py` читает окружение:
   - `HYPOTHESES_MAX_CARDS` (по умолчанию: `8` для `pre-handoff`, `5` для `intent`),
   - `HYPOTHESIS_DEDUPE` (по умолчанию `0.5`).
   В `HYPOTHESES.json` добавляются поля `norm` и `suppressed`
   (список `{card, suppressed_by, jaccard}`); `hits` содержит только
   неподавленные. `MANIFEST.json.skills` собирается **только** с поднятых
   карточек.
5. **Тесты.** Добавить `aiml/plugins/hypothesis-router/tests/test_card_match.py`
   и `.../tests/test_hook_topn.py` (pytest, stdlib-only, без сети).

## 3. Критерии приёмки (механические)

| ID | Проверка |
|---|---|
| K1 | `card_match --project <кейс kimi-killer> --max-cards 5` печатает ровно 5 карточек, отсортированных по `score` (убыв.) |
| K2 | При двух карточках с равным `score` порядок совпадает при повторных прогонах и соответствует `id` по возрастанию |
| K3 | `--dedupe 0.5 --project <кейс>` подавляет вторую карточку хотя бы одной пары с Jaccard ≥ 0.5 (на 14.09 — `frozen-router-mopd` ↔ `router-prior-anchor`; в `suppressed` записан коэффициент **по совпавшим триггерам — 0.7778**, пара и коэффициент указаны). Уточнение архитектора 14.09: коэффициент в `suppressed` считается по совпавшим триггерам согласно §2.3; величина 0.5714 из §1.4 — это Jaccard по **полным** наборам (метрика обзора перекрытия, не критерий) |
| K4 | `pre-handoff` при `HYPOTHESES_MAX_CARDS=8` пишет `HYPOTHESES.json` с `len(hits) ≤ 8`, поля `norm` есть у каждого hit, `suppressed` — список |
| K5 | `MANIFEST.json.skills` содержит объединение скиллов только `hits` (проверяется сверкой с `routing.json`) |
| K6 | Без новых флагов CLI поведение `card_match` не менялось (сравнение вывода на сохранённом снимке): тот же набор и порядок, что до дельты |
| K7 | `pytest aiml/plugins/hypothesis-router/tests/ -q` — зелёный; `arch-ml control check . --constraints aiml/library/fitness/hypothesis-routing.yaml` — без новых нарушений (HYP-01..04 как были) |
| K8 | `routing.json` по формату прежний: `{"min_score": N, "rows": [...]}`; правило HYP-02 проходит |

## 4. Запреты

- Не менять `--min-score` по умолчанию (2) и не менять веса триггеров (files/keys 3, deps 2, words 1).
- Не менять карточки в `~/hypotheses` и не трогать `routing.json` в части формата.
- Не удалять карточки и не менять их состояния.
- Не добавлять LLM-вызовы в отбор: механизм обязан оставаться детерминированным (внешний результат SYNAPSE, arXiv:2609.06815: статистика над тем же опытом бьёт LLM-роутинг на 26–48 п.п.).
- Не трогать `card_new.py`, `card_review.py`, `cardio.py` (кроме чтения — если понадобится вынести расчёт `norm`, выносить в `card_match.py`).

## 6. Открытые вопросы (решаются в реализации, с фиксацией в отчёте)

- Точная формула `max_possible`: учитывать ли уникальные значения или суммы с повторами (в 43 карточках повторов внутри одного вида нет).
- Нужно ли нормировать по «виду» (например, отдельно считать норм для files) — если простая нормы окажется неразличительной.
- Порог по умолчанию для `--dedupe` в CLI (предлагается 0.0 = выключено, чтобы не менять поведение по умолчанию).
