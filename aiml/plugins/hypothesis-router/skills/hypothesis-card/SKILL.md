# Карточки гипотез

Скилл кодирует одно правило: **дистилляция без карточки в библиотеку не
принимается.** Скилл отвечает на «как», карточка — на «зачем и когда».
Без второй первый через полгода неотличим от тысячи соседей, и поиск по
description его честно не находит — не с чего предпочесть.

Карточка — файл `HYPOTHESIS.md` с YAML-фронтматтером (машиночитаемая
часть: состояние, триггеры, связи) и коротким телом (человеческая часть:
намерение, что сделало бы это проектом, открытые вопросы). Полная схема —
`references/card-schema.md`, живой пример — `references/example-laguna.md`.

## 1. Когда заводить

В момент дистилляции, пока контекст в голове: сразу после того, как из
отчёта/статьи/разговора сделан набор скиллов, плагин или просто заметка
«интересно». Через полгода триггеры не восстановишь. Если пользователь
принёс готовые скиллы без карточки — предложи завести её первым шагом.

## 2. Как заводить — короткое интервью, не форма

Спроси только то, чего нет в контексте (обычно источник и скиллы уже
известны):
1. **Намерение** одной фразой: что хочется уметь/понять.
2. **Состояние**: мимолётно (`fleeting`), пригодится (`latent`), уже
   применяю (`active`), это отдельный проект (`project`).
3. **Триггеры** — факты, по которым это должно всплыть *без поиска*:
   имена/паттерны файлов в репо, ключи конфигов и env, зависимости,
   слова в формулировке намерения. Просить конкретику: «GB10» и
   `rollouts_log.jsonl` — триггеры; «обучение моделей» — шум.
4. **Что сделало бы это проектом** — условие перехода `latent → project`.

Затем:
```bash
python3 scripts/card_new.py --dir ~/hypotheses --id laguna-gb10-ladder \
  --title "Лесенка маленьких моделей на GB10" --state latent \
  --source "Отчёт v12_qwen25-15b_s42, 13.09.2026" \
  --trigger-file 'rollouts_log.jsonl' --trigger-file 'eval_results_*.json' \
  --trigger-key LAGUNA_MEM_FRACTION --trigger-word GB10 --trigger-word CPT \
  --skill laguna-ladder-run --skill ood-stage-eval
```
Тело карточки допиши руками (скрипт оставляет заготовки разделов). Триггеры
задаются с весами по умолчанию: файл/ключ конфига — сильный сигнал,
зависимость — средний, слово — слабый (см. схему).

## 3. Роутинг по фактам проекта

Это вторая половина механизма: карточки всплывают не потому, что модель
угадала по описанию, а потому что в проекте лежит нужный файл.

```bash
# что из теплицы относится к этому репо / намерению
python3 scripts/card_match.py --dir ~/hypotheses --project ~/work/spark-run \
    --intent "поднять RL для 3B на Spark" [--min-score 2] [--json]
# сколько поднять и без почти-дублей
python3 scripts/card_match.py --dir ~/hypotheses --project ~/work/spark-run \
    [--max-cards 5] [--dedupe 0.5]
# таблица триггеров для детерминированного слоя харнесса
python3 scripts/card_match.py --dir ~/hypotheses --emit-routing routing.json
```
`card_match.py` считает балл по совпавшим триггерам и печатает карточки с
привязанными скиллами. Порог `--min-score` — чтобы слабые словесные
совпадения не поднимали всё подряд; `norm` (балл к потолку карточки) —
чтобы сравнивать карточки с разным числом триггеров. `--max-cards`/`--dedupe`
сдерживают размер набора: карточка с перекрытием совпавших триггеров ≥ J не
поднимается, но попадает в `suppressed` с причиной. Точки вызова в харнессе —
в `references/harness-integration.md` (вход намерения, сборка handoff-пакета,
старт проекта).

## 4. Жизненный цикл

```
fleeting ──(триггер сработал / вспомнил)──► latent ──(использовал в задаче)──► active
   │                                          │                                  │
   └──(не трогал 6 мес.)──► archived ◄────────┘(12 мес.)          (условие «проект» выполнено)
                                                                                 ▼
                                                                              project
```
Переходы делаются явно (`card_review.py --touch`, `--promote`), архив —
только вниз по ярусу, не удаление. Ревизия:
```bash
python3 scripts/card_review.py --dir ~/hypotheses            # состояния, залежавшиеся, кандидаты на переход
python3 scripts/card_review.py --dir ~/hypotheses --touch laguna-gb10-ladder --project spark-run
```
`--touch` записывает факт использования (дата, проект) — это данные для
повышения/понижения, а не мнение.

## 5. Ярусы библиотеки

Карточка определяет, где живут её скиллы: `fleeting`/`latent` — теплица
(не участвует в общем поиске, поднимается триггером или явно), `active`
— доменный ярус (грузится профилем проекта), `project` — свой репо.
Перенос между ярусами — следствие перехода состояния, не отдельное решение.

## 6. Чего не делать

- Не заводить карточку без триггеров: карточка без триггеров — заметка.
- Не писать в триггеры общие слова; лучше один точный файл, чем пять тем.
- Не удалять карточки: `archived` хранит происхождение; удалённое нельзя
  повысить обратно.
- Не смешивать в одной карточке две гипотезы с разными условиями
  «стать проектом» — разделить, связать полем `related`.
