# Интеграция карточек в харнесс (Spine и подобные)

Скилл даёт формат и три скрипта; когда их вызывать — решает харнесс. Три
точки, где карточки должны всплывать сами, и одна — где фиксируется
использование.

## 1. Вход намерения (первый контур)

Пользователь формулирует намерение → до сбора REQ/NFR запустить
`card_match.py --intent "<текст>" [--project <repo>]`. Совпадения с баллом
≥ порога показать одной строкой: «латентные гипотезы, пересекающиеся с
намерением: laguna-gb10-ladder (5 скиллов) — поднять?». Это единственное
место, где мимолётный интерес полезен: в момент выбора направления, а не
как результат поиска, который никто не запустит.

## 2. Сборка handoff-пакета / старт проекта

При `handoff_create` (или эквиваленте) — `card_match.py --project <repo>`
по фактическим файлам и конфигам. В пакет идут только поднятые карточки
(top-N и без почти-дублей: `--max-cards`/`--dedupe`, хук берёт их из
`HYPOTHESES_MAX_CARDS`/`HYPOTHESIS_DEDUPE`), их `skills` — в MANIFEST,
а карточка получает `--touch --project <name>`. Так роутинг идёт по
свидетельствам в репо, а не по description. Подавленные перекрытием
карточки не исчезают молча: они перечислены в `suppressed`
(`HYPOTHESES.json`) с парой и коэффициентом.

## 3. Детерминированный слой без LLM

`card_match.py --emit-routing routing.json` выгружает плоскую таблицу
`{trigger, kind, weight, card, skills}`. Её может читать контроль без модели
(в Spine — слой правил/`preflight`): «в репо есть файл по маске X → набор Y
доступен». Обновлять при каждом изменении карточек (хук на коммит в
каталог `hypotheses/`).

## 4. Фиксация использования

После принятия результата (accept worktree, закрытие задачи) — `--touch`
для карточек, чьи скиллы фигурировали в пакете. Эти касания — данные для
`card_review.py`: ≥ 2 проекта → предложить `active`; нет касаний
`decay_months` → предложить `archived`. Если в харнессе есть петля
propose/commit для доменного слоя (в Spine — evolve), переходы состояний
должны идти через неё: скрипт предлагает, человек утверждает.

## 5. Ярусы библиотеки

| Ярус | Что грузится | Из каких состояний |
|---|---|---|
| ядро | всегда, десятки скиллов | — |
| доменный | профилем проекта, сотни | active |
| теплица | только по триггеру или явно | fleeting, latent |
| архив | вне роутинга; поднимается `card_match --include-archived` | archived |

Теплица снимает главную проблему: личные наборы не конкурируют с
корпоративными плагинами в общем поиске и не разбавляют его.

## 6. Минимальный вариант без хуков

Если интеграции нет — один ритуал: при старте любого проекта вручную
`card_match.py --project . --intent "<что делаю>"`. Это уже закрывает
«когда вспомнить»; автоматизация лишь убирает необходимость помнить о
ритуале.

## 7. Готовая реализация хуков
Плагин `hypothesis-router` (рядом с этим скиллом): `hooks/hypothesis-hook.sh
{intent|pre-handoff|post-accept|refresh|check}`, fitness-правила и
ADR-черновик для evolve propose. Скилл описывает «что», плагин делает «когда».
