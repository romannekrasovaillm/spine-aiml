# LLM-графтинг: трансплантация компонентов и model surgery

Хирургия весов: собрать работоспособную модель из частей разных вендоров
(«franken-модель») или заменить устаревший компонент обученного чекпоинта,
не переобучая модель с нуля. Сквозной принцип: **мозг и доноры заморожены,
обучается только шов** (проектор / заменённый слой / merge-коэффициенты).
Граница train/inference стирается: часто «нужна очень хорошая тренировка,
чтобы делать быстрый инференс».

Правило №1 — **сначала карта, потом скальпель.** Любое вмешательство
предваряется сравнением конфигов донора и реципиента и замером baseline.

## Шаг 0. Среда и инвентаризация (обязательно до любых правок)

1. **GPU/память**: `nvidia-smi`; обучаемый шов (единицы–десятки млн
   параметров) влезает на 1 GPU, ретрофит слоя большой MoE — multi-GPU +
   FSDP/DeepSpeed. Нет GPU → готовь код и конфиги для удалённого кластера,
   локально прогоняй smoke-тест на карликовых моделях
   (`HuggingFaceTB/SmolLM2-135M` + `openai/clip-vit-base-patch32`).
2. **Стек**: `python -c "import torch, transformers; print(...)"` — нужны
   `torch`, `transformers`, `accelerate`, `safetensors`; данные — `datasets`
   (потоково); оценка — `lm-eval` (текст), `lmms-eval` (VLM); spec dec —
   vLLM/SGLang.
3. **Доступ к весам**: HF Hub (`huggingface-cli whoami`), ModelScope-зеркала
   для Kimi/GLM/Qwen; гейтед-модели — токен. `df -h`: донорские чекпоинты
   крупных моделей — сотни ГБ.

**Карта совместимости (перед любым графтом).** Выпиши и сравни таблицу
полей донора и реципиента: `hidden_size`, `num_attention_heads`,
`num_key_value_heads`, `head_dim`, тип и `rope_theta`/scaling позиционных
эмбеддингов, норму (RMSNorm/LayerNorm + eps), `vocab_size`, `tie_word_embeddings`,
раскладку (fused qkv vs раздельные проекции). Несовпадения — это **план
адаптеров, а не стоп-сигнал**. Готовый скрипт есть в библиотеке:
`plugins/grafting/skills/llm-grafting/scripts/compare_configs.py`.

**Точечная работа с чекпоинтами** — не грузи гигантов целиком:
```python
from huggingface_hub import hf_hub_download
idx = hf_hub_download(repo, "model.safetensors.index.json")   # weight_map
import safetensors.torch as st
with st.safe_open(shard, framework="pt") as f:                # один тензор
    w = f.get_tensor("model.layers.12.self_attn.k_proj.weight")
```
Никогда не полагайся на «стандартные» имена тензоров: у Kimi, GLM,
DeepSeek, MiniMax, Qwen префиксы (`vision_tower.` / `visual.` /
`vision_model.`) и раскладка различаются — смотри `weight_map`, не угадывай.

## Сценарий A. Vision-графтинг: глаза к чужому мозгу

Замороженный vision-энкодер X + замороженная LLM Y → VLM, обучается только
проектор. Линия LLaVA / LLaVA-1.5 / LLaVA-NeXT; энкодеры CLIP → MetaCLIP →
SigLIP2, либо нативные энкодеры VLM (MoonViT из Kimi-VL, ViT Qwen2-VL).

```
изображение → [Vision Encoder, FROZEN] → патч-эмбеддинги
            → [Projector, TRAINABLE: MLP 2 слоя + GELU] → пространство LLM
            → конкатенация с текстовыми токенами → [LLM, FROZEN] → ответ
```

Критические правила:
- **Заморозь всё, кроме шва**: `requires_grad_(False)` на энкодере и LLM;
  напечатай счётчик `sum(p.numel() ... if p.requires_grad)` — ждём единицы–
  десятки M, НЕ миллиарды.
- **Нулевая деградация базы обязательна**: в forward энкодер и проектор
  вызываются только при наличии картинки, текстовый путь = байт-в-байт
  оригинальная LLM. Приём: `if pixel_values is not None:` вокруг графта.
- **Кэпшены дают плато — Grokking на VQA.** Стадия 1 (LLaVA-Pretrain
  LCS-558K, короткая, lr ~1e-3) — грубое выравнивание пространств; лосс
  выйдет на плато, это ожидаемо. Стадия 2 (LLaVA-Instruct-665K / VQAv2 / GQA /
  OK-VQA / DocVQA; lr 2e-5…2e-4) — здесь скачок: проектор вынужден передавать
  локализованную информацию, а не сводку. Не останавливайся на плато кэпшенов.
- **Маскируй патч-токены в labels** (`-100`), иначе модель учится
  «предсказывать картинку».
- **Dtype-щель**: проектор в fp32, каст к dtype LLM при вставке в embeds;
  иначе NaN на bf16. Препроцессинг картинки — родной `image_processor`
  энкодера, не LLaVA-дефолт. Динамическое разрешение фиксируй на 1-й итерации.
- **Оценка**: сначала регрессия текста (MMLU-Pro базы обязана совпасть с
  оригиналом — ориентир из практики: ~56% сохраняется без изменений), потом
  VLM-метрики (VQAv2/GQA/TextVQA/MMBench/POPE) и смоук глазами на 10–20
  картинках с вопросами на локализацию.

Полная методика, код проектора, датасеты, гиперпараметры:
`plugins/grafting/skills/llm-grafting/references/vision-grafting.md`.

## Сценарий B. Ретрофит слоёв: замена неэффективного внимания

Мотивация-образец: слой на full attention даёт O(N²) и раздутый KV-кэш →
убивает speculative decoding. Лечение: пересадить GQA (или MLA) из донора и
**дообучить до того же acceptance rate**.

1. **Диагностика (до скальпеля)**: профиль KV-кэша по слоям; baseline
   acceptance rate spec dec (vLLM `spec_decode_*`), tokens/s, пиковая память
   на целевых длинах; perplexity + 2–3 целевых бенчмарка. Без baseline
   «довести до того же acceptance rate» проверить нечем.
2. **Пересадка**:
   - донор той же размерности (`hidden_size`/`head_dim` совпали) — копируем
     `q/k/v/o_proj` как есть;
   - **часто лучший донор — сама модель**: MHA→GQA сжатием собственных весов
     (mean-pooling K/V внутри группы голов, приём из статьи GQA) даёт тёплый
     старт заметно лучше случайной инициализации:
     ```python
     g = n_heads // n_kv_heads
     w = w.view(n_heads, head_dim, -1)
     w_gqa = w.view(n_kv_heads, g, head_dim, -1).mean(dim=1).reshape(n_kv_heads*head_dim, -1)
     ```
     Q и O не трогаем;
   - несовпадение `head_dim` → линейные адаптеры (обучаемые) или интерполяция
     весов только как инициализация;
   - **RoPE**: при расхождении `rope_theta`/scaling оставляй RoPE реципиента —
     донор доводится дистилляцией, иначе тихо ломается длинный контекст;
     норму бери схему реципиента.
3. **Дистилляция слоя** (stage 1): заморозь всю модель, кроме нового слоя;
   собери хуками пары (вход слоя, эталонный выход) на прогоне учителя по
   реальному миску (обязательно длинные последовательности — именно там
   full attention отличался), учи MSE/KL по выходам слоя.
4. **Сквозная доводка** (stage 2): дистилляция логитов KL(teacher‖student),
   опц. LoRA r=8–16 на 1–2 соседних слоях. Критерий остановки — **не лосс,
   а acceptance rate**: замер каждые N шагов, цель — вернуться к baseline.
5. **Верификация**: acceptance rate ≥ baseline; ppl Δ ≤ ~0.5% относительных;
   KV-кэш на токен сжат в `n_heads/n_kv_heads` раз; tokens/s @ длинный контекст
   вырос; needle-тест не деградировал.

**Тяжёлый случай — конверсия в MLA / линейное внимание** (сжатие KV-кэша):
методика Ling/Ring 2.6 (arXiv:2606.15079) — четырёхшаговая миграция уже
обученного GQA-чекпоинта на гибрид Lightning Attention + MLA без обучения с
нуля: (1) Lightning Conversion с сохранением QK Norm и Partial RoPE;
(2) Linear Warmup (заморожено всё кроме новых параметров, прогрев LR до
восстановления лосса); (3) MLA Conversion — снятие QK Norm через
**калибровочное слияние** (впитывание γ_Q/γ_K в проекции по статистикам
q_ij/k_ij; ожидай контролируемую просадку, в mini-реплике ppl 6.65 → 11.13 —
она восстановима), затем Partial RoPE adaptation + **TransMLA**
(arXiv:2502.07864); (4) MLA Warmup. Критерий перехода между шагами — лосс
вернулся к уровню до конверсии. Доля линейных слоёв выбирается scaling-law,
не интуицией (отчёт: M=8, 7:1 — лучший тренд; M=16 деградирует). Подробно:
библиотечные скиллы `plugins/antgroup-ling/skills/ling26-attention-retrofit/`
и `.../ling26-hybrid-attention-retrofit/`.

Детали (маппинг GQA↔MHA, репликация KV-голов, конверсия в MLA, RoPE):
`plugins/grafting/skills/llm-grafting/references/layer-retrofit.md`.

## Сценарий C. Трансплантация токенизатора (cross-lingual / domain grafting)

Смена словаря у претрейн-модели без переобучения — ключ к кросс-языковому и
доменному графтингу, а также к дистилляции и spec dec между моделями с
разными токенизаторами. Метод Arcee **Training-Free Tokenizer
Transplantation via Orthogonal Matching Pursuit (OMP)**: (1) найти общий
«земляной» словарь двух моделей; (2) OMP-ом выучить, как донор выражает
новые концепты через комбинации знакомых токенов; (3) перенести эти
паттерны в пространство словаря реципиента; (4) **без обучения весов**.
Результаты Arcee: Llama→Mistral-NeMo сохранил 96% исходного качества при
пересечении словарей 54%, трансплантация < 2 минут. Инструмент —
`mergekit-tokensurgeon` (библиотека MergeKit).

Применения: выравнивание словарей для дистилляции, spec dec любой пары
моделей, доменная адаптация (медицина/право/код), кросс-языковые модели.
Риск-сосед: дрейф словаря после SFT (Sparse Token Forgetting — `lm_head`
дрейфует, `embed_tokens` почти неподвижен; асимметрия «генерация vs
понимание») — диагностика и лечение «чтением словаря вслух» в скилле
`plugins/postrain/skills/tokenizer-vocab-health/`.

Источник: `11_Техотчёты_лабораторий_LLM/2025/Arcee/2025-06-10_Blog-Tokenizer-Transplantation.pdf`.

## Сценарий D. Merge / TIES / task arithmetic и conflict-driven слияние

Слияние в пространстве весов специализированных экспертов (код/математика/
текст) без полного переобучения. Классы методов: усреднение (`model soup`),
task arithmetic (θ_base + Σλᵢ·τᵢ), TIES (trim → elect sign → disjoint merge,
снимает конфликт знаков) и родственные разреживающие методы; SLERP — для
двух моделей. Основная проблема — **параметрическая интерференция**: наивное
слияние гасит способности отдельных экспертов (на конфликт-чувствительных
задачах: instruction-following, safety).

**CoMerge** (arXiv:2609.02273) переформулирует слияние как preference
optimization: self-supervised conflict-driven стратегия использует дефекты
наивного слияния (task arithmetic) как hard negatives и обучает
**лёгкие покомпонентные (tensor-wise) коэффициенты слияния** — на
Llama-3.1-8B всего 1445 скаляров; средняя нормализованная оценка 0.9968 на
MergeBench, выше data-free и data-driven бейзлайнов на конфликт-чувствительных
задачах, вровень с full fine-tuning.

Правила: сначала baseline каждой экспертной модели и наивного merge; merge —
только для **общей базы** (иначе расхождение активаций, см. ниже); для
кросс-токенизаторных пар сначала выравнивай словари (сценарий C). Инструмент
Arcee **MergeKit** (с 31.10.2025 — LGPL v3: свободно в коммерческих продуктах;
модификации самой библиотеки — под LGPL). Источники:
`11_Техотчёты_лабораторий_LLM/2025/Arcee/2025-10-31_Blog-Mergekit-Returns-to-Roots.pdf`,
`.../2025-10-06_Blog-IBM-Mergekit-Granite-4.pdf`,
`03_ПОСТ-ТРЕЙНИНГ_RL/03_Reward_и_верификация/2609.02273_CoMerge_...pdf`.

## Сценарий E. LoRA/адаптер на чужой базе

Дообучение замороженной модели-реципиента малой обучемой надстройкой —
наиболее щадящий графтинг (когда полная разморозка не нужна и опасна).
Методология «LoRA Without Regret» (Schulman / Thinking Machines, 2025):
адаптер на **все линейные слои** (`target_modules="all-linear"`, особенно
MLP/MoE, не только attention), rank по capacity датасета (`r=1–32` для RL,
`32–128` для среднего SFT, `256` для крупного), learning rate ~10× выше
FullFT, малый батч. Для чужой/незнакомой базы это ещё и способ проверить
совместимость латентных пространств: если адаптер не сходится — вероятно
расхождение активаций (см. «Риски»). Детали:
`plugins/lora/skills/lora-without-regret/SKILL.md`. Смежное — MoE-графтинг
(перенос/инициализация экспертов, роутер): `plugins/moe/`, дистилляция
учитель→ученик: `plugins/distillation/`.

## Общие принципы хирургии весов

1. **Сначала карта, потом скальпель** (см. Шаг 0): сравнение конфигов и
   `weight_map` — источник плана адаптеров.
2. **Точечная загрузка safetensors**: читай нужные тензоры по `weight_map`,
   не качай модель целиком ради одного слоя.
3. **Обучай минимум параметров.** Иерархия вмешательства: проектор/один слой
   → +LoRA соседей → полная разморозка (крайний случай, почти не нужен).
4. **Всегда сохраняй обходной путь.** Графт отключаем флагом в forward (без
   картинки — чистый текст); конфиг ретрофита версионируем, оригинальные
   тензоры заменённого слоя храним отдельным safetensors для отката.
5. **Измеряй деградацию первым делом** — на том, что графт НЕ сломал
   (текстовая метрика базы, ppl, acceptance rate), и только потом на том, что
   добавил.
6. **Карта происхождения весов (graft manifest)** — обязательный артефакт:
   какой тензор откуда (`repo@revision`, операция `copy|mean-pool|svd|merge`,
   число шагов обучения). Без манифеста franken-модель невоспроизводима.
   Шаблон — `plugins/grafting/skills/llm-grafting/references/recipes.md`, §5.
7. **Лицензии.** Компоненты разных вендоров = разные лицензии; предупреди о
   совместимости лицензий при публикации franken-модели.

## Риски (проверяй явно, не надейся на «само заработает»)

- **Расхождение активаций (activation mismatch).** Слои донора обучены в
  распределении активаций своей модели; при вставке в реципиента новый слой
  видит чужие статистики → даже при совпадающих размерностях выход
  «съезжает». Лечение: инициализация из собственных весов (mean-pool/SVD),
  послойная дистилляция по (h_in, h_out) реального мисса реципиента,
  короткий warmup. Симптом несовместимости — слой не сходится MSE или
  сквозной лосс не восстанавливается прогревом.
- **ABI / раскладка тензоров.** Несовпадение формата: fused qkv против
  раздельных `q_proj/k_proj/v_proj`, другие имена/префиксы, иной `head_dim`,
  tied vs untied `lm_head`/`embed_tokens`, dtype-щели (fp32-шов в bf16-модели
  → NaN), разные схемы норм и eps. Это «ABI» уровня чекпоинта: копирование
  тензора без учёта раскладки даёт молчаливо неверную модель. Проверяется
  таблицей конфигов и сверкой форм тензоров, а не «похоже на правду».
- **RoPE-несовместимость.** Разные `rope_theta`/scaling (yarn/linear/dynamic)
  и Partial RoPE → тихая деградация после 4–8k токенов. Оставляй RoPE
  реципиента; проверяй needle-тестом.
- **Деградация базы.** Любой графт сначала проверяется на сохранность
  исходных способностей (текстовый бенчмарк, ppl, acceptance rate): метрика
  до == после в пределах шума. Для VLM ориентир из практики — текстовая
  MMLU-Pro базы не меняется.
- **Расползание поведения.** LoRA на слишком многих слоях или неограниченная
  разморозка меняют модель глобально; держи вмешательство локальным и
  обратимым.
- **Дистилляция только на коротких последовательностях** → acceptance rate
  на длинных не восстанавливается (full attention отличался именно там).
- **Забытые causal-маска/position_ids** при послойной дистилляции: MSE
  сходится, модель сломана.

## Чек-лист перед сдачей результата

- [ ] Сравнены конфиги донора/реципиента, составлена карта совместимости
- [ ] Заморожено всё, кроме шва; напечатан счётчик trainable params
- [ ] Замерен baseline ДО вмешательства (текст/ppl/acceptance rate)
- [ ] Метрика сохранности базы: «до == после» (регрессия текста для VLM;
      ppl+бенчи для ретрофита)
- [ ] Для VLM обучение прошло стадию VQA, не остановлено на плато кэпшенов
- [ ] Для ретрофита: acceptance rate ≥ baseline, KV-кэш сжат, скорость
      замерена, длинный контекст не деградировал
