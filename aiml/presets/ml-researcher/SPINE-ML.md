# SPINE-ML — спайн-шаблон ML-контура (Spine AI/ML Edition)

Пресет для домена AI/ML-исследователя: обязательные инварианты контура
обучения/вывода, готовые к включению в `ARCHITECTURE-SPINE.md` проекта.
Дистиллирован из дорожной карты продукта (`ROADMAP.md` в корне) и рабочей
дисциплины ML-экспериментов (`~/.claude/projects/<слаг-рабочего-каталога>/memory/`,
где слаг — абсолютный путь рабочего каталога, в котором каждый символ вне
`[A-Za-z0-9]` заменён на `-`); ключевые темы — гибридная маршрутизация
в приватном периметре и формальная подотчётность.

Аналог банковского `SPINE-PAYMENTS.md`: ID `ML-*` стабильны — условие
сравнимости проектов между собой.

## Как применять

1. Скопируйте нужные блоки в спайн проекта, сохранив ID `ML-*`.
2. **mandatory**-блоки исключаются из спайна проекта только через ADR
   с обоснованием (архитектурное исключение).
3. **conditional**-блоки включаются, если выполняется условие; невыполнение
   фиксируется строкой «не применимо: <причина>».
4. Каждый включённый блок обязан получить fitness-правило в
   `CONSTRAINTS.yaml` проекта (AD без правила — error трассируемости).
   Типы правил пресета: `must_contain` / `must_not_contain` / `file_exists`
   (образец — `aiml/library/fitness/wave1-ml-experiment.yaml`).

Обозначения: [M] = mandatory, [C] = conditional.

## Приватный периметр и маршрутизация (ядро контура)

### ML-01: Приватный периметр — датасеты и веса не покидают контур [M]

- **Binds**: локальные датасеты/чекпоинты/токенизаторы ↔ локальный шлюз (vLLM/Ollama)
  ↔ внешние фронтир-API (`[models.deepseek|glm|kimi]`)
- **Prevents**: передачу приватного корпуса, закрытых весов или
  неопубликованных результатов во внешний облачный API; необратимую утечку
  данных в чужой контур (событие, которое нельзя отозвать)
- **Rule**: классификация ассетов (открытые / внутренние / закрытые)
  ведётся явно; **закрытые и внутренние ассеты обрабатываются только локальными
  моделями** (`local-*` за 127.0.0.1). Во внешний API уходит только то, что
  помечено открытым. Смена класса ассета — решение владельца, не хода агента.
  Страж: `must_contain` классификации ассетов в манифесте датасета; политика
  контура в `[models.*]` (наличие локальных провайдеров).
- **Статус**: шаблон

### ML-02: Маршрутизация локальное ↔ фронтир по чувствительности и уверенности [M]

- **Binds**: тип хода (чувствительность данных) ↔ выбор модели ↔ эскалация
- **Prevents**: две ошибки сразу — приватный ход, ушедший на фронтир
  (утечка), и «дешёвый» ход, где локальная модель ошибается молча
  (неверная маршрутизация без сигнала)
- **Rule**: маршрутизация — по **чувствительности входа и требуемому
  ризонингу**, не по удобству. Приватный вход → только `local-*`. Доменные
  задачи ризонинга/ревью → фронтир. **Эскалация по уверенности обязательна**:
  низкая уверенность локальной модели (классификация значимости, извлечение
  сущностей) ведёт на фронтир, а не в Fast Path. Ошибочная маршрутизация
  Critical-изменения по дешёвому пути — аудируемое событие с гейтом.
  Страж: fitness-правило на таблицу маршрутизации/порог уверенности;
  событие эскалации в журнале сессии.
- **Статус**: шаблон

### ML-03: Запрет утечки датасетов — в промпт, логи и трассы только разрешённое [M]

- **Binds**: содержимое датасета ↔ промпты ↔ журналы сессии ↔ W&B/логи прогонов
- **Prevents**: персональные/закрытые данные в промпте внешнему провайдеру, в
  JSONL-журнале сессии, в логах обучения или в отчёте, который покидает контур
- **Rule**: в промпт внешней модели, в журнал сессии и в публикуемый отчёт
  попадают только обезличенные фрагменты (примеры, схемы, агрегаты) —
  сырые строки датасета не цитируются. Секреты (HF_TOKEN, WANDB_API_KEY,
  провайдерные ключи) вычищаются из окружения bash-команд (`[bash].env_scrub`).
  Страж: `must_not_contain` на паттерны сырых записей датасета в промпт-шаблонах
  и на присваивания секретов; `env_scrub = true`.
- **Статус**: шаблон

### ML-04: Секреты вне кода и конфигов [M]

- **Binds**: рантайм ↔ env/менеджер секретов ↔ скрипты эксперимента
- **Prevents**: ключи HF/W&B/провайдеров, токены и пароли в git, ноутбуках,
  конфигах прогона и логах
- **Rule**: ключи передаются только именем env-переменной в конфиге
  (`api_key_env`/`api_key_file`), значение в конфиг/код/промпт не пишется
  (AD-3 ядра). Литералы секретов запрещены механически; ротация описана.
  Страж: `must_not_contain` на присваивания секретов; `file_exists` описания
  ротации. Совместно с ML-03.
- **Статус**: шаблон

## Доменное знание и достоверность

### ML-05: ML-факты не берутся из весов — только из источника [M]

- **Binds**: утверждение о методе/архитектуре/бенчмарке ↔ первоисточник
  (статья, техотчёт, карточка модели) ↔ доменная база концептов
- **Prevents**: уверенно выдуманные ML-факты (id модели, цифры бенчмарка,
  название метода) — ошибку, которая распространяется дальше как «знание»
- **Rule**: любое доменное ML-утверждение опирается на указанный источник —
  препринт/техотчёт/карточку из библиотеки, с путём или ссылкой. Ответ малой
  доменной модели (Ариадна) — **гипотеза для проверки**, не факт (ML-11).
  Страж: fitness-правило на обязательную ссылку-источник в разборах;
  присутствие каталога библиотеки в `[knowledge].dirs`.
- **Статус**: шаблон

### ML-06: Воспроизводимость прогона — конфиг, версии и seed в артефакте [M]

- **Binds**: результат эксперимента ↔ зафиксированный конфиг ↔ версии стека
  (torch/CUDA/vLLM/среда) ↔ seed
- **Prevents**: результат, который нельзя повторить, — «работало у меня»;
  невоспроизводимое сравнение конфигураций (A/B теряет смысл)
- **Rule**: каждый прогон сохраняет артефакт-манифест: полный конфиг
  (валидированный, не по памяти), версии ключевых пакетов, seed, хеш
  датасета/чекпоинта. Версии сверяются по матрице совместимости до аренды
  GPU (pre-flight), а не после падения. Страж: `file_exists` манифеста
  прогона; `must_contain` seed и версий в конфиге эксперимента.
- **Статус**: шаблон

### ML-07: Провенанс датасета и чекпоинта [M]

- **Binds**: ассет (датасет/веса) ↔ лицензия ↔ хеш ↔ происхождение
- **Prevents**: обучение на датасете с несовместимой лицензией и публикация
  производной модели; подмену/повреждение чекпоинта без следа
- **Rule**: у каждого ассета фиксируются источник, лицензия и хеш; лицензия
  проверяется **до** обучения на данных, а не перед релизом. Несовместимость
  лицензий датасета и цели распространения — блокирующий факт. Страж:
  `must_contain` полей license/source/hash в манифесте ассетов.
- **Статус**: шаблон

## Ресурсы и прогон

### ML-08: Pre-flight до аренды GPU — версии, VRAM, железо [M]

- **Binds**: план прогона ↔ оценка памяти/совместимости ↔ выбор инстанса
- **Prevents**: арендованную GPU под конфиг, который не стартует
  (несовместимость ABI/версий, OOM, отсутствие железа), — сожжённый бюджет
- **Rule**: до аренды — измеримые ворота: (а) сверка версий стека
  (torch × CUDA × vLLM × каркас RL); (б) оценка VRAM (веса × 2 байта ×
  копии train+инференс + overhead); (в) проверка наличия железа; (г) список
  известных сбойных хостов учтён. Оценка и решение фиксируются до спенда.
  Страж: `file_exists` pre-flight-заметки прогона; `must_contain` секции
  версий/VRAM в плане.
- **Статус**: шаблон

### ML-09: Бюджет прогона — потолок стоимости и его контроль [M]

- **Binds**: прогон ↔ бюджет (GPU/API) ↔ решение о продолжении
- **Prevents**: незамеченный перерасход — обучение идёт, счёт растёт;
  бюджет исчерпан, результат не получен
- **Rule**: у прогона объявлен потолок стоимости (GPU-часы и/или токены API);
  превышение — остановка и решение владельца, а не автоматическое продолжение.
  Стоимость на governed-результат отслеживается (`arch-ml metrics --cost-report`).
  Страж: `must_contain` поля budget в манифесте прогона.
- **Статус**: шаблон

### ML-10: Логи и чекпоинты сохраняются до teardown [M]

- **Binds**: прогон ↔ журналы/чекпоинты ↔ жизненный цикл инстанса
- **Prevents**: безвозвратную потерю логов и весов при уничтожении инстанса —
  истраченный спенд без результата и без разбора причин
- **Rule**: логи и чекпоинты выгружаются из контура **до** teardown/очистки;
  порядок фиксирован (сначала выгрузка, потом удаление). Необратимое удаление
  чекпоинтов — деструктив (повышение автономии до R4, ML-routing решения —
  `[policy].autonomy`). Страж: `file_exists` инструкции teardown с шагом
  выгрузки.
- **Статус**: шаблон

## Доменный инструмент и достоверность отчётов

### ML-11: Доменная модель концептов — инструмент, не исполнитель [M]

- **Binds**: инструмент concept_search / significance_score ↔ доменная база
  концептов (Ариадна, локальная 4B) ↔ агентный цикл
- **Prevents**: подмену исполнителя малой моделью (субагент на 4B сочиняет
  уверенно и красиво) и доверие её ответу как факту
- **Rule**: endpoint модели концептов живёт **только** как доменный инструмент
  (concept_search/significance_score), не как модель-исполнитель сессии или
  субагента; исполнитель остаётся на большой модели. Ответ малой модели —
  гипотеза, требующая подтверждения первоисточником (ML-05). Модель живёт
  в приватном контуре (ML-01). Страж: `must_contain` отдельной записи модели
  концептов в `[models.*]`; политика инструмента в конфиге.
- **Статус**: шаблон

### ML-12: Честный отчёт — различай измеренное и предположенное [M]

- **Binds**: отчёт/вывод эксперимента ↔ первичные артефакты (логи, метрики)
  ↔ формулировка результата
- **Prevents**: уверенный вывод из непроверенного или частичного прогона;
  сокрытие отрицательного результата (потеря знания и повторный спенд)
- **Rule**: в отчёте явно разделены **измеренное** (с путём к логу/метрике) и
  **предположенное** (гипотеза); незавершённый/частичный прогон помечается как
  таковой, а не подаётся результатом. Отрицательный результат сохраняется и
  документируется. Страж: `must_contain` секций «измерено»/«гипотеза» в
  шаблоне отчёта; ссылка на артефакт-логи обязательна.
- **Статус**: шаблон

## Conditional-блоки (включать по условию)

### ML-13: Публикация артефактов — обезличивание и лицензия [C: артефакт покидает контур]

- **Binds**: чекпоинт/датасет/разбор ↔ публикация (HF, git, отчёт) ↔ лицензия
- **Prevents**: публикацию данных с PII, закрытых весов или производной модели
  с несовместимой лицензией — необратимое раскрытие
- **Rule**: перед выпуском артефакта за периметр — проверка на PII/закрытые
  фрагменты и сверка лицензий производной модели с лицензией базовых данных и
  весов (совместно с ML-07). Публикация — осознанное действие владельца, не ход
  агента. Страж: `file_exists` чек-листа выпуска; `must_not_contain` PII-паттернов
  в артефактах релиза.
- **Статус**: шаблон

### ML-14: Изоляция недоверенного кода и данных [C: прогон чужого кода/моделей]

- **Binds**: сторонний код/чекпоинт-скрипт ↔ окружение прогона ↔ контур
- **Prevents**: исполнение недоверенного кода (чужие репозитории, веса с
  произвольным кодом загрузки) с доступом к секретам и сети контура
- **Rule**: недоверенный код исполняется в изолированном окружении без
  ambient-секретов: scrub окружения (`[bash].env_scrub`), при статическом
  анализе — `[bash].sandbox = "bwrap"` (сеть отрезана, ФС ro; нет бинаря —
  команда не выполняется). Модели/датасеты из недоверенных источников — под
  проверку провенанса (ML-07). Страж: политика sandbox в конфиге;
  `file_exists` политики изоляции.
- **Статус**: шаблон
