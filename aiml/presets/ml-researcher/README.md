# Пресет `ml-researcher` — домен AI/ML-исследователя

Доменный пресет Spine AI/ML Edition для контура AI/ML-исследователя: рабочая
модельная матрица, доменное знание и инварианты приватного контура. Ставится
поверх ядра (`src/`, бинарь `arch-ml`), не меняя его. Аналог
`banking/presets/bank-profile/` в банковском издании.

Файлы пресета:

| Файл | Назначение |
|------|-----------|
| `config.toml` | Модельная матрица (три уровня), `[agent]`, `[knowledge]`, `[web]`, `[policy]`, `[bash]`, `[judge]`, `[plugins]`, `[paths]`. Копируется/сливается в `~/.config/arch-ml/config.toml`. |
| `SPINE-ML.md` | Доменные инварианты контура `ML-01…ML-14` — блоки для `ARCHITECTURE-SPINE.md` проекта. |
| `README.md` | Этот файл: что пресет закрывает, матрица, применение, границы. |

## Что пресет закрывает

- **Модельная матрица из трёх уровней** — внешние API для разработки,
  локальные open-weights для приватных ходов, доменная модель концептов как
  инструмент (см. таблицу ниже).
- **Маршрутизация по чувствительности** — приватный вход только на `local-*`;
  доменный ризонинг/ревью — на фронтир (инвариант ML-02).
- **Доменное знание** — библиотека разборов и плагинов подключается через
  `[knowledge].dirs`; ML-факты грундуются в первоисточниках, не в весах (ML-05).
- **Веб-доступ для открытой ML-науки** — архивы arXiv/HF/OpenReview/PapersWithCode
  как `[[web.arch_sites]]`; при работе с закрытым контуром канал сужается
  дисциплиной ML-01/ML-03.
- **Дисциплина секретов** — ключи только именами env-переменных (AD-3),
  `[bash].env_scrub = true` вычищает HF/W&B/провайдерные ключи из окружения
  bash-команд.

## Модельная матрица

### 1. Внешние API — разработка, ризонинг, ревью (ключи из env)

| `[models.*]` | model id | ключ (env) | context_limit | thinking |
|--------------|----------|-----------|---------------|----------|
| `deepseek` | `deepseek-flash` | `DEEPSEEK_API_KEY` | 1 000 000 | `thinking = {type=enabled\|disabled}` |
| `deepseek-pro` | `deepseek-v4-pro` | `DEEPSEEK_API_KEY` | 1 000 000 | `thinking = {type=…}`; timeout 300 |
| `glm` | `glm-5.2` | `ZHIPU_API_KEY` | 1 000 000 | `thinking = {type=…}` |
| `"glm-4.7"` | `glm-4.7` | `ZHIPU_API_KEY` | 204 800 | `thinking = {type=…}` |
| `glm-air` | `glm-4.5-air` | `ZHIPU_API_KEY` | 131 072 | `thinking = {type=…}` |
| `glm-flash` | `glm-4.7-flash` | `ZHIPU_API_KEY` | 204 800 | `thinking = {type=…}` |
| `kimi` | `k3` | `KIMI_API_KEY` (+ `api_key_file = ~/.kimi_api_key`) | 1 000 000 | поверхность не принимает |

Рабочий дефолт — `default_model = "deepseek"` (черновики кода, разбор логов,
скрипты). Тяжёлый ризонинг — `deepseek-pro`. Дешёвая массовая обработка —
`glm-air` / `glm-flash`. Id моделей сверены по `config.example.toml` и
`docs/models.md` на дату форка; при снятии модели провайдером id правится здесь.

### 2. Локальные open-weights — приватные ходы (127.0.0.1, OpenAI-совместимый шлюз)

| `[models.*]` | model id | шлюз | context_limit |
|--------------|----------|------|---------------|
| `local-qwen25` | `qwen2.5-7b-instruct` | vLLM :8000 | 32 768 |
| `local-qwen3` | `qwen3-8b` | vLLM :8000 | 40 960 |
| `local-r1-distill` | `deepseek-r1-distill-qwen-7b` | vLLM :8000 | 65 536 |
| `local-llama` | `llama-3.1-8b-instruct` | Ollama :11434 | 32 768 |

Порты по серверу: vLLM 8000 · Ollama 11434 · llama.cpp 8080 · LM Studio 1234 —
правится `base_url`. `context_limit` выставляется **ровно как на сервере**
(vLLM `--max-model-len`, Ollama `num_ctx`) — иначе компактификация считается от
неверного окна.

**Ключ локального шлюза.** Харнесс читает ключ лениво и на пустое значение
отвечает отказом «нет API-ключа» (`src/llm/openai_compat.rs`). vLLM/Ollama ключ
не проверяют, поэтому `api_key_env = "LOCAL_LLM_KEY"` обязателен, а переменная
должна быть задана непустой:

```bash
export LOCAL_LLM_KEY=sk-local
```

Если сервер поднят с `--api-key` — туда кладётся реальный ключ (в конфиг
значение не пишется, AD-3).

### 3. Доменная модель концептов — инструмент, не исполнитель

| `[models.*]` | model id | шлюз | context_limit |
|--------------|----------|------|---------------|
| `ariadna` | `ariadna-concept-4b` | Ollama :11434 | 8 192 |

«Ариадна» — локальная 4B, обученная на концептах arXiv 2020–2026. Стоит за
инструментом `concept_search` / `significance_score`: атомарный вопрос о
ML-термине → ответ из доменной базы. Живёт **только** в приватном контуре.
Правила эксплуатации:

- протокол — короткие самодостаточные вопросы, temperature 0–0.3;
- контекст 4B-модели мал (2–8k) — простыни промптов не подавать;
- endpoint малой модели — доменный инструмент; исполнителя-субагента на неё
  **не переводить** (он остаётся на большой модели), см. ML-11;
- ответ малой модели — гипотеза для проверки первоисточником (ML-05), не факт.

Фиктивный ключ для локального сервера: `export ARIADNA_KEY=sk-local`.

## Применение

1. Скопируйте `config.toml` в `~/.config/arch-ml/config.toml` (или слейте с
   существующим) и замените placeholder'ы локального шлюза на свои адреса/порты.
2. Задайте ключи внешних провайдеров в окружении: `DEEPSEEK_API_KEY`,
   `ZHIPU_API_KEY`, `KIMI_API_KEY`. Локальному шлюзу — фиктивные
   `LOCAL_LLM_KEY`, `ARIADNA_KEY`.
3. Поднимите локальный шлюз (vLLM/Ollama) и убедитесь, что `context_limit` в
   конфиге совпадает с окном сервера.
4. Скопируйте нужные блоки `SPINE-ML.md` в `ARCHITECTURE-SPINE.md` проекта,
   сохранив ID `ML-*`.
5. На каждый включённый блок заведите fitness-правило в `CONSTRAINTS.yaml`
   (`must_contain` / `must_not_contain` / `file_exists`; образец —
   `banking/presets/payments/profiles/go-kafka-pg.yaml`).
6. Прогоните трассируемость: каждый инвариант `ML-*` без правила — error.

## Что пресет НЕ делает (честно)

- **Не заменяет `[harnesses.*]`** конкретного проекта — матрица задаёт
  провайдеров и политику, а не сборочные пайплайны.
- **Не поднимает локальные серверы** — vLLM/Ollama ставит и запускает
  владелец; пресет лишь описывает клиентские точки входа.
- **Не гарантирует приватность сам по себе** — периметр держится дисциплиной
  ML-01/ML-02/ML-03 и fitness-правилами, а не наличием блоков в конфиге.
- **Не является ADR** — обязательные блоки исключаются только через ADR
  с обоснованием (см. «Как применять» в `SPINE-ML.md`).

## Обслуживание

- **Id моделей** сверять с `docs/models.md` и `config.example.toml` при каждом
  релизе провайдера; снятые id (пример: `deepseek-chat/reasoner` сняты
  2026-07-24 → `v4-flash`/`v4-pro`) обновлять здесь.
- **ID `ML-*` стабильны** — это условие сравнимости проектов между собой;
  переименование ломает трассируемость.
- **Порты/окна локального шлюза** менять синхронно: `base_url` в `config.toml`
  и `--max-model-len`/`num_ctx` на сервере.
- Прецедент-источники: дорожная карта Spine AI/ML Edition
  (`~/Загрузки/Spine-BE_Дорожная_карта_развития_2026-09-11.md`) и рабочая
  дисциплина ML-экспериментов (`~/.claude/projects/-home-roman/memory/`).
