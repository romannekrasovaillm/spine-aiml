**I-6. Hard-fail табу (нарушение ограничивает итог 39 баллами):**

- **HF-01**: DR для Pangolin построен на **растянутом синхронном кластере на 2 ЦОД с автоматическим failover** или на **автоматическом promote standby-кластера** — подано как решение, вопреки прямой рекомендации документации (CONTEXT §1.4)
- **HF-02**: Сквозному контуру (БД + шина + шлюз) приписан **RPO = 0** без оговорки об асинхронности межкластерной репликации Corax Mirror Maker 2; либо MM2 заявлен как синхронный механизм
- **HF-03**: Продуктам приписаны **отсутствующие DR-функции**: межинстансовая кластеризация/синхронизация состояния SynGX (VRRP, общие лимиты), автоматическое переключение клиентов шины между кластерами средствами MM2, штатный бэкап Corax в файловое хранилище и т.п.
- **HF-04**: Вывод standby-кластера из-под репликации предложен штатно через **`pg_ctl promote`** (документация: удаление секции `standby_cluster` из динамической конфигурации) и/или процедура promote **без STONITH** основного сайта
- **HF-05**: Платёжные топики спроектированы с `acks=1` / `min.insync.replicas=1` по образцу НФТ-стенда вендора, поданному как рекомендация для прода (CONTEXT §1.7: это параметры производительного теста)
