# ARCHITECTURE-SPINE — DTM-ARCH-001

Продукт: Platform V DataMarts (СберТех)

## Инварианты (нарушать нельзя)

**I-1. Обязательные артефакты.** Ответ ОБЯЗАН содержать все разделы D1–D10 с заголовками, в порядке из TASK.md:

- **D1** — Резюме решения для руководства (≤ 15 строк)
- **D2** — Схема развёртывания (текстовая: Mermaid или PlantUML) с узлами `datamarts-server` (шарды/реплики), кворумом `datamarts-keeper`, ЦОД, шиной Corax/Kafka, источником Pangolin, SecMan и служебной БД PSQ
- **D3** — Отказоустойчивость и DR: сценарии отказа узла, реплики шарда и ЦОД; роль keeper-кворума; условия достижения заявленной вендором доступности; RPO/RTO аналитического контура
- **D4** — Конвейер загрузки из транзакционного контура: движок Kafka (аутентификация, форматы, группы потребителей), движок PostgreSQL/named collections для справочников, материализованные представления, версионные таблицы
- **D5** — Модель данных витрин: движки таблиц, первичные ключи, стратегия хранения истории; позиции, не раскрытые в документации (партиционирование, TTL данных), — как явные допущения/вопросы к вендору
- **D6** — Изоляция нагрузки и SLA отчётности: профили настроек, правила токсичности и блокировки, расписания профилей, границы управления safeguard
- **D7** — Контур безопасности и аудита: RBAC + datamarts-rrm, LDAP/Kerberos, TLS/OCSP, SecMan, аудит в SIEM
- **D8** — Мониторинг и эксплуатация: системные таблицы и метрики, внешний мониторинг, Correlation ID для сквозной трассировки, эксплуатационные процедуры
- **D9** — Таблица трассировки требований → решения
- **D10** — Реестр допущений, рисков, открытых вопросов и отвергнутых альтернатив

**I-2. Фактология.** Единственный источник фактов о продукте — CONTEXT.md §1 (`[DOC]`). Всё за пределами §1 — только как допущение с явной пометкой «Допущение: …» или как вопрос к вендору с планом проверки. Проверка: каждое утверждение о возможностях продукта сверено с §1.

**I-4. Трассировка.** Каждое требование NFR/SEC/INF из TASK.md покрыто решением в разделе трассировки (статус: выполнено / с оговоркой / требует проверки у вендора). Проверка: все ID NFR-xx, SEC-xx, INF-xx присутствуют в таблице трассировки.

**I-6. Hard-fail табу (нарушение ограничивает итог 39 баллами):**

- **HF-01**: Кворум keeper нарушен: 1–2 экземпляра `datamarts-keeper` или keeper совмещён с `datamarts-server` на одних серверах — без явного обоснования и компенсирующих мер
- **HF-02**: DataMarts спроектирована как система транзакционной записи (OLTP) / система-источник транзакционного контура
- **HF-03**: Вымышленные/недокументированные возможности поданы как факт: штатный CDC DMS, «балансировщик/прокси DataMarts», движок Distributed, порт 8123, JDBC/ODBC, партиционирование/TTL, версия ядра ClickHouse — без пометки «требует проверки у вендора» (§1.9)
- **HF-04**: Заявлена доступность «до 99.99 %» при < 3 репликах сегмента или без keeper — без оговорки, что условия вендора не выполняются
- **HF-05**: Отсутствует хотя бы один обязательный артефакт D1–D10
