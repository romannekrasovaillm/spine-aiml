# Рубрики оценки для задачи CRX-DR-001

## 1. Общие правила для судей

1. **Порядок:** (a) прочитать TASK.md и CONTEXT.md; (b) проверить HF §2;
   (c) оценить каждый критерий §3 по шкале 0–4 с цитатами из ответа;
   (d) сформировать вердикт по схеме §6.
2. **Фактическая база** — CONTEXT.md §1 (`[DOC]`). Утверждение о Corax,
   которого нет в §1 и которое не помечено решающим как допущение, считается
   **непроверенным**; если оно ещё и ложно — **ложным**. Не «додумывать» за
   решающего. Пометка `[ТРЕБУЕТ ПРОВЕРКИ]` + вопрос к вендору — признак
   зрелости, а не пробел.
3. **«Упомянул ≠ применил»** — балл за решение, привязанное к требованию
   (NFR/SEC/INF) и обоснованное, а не за ключевое слово.
4. **Шкала 0–4:** 0 — отсутствует или ошибочно; 1 — фрагментарно; 2 — базово
   корректно, есть пробелы; 3 — полно, мелкие недочёты; 4 — образцово, с
   учётом компромиссов и ловушек §4.
5. **Цитирование:** 1–3 цитаты (≤ 25 слов) на критерий + чего не хватает до
   следующего уровня.
6. Режим прогона фиксирован: `agentic` (см. `run_mode_adjustments`). Стиль и
   объём сверх C10 не оцениваются.

## 2. Правила hard-fail (HF)

При срабатывании любого правила итог ограничивается 39 баллами, критерии
оцениваются для диагностики. «Только судья» = regex-детектор ненадёжен.

| ID | Правило | Как обнаружить |
|---|---|---|
| HF-01 | Кворум координационного слоя не переживает потерю одного ЦОД: ZK-ансамбль/кворум KRaft из чётного числа узлов или из одного узла, либо весь кворум размещён в одном ЦОД, либо третья площадка (INF-01) полностью проигнорирована — **без** явного обоснования и компенсирующих мер; либо брокер Corax размещён на третьей площадке вопреки INF-01 | Число и размещение узлов ZK/KRaft в схеме/тексте; A-06. Только судья |
| HF-02 | Corax Mirror Maker 2 назван синхронным механизмом репликации, либо заявлен RPO = 0 при полной потере ЦОД-1 (вне контекста явного «недостижимо при MM2») | A-06; CONTEXT §1.7, §1.4 |
| HF-03 | Вымышленные компоненты/функции Corax поданы как факт (например: «штатный автоматический фейловер Corax между ЦОД», «Records Policy входит в Apache Kafka», «архивирование топиков в произвольное хранилище — штатная функция», «MM2 гарантирует exactly-once доставку в целевой кластер») | A-05, ловушки §4 |
| HF-04 | Как факт заявлено, что S3-бэкап сохраняет consumer offsets, либо что смещения/партиционирование в восстановленном из S3 топике совпадают с исходными (в документации не описано — только как помеченное допущение или вопрос к вендору допустимо) | A-05; CONTEXT §1.8 |
| HF-05 | Отсутствует хотя бы один обязательный артефакт D1–D10 | A-01 (механические паттерны) |

## 3. Критерии

### C1. Фактическая корректность по Corax (вес 14)

**Что оценивается:** соответствие утверждений о продукте CONTEXT.md §1;
корректные наименования; отделение фактов от допущений; честная работа с
пробелами съёма (mm2-scenarious, s3-options, KRaft-конфигурация).

| Уровень | Якорь |
|---|---|
| 0 | Сработал HF-03/HF-04, либо ≥ 4 ложных утверждения о продукте |
| 2 | 2–3 неточности или одно ложное утверждение о ключевом механизме (MM2, checkpoints, S3-коннекторы, кворум ZK), не разрушающее решение; допущения помечены частично |
| 4 | Все утверждения верны; всё за пределами §1 помечено допущением или подтверждено ссылкой с разрешённых доменов; различаются внутрикластерная репликация (ISR/acks) и межкластерная (MM2); учебные значения из примеров документации (RF=1 у connect-*, `qwe123`, Secman-фабрика) не перенесены в пром без корректировки; пробелы съёма честно оформлены как вопросы к вендору |

**Признаки сильного ответа:** официальные имена (Apache Kafka, Apache
ZooKeeper, Corax Schema Registry, Corax UI, Corax Mirror Maker 2,
Checkpoint/Heartbeat/Config Connector, Auto Data Balancer); «13 000 tps»
не подан как гарантия производительности репликации; тестовые параметры
НФТ-стенда не выданы за пром-рекомендацию.

**Типичные ошибки:** «MM2 реплицирует синхронно»; «checkpoints гарантируют
точное восстановление позиции»; «S3-коннектор сохраняет offsets топика»;
иерархические кворумы ZK выдуманы (на самом деле — [DOC], §1.2).

### C2. Кворум координации и третья площадка (вес 13)

**Что оценивается:** D2 + D3, INF-01, NFR-04.

| Уровень | Якорь |
|---|---|
| 0 | Нет решения по координации или HF-01 |
| 2 | Кворум есть и нечётный, но: потеря одной из площадок не разобрана; выбор ZK vs KRaft не обоснован; третья площадка формально упомянута без роли; ресурсы ВМ третьей площадки не сверены с минимальными требованиями к ZK/KRaft-узлу |
| 4 | (a) явный выбор ZK vs KRaft с учётом пробела съёма по KRaft (§1.2, §1.12); (b) схема размещения вида 2+2+1 (или обоснованная иная) с узлом(-ами) на третьей площадке, переживающая потерю любой одной площадки; разобраны потеря ЦОД-1, ЦОД-2 и третьей площадки (NFR-04 — платформа не деградирует); (c) сверка минимальных требований к узлу координации (4 CPU / 4 ГБ / 64 ГБ) с ВМ третьей площадки (4 vCPU / 8 ГБ / 100 ГБ); (d) рассмотрены и корректно оценены иерархические кворумы ZK (`group.x`/`weight.x`) как вариант; (e) отдельные кворумы для кластеров ЦОД-1 и ЦОД-2 (каждый кластер — свой ансамбль) осознанно спроектированы, а не «один ансамбль на оба кластера» без анализа |

**Ловушки:** кворум 2 узла по ЦОД (split-brain); весь ансамбль в ЦОД-1;
брокер на третьей площадке вопреки INF-01; «KRaft настроим по стандартным
параметрам» без пометки [ТРЕБУЕТ ПРОВЕРКИ].

| Уровень | Якорь |
|---|---|

| 4 | Active-Standby ЦОД-1 → ЦОД-2 с явной асинхронностью и обоснованием против Active-Active; состав коннекторов по ролям (Source/Sink — данные, Checkpoint — offsets, Heartbeat — доступность, Config — динамическая реконфигурация); **лаг/RPO выведен из данных**: пик 12 000 соб/с × 2 КБ ≈ 24 МБ/с (~200 Мбит/с) vs канал 2×10 Гбит/с — канал не лимит, лаг определяется обработкой коннекторов и не нормирован документацией ⇒ цель ≤ 60 с достижима при нормальной работе, подтверждается НТ и мониторингом лага (NFR-10); при разрыве канала лаг накапливается (~0,5 ТБ/6 ч в пике — посчитано) и догоняется после восстановления, данные не теряются (retention 14 дней покрывает); динамическое обнаружение новых топиков/партиций учтено в эксплуатации; нагрузка MM2-чтения на ЦОД-1 оценена против NFR-08 |

при переключении; репликация служебных топиков без анализа.

## 6. Формат вердикта {#verdict-schema}

```json
{
  "rubric_id": "CRX-DR-001-RUB",
  "task_id": "CRX-DR-001",
  "run_id": "string",
  "run_mode": "agentic",
  "judge": {"type": "llm-judge | agent-judge | human", "model": "string", "ensemble_index": 0},
  "hard_fails": [{"id": "HF-01", "triggered": false, "evidence": "string"}],
  "criteria": [
    {
      "id": "C1",
      "score": 0,
      "evidence": ["цитата ≤ 25 слов", "..."],
      "missing_for_next_level": "string",
      "traps_hit": ["T1"]
    }
  ],
  "checks": [{"id": "A-01", "status": "pass | fail | skipped", "details": "string"}],
  "total": 0,
  "verdict": "excellent | pass | fail",
  "summary": "3–5 предложений: сильные стороны, главные пробелы, рекомендация",
  "confidence": 0.0
}
```

Правила: `total` по формуле из frontmatter; `excellent` при `total ≥ 85`,
`pass` при `≥ 70`, иначе `fail`; при любом `hard_fails[].triggered = true`
— `fail`.
