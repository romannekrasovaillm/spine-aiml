# Рубрики оценки для задачи CMP-ARCH-001

## 1. Общие правила для судей

1. **Порядок:** (a) прочитать TASK.md и CONTEXT.md; (b) проверить HF §2;
   (c) оценить критерии §3 по шкале 0–4 с цитатами; (d) вердикт по §6.
2. **Фактическая база** — CONTEXT.md §1 (`[DOC]`). Утверждение, которого
   нет в §1 и которое не помечено `[ТРЕБУЕТ ПРОВЕРКИ]`, — **непроверенное**;
   если ложно — **ложное**. Судья не «додумывает» за решающего.
3. **«Упомянул ≠ классифицировал».** Балл — за требование, классифицированное
   (продукт / решение / процесс / пробел / компенсирующая мера) с привязкой
   к функции продукта или процессу банка, а не за ключевые слова.
4. **Шкала 0–4:** 0 — отсутствует/ошибочно; 1 — фрагментарно; 2 — базово
   корректно, есть пробелы; 3 — полно, мелкие недочёты; 4 — образцово, с
   учётом ловушек §4 и специфики сценария (INF-03, SEC-04, SEC-06).
5. **Цитирование.** По критерию 1–3 цитаты (≤ 25 слов) + чего не хватает до
   следующего уровня. Стиль сверх C10 не оценивается.

## 2. Правила hard-fail (HF)

При срабатывании любого правила итог ограничивается 39 баллами; критерии
оцениваются для диагностики. Детектируемость: HF-02/03/04 имеют
regex-детекторы (§9) — они дают **кандидатов** (regex не различает
отрицания), вердикт подтверждает судья; HF-05 ловится блоком
`deliverables` (§9); HF-01 — **только судья**.

| ID | Правило | Как обнаружить |
|---|---|---|
| HF-01 | Заключение **декларирует соответствие** ландшафта требованиям как факт («ландшафт соответствует 719-П», «продукты обеспечивают соответствие») вместо фиксации механизмов и остаточных мер — нарушение правила карты (CONTEXT §1.1) | Только судья: формулировки резюме D1 и выводов |
| HF-02 | 683-П применён как **действующий** акт: нормы 683-П использованы в матрице без пометки об утрате силы и замене на 851-П (CONTEXT §1.10–1.11) | Regex-кандидаты (§9) + судья; A-06 |
| HF-03 | Вымышленные/искажённые функции продуктов поданы как факт: TDE в редакции Standard; Radish как MPP/OLAP или система записи критичных данных; DataMarts как OLTP/система записи; WAF в составе SynGX; штатный прямой CDC в DataMarts; «Records Policy — функция Apache Kafka» | Regex-кандидаты (§9) + ловушки §4; A-05 |
| HF-04 | Процессы, которые продукт по определению не выполняет (ежегодный pentest, оценка соответствия по 57580.2, сертификация ПО, классификация данных, DR-учения), приписаны продуктам Platform V как штатная функция | Regex-кандидаты (§9) + судья; A-08 |
| HF-05 | Отсутствует хотя бы один обязательный артефакт D1–D10 | Блок `deliverables` (§9); A-01 |

## 6. Формат вердикта {#verdict-schema}

```json
{
  "rubric_id": "CMP-ARCH-001-RUB",
  "task_id": "CMP-ARCH-001",
  "run_id": "string",
  "run_mode": "agentic",
  "judge": {"type": "llm-judge | agent-judge | human", "model": "string", "ensemble_index": 0},
  "hard_fails": [{"id": "HF-01", "triggered": false, "evidence": "string"}],
  "criteria": [
    {
      "id": "C1",
      "score": 0,
      "evidence": ["цитата ≤ 25 слов", "..."],
      "missing_for_next_level": "string",
      "traps_hit": ["T1"]
    }
  ],
  "checks": [{"id": "A-01", "status": "pass | fail | skipped", "details": "string"}],
  "total": 0,
  "verdict": "excellent | pass | fail",
  "summary": "3–5 предложений: сильные стороны, главные пробелы, рекомендация",
  "confidence": 0.0
}
```

Правила: `total` — по формуле из frontmatter; `verdict = excellent` при
`total ≥ 85`, `pass` при `≥ 70`, иначе `fail`; при любом
`hard_fails[].triggered = true` — `fail`.

## 8. Калибровка и контроль качества судей

1. Подготовить эталоны (`gold`, `silver`, `fail`); медиана ансамбля должна
   попадать в `expected_totals`.
2. Согласованность судей по критериям; при `alpha < 0.75` — уточнить якоря
   (обычно C3 и C4).
3. Для 10 % прогонов — выборочная проверка человеком; расхождение > 1 балла
   — инцидент калибровки.

   `docs_snapshot_date`; повысить `version`; перепрогнать эталоны.
