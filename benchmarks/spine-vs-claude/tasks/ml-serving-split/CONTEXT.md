# Контекст: ML-платформа (текущее состояние)

Корпус предметной области. Одинаков для всех рук бенчмарка.

## Ландшафт «как есть»

- `ml-monolith` — Python-сервис: FastAPI (`/predict`), фоновый цикл
  переобучения каждые 6 часов, чтение признаков из PostgreSQL напрямую.
- Хранилище признаков как отдельный компонент отсутствует: обучающий цикл
  строит признаки SQL-запросом, инференс — другим SQL-запросом к тем же
  таблицам. Расхождение логик уже приводило к расхождению офлайн- и
  онлайн-метрик (train/serve skew).
- Модели лежат в `models/` внутри репозитория сервиса, версия — имя файла
  (`model_2026_08_30.pkl`).
- GPU: один пул из 4 карт, делится между обучением и инференсом через
  `CUDA_VISIBLE_DEVICES`, назначаемый вручную.
- Деплой: `docker compose up -d --build`, рестарт сервиса — простой инференса
  40–90 секунд, во время которого растёт очередь.

## Боли, названные владельцем продукта

1. Переобучение вытесняет инференс: p99 latency в окне обучения ×3.
2. Признаки считаются двумя разными реализациями — расхождения на 3–7%
   значений, разбор инцидентов занимает дни.
3. Откат модели = git revert + пересборка образа (20–40 минут).
4. Датасеты обучения ссылаются на `/mnt/data/raw` — путь менялся дважды за
   квартал, ломая воспроизводимость.

## Ограничения среды

- Команда: 6 инженеров; отдельного MLOps-подразделения нет.
- Бюджет на инфраструктуру: без роста более чем на 30% за квартал.
- Продовый SLA инференса: p99 ≤ 200 мс, доступность 99.5%.
- Окно обучения: ночное, допустимая длительность — до 4 часов.
- Нормативные рамки (справочно, не предмет задачи): внутренний регламент по
  обработке персональных данных; политика хранения артефактов моделей —
  12 месяцев.

## Словарь

- **Feature store** — слой, где признак определён один раз и читается обоими
  контурами.
- **Train/serve skew** — расхождение значений признаков между обучением и
  инференсом из-за разных реализаций.
- **Serving contract** — контракт между обучающим и сервирующим контурами:
  какие артефакты и как передаются.
