# Спецификация: граница происхождения экспериментов

Версия: 1.0 (заморожена пререгистрацией). Хэш этого файла цитируется в
`DECISION.md` (`spec: sha256:<...>`).

## Функциональные требования

- **FR-1.** Каждая продовая модель имеет машинно-читаемую связь с запуском
  трекера, породившим её артефакт.
- **FR-2.** Цепочка происхождения полна: от продовой модели до версии
  датасета, включая код (коммит) запуска.
- **FR-3.** Происхождение проставляется автоматически на пути обучения;
  ручное заполнение — только как исключение с явной пометкой.
- **FR-4.** Реестр моделей хранит метаданные, достаточные для ответа на
  аудиторский запрос без обращения к ноутбукам.
- **FR-5.** Модель из незавершённого запуска не может попасть в прод:
  контракт публикации явно различает состояния запуска.

## Нефункциональные требования

- **NFR-1.** Накладные расходы на запуск обучения ≤ 10% по времени.
- **NFR-2.** Решение выдерживает 1800 запусков/месяц без смены архитектуры.
- **NFR-3.** Привычный цикл исследователя (ноутбук) не требует ручных
  действий сверх уже существующих.

## Границы

- Смена трекера не рассматривается: MLflow остаётся источником запусков.
- Хранение самих артефактов моделей не переезжает: меняется контракт
  метаданных, а не хранилище.
- Задача не включает переписывание обучающих скриптов с нуля — допускается
  обёртка/адаптер.

## Ожидаемый результат

Целевая архитектура, зафиксированная как: инварианты (`ARCHITECTURE-SPINE.md`),
решения (`ADR`), журнал с именным аппрувером (`DECISION.md`), адресный след
приёмки (`TRACE.md`), доказательства (`ACCEPTANCE-EVIDENCE.md`).
