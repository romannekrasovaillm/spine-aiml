# Задача: граница происхождения экспериментов (lineage)

## Постановка

Вы — архитектор ML-платформы. Эксперименты исследователей живут в ноутбуках:
метрики — в трекере (`mlflow`-совместимом), код — в git, датасеты — в
объектном хранилище, а модель, попавшая в прод, не имеет машинно-читаемой
связи ни с одним из трёх. Вопрос «из какого эксперимента и на каком срезе
данных получена продовая модель» отвечается вручную и не всегда.

Спроектируйте границу происхождения: контракт между трекером экспериментов,
реестром моделей и обучением, при котором провенанс продовой модели
восстанавливается машинно, без чтения ноутбуков.

## Что нужно сдать

Ровно эти файлы (пути от корня рабочего каталога):

1. `docs/ARCHITECTURE-SPINE.md` — инварианты, каждый помечен `AD-<n>`.
2. `docs/adr/ADR-00N-<slug>.md` — минимум одно решение (формат ADR:
   заголовок `# ADR-NNN. <название>`, статус, контекст, решение,
   последствия, отвергнутые альтернативы).
3. `DECISION.md` — журнал решений (формат — в `TASK.md` задачи, журнал с
   именным аппрувером и хэшем `SPEC.md`).
4. `TRACE.md` — адресный след: `AC-NN -> ADR-NNN`, по строке на критерий.
5. `ACCEPTANCE-EVIDENCE.md` — ссылки `AC-NN: <файл>#L<строка>`.

Формат `DECISION.md` (обязателен, проверяется механически):

```
# Журнал решений

- Approver: <ФИО>
- spec: sha256:<64 hex — хэш файла SPEC.md>

## DEC-001 (2026-09-11)
- Решение: ...
- Обоснование: ...
- Отвергнуто: ...
- Срок пересмотра: <YYYY-MM-DD>
```

`ACCEPTANCE.md` изменять нельзя — приёмочные тесты зафиксированы человеком до
начала работы.
