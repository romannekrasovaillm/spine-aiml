# Задача: квоты и планирование GPU как отдельная политика

## Постановка

Вы — архитектор ML-платформы. GPU-пул (16 карт) распределяется вручную через
переписку: исследователи запускают обучение «кто первый», часть карт простаивает
ночью, а критичный инференс страдает в часы пик. Драки за карты, ручные
договорённости, отсутствие учёта потребления.

Спроектируйте целевую архитектуру: квоты как декларативная политика и
планировщик, который её исполняет. Решение должно быть зафиксировано в
артефактах; проверит его механический гейт, а не рецензент.

## Что нужно сдать

1. `docs/ARCHITECTURE-SPINE.md` — инварианты, каждый помечен `AD-<n>`.
2. `docs/adr/ADR-00N-<slug>.md` — минимум один ADR (заголовок
   `# ADR-NNN. <название>`, статус, контекст, решение, последствия,
   отвергнутые альтернативы).
3. `DECISION.md` — журнал решений с именным аппрувером и хэшем `SPEC.md`:

```
# Журнал решений

- Approver: <ФИО>
- spec: sha256:<64 hex — хэш файла SPEC.md>

## DEC-001 (2026-09-11)
- Решение: ...
- Обоснование: ...
- Отвергнуто: ...
- Срок пересмотра: <YYYY-MM-DD>
```

4. `TRACE.md` — адресный след, по строке на критерий: `AC-NN -> ADR-NNN`.
5. `ACCEPTANCE-EVIDENCE.md` — ссылки `AC-NN: <файл>#L<строка>`.

`ACCEPTANCE.md` изменять нельзя — приёмочные тесты зафиксированы человеком до
начала работы.
