# Спецификация: квоты и планирование GPU

Версия: 1.0 (заморожена пререгистрацией). Хэш этого файла цитируется в
`DECISION.md` (`spec: sha256:<...>`).

## Функциональные требования

- **FR-1.** Квоты задаются декларативно (файл/ресурс политики) и
  применяются планировщиком автоматически.
- **FR-2.** Инференс прода получает ресурс приоритетно: планировщик
  резервирует или вытесняет ресурс под него.
- **FR-3.** Потребление учитывается по команде и исследователю в машинно
  читаемом виде; отчёт строится автоматически.
- **FR-4.** Приоритет запуска — атрибут класса задачи, а не устная
  договорённость; отказ в запуске объясним со ссылкой на правило квоты.
- **FR-5.** Короткие итерации (≤ 1 часа) не вытесняются длинными задачами
  безусловно: политика предусматривает окно для них.

## Нефункциональные требования

- **NFR-1.** p99 инференса ≤ 200 мс, доступность 99.5% при любом состоянии
  пула обучения.
- **NFR-2.** Ночная утилизация пула ≥ 60%.
- **NFR-3.** Рост стоимости инфраструктуры ≤ 30% за квартал (пул не растёт).

## Границы

- Пул фиксирован (16 карт): масштабирование не рассматривается.
- Смена облачного провайдера не рассматривается.
- Задача не включает переписывание обучающих скриптов; допускается их
  обёртка/адаптер к планировщику.

## Ожидаемый результат

Целевая архитектура, зафиксированная как: инварианты (`ARCHITECTURE-SPINE.md`),
решения (`ADR`), журнал с именным аппрувером (`DECISION.md`), адресный след
приёмки (`TRACE.md`), доказательства (`ACCEPTANCE-EVIDENCE.md`).
