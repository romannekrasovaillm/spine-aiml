# Задача: обратимая миграция реестра моделей

## Постановка

Вы — архитектор ML-платформы. Реестр моделей — самописный сервис на
PostgreSQL с 4-летним стажем: 380 моделей, 30 из них в проде, схема менялась
аддитивно и обросла легаси. Требуется перейти на целевое хранилище
(объектное + каталог метаданных) без остановки инференса и с гарантированным
откатом.

Миграция необратима по природе (смена хранилища артефактов), поэтому решение
обязано описывать обратимость на уровне контракта и указателя, а не «мы
сделаем бэкап».

## Что нужно сдать

1. `docs/ARCHITECTURE-SPINE.md` — инварианты, каждый помечен `AD-<n>`.
2. `docs/adr/ADR-00N-<slug>.md` — минимум один ADR (заголовок
   `# ADR-NNN. <название>`, статус, контекст, решение, последствия,
   отвергнутые альтернативы).
3. `DECISION.md` — журнал решений с именным аппрувером и хэшем `SPEC.md`:

```
# Журнал решений

- Approver: <ФИО>
- spec: sha256:<64 hex — хэш файла SPEC.md>

## DEC-001 (2026-09-11)
- Решение: ...
- Обоснование: ...
- Отвергнуто: ...
- Срок пересмотра: <YYYY-MM-DD>
```

4. `TRACE.md` — адресный след, по строке на критерий: `AC-NN -> ADR-NNN`.
5. `ACCEPTANCE-EVIDENCE.md` — ссылки `AC-NN: <файл>#L<строка>`.

`ACCEPTANCE.md` изменять нельзя — приёмочные тесты зафиксированы человеком до
начала работы.
