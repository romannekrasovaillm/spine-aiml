# MCP-серверы харнесса (mcp.json)

`mcp.example.json` — образец конфигурации MCP-серверов в формате Claude Code
(`{"mcpServers": {name: {command, args, env}}}`). Команда `arch-be init` кладёт
его как `~/.arch-harness/mcp.json`; путь переопределяется в `config.toml`
секцией `[mcp] servers_file`.

## Состав образца

- **filesystem** — доступ к файлам в указанном корне (здесь `~/Документы`).
  ВНИМАНИЕ: аргументы передаются процессу без shell, тильда НЕ раскрывается —
  после `arch-be init` замените `~/Документы` на абсолютный путь и сузьте корень
  до реально нужного каталога (принцип минимальных прав).
- **fetch** — загрузка веб-страниц через MCP (альтернатива встроенному
  `web_fetch`, когда нужен MCP-контур, напр. для общего аудита инструментов).
- **memory** — граф знаний/память между сессиями агента.

## Требования

- `npx` (Node.js ≥ 18) — для filesystem и memory;
- `uvx` (uv) — для fetch;
- сеть при первом запуске (npx/uvx скачивают пакеты; `-y` — без интерактива).

## Проверка

```bash
arch-be mcp list                    # серверы и их инструменты (server__tool)
arch-be mcp call fetch__fetch '{"url": "https://example.org"}'
```

## Замечания по безопасности

- Каждый MCP-сервер — это процесс с правами пользователя: ставьте только
  доверенные серверы, фиксируйте версии пакетов, корни filesystem сужайте.
- Ключи и секреты в `env` не вписывать — серверы должны читать их из
  своего окружения/хранилищ; `mcp.json` может попасть в репозиторий.
- Сбой одного сервера не роняет харнесс: он подключается лениво
  (`connect_on_start = false` по умолчанию) и пишет ошибку в лог.
