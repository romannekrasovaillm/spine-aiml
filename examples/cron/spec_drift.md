# Cron-задача: дрейф-чек спецификаций (spec-drift)

Ты — дежурный агент харнесса, реализующий гейт A5 (post-deploy drift check)
по расписанию: ищешь расхождение «спецификации ↔ код» в целевом репозитории.

## Входные параметры

- Целевой репозиторий: берётся из первого аргумента отчёта-запуска либо
  настраивается правкой этого файла (укажи путь ниже).
  РЕПОЗИТОРИЙ: `./` (по умолчанию — текущий каталог запуска `arch-be cron run`).
- Спецификации: `docs/specs/*.md` и `docs/ARCHITECTURE-SPINE.md` внутри
  репозитория; код: `src/`, `services/`, `db/migrations/`.

## Шаги

1. Через `bash` сравни свежесть: `ls -lt docs/specs/*.md` против
   `git log --since='14 days ago' --name-only --oneline -- src services db`
   (если нет git — `find src services db -type f -mtime -14`).
2. Для каждой спеки, затронутые темы которой менялись в коде позже даты
   спеки, прочитай спеку и диффы коммитов; зафиксируй РАСХОЖДЕНИЯ:
   поведение кода противоречит тексту спеки (контракты, идентификаторы,
   статусы, лимиты). Расхождение — только со свидетельством: цитата спеки
   + файл:строка кода или хеш коммита.
3. Отдельно проверь spine: `arch-be control spine docs/ARCHITECTURE-SPINE.md`
   и новые `unsafe`-маркеры/заглушки в свежих коммитах.
4. Классифицируй: `DRIFT` (код ушёл от спеки — чинить код или спеку решением
   владельца), `STALE-SPEC` (спека устарела, код прав — обновить спеку
   дельтой), `OK`. Ничего не выдумывай: нет свидетельства — нет находки.

## Формат отчёта

Markdown: дата, репозиторий, таблица «спека — последнее изменение —
свежие коммиты по теме — вердикт», находки со свидетельствами, предложение
чинящего действия на каждую находку (дельта-спека / задача на код / вопрос
владельцу домена). В конце — headless JSON-статус:

```json
{"status": "complete | partial | blocked", "assumptions": [], "open_questions": [], "conflicts_with_prior_decisions": []}
```

`partial` — репозиторий доступен частично (нет git, нет каталога спек);
`blocked` — репозиторий недоступен.
