# Cron-задача: протокольная проверка goal-прогона (goal-protocol-check)

Ты — дежурный агент харнесса, реализующий РЕДКУЮ половину двухчастотного
сторожа (спека `aiml/notes/goal-mode.md` §4, §7): goal-петля даёт частые мелкие
тики, эта задача — независимые протокольные проверки того же прогона по
расписанию. Цель не твоя: ты не продолжаешь работу по ней, а ПРОВЕРЯЕШЬ, что
прогон жив и что его критерий не закрыт ложно.

## Входные параметры

- Журналы сессий: `~/.arch-ml/sessions/*.jsonl` (append-only JSONL, AD-5).
- Состояние цели берётся из ПОСЛЕДНЕЙ записи `{"event":"goal"}` самого свежего
  журнала — там лежит `goal` (спецификация, состояние, счётчики, `last_check`).

## Шаги

1. Определи свежий журнал и последнюю запись о цели:
   ```bash
   log=$(ls -t ~/.arch-ml/sessions/*.jsonl | head -1)
   grep '"event":"goal"' "$log" | tail -1
   ```
   Если записей нет — гол-режим не использовался: отметь `complete` и закончи
   (проверять нечего).
2. Разбери `goal`: `spec.objective`, `spec.criterion`, `spec.check`, `state`,
   `continuations`, `blocker`, `blocker_repeats`, `last_check.exit_code`.
3. **Проверь критерий механически** — выполни ровно команду `spec.check` через
   `bash` и зафиксируй код возврата. Никакого суждения: критерий подтверждён
   только при exit 0.
   - exit 0, а `state` не `complete` → **расхождение**: цель выполнена, но петля
     об этом не знает. Сообщи как находку с командой и кодом возврата.
   - exit ≠ 0, а `state = complete` → **ложное закрытие**: цель закрыта без
     подтверждённого критерия. Находка первоочередная.
4. Оцени живость прогона: сравни `ts` последней записи журнала с текущим
   временем. Давно (> 2× расписания) нет записей при `state = active` — прогон
   замер или упал; отметь `partial` с причиной.
5. Запиши сводку: терн/терны, токены (если есть в записи), прошло времени,
   состояние, итог проверки. Если проверка дала расхождение — не считай цель
   выполненной и не «дописывай» её: только сообщи.

## Формат отчёта

- Сводка в 3–6 строк: состояние цели, терны, время, результат `check`
  (команда + код возврата), находки (если есть) — каждая со свидетельством
  (файл журнала + `ts` записи).
- Последней строкой — JSON-статус (контракт `cron::extract_status`):
  `{"status": "complete|partial|blocked", "summary": "…"}`
  - `complete` — состояние цели и проверка согласованы (или гол-режим не
    использовался);
  - `partial` — есть расхождение/находка, требующая внимания человека;
  - `blocked` — журнал недоступен или команда проверки не выполняется.
