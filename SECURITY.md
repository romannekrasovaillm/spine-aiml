# SECURITY — сообщение об уязвимостях

## Куда сообщать

Напрямую владельцу продукта (контакт — в лицензионном договоре; до
первого договора — через канал, указанный в сопроводительном письме
поставки). **Не** публиковать в общих трекерах и чатах до фикса —
уязвимость агента с bash-доступом в периметре банка чувствительна даже
в описании.

## Что приложить

Минимальное воспроизведение, версию поставки, вывод `arch-ml doctor`,
оценку вектора (по `docs/threat-model.md`: T1–T8 или новый класс).

## Процесс

1. Подтверждение получения — 1 рабочий день.
2. Триаж по модели угроз (`docs/threat-model.md`): вектор, остаточный
   риск, затронутые границы доверия.
3. Фикс: S1 — hotfix в 3 рабочих дня; S2/S3 — по политике `SUPPORT.md`.
4. Раскрытие: после фикса — запись в CHANGELOG с классом угрозы (без
   деталей эксплуатации), при существенной — обновление
   `docs/threat-model.md` (реестр GAP §5).

## Область

- Агент `arch-ml` (инструменты, policy, журналы, секреты), цепочка
  поставки (зависимости, `vendor/archify/`, node, SBOM), банковская зона
  `banking/`.
- ВНЕ области: уязвимости кодовой базы заказчика, найденные агентом
  (это предмет процесса ИБ заказчика), компрометация ОС/учётной записи
  (периметр защиты ДИТ) — см. §6 threat model.

## Смежные документы

`docs/threat-model.md` (модель угроз, ADR-031), `docs/supply-chain.md`
(проверка поставки), `ROADMAP.md` (подпись артефактов, SLSA — план).
