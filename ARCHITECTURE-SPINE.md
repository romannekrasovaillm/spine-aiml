# ARCHITECTURE-SPINE — Spine (доменный харнесс solution-архитектора)

> Dogfood: инварианты собственной кодовой базы харнесса. Проверяются
> механически: `arch-be control spine ARCHITECTURE-SPINE.md` (линтер) и
> `arch-be control check . --constraints CONSTRAINTS.yaml` (fitness-гейт),
> CI-джоба `dogfood`. Связь AD ↔ правил — по ссылкам `C-NN` в поле Rule.

---

## AD-1: Тонкое ядро — механика в коде, знания в плагинах

- **Binds**: ядро (`src/`) ↔ библиотека плагинов (`assets/plugins/`)
- **Prevents**: раздувание бинаря доменными методиками; пересборка ради правки промпта или скилла
- **Rule**: в ядре живёт только механика — агентный цикл, инструменты, линтеры, гейты, TUI. Доменное знание (скиллы, промпты, субагенты, хуки, MCP-примеры) живёт в плагинах и ассетах и подключается без перекомпиляции. Новая возможность сначала оформляется плагином; в `src/` попадает только обобщённая механика. Страж: C-09 (библиотека плагинов в репозитории).
- **Статус**: [ADOPTED]

## AD-2: Детерминированный слой контроля — без LLM

- **Binds**: policy (R0–R5), spine-линтер, fitness-функции, trace check, NFR-расчёты ↔ CI-гейты
- **Prevents**: «контроль по настроению модели» — невоспроизводимые вердикты, невозможность механического гейта
- **Rule**: механика контроля (`src/policy.rs`, `src/control.rs`, `src/trace.rs`, `src/nfr.rs`) — детерминированные функции: один вход → один вердикт, локально и в CI. LLM допускается только в судье рубрик — и там с калибровкой (k-сэмплы, изоляция evidence от инъекций, golden-гейт `arch-be bench run --golden`, ADR-004). Вердикт контроля никогда не генерируется моделью. Политика применяется в dispatch каждого инструмента (правило C-07).
- **Статус**: [ADOPTED]

## AD-3: Секреты — только через окружение

- **Binds**: `Config` ↔ переменные окружения / файлы ключей; bash-инструмент ↔ env_scrub
- **Prevents**: ключ в конфиге, журнале, скриншоте или репозитории; утечка env в процесс, порождённый командой модели
- **Rule**: конфиг хранит имена переменных (`api_key_env`) и пути к файлам (`api_key_file`), не значения. Значения ключей не печатаются в логи, ошибки, скриншоты. Bash-инструмент выбрасывает секретоподобные переменные (KEY/SECRET/TOKEN/PASSWORD/PASSWD/PASS/CREDENTIAL(S)/AUTH) из окружения команды; исключения — только явный `env_allow`. Механический страж: правила C-05/C-06 (запрет литералов ключей в коде и конфигах).
- **Статус**: [ADOPTED]

## AD-4: Единый OpenAI-совместимый провайдерный слой

- **Binds**: агентный цикл ↔ трейт `LlmProvider` (`src/llm.rs`) ↔ DeepSeek / Kimi / GLM
- **Prevents**: N разных клиентов с разъехавшимся поведением ретраев, ризонинга и стриминга
- **Rule**: все провайдеры — за одним трейтом `LlmProvider`; отличия — в конфиге (base_url, модель, флаги ризонинга, контекстное окно), не в ветвлениях кода. Ретраи — единая классификация ошибок (`src/retry.rs`). Новый OpenAI-совместимый провайдер добавляется конфигурацией, без кода. Страж: C-10.
- **Статус**: [ADOPTED]

## AD-5: Журнал — единственный источник аудита

- **Binds**: агентный цикл ↔ `sessions/*.jsonl`; метрики и аудит ↔ те же журналы
- **Prevents**: «аудит по памяти» — решения, отказы политики и стоимость, которые нельзя восстановить
- **Rule**: каждая сессия пишет JSONL: сообщения, вызовы инструментов, вердикты политики (включая отказы), токены и стоимость. Метрики (`arch-be metrics`), детектор approval theater и аудит строятся только по журналам, не по состоянию агента. Журнал не отключается (уровень R3 встроен по умолчанию). Страж: правило C-08.
- **Статус**: [ADOPTED]

## AD-6: Безопасный Rust — без unsafe, с пином MSRV

- **Binds**: весь `src/` ↔ `Cargo.toml` (`[lints] unsafe_code = "forbid"`, `rust-version = "1.85"`)
- **Prevents**: UB в долгоживущем TUI-процессе; дрейф MSRV («собирается только на машине автора»)
- **Rule**: unsafe запрещён линтом `unsafe_code = "forbid"`; обход через макросы ловится правилом C-01. MSRV 1.85 пиннится в `rust-version` (C-03) и проверяется отдельной CI-джобой. Ошибки — `HarnessError`/`Result` (thiserror); библиотечный код не паникует. Линты-пины: C-02.
- **Статус**: [ADOPTED]

## AD-7: Тесты и git-операции — изолированы от машины

- **Binds**: `tests/`, git-операции (`src/worktree`… harness) ↔ CI-раннер без пользовательского окружения
- **Prevents**: «зелёно у автора, красно в CI» — скрытая зависимость от `~/.gitconfig`, HOME, локальных путей
- **Rule**: тесты изолируют HOME (tempdir), не читают пользовательские конфиги, не ходят в сеть (live-прогоны — только под `#[ignore]`). Git-операции продакшен-кода, создающие коммиты, обязаны иметь фолбэк-идентичность коммиттера (инцидент: красный CI без `~/.gitconfig`). Персональные пути — в конфиге пользователя, не в коде; страж — шаг personal-paths в CI-джобе dogfood.
- **Статус**: [ADOPTED]

## AD-8: Handoff кодовым харнессам — механический контракт

- **Binds**: генератор `.arch-handoff/` ↔ адаптеры кодовых харнессов (Claude Code, Qwen Code, OpenClaw, Hermes, Theseus, CodeWhale)
- **Prevents**: «сводка извлекается эвристикой» — результат исполнителя не парсится, гейта нет, откат не за что зацепить
- **Rule**: пакет несёт инварианты, критерии приёмки и план отката; headless-результат — типизированный JSON (status/assumptions/open_questions/conflicts), валидируемый схемой (Valid/Invalid/Missing); `blocked` и непустые conflicts меняют exit-код. Исполнитель обязан сделать финальный коммит; харнесс страхует auto-commit'ом. Предгейт: git-репозиторий с baseline-коммитом гарантирован (якорь отката). Детали — ADR-001. Страж: C-11 (поля JSON-контракта в коде).
- **Статус**: [ADOPTED]

## AD-9: Spine и трассировка — гейт, а не документация задним числом

- **Binds**: этот файл + `CONSTRAINTS.yaml` ↔ `arch-be control` и CI-джоба `dogfood`
- **Prevents**: инварианты «на бумаге»: файл есть, проверка не запускается, дрейф не ловится
- **Rule**: харнесс применяет собственные механики к самому себе: spine-линтер и fitness-гейт запускаются в CI по корневым `ARCHITECTURE-SPINE.md` и `CONSTRAINTS.yaml`. Каждый AD либо связан с механическим стражем (fitness-правило C-NN или шаг CI), либо помечен `unverifiable` с обоснованием (контракт trace check, ADR-006). Правки, ломающие инвариант, не мержатся. Стражи: C-04 (audit-джоба), C-12 (сама джоба dogfood).
- **Статус**: [ADOPTED]

## AD-10: Плагин — единица распространения знаний

- **Binds**: `assets/plugins/` ↔ `arch-be init` ↔ библиотека пользователя
- **Prevents**: знания, зашитые в бинарь; обновление харнесса, затирающее наработки пользователя
- **Rule**: скиллы, субагенты, хуки и MCP-примеры упаковываются в плагины (открытый стандарт agent-plugins.org). `arch-be init` раскладывает ассеты, не затирая существующие файлы пользователя. Дистилляция новых знаний из сессий и статей — тоже в плагины (скиллы skill-creator и distill). Страж: C-09.
- **Статус**: [ADOPTED]

## Deferred (с условиями возврата)

### DEF-1: Интерактивное подтверждение на R4 (диалог в TUI)

- **Причина**: сейчас RequireConfirm реализован как остановка с текстом эскалации (`src/tool.rs`) — безопасно и достаточно для headless; модальный диалог требует протаскивания подтверждения через акторную модель TUI.
- **Условие возврата**: R4 становится рабочим уровнем команды (частые деструктивные операции в интерактиве), а не аварийной ступенью.

### DEF-2: cargo deny (лицензии, баны, источники зависимостей)

- **Причина**: supply-chain покрыт `cargo audit` (уязвимости, CI-джоба audit); лицензионная политика исследовательскому проекту с одним автором не критична.
- **Условие возврата**: публикация бинарных артефактов, включение в чужой дистрибутив или появление внешних контрибьюторов.

### DEF-3: Декомпозиция крупных модулей (harness.rs, tui/app.rs)

- **Причина**: модули ~2.5k строк — читаемы, но выросли; декомпозиция без смены API — задача P2-3 ревью, отдельным проходом.
- **Условие возврата**: первое изменение, которое упирается в навигацию по этим файлам, либо рост сверх ~3k строк.
