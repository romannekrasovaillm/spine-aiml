# Дельта-спека: панель «Флот» — явное пустое состояние вместо тихой деградации

- Маршрут: **Fast** (`significance_score` = 0 триггеров; контракты, данные, security-границы,
  владение доменом не затрагиваются — меняется только наблюдаемое поведение вкладки TUI).
- Статус: Proposed, исполняется кодовым харнессом.
- Дата: 2026-09-12.
- Повод: инцидент «дашборд флота не очистился после удаления журналов прогонов»
  (удалены `~/.arch-ml/state/fleet/*` и 6 worktrees флота; панель продолжала показывать прогон).

## 1. Измеренный дефект (файл:строка)

1. `src/tui/app.rs:940-965` — `refresh_fleet()` пишет в `self.panels.fleet` только внутри
   `if let Ok(path) = latest_log(...) { if let Ok(s) = render_log(...) { … } }`. Ветки `else` нет.
2. `src/fleet_run.rs:1106-1134` — `latest_log()` на пустом каталоге возвращает
   `Err(Harness("нет журналов прогона в каталоге флота"))`.
3. Следствие: при пустом `state_dir/fleet` панель сохраняет последний успешный кадр неограниченно
   долго (комментарий `app.rs:937-939` называет это «тихой деградацией»). Наблюдаемо: вкладка `F6`
   (Флот) продолжает показывать прогон и пульс heartbeat, рассчитанный по `mtime` уже удалённого
   файла (`app.rs:944-959`).
4. Смена вкладок состояние не сбрасывает: `refresh_fleet()` вызывается только при активной вкладке
   «Флот» раз в ~2 с (`app.rs:926-934`).

## 2. Решение

`refresh_fleet()` обязана ВСЕГДА перезаписывать `self.panels.fleet` — ровно одним из трёх состояний:

| Состояние | Условие | Текст панели |
|---|---|---|
| Журнал прочитан | `latest_log` = Ok и `render_log` = Ok | как сейчас: заголовок `progress_header` + dashboard |
| Журналов нет | `latest_log` = Err | строка 1: `Журналов прогонов нет: <абсолютный путь fleet_dir>`; строка 2: подсказка `запуск: arch-ml fleet run --plan <файл-плана>` |
| Журнал не читается | `latest_log` = Ok, `render_log` = Err | `Журнал <path> не читается: <текст ошибки>` |

Инвариант, проверяемый тестом: в состоянии «журналов нет» панель не содержит признаков прежнего
прогона (`fpl-…`, имена узлов/агентов).

## 3. Границы изменения

Меняем:
- `src/tui/app.rs` — тело `refresh_fleet()` (+ приватный хелпер рядом, если он реально нужен)
  и тесты в `mod tests` этого же файла;
- `docs/tui.md` — одна строка в таблице «Правая панель» (`docs/tui.md:63`), в конце описания вкладки
  `▶ Флот` добавить: «При отсутствии журналов прогонов панель явно сообщает об этом — прежний кадр
  не сохраняется.»;
- `docs/fleet-panel-empty-state.delta.md` — эта дельта-спека.

НЕ меняем:
- `src/fleet_run.rs`: `latest_log` / `render_log` / `progress_header` / `FleetProgress` уже дают всё
  необходимое, сигнатуры не трогать;
- `src/tui/render.rs`, `src/tui/keymap.rs`, `src/tui/caps.rs`, `src/tui/shot.rs`;
- `ARCHITECTURE-SPINE.md`, `CONSTRAINTS.yaml`, `docs/adr/**`, `кейсы/**` — зоны архитектора и кейсов;
- поведение при найденном и прочитанном журнале: существующие тесты (в том числе
  `f6_unhides_panel_and_loads_fleet_dashboard`, `app.rs:3318-3360`) остаются без правок.

Вне объёма (сознательно):
- аналогичные «тихие» плейсхолдеры других вкладок (`Mermaid` / `Рубрика` / `Знания`);
- семантика слэш-команды `/fleet` (`app.rs:1997`): рефреш и далее владеет панелью, агентский текст
  живёт до следующего тика;
- пороги `HEARTBEAT_ALIVE_SECS = 30` / `HEARTBEAT_STALE_SECS = 90` (`src/fleet_run.rs:1371-1373`).

## 7. Решения архитектора по открытым вопросам исполнителя (2026-09-12, гейт A4)

Прогон `hr-20260912-170007-00` (claude-code, коммит `26f778c`) закрыл A1–A6. Разбор вопросов:

1. **A4 и литерал `fpl-test` (валидность проверки).** Изменение фикстуры принято: проверка
   «панель не хранит признаков прежнего прогона» усилена событием `plan_started` с `plan_id`,
   который реально рендерится, — вакуумность снята. Печатать `run_id` в панель в этой дельте
   **не требуем**: это правка `fleet_run.rs`, за границей задачи.
   *Отложено, не отклонено:* панель различает прогон по `plan_id`, поэтому два прогона одного
   плана визуально неразличимы. Если понадобится — отдельная Fast-дельта (одна строка в
   `progress_header`: `Прогон: <имя файла журнала>`).
2. **Пустой, но читаемый журнал.** Поведение принято: 0-байтовый файл — легитимное промежуточное
   состояние (журнал создан, первое событие ещё не записано), ветка «прочитан» с текстом
   `журнал пуст или не найден`.
   *Замечание отложено:* фраза «или не найден» вводит в заблуждение, когда файл существует;
   формулировка живёт в `fleet_run.rs` — вне границ дельты.
3. **«Каталог отсутствует» vs «каталог пуст».** Не различаем: действие пользователя одинаково
   (журналов нет → запустить прогон), путь в сообщении есть, различие не добавляет ценности и
   лишнюю ветку кода. Решение окончательное для этой дельты.
