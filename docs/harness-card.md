# Harness Card — Spine AI/ML Edition (`arch-ml`)

Карта харнесса — добровольное раскрытие того, что «между моделью и
пользователем»: как собирается системный промпт, как сжимается контекст, что
считается невытесняемым, как работают маршрутизация значимости и выбор
модели. Без этой карты сравнение моделей внутри разных обвязок
бессмысленно: смена одного лишь слоя оркестрации сдвигает счёт сильнее,
чем смена модели (концепция «There Is No Neutral Harness»; см. раздел
«Источники»).

**Редакция:** Spine AI/ML Edition, бинарь `arch-ml`, точка форка
`b928684` (2026-09-11, от банковской линии Spine — `NOTICE.md`). Всё
описанное ниже **унаследовано от исходной редакции без изменений в ядре**; отличия форка — только имя бинаря
и каталоги состояния (`~/.arch-ml`, `~/.config/arch-ml`). Где возможность
ещё не реализована — это отмечено явно.

## 2. Состав системного промпта

Системный промпт собирается один раз на сессию и **логируется в журнал как
событие `system`** (инвариант «видимое модели ⟺ записанное в журнал»).

1. **Шаблон из библиотеки промптов.** Загружается из `assets/prompts/*.md`
   (`src/agent/prompts.rs::load_library`); имя файла = имя шаблона, первая
   `#`-строка = описание. Основной шаблон архитектора — `architect.md`.
   Плейсхолдеры `{{var}}` подставляются через `render`. Каталог отсутствует
   — библиотека пуста, харнесс работает и без ассетов.
   Состав библиотеки: `architect`, `spine`, `adr`, `nfr_design`,
   `readiness_gate`, `reverse_discovery`, `review_adversarial`,
   `handoff_compile`, `skill_distiller`.
2. **Инжект персистентной памяти.** `memory::augment_system_prompt`
   (`src/memory.rs`) дописывает в конец секцию с содержимым
   `paths.memory_file`. Секция инжектится всегда, даже когда память пуста:
   агент получает путь к файлу и правило «пополнять только по явной просьбе
   пользователя».
3. **История + спецификации инструментов.** На каждый ход запрос =
   `system` + история + `tools.specs()` (`build_request`, `src/agent.rs`).

**Неизменяемое ядро промпта:** ни шаг 1, ни шаг 2 не подвергаются
компактификации — сжатию подлежит только история диалога (см. §3).

**Домен форка:** шаблон `architect.md` — банковский по содержанию и **пока
не заменён** на ML-редакцию. Это известный долг: пресет `ml-researcher`
ещё не создан (см. ADR-040).

## 3. Правила компактификации контекста

Трёхуровневая схема (`src/agent.rs`), пороги — в `[agent]`
(`compact_l1_pct = 70`, `compact_l3_pct = 95`).

| Уровень | Порог | Что делает |
|---|---|---|
| **L1 — маскирование** | 70 % бюджета (`compact_l1_pct`) | Старые tool-результаты усекаются до 500 символов (`COMPACT_TOOL_CHARS`), кроме последних 4 (`COMPACT_KEEP_TOOL`); затем удаляются самые старые сообщения, хвост из 6 (`COMPACT_KEEP_TAIL`) неприкосновенен. |
| **Прунинг** | только >100 % | Если после L1 сумма всё ещё превышает бюджет — продолжается удаление из середины. |
| **L3 — LLM-саммари** | 95 % (`compact_l3_pct`) | Диалог сворачивается LLM-«компактификатором» в заметки для продолжения (до 1500 символов), до последнего user-сообщения; результат вклеивается как `CONTEXT COMPACTED`, хвост сохраняется. |

**Дополнительные механики:**

- **Бюджет** — `min(agent.context_budget_tokens, models.<active>.context_limit)`,
  где `context_limit` берётся из окна модели (`docs/models.md`). Так L3
  стартует на ~95 % **реального** окна API, не дожидаясь HTTP 413.
- **`l3_futile`** — флаг гасит бесполезную L3 (когда сворачивание не
  уменьшает историю): иначе на каждом ходу жёгся бы API.
- **Форсированная L3 по ошибке** — HTTP 413 / «context length» →
  принудительная L3 и **ровно один** повтор хода.
- **Ручная компактификация** — `/compact` в TUI (событие `compact_manual`).
- **События журнала:** `compact`, `compact_l3`, `compact_manual`.

**Слой невытесняемых инвариантов.** Сегодня невытесняемое — это системный
промпт (§2): он не сжимается, и именно в нём живут role/guard-инструкции.
Инварианты спин `ARCHITECTURE-SPINE.md` (блоки `AD-n`) читаются
инструментами как файлы и, строго говоря, **попадают под компактификацию
истории**. Машино-проверяемого «дистиллята с адресным следом» (roadmap,
H0.3 — правило, переживающее много ходов и возвращаемое вместе со ссылкой
на источник) в этой ревизии ещё нет. Это честная граница текущего
состояния, а не желаемое.

**Источник:** `docs/theseus_hardening.md` (строки о L1/прунинге/L3,
`l3_futile`), `src/agent.rs`, `src/config.rs`.

## 4. Бюджет окна и наблюдаемость

- Бюджет по умолчанию — `agent.context_budget_tokens` (в примере конфига
  крупный, порядка миллионов токенов), плюс потолок окна модели.
- Оценка размера — по символам (≈4 символа/токен).
- В TUI — индикатор заполнения окна: зелёный до L1, оранжевый до L3,
  красный за порогом.
- Журнал сессии (JSONL) фиксирует каждый переход уровня — по нему
  восстанавливается, что именно модель видела на каждом ходу.

## 5. Маршрутизация значимости

Детерминированная, не «на усмотрение модели». Считаются 15 канонических
триггеров (`SIGNIFICANCE_TRIGGERS`, `src/control.rs`); score = число
сработавших.

| Маршрут | Условие | Режим |
|---|---|---|
| `Fast` | score ≤ `fast_max` (дефолт 1) | Дельта-спека + авто-валидация |
| `Standard` | `fast_max` < score ≤ `standard_max` (дефолт 4) | Контракт Spec→Plan→Tasks + Architecture Fit |
| `Critical` | score > `standard_max` **или** любой из `security_boundary_change` / `irreversible_migration` / `criticality_or_exception` | Solutioning + решение человека (гейт A3) |

- Маршрут задаёт профиль Evidence Bundle (`docs/governance.md`) и
  рекомендованный таймаут handoff: Fast 1800 с, Standard 3600 с,
  Critical 7200 с (`docs/harness_integrations.md`).
- Анти-обход: `--from-diff` даёт механический «пол» score по diff, чтобы
  маршрут нельзя было занизить вручную.
- Настраивается секцией `[significance]`; статус — рабочая гипотеза.

**Домен форка:** таблица триггеров банковская (`financial_impact`,
`rto_rpo_targets`, `trust_zone_change`). Для ML-домена её состав подлежит
пересмотру — часть триггеров нерелевантна (см. ADR-040).

## 6. Гибридный выбор модель/локально ↔ frontier

**В текущей ревизии НЕ реализован.** Что есть сегодня:

- Матрица провайдеров и переключатель модели (`default_model` в конфиге,
  `/model` в TUI) — выбор **ручной**, на сессию.
- Единый OpenAI-совместимый транспорт (`POST {base_url}/chat/completions`)
  для всех провайдеров, включая self-hosted open-weights через фабрику
  `openai_compat`. То есть **техническая возможность** позвать локальную
  модель есть, автоматики — нет.
- Бюджет окна и пороги компактификации учитывают `context_limit` активной
  модели.

Чего **нет** и что числится в дорожной карте как «достроить»: оценка
сложности задачи, авто-эскалация локальная→frontier по уверенности,
каскад с контролем стоимости. Harness Card намеренно фиксирует это как
разрыв, а не выдаёт за готовое.

## 7. Периметр, вывод данных, телеметрия

- **Два канала вывода:** (1) API активной модели, (2) web-инструменты
  (если включены). Оба явно конфигурируемы.
- **MCP** — локальные stdio-серверы по списку (`~/.arch-ml/mcp.json`).
- **Секреты** — только из окружения/файлов ключей; значения никогда не
  выводятся в лог (`src/secrets.rs` редактирует 7 классов секретов в
  выводе инструментов и в журнале tool-аргументов).
- **Песочница** — политика R0–R5 (`src/policy.rs`); профиль домена задаёт
  уровень (например, bwrap — в банковском профиле).
- **Собственной телеметрии/бэкдоров нет.** Всё, что уходит наружу, —
  содержимое запросов к выбранному API.

## 8. Сводка честного статуса

| Возможность | Состояние |
|---|---|
| Состав системного промпта + логирование | реализовано (унаследовано) |
| Трёхуровневая компактификация L1/prune/L3 | реализовано (унаследовано) |
| `l3_futile`, форс-L3 по 413, `/compact` | реализовано (унаследовано) |
| Маршрутизация значимости (15 триггеров, anti-bypass) | реализовано (унаследовано), домен банковский |
| Бюджет окна от `context_limit` модели | реализовано (унаследовано) |
| Невытесняемый слой инвариантов (машино-проверяемый дистиллят) | **нет** — roadmap H0.3 |
| Гибридная маршрутизация локальная↔frontier | **нет** — roadmap, ось 3 |
| ML-шаблон промпта / пресет `ml-researcher` | **нет** — создаётся в рамках ADR-040 |
| Доменная база знаний / MCP-поиск концептов | **нет** — план (Ариадна как MCP-инструмент) |
