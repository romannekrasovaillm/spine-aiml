# Каноническое хранение весов и датасетов

Инвариант владельца: **веса моделей и датасеты канонически лежат вне
репозитория** — в едином каноническом сетевом хранилище, обычными файлами.
В рабочем дереве репозитория допустимы только **симлинки** на них: копий
(дубликатов байтов) не держим. Это защищает от расползания десятков
гигабайт по рабочим каталогам, нескольких расходящихся версий одних и тех
же весов и от случайного коммита тяжёлых бинарей в историю.

Репозиторий форсит инвариант двумя механическими правилами корневого
`CONSTRAINTS.yaml`: **C-34** (веса) и **C-35** (крупные копии/датасеты).
Их аналоги заведены в кейсе axiom как C-032/C-033; корневые правила
переносят ту же дисциплину на весь репозиторий.

## Что именно проверяют правила

Декларативного типа «файла быть не должно» у движка fitness-функций нет
(см. `docs/control.md`, `src/control.rs`), поэтому оба правила построены на
`command_succeeds` — shell-команда должна завершиться кодом 0.

- **C-34 — `no_weight_copies_in_working_tree`.** `find` по рабочему дереву
  ищет **регулярные файлы** весовых форматов: `*.safetensors`, `*.gguf`,
  `*.pt`, `*.pth`, `*.ckpt`, а также `*.bin` и `*.onnx`. Находка — команда
  падает.
- **C-35 — `no_large_dataset_copies_in_working_tree`.** `find` ищет любые
  регулярные файлы крупнее **500 MiB** — копии датасетов, чекпойнтов и
  прочих тяжёлых бинарей. Находка — команда падает.

Оба правила игнорируют **симлинки**: `find -type f` ссылки не
разыменовывает, поэтому симлинк на веса или большой датасет в каноническом
хранилище правилом не ловится — именно это и требуется инвариантом.

### Почему в команде продублирован `-prune`

`command_succeeds` исполняется **один раз** через `bash -c` в корне
репозитория; поля `glob`/`exclude_glob` у команды **игнорируются**.
Список каталогов, которые обходчик движка пропускает автоматически
(`.git`, `target`, `node_modules`, `dist`, `__pycache__`, `.next`,
`.pytest_cache`, `.arch-handoff`), внутри самой команды **не наследуется**.
Поэтому каждый из этих каталогов явно вычищается через `-prune` — иначе
build-артефакты вида `target/**/*.bin` красили бы C-34 навсегда.

Расширения `jsonl/csv/tsv` в C-34 сознательно **не** перечислены: такие файлы
в репозитории есть и легитимны; крупные копии датасетов при необходимости
ловит размерный порог C-35.

## Как запускать проверку

Полный прогон — тот же гейт, что и в CI (джоба dogfood):

```bash
./target/debug/arch-ml control check . --constraints CONSTRAINTS.yaml
```

Итог обязан остаться `PASS` при `error: 0`; при находке любого из правил
C-34/C-35 в таблице появляется строка, а `error` становится ≥ 1 — гейт
падает (`severity: critical` нормализуется движком в `error`).

Проверить ровно то, что делает правило, можно и вручную — команда из
`CONSTRAINTS.yaml`:

```bash
# C-34: копии весов
find . \( -name .git -o -name target -o -name node_modules -o -name dist \
  -o -name __pycache__ -o -name .next -o -name .pytest_cache \
  -o -name .arch-handoff \) -prune \
  -o -type f \( -name '*.safetensors' -o -name '*.gguf' -o -name '*.pt' \
  -o -name '*.pth' -o -name '*.ckpt' -o -name '*.bin' -o -name '*.onnx' \) -print -quit

# C-35: крупные копии
find . \( -name .git -o -name target -o -name node_modules -o -name dist \
  -o -name __pycache__ -o -name .next -o -name .pytest_cache \
  -o -name .arch-handoff \) -prune -o -type f -size +500M -print -quit
```

Пустой вывод = чисто. Любая напечатанная строка = нарушитель.

## Какие артефакты существуют сейчас

Честный статус на момент введения правил:

- канонические байты ML-артефактов лежат в каноническом сетевом хранилище
  **обычными файлами** (не симлинками);
- артефактов кейса axiom на диске **пока нет** — ни базовых весов K3,
  ни чекпойнта скелета L3, ни MoE-дельты;
- предвычисленных хешей почти нет, `LICENSE`/model-card рядом с весами
  почти нет.

Поэтому на чистом дереве оба правила **зелёны**: C-34 и C-35 не находят ни
весовых файлов, ни копий крупнее порога. Правила — не отчёт о текущем
наличии артефактов, а гейт против их появления копиями в рабочем дереве.
