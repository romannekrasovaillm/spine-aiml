# ADR-020. Headless-контур Spine BE: единый JSON-контракт, таймауты, чистый stdout, аудит-трейл

- Date: 2026-09-01
- Status: Accepted

## Context

Headless — основной режим продукта в контуре банка: ночные сверки
(fitness/fleet/trace), cron-задачи, CI-гейты, оркестрация скриптами
ДИТ. Текущее состояние (проверено по коду, 2026-09-01):

- `arch run` (src/main.rs cmd_run): финальный ответ — голый текст в
  stdout; exit code различает только сбой/успех процесса; флаг `-q`
  даёт «stdout=только ответ», но НЕ машиночитаемый статус.
- Cron (src/cron.rs): статус `{status, summary}` извлекается из
  последней строки markdown-ответа (хрупко); `unknown` не влияет на
  исход; контракт беднее harness-контракта ядра
  (`status/assumptions/open_questions/conflicts_with_prior_decisions`,
  src/harness.rs) — три несогласованных контракта результата.
- Таймаутов сессии нет (только per-tool); стриминг-прогресс пишет
  ANSI-коды безусловно — в пайпах CI мусор; путь к JSONL-журналу
  сессии не отдаётся наверх — ответ и его аудит-трейл не связаны.

Significance: Standard (api_contract_change, significant_nfr_change).

## Decision

**1. Единый headless-контракт** — `arch run --json`:

- stdout — единственный JSON-объект: `{status, summary, assumptions,
  open_questions, session_log, elapsed_secs}` (status:
  complete|partial|blocked|unknown — парсер общий с cron, поля
  выравнены с harness-контрактом ядра; конфликт-поле — только в
  handoff-контракте харнессов, где оно семантически определено).
- Exit codes: 0 — complete; 1 — ошибка процесса; 2 — blocked; 3 —
  partial; 4 — unknown (модель не выдала контракт). Для CI: полный
  статус без парсинга stdout.
- Без `--json` поведение не меняется (обратная совместимость).

**2. Таймауты сессии**: `--timeout-secs` (потолок прогона) и
`--idle-timeout-secs` (тишина: нет токенов и событий инструментов);
по истечении — финальный ответ из накопленного контекста со статусом
partial (не kill: менеджер сессии завершает ход корректно, журнал
остаётся валиден). В `CronJob` — поля `timeout_secs`/`idle_timeout_secs`
(serde default — нет лимита, обратная совместимость).

**3. Чистый stdout**: ANSI-прогресс только при tty stdout
(`IsTerminal`); в пайпах — тот же прогресс без цветов (читаемо в
CI-логах), `--no-color` — принудительно. `-q` сохраняет семантику
«только финальный ответ».

**4. Аудит-трейл**: `--json` и шапка cron-отчёта несут путь к
JSONL-журналу сессии (`session_log`); оркестратор связывает ответ с
полным трейлом (что агент реально вызывал) без поиска по каталогу
сессий.

**5. Cron-статус значим**: `arch cron run <job>` — exit code по
статусу задачи (по правилам п.1); в шапке md-отчёта — session_log и
поля контракта. `unknown` больше не «молча» — отдельный код + stderr.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Единый контракт + таймауты + tty-детект + трейл (принято)** | оркестрация без парсинга markdown; ночные задачи не висят; ответ связан с доказательствами; три контракта сведены к двум (run/cron — один; handoff-харнесс — свой, семантически иной) | рост CLI-поверхности (флаги) — осознанно |
| Только `-q` (текст+exit 1), как сейчас | ноль работы | CI вынужден парсить текст; статусы lost — противоречит дисциплине headless-контрактов самого продукта |
| Убрать cron-статус, всё через run --json | один путь | cron уже несёт отчёты/расписания — дублирование функционала, миграция скриптов заказчика |
| Kill по таймауту (внешний timeout) | просто | убитый процесс = битый журнал + потерянный ответ; graceful-финал дешевле |
| Resume упавших прогонов по журналу | закрыл бы разрыв полностью | крупная архитектурная работа (восстановление AgentSession из JSONL) — Deferred: условие возврата — реальные срывы длинных прогонов в контуре |

## Consequences

### Positive

- CI/cron ДИТ гейтят по exit code: blocked/partial/unknown различимы
  без разбора stdout — тот же принцип, что у harness_run.
- Ночные сверки в банке имеют потолок и таймаут тишины — предсказуемое
  окно обслуживания.
- `session_log` в контракте — надзорная ценность: любой ответ
  headless-агента прослеживается до полного журнала (совместимо с
  R-07/R-18: документирование решений ИИ).

### Negative

- Exit code 2/3/4 ломает скрипты, проверяющие «только 0/1» —
  миграционная заметка в docs (внутренних скриптов на это нет,
  проверено grep).
- Graceful-финал по таймауту добавляет ветку в агентный цикл —
  аккуратность с инвариантом «model-visible ⟺ logged» (dsh):
  финальный ответ после таймаута тоже логируется.
- Два таймаута (потолок/тишина) — конфигурационная сложность;
  дефолты отсутствуют = текущее поведение (без сюрпризов).

## Reversibility

**reversible** для флагов/полей (аддитивно, обратная совместимость
serde/CLI); **costly** для exit-кодов после распространения скриптов
заказчика — менять коды после первого контракта нельзя.
