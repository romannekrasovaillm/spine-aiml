# ADR-009. Расширение нотации диаграмм (ER, C4) и обмен моделью с отраслевыми форматами

- Date: 2026-08-17
- Status: Accepted
- Expiry review: при появлении потребности в deployment-видах как первоклассных
  диаграммах (узлы/окружения с вложенностью, а не flatten-рецепт) или при
  подключении второго формата импорта (PlantUML/drawio обратно) — пересмотреть
  границы подмножеств и направление «один парсер на формат».

## Context

Ревью `SPINE-REVIEW.md` (находка F-4, задача P1-3): mermaid-фронтенд харнесса
принимает только `graph|flowchart` и `sequenceDiagram`; C4, ER и deployment
не поддерживаются. Экспорт (`src/export.rs`) умеет лишь журнал сессии в
docx/xlsx; обмена **моделью архитектуры** с отраслевыми форматами нет —
артефакты не втягиваются в корпоративный репозиторий архитектуры, хотя
рубрика `portability` требует оценивать цену выхода. DoD задачи: round-trip
`модель → Structurizr DSL → модель` без потери сущностей и связей (тест).

Ограничения площадки: модель P0-1 (ADR-003) не хранит вложенность
компонентов в системы и не различает «внешность» системы типом — только
связи `depends_on`/`implements`/`affects`/`verified_by`. Новых внешних
зависимостей вводить нельзя (XML для drawio пишется руками с экранированием).

## Decision

1. **Нотация — через понижение к общей модели диаграмм.** Парсер mermaid
   (`src/mermaid/parse.rs`) дополняется двумя фронтендами, каждый со своим
   AST (`src/mermaid/model.rs`) и функцией понижения в `FlowAst`:
   - `erDiagram`: сущности (`CUSTOMER { string name\n int id PK }`), связи
     `A ||--o{ B : label` (кардинальности `||/|o/o|/}|/}o` слева и
     `||/o|/|{/o{` справа; `--` identifying → стрелка, `..` non-identifying →
     линия без стрелки). Понижение: сущность → узел с многострочной меткой
     (имя, разделитель, атрибуты `тип имя ключи`); связь → ребро с меткой
     `label (from:to)`, кардинальности текстом UML-множественности
     (`1`, `0..1`, `1..*`, `0..*`).
   - C4-подмножество mermaid (`C4Context`/`C4Container`/`C4Component`):
     элементы `Person[_Ext]`, `System[_Ext|Db|Queue|…]`,
     `Container[Db|Queue|…]`, `Component[Db|…]` (позиционные аргументы
     `(alias, "label"[, "tech"[, "desc"]])`) и связи `Rel*`/`BiRel`
     (`(from, to, "label"[, "tech"])`). Понижение: элемент → узел с меткой
     `«стереотип»\nlabel[\n[tech]]`; `Rel` → ребро со стрелкой и меткой,
     `BiRel` → линия без стрелки. Направление раскладки — всегда TD
     (суффиксы `Rel_U/D/L/R` игнорируются). Границы `*_Boundary(...) { … }`
     и стили/легенды (`title`, `UpdateElementStyle`, `SHOW_LEGEND`, …)
     пропускаются с предупреждением `%% пропущено` — как subgraph в
     flowchart: содержимое границ разбирается, рамки не рисуются.
   - Рендер переиспользует `layout`/`draw`: `draw` обобщается с
     фиксированной высоты узла 3 на переменную (многострочные метки у
     Rect/Rounded, пустая строка метки = разделитель `├─┤`); однострочные
     узлы рендерятся побайтово как раньше (золотые тесты flowchart/sequence
     не меняются).
2. **Deployment — осознанно out-of-scope.** Отдельного вида deployment-
   диаграммы в mermaid нет; `C4Deployment` детектируется и отклоняется с
   подсказкой-рецептом: deployment-вид выражается через `flowchart TD` +
   `subgraph` (окружение/узел → subgraph, артефакты → узлы, связи → рёбра);
   subgraph честно деградирует в предупреждение, узлы и рёбра рендерятся.
   Это соответствует духу «символьная сетка», а не полноценный C4-движок.
3. **Обмен моделью — `src/model/exchange.rs`.** Экспортируемое подмножество
   модели: сущности `SYS`/`CMP`/`INT` и связи между ними (оба конца —
   экспортируемые сущности; вид связи сохраняется). Прочие типы
   (`CAP`/`NFR`/`REQ`/`AD`/`ADR`/`RISK`/`OWNER`) и связи на них не
   экспортируются — они не имеют аналога в C4-форматах.
   - `arch model export <dir> --format structurizr|plantuml|drawio` → stdout:
     - **Structurizr DSL**: `workspace { model { … } }`; `SYS` →
       `softwareSystem`, `INT` → `softwareSystem` с тегом `External`,
       `CMP` → `container` внутри единственной системы, если `SYS` ровно
       одна (визуальная вложенность), иначе `softwareSystem` (плоско).
       Тело сущности → `description` (однострока), связи → `a -> b "kind"`.
       **Каждый элемент получает `properties { "spine.id" …, "spine.type" …,
       "spine.status" …, "spine.date" … }`** — это носитель точного
       round-trip: id/тип/статус не угадываются при импорте.
     - **PlantUML**: `@startuml` component-диаграмма (`[label] as alias`,
       `package` для вложенности при единственной `SYS`, `-->` с меткой
       вида связи, `<< External >>` для `INT`).
     - **drawio**: минимально валидный mxfile XML (`mxGraphModel/root` с
       `mxCell id="0"/"1"`), вершины — детерминированная сетка, рёбра
       `source/target` с меткой-видом связи; значения XML-экранируются.
   - `arch model import <file> --format structurizr --dir <model/>`:
     толерантный парсер подмножества Structurizr DSL (токенизатор с
     переводами строк; `alias = softwareSystem|container|component "name"
     … { … }`, вложенные контейнеры, `properties { "k" "v" }`, `tags`,
     `description`, связи `a -> b "desc"`; `views`/`configuration` и прочие
     блоки пропускаются по балансу скобок). Маппинг: элемент со
     `spine.id`/`spine.type` → сущность ровно этого id/типа (round-trip);
     иначе `softwareSystem` с тегом `External` → `INT`, прочие
     `softwareSystem` → `SYS`, `container`/`component` → `CMP`, id
     синтезируются `PREFIX-NNN` в порядке документа; `person` пропускается
     с предупреждением. Описание связи, совпадающее с именем вида связи
     (`depends_on`/`implements`/`affects`/`verified_by`), восстанавливает
     вид; прочие → `depends_on`. Импорт пишет файлы `ID-slug.md` (слаг —
     `control::kebab_slug`) с frontmatter экспортируемых полей
     (`id/type/title/status/date` + связи) и телом из `description`;
     существующий файл — ошибка (ничего не затираем). Статус без
     `spine.status` — `imported`.
   - Экспорт пустого экспортируемого подмножества — ошибка («нечего
     экспортировать»), а не пустой документ.
4. **CLI**: `ModelCmd::Export { dir, --format }` (печать в stdout, как
   `model graph`) и `ModelCmd::Import { file, --format, --dir }` (отчёт:
   записанные файлы + предупреждения). Инструмент агента не добавляется —
   обмен файловый, агент вызывает через bash.
5. **Ограничения round-trip (задокументированные)**: кавычки в заголовках/
   описаниях при экспорте в Structurizr заменяются на `'` (DSL-строки без
   escape-спецификации), переводы строк тела — на пробелы; связи на
   неэкспортируемые типы не переживают круг. Тест round-trip сравнивает
   множества id и тройки связей `(источник, вид, цель)` — это и есть DoD.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Понижение ER/C4 к `FlowAst` + обобщённый draw (выбрано) | один layout/рендер, одни граничные тесты, предупреждения единообразны | многострочные метки потребовали обобщения геометрии draw |
| Отдельный рендер ER и C4 | независимая эволюция | три копии раскладки/канваса, размножение багов рендера |
| Полный C4 (boundaries как рамки, deployment) | ближе к C4-нотации | символьная сетка плохо несёт вложенные рамки; взрыв объёма; deployment-вида в mermaid нет — всё равно рецепт |
| Structurizr id только из alias/имени (без `properties`) | чище DSL | round-trip угадывает id/тип из строк — хрупко; properties — штатный механизм DSL для метаданных |
| XML-библиотека для drawio | гарантированная валidity | новая зависимость ради 40 строк печати с экранированием — запрещено инвариантом «ноль новых зависимостей» |
| Импорт plantuml/drawio тоже | симметрия | парсеры двух форматов ради незаявленного сценария; DoD требует только Structurizr |

## Consequences

### Positive

- `arch mermaid` и инструмент `mermaid_render` принимают `erDiagram` и три
  C4-вида; ошибки — с номерами строк, неподдерживаемое — с предупреждениями,
  как заведено.
- `arch model export/import` замыкают обмен с корпоративными репозиториями
  архитектуры: Structurizr DSL — вход для structurizr-cli/Lite, PlantUML и
  drawio — для Confluence/draw.io. Рубрика `portability` получает
  детерминированный артефакт «цены выхода».
- Round-trip через `spine.*` properties точный по построению: импорт не
  угадывает. Диаграммы генерируются из модели (export/graph), а не пишутся
  руками параллельно ей — требование P1-3.
- Ноль новых зависимостей; весь обмен — чистые функции над `Model`.

### Negative

- Парсер Structurizr DSL — подмножество: экзотика (`!identifiers`,
  `element`-наследование, dotted-aliases в связях, многострочные строки)
  пропускается с предупреждением или отклоняется. Чужие файлы вне
  подмножества импортируются частично — предупреждения перечисляются в
  отчёте импорта.
- Вложенность `CMP → SYS` при экспорте эвристическая (единственная система);
  при нескольких `SYS` структура плоская (тип сохраняется в `spine.type`,
  визуальная иерархия теряется до появления поля владения в модели).
- Кавычки/переводы строк в заголовках и телах при круге нормализуются
  (экранирования в DSL-строках нет) — содержательно без потерь, побайтово нет.

## Reversibility

reversible. Нотация — аддитивные ветки детекта в `mermaid`; обмен — новый
модуль и две подкоманды. Удаление `exchange.rs`, веток `Export`/`Import` и
фронтендов ER/C4 возвращает поведение к ADR-003 без потери данных (импорт
только создаёт новые файлы и отказывается затирать существующие).
