# ADR-029. Структурные fitness-функции: dependency_direction в движке, dogfood слоистости, эталонный скрипт deps-check

- Date: 2026-09-04
- Status: Accepted

## Context

Внешнее ревью Spine-BE зафиксировало «потолок fitness-функций»: движок
умел только regex (`must_contain`/`must_not_contain`/`each_file_must_contain`),
наличие файлов (`file_exists`/`dir_must_have_file`/`max_age`) и команды
(`command_succeeds`). Нарушение слоёв, направление зависимостей и границы
контекстов (класс ArchUnit) были задекларированы в библиотеке (карточка
GEN-16, `banking/library/fitness/wave1-mechanizable.yaml`), но нигде не
продемонстрированы: паттерн GEN-16 `test -x scripts/deps-check.sh && …`
молча проходит при отсутствии скрипта, каталога `scripts/` в репозитории
не было, а единственное правило направления зависимостей
(`no-banking-deps-in-core`) выражено regex'ом — он не отличает импорт от
комментария и не выражает «слой A не зависит от слоя B».

При этом философия делегирования (ArchUnit-класс проверок — стек-нативным
инструментам через `command_succeeds`, а не переизобретение ArchUnit в
тонком ядре, AD-1) остаётся верной; проблема — отсутствие работающего
прецедента и нативного минимума для типовых стеков.

Снятие фактического графа `crate::…` по `src/` (75 файлов) дало базовую
слоистость, зелёную на текущем коде (неретроактивность, ADR-019):
провайдерный слой `llm` зависит только от `{config, error, llm, net, retry}`
(AD-4); `tui` импортируется только из `tui/*` и `export.rs`
(переиспользование `tui::app::ChatBlock` — задокументированное исключение);
`error`/`secrets`/`retry` — листовые модули без внутрикрейтовых
зависимостей.

## Decision

**1. Новый тип правила `dependency_direction`** в `src/control.rs`
(RuleKind; обратная совместимость: старые CONSTRAINTS парсятся без
изменений):

```yaml
- name: llm_provider_isolation
  type: dependency_direction
  glob: ["src/llm.rs", "src/llm/**"]   # строка или список (новое: список)
  exclude_glob: ["src/llm/gen/**"]     # как у прочих правил
  allow: [config, error, llm, net, retry]   # ровно одно из allow/forbid
  severity: critical
```

- Извлечение импортов по расширению файла: Rust (`use crate::…` и
  инлайн-пути `crate::…::`), Python (`import`/`from … import`),
  Java/Kotlin (`import …;`), TS/JS (`from`/`import`/`require`; относительные
  `./…` пропускаются — их разрешает `context_boundary`, ADR-030).
  Координаты модулей нормализуются к `/` (`::` и `.` → `/`).
- Совпадение — префикс модульного пути с границей сегмента (`agent/slash`
  совпадает с `agent`, `agentworld` — нет). `allow: []` — запрет любых
  внутренних зависимостей (листовые модули).
- Строки-комментарии (`//`, `///`, `//!`, `#`) игнорируются; блочные
  комментарии и строковые литералы не разбираются — эвристика
  документированно приблизительна (при dogfood-вводе поймано ложное
  срабатывание на `crate::tui` внутри строкового литерала теста).
- Пустой набор файлов — находка «правилу нечего проверять» (мёртвый glob =
  мёртвое правило), как у `each_file_must_contain`.

**2. Поле `glob` теперь принимает список** (строка — частный случай,
десериализатор общий с `exclude_glob`): слоевые правила покрывают
`src/x.rs` + `src/x/**` одним правилом вместо пар вида BE-20a/BE-20b.

**3. Dogfood на собственном коде** (`CONSTRAINTS.yaml`, джоба dogfood в
CI подхватывает автоматически): C-23 `llm_provider_isolation` (allow),
C-24 `no_tui_below_ui` (forbid tui; `export.rs` — исключение с
комментарием), C-25 `tools_layer_no_agent_tui`, C-26
`leaf_modules_stay_leaf` (error/secrets/retry, `allow: []`), C-27
`no_banking_in_core_structural` (структурная замена regex-правила),
C-28 `deps_check_script` (п. 4). Все правила — severity critical, введены
зелёными (гейт блокирует эрозию слоёв, а не требует рефакторинга задним
числом).

**4. Эталонный скрипт `scripts/deps-check.py`** (stdlib-only): та же
семантика извлечения и правил, что у нативного типа, переносимый образец
для карточки GEN-16 в проектах, где харнесс не пересобирается; для JVM/TS
по той же схеме подключаются ArchUnit/depcruise. Прогон — правилом C-28
(`command_succeeds`), тот же гейт, два независимых исполнителя.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Нативный dependency_direction + dogfood + эталонный скрипт (принято)** | класс ArchUnit продемонстрирован на живом коде; мультистек без внешних инструментов; fail-closed allow-списки; скрипт переносим | эвристика извлечения приблизительна (строки/блочные комментарии); новый тип — расширение схемы FitnessRule |
| Только ответ документацией (философия делегирования + ссылка на GEN-16) | ноль кода | «не показаны» остаётся фактом; следующий ревью повторит находку |
| Только внешний скрипт (без нативного типа) | ноль правок ядра | Python в гейте Rust-репозитория — внешняя зависимость рантайма; правило молча зеленеет без python3; семантика не доступна SDK/headless-потребителям |
| Полноценный парсинг AST (syn/tree-sitter) | точность ArchUnit | тяжёлые зависимости в тонком ядре (AD-1), мультистек требует N парсеров; оверкилл для проверки направления |
| Интеграция cargo-modules/mamba как внешнего инструмента | настоящий граф модулей Rust | внешний бинарь в CI каждого потребителя; не мультистек |

## Consequences

### Positive

- Замечание ревью закрыто демонстрацией: нарушение слоёв и направление
  зависимостей проверяются нативно (C-23…C-27) и внешним инструментом
  (C-28), оба гейта зелены и ломаются при инъекции нарушения (негативный
  тест при вводе).
- Allow-списки fail-closed: новая зависимость провайдерного слоя ломает
  сборку до ревью (AD-4 enforce'ится механически, а не прозой AGENTS.md).
- Снятый граф зафиксировал реальное отступление (`export.rs` →
  `tui::app::ChatBlock`) — оформлено исключением с комментарием и
  кандидатом на рефакторинг, а не скрыто.
- GEN-16 получила эталонную реализацию; замечания адаптации в
  `wave1-mechanizable.yaml` ссылаются на живой пример.

### Negative

- Извлечение импортов — текстовая эвристика: `crate::…` в строковом
  литерале даёт ложное срабатывание (поймано при вводе на тестовой строке
  в `src/control.rs`, обход — переформулировка строки); блочные комментарии
  `/* … */` не вырезаются.
- TS/JS-относительные импорты в `dependency_direction` не матчатся (нет
  модульных координат) — покрываются `context_boundary` (ADR-030) либо
  внешним depcruise.
- Правила слоёв привязаны к именам модулей: переименование модуля требует
  правки CONSTRAINTS.yaml (это и есть желаемое поведение гейта — карта
  слоёв пересматривается вместе с рефакторингом).

## Reversibility

**reversible** для скрипта и правил CONSTRAINTS (удаление возвращает
прежний контур); **costly** для типа `dependency_direction` после того,
как CONSTRAINTS заказчиков начнут использовать его в CI — обратная
совместимость декларацией старых типов сохраняется (прецедент `max_age`,
ADR-019).
