# ADR-010. Стратегия форка Spine → банковский продукт: чистый продуктовый старт

- Date: 2026-08-31
- Status: Accepted

## Context

Spine (crate `arch-harness`, бинарь `arch`) — исследовательский доменный
харнесс solution-архитектора: 81 коммит, позиционирование «research project,
not for production». Возникла задача продуктового форка: адаптация под
банковских solution-архитекторов с продажей в ДИТ (департаменты ИТ банков).

Силы, определяющие решение:

- **Due diligence закупки.** ДИТ при вендорском отборе смотрит git-историю:
  framing «не для промышленной среды», публичные remote-ссылки и смешанная
  исследовательская история удлиняют цикл закупки и порождают вопросы.
- **Лицензионная свобода.** Единственный держатель копирайта апстрима —
  Roman Nekrasov (MIT). Форк можно перелицензировать, включая
  проприетарную продуктовую лицензию для продаж.
- **Развитие апстрима продолжается.** Исследовательский Spine — живой
  проект; форку нужен механизм получать его улучшения без обязательной
  истории.

## Decision

**Чистый продуктовый старт**: форк создаётся побайтовой копией апстрима без
`.git` (точка форка `b2088cf0`), с новой git-историей от единственного
baseline-коммита. Происхождение фиксируется в `NOTICE.md`; развитие апстрима
отслеживается вручную, улучшения переносятся патчами/cherry-pick по
осознанному решению (каждый перенос — отдельный коммит со ссылкой на
апстрим-коммит). Продуктовая лицензия форка — отдельное решение (ADR-013);
пока действует унаследованный MIT.

Нумерация ADR продолжается с ADR-010; ADR-001…009 унаследованы как
описание архитектуры на точке форка.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Чистый старт (принято)** | продуктовая история с первого коммита; чистый фасад для due diligence ДИТ; свобода перелицензирования; никакой дисциплины синхронизации веток | нет bisect в историю апстрима; ручной перенос улучшений; история зрелости не видна заказчику |
| Клон с полной историей (81 коммит) | bisect, merge/cherry-pick из апстрима напрямую, видна зрелость | история несёт «research project»-фрейминг и ссылки на публичный GitHub; при закупке объяснять происхождение каждого коммита |
| Гибрид: клон + продуктовая ветка от squash | и чистый фасад, и история под рукой | два набора веток; дисциплина синхронизации обязательна; риск случайного пуша «грязной» ветки заказчику |
| Статус-кво (не форкать, развивать Spine) | нулевые затраты на ветвление | исследовательское позиционирование и история несовместимы с продуктовыми продажами в регулируемый контур |

## Consequences

### Positive

- ДИТ получает историю, начинающуюся с продуктового baseline-коммита;
  NOTICE и ADR-010 дают прозрачное, документированное происхождение.
- Свобода выбрать продуктовую лицензию (включая проприетарную) без
  обязательств перед унаследованной историей.
- Апстрим остаётся «песочницей»: рискованные эксперименты не попадают в
  продуктовую ветку автоматически.

### Negative

- Перенос улучшений апстрима — ручная работа: каждый патч читается и
  адаптируется; без регулярной дисциплины форк начнёт отставать (риск
  дрейфа, митигируется cron/регламентным окном сверки с апстримом).
- `git bisect` в унаследованную архитектуру невозможен — регрессии
  придётся локализовать по коду форка.
- История зрелости (81 коммит, кейсы, CI) не видна заказчику из коробки —
  потребуется продуктовый «proof of maturity» (релизы, бенчмарки, кейсы).

## Reversibility

**reversible**: исходный репозиторий апстрима сохраняется нетронутым;
стратегию можно сменить на гибрид в любой момент (повторный импорт истории
в отдельную upstream-ветку не меняет продуктовую main). Стоимость смены —
работа по перелинковке, а не потеря данных.
