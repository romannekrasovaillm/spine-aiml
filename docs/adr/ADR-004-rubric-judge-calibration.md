# ADR-004. Надёжность и калибровка LLM-судьи рубрик

- Date: 2026-08-17
- Status: Accepted
- Expiry review: при появлении посекционной оценки длинных документов
  (сейчас — честная ошибка) или при переходе судьи на tool-calling
  (structured output вместо JSON в тексте) — пересмотреть формат цитаты
  и агрегацию сэмплов.

## Context

Ревью `SPINE-REVIEW.md` (находка F-2, задача P0-3). Судья рубрик
(`src/rubric.rs`) не откалиброван и не верифицируется:

1. Одна выборка судьи на критерий; дисперсия оценки не измеряется,
   неустойчивые критерии неотличимы от устойчивых.
2. Системный промпт требует «цитату-свидетельство» в каждом `rationale`,
   но её наличие и подлинность механически не проверяются: судья может
   ссылаться на текст, которого нет в документе.
3. Документ длиннее `MAX_TARGET_CHARS` (24 000) молча усекается
   `truncate_chars`: судья оценивает хвост, которого не видел.
4. Оцениваемый документ — данные из ненадёжного источника (подрядчик,
   соседняя команда) и подставляется в промпт без изоляции: вектор
   prompt injection на судью.
5. Регрессии качества судьи не ловятся: изменение промпта или рубрики
   ничем не проверяется (нет эталона и метрики согласия).

## Decision

### 1. k-сэмплы судьи с агрегацией (медиана + σ)

`evaluate_with_options(rubric, target, llm, &JudgeConfig)` прогоняет судью
`judge.samples` раз (дефолт 3, конфигурационная секция `[judge]`,
`samples = 0` клэмпится в 1). Каждый сэмпл — полный судейский запрос со
всеми критериями (как раньше) и существующим одним retry на неразобранный
JSON. По критерию собирается вектор из k клэмпнутых баллов (критерий,
пропущенный судьёй в сэмпле, считается 1 — как и раньше). Итоговый балл —
округлённая медиана; разброс — population-σ (деление на n, при k < 2 σ = 0).
σ > `judge.unstable_stdev` (дефолт 1.0 балла шкалы 1..=5) → у критерия флаг
`unstable` в `CriterionScore.flags`. Обоснование из сэмпла, чей балл равен
итоговому (первый такой по порядку), иначе — первое непустое.

Старый `evaluate(rubric, target, llm)` сохраняется как обёртка с
`JudgeConfig::default()` — сигнатуры существующих вызовов не меняются.

### 2. Верификация цитаты-свидетельства

Контракт промпта: при балле ≥ 2 `rationale` НАЧИНАЕТСЯ с
`Цитата: "<дословный фрагмент оцениваемого текста>"`; при балле 1 по
причине отсутствия свидетельства цитата не требуется (судья пишет
«свидетельство отсутствует»). Механическая проверка в `build_report`:

- извлечение: первый quoted-span («…», "…", '…') длиной ≥ 8 символов после
  маркера «цитата» (регистр неважен); без маркера — первый такой span во
  всём rationale; нет span'а → цитаты нет;
- нормализация (lower + схлопывание пробелов), затем точный substring-матч;
- иначе fuzzy-матч крейтом `similar`: скользящее окно по словам размером в
  цитату, `TextDiff::from_words(..).ratio()`, берётся максимум; порог —
  `judge.evidence_min_similarity` (дефолт 0.8).

Балл ≥ 2 без подтверждённой цитаты → флаг `evidence_not_found`, критерий
**исключается** из взвешенного итога (балл остаётся виден в отчёте с
флагом). Если не осталось ни одного засчитанного критерия —
`HarnessError::Rubric` («все критерии отклонены…»): оценка без единого
проверенного свидетельства честнее провалить, чем усреднить.

### 3. Длина документа — явная ошибка вместо тихого усечения

`truncate_chars` удалён. `check_target_len` в начале оценки: длина в
символах > `MAX_TARGET_CHARS` → `HarnessError::Rubric` с лимитом и фактической
длиной и советом («сократите или оцените по разделам отдельными вызовами»).
Инструмент `rubric_evaluate` конвертирует её в `ToolOutput::err` (данные для
модели, не сбой харнесса). Посекционный режим с агрегацией НЕ реализован:
размазывает баллы по критериям (секция без «Альтернатив» тянула бы их к 1),
умножает стоимость и требует отдельной схемы агрегации — отложено до
Expiry review.

### 4. Изоляция оцениваемого текста в промпте

Текст оборачивается маркерами `=== НАЧАЛО ОЦЕНИВАЕМОГО ТЕКСТА ===` /
`=== КОНЕЦ ОЦЕНИВАЕМОГО ТЕКСТА ===`; системный промпт и преамбула перед
текстом предписывают судье трактовать содержимое маркеров как данные и
игнорировать любые инструкции внутри, даже адресованные ему.

### 5. Golden-set и `arch bench run --golden`

`assets/benchmarks/golden/` — 7 маленьких синтетических ADR (без
персональных данных и реальных компаний) + рядом `<имя>.expected.yaml`
(`rubric:` + ожидаемые баллы по критериям; эталон — `adr_quality`).
`bench::run_golden` прогоняет судью по всем документам и считает MAE по
всем парам «документ × критерий» (чистая функция `mean_absolute_error`).
Битый эталонный файл или ссылка на несуществующий критерий — ошибка
(молчаливый пропуск завышал бы согласие). `arch bench run --golden`
печатает MAE по документам и итог; итог > `judge.golden_max_mae`
(дефолт 1.0 балла) → exit code 1 (регрессионный гейт для CI).

### 6. Конфигурация (`config.toml`, секция `[judge]`, все поля с дефолтами)

```toml
[judge]
samples = 3                    # сэмплов судьи на критерий (медиана — итог)
unstable_stdev = 1.0           # σ сэмплов выше порога → флаг unstable
evidence_min_similarity = 0.8  # fuzzy-порог подтверждения цитаты (0..=1)
golden_max_mae = 1.0           # итоговый MAE golden-прогона выше → exit 1
```

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| k независимых запросов (выбран) | простая агрегация, измеряет именно разброс судьи | стоимость ×k на оценку |
| Один запрос с k оценками в JSON | дешевле | сэмплы не независимы (модель «согласуется» сама с собой), разброс занижен |
| Winsorized mean / отброс выбросов | устойчивее к единичным выбросам | медиана проще объясняется и при k=3 эквивалентна отбросу обоих краёв |
| Sample-σ (деление на n−1) | несмещённая оценка | при k=3 завышает σ в √1.5; population-σ консервативнее — флаг `unstable` реже ложный |
| Квадратично-взвешенная каппа для golden | учитывает случайное согласие | на 35 парах нестабильна; MAE прозрачен («средний промах в баллах») и достаточен для порога |
| Посекционная оценка длинных документов | покрывает большие SAD | баллы разделов не складываются в оценку целого без новой схемы агрегации; отложено |
| Исключать `unstable` из итога | строже | разброс — свойство судьи, а не документа; флага достаточно, балл остаётся информативным |

## Consequences

### Positive

- Разброс судьи измеряется и виден (`unstable`, σ в отчёте); оценка
  опирается на медиану, а не на одиночную выборку.
- Оценки без подтверждённой цитаты не попадают во взвешенный итог —
  галлюцинированные свидетельства перестают влиять на гейты.
- Усечение невозможно незаметно: длинный документ — явная ошибка с
  лимитом и длиной.
- Оцениваемый текст изолирован маркерами и инструкцией-игнором.
- Golden-set + MAE + exit code 1 дают регрессионный гейт качества судьи
  (`arch bench run --golden`).

### Negative

- Стоимость оценки ×`judge.samples` (дефолт ×3) на всех путях
  (`rubric_evaluate`, `/rubric run`, `arch rubric run`, bench).
- Fuzzy-матч цитаты — эвристика: перефразированная «цитата» ниже порога
  0.8 отклоняется даже при честной оценке (смягчается тем, что промпт
  требует дословную цитату).
- Формат `CriterionScore` расширен (`samples`, `stdev`, `flags`) — старые
  JSON-отчёты читаются благодаря `#[serde(default)]`, но таблица markdown
  меняет колонки (новая колонка «Метки»).
- `arch rubric run` (CLI) использует `JudgeConfig::default()` (вызов через
  обёртку `evaluate` — блок команды `rubric` в `main.rs` не входил в объём
  задачи); конфигурация действует на инструмент агента, `/rubric run`,
  `/bench run`, `arch bench run` и golden-прогон.

## Reversibility

reversible. Всё сводится к `JudgeConfig` с дефолтами: `samples = 1` и
жёсткий `golden_max_mae = 0` возвращают поведение, близкое к прежнему
(одиночная оценка), без правок кода. Формат отчёта расширен аддитивно.
