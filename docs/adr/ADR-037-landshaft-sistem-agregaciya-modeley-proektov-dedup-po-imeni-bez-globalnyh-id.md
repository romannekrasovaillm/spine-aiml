# ADR-037. Ландшафт систем: агрегация моделей проектов, дедупликация по имени, без глобальных ID

- Date: 2026-09-04
- Status: Accepted

## Context

Замечание ревью (EA-3): «спайн живёт внутри проекта; нет связи с
ландшафтом и реестром систем». Модель архитектуры (ADR-003) описывает
системы (`SYS-*`) и интеграции (`INT-*`) одного проекта; у банка таких
проектов десятки (кейсы, сервисы, флот worktree). Среза «какие системы
есть в ландшафте, где одна и та же система описана в нескольких проектах
и как они связаны» нет — видна только локальная модель каждого проекта.

Прямое решение «ввести глобальный реестр систем со сквозными ID»
противоречит уже принятым рамкам: ADR-033 (single-user by design —
реестры у нас агрегация файлов, а не сервис) и ADR-036 (реестр ADR — та
же механика набора проектов: ROOT + непосредственные подкаталоги,
read-only). Кроме того, глобальные ID инвазивны: потребовали бы
переписывания существующих `model/` всех проектов и синхронизации
нумерации между командами — то есть процессной обвязки, которую мы
осознанно не строим.

Связь с EA-мостом (ea-repository-bridge): ландшафт банка в EA-репозитории
— контекст, проектная модель — мастер-источник. Агрегация read-only не
претендует на роль мастера: она ВИТРИНА над проектными моделями, а не
новый источник истины.

## Decision

**1. Команда `arch-be model landscape <ROOT> [--mermaid]`** (модуль
`src/landscape.rs`). Та же механика набора проектов, что в ADR-036:
сканируется сам `ROOT` и непосредственные подкаталоги на предмет
`model/` (загрузка — `crate::model::load_model`); проект без `model/`
молча пропускается; ни одного `model/` — понятная ошибка. Каталоги
`.git`/`target`/`node_modules` не считаются проектами.

**2. Дедупликация по имени, БЕЗ глобального пространства ID.** Ключ
системы — каноническая форма title (lowercase, дефисы → пробелы,
схлопывание пробелов): «Процессинг» и «процессинг» в разных проектах —
ОДНА строка реестра с перечнем проектов, id и статусов всех вхождений
(дедуп-витрина). ID остаются проектными: ничего переписывать не нужно,
агрегация read-only.

**3. Находки ландшафта:**

- `id-divergence` — одна каноническая система под разными id в разных
  проектах (сигнал к выравниванию, не ошибка);
- `status-conflict` — у вхождений одной системы расходятся статусы;
- `dangling-ref` — связь (`depends_on`/`implements`/`affects`) на id,
  отсутствующий во ВСЕХ моделях набора (разрешение связей сквозное:
  сначала ищем цель по всему ландшафту, а не локально);
- `cross-project-link` — связь на систему (SYS/INT) другого проекта —
  ПОКАЗЫВАЕМЫЙ положительный факт ландшафта, не ошибка и не гейт.

**4. Топ связности и mermaid.** Топ-5 систем по числу связей
(вход+исход) по рёбрам между каноническими системами (саморебра после
дедупликации схлопываются). `--mermaid` — `graph TD`: узлы —
канонические системы (при id-divergence — с перечнем проектов),
идентификаторы узлов санитизированы (`s1..sN`), рёбра — связи
ландшафта. Рендер совместим с `arch-be mermaid`/публикацией.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Дедуп по имени, read-only агрегация (принято)** | ноль миграций; совместимо с ADR-033/ADR-036; дивергенция id/статусов видна механически как находка | совпадение имён — эвристика (омонимы сольются; переименование разведёт); снимок по запросу |
| Глобальное пространство ID (единый реестр SYS-NNN на банк) | однозначные ссылки между проектами | инвазивно: переписывание существующих model/ всех проектов; нужна координация нумерации между командами — процессная обвязка, которую ADR-033 не строит |
| Мастер-модель банка в одном репозитории | единый источник истины | конфликтует с EA-мостом: мастер — проектные модели, EA-репозиторий — контекст; монорепо-модель — смена границ владения |
| Только импорт в EA-инструмент (без CLI-витрины) | реестр «как у всех» | нет механических находок (dangling/divergence) до загрузки в EA; связка ломается при первом дрейфе |
| Дедуп по id (без имён) | проще | бесполезно: id проектные, совпадения случайны; дубли под разными id невидимы |

## Consequences

### Positive

- Разрыв «нет связи с ландшафтом» закрыт витриной: один вызов — реестр
  систем набора проектов с дедупликацией, находками и топом связности;
  mermaid пригоден для evidence bundle и архкомитета.
- Дивергенция id и конфликты статусов между проектами видны механически
  — то, что раньше находилось устно.
- Кросс-проектные связи (реальная интеграционная ткань банка) показаны
  как факт, а не висят «данглингом» локальной валидации.
- Ни одного нового источника истины: проектные модели не меняются,
  команда не зависит от глобальной нумерации.

### Negative

- Дедуп по имени — эвристика: системы-омонимы (одно имя, разные
  системы) сольются в одну строку; переименование системы в одном
  проекте разведёт витрину на две строки. Цена приемлема для витрины,
  находки читаются человеком.
- Разрешение связей по id сквозное по набору: совпадение проектных id
  (SYS-001 в двух проектах) трактуется как кросс-проектная связь —
  документированная аппроксимация той же без-id модели.
- Снимок по запросу: живость — дисциплина перезапуска (CI контура,
  ADR-033).

## Reversibility

**reversible.** Команда read-only: ничего не пишет в проекты; удаление
модуля не затрагивает формат `model/` и существующие команды
(`model validate/show/graph/export/import`). Переход к глобальным ID в
будущем не блокируется: витрина останется валидной и над ними.
