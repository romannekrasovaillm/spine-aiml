# ADR-044. Контур артефактов ML: реестр весов/датасетов и eval траекторий как CLI-поверхность

- Date: 2026-09-13
- Status: Accepted

## Context

Харнесс AI/ML-контура работает с тяжёлыми артефактами — весами, датасетами,
токенизаторами — и с эпизодами исполнения. Инварианты по хранению уже
зафиксированы практикой кейсов и памятью владельца: веса и датасеты живут на
сетевом диске (`~/gb10-shared`), в рабочих каталогах — только симлинки, копии
запрещены (C-032/C-033); датасет сопровождается карточкой с хешем, лицензиями
и объёмом (ADR-004 публичного корпуса); эпизоды лежат в трёх разных форматах
(эталонный JSONL, журналы сессий `~/.arch-ml/sessions/*.jsonl`, selfplay).

Сегодня это проверяется глазами или разовыми скриптами кейса: единого
механического гейта нет.

Перенесённая дельта (ветка `arch/delta-triage`, коммит «feat(cli): каркас
команд weights/data-card/trajectory») уже экспонировала три подкоманды:
`arch-ml weights list|verify`, `arch-ml data-card check`,
`arch-ml trajectory metrics`. При этом ядро — скелеты: `verify` возвращает
`Warn «проверка не реализована»` любому артефакту, `validate` не заполняет
`problems`, `parse_episodes` не разбирает строки. То есть бинарь обещает
проверку и не выполняет её.

Отдельная проблема процесса: решение о новой поверхности не было оформлено
ADR до появления каркаса — это дисциплинарный долг, который закрывается этим
ADR (статус Proposed; дореализация — условие приёмки).

## Decision

1. Поверхность признаётся частью инструментального контура: три подкоманды
   остаются в CLI, дореализуются по зафиксированной ниже семантике и
   документируются (`docs/headless.md` §4 «Детерминированные команды без LLM»,
   README). Команда не имеет права сообщать «проверено», если проверка не
   выполнена: до дореализации любая из трёх команд обязана возвращать честный
   отказ, а не зелёный отчёт.

2. Семантика проверок (контракт, а не настройка):

   **`weights verify`** — механическая сверка манифеста `artifacts.yaml`
   с файловой системой:
   - артефакт не найден → `Warn` «объявлен, не найден» (отсутствие артефакта
     на данном стенде — не провал);
   - найден симлинком → `Ok`, с предупреждением, если цель симлинка лежит
     внутри рабочего дерева;
   - найден регулярным файлом при `kind = weights | dataset` → `Fail`
     «копия в рабочем дереве» (C-032/C-033);
   - объявлен `sha256` → сверка через subprocess `sha256sum`; несовпадение →
     `Fail`; сверка не выполнена (нет утилиты) → `Warn`, не `Ok`.

   **`data-card check`** — карточка датасета против обязательных полей:
   - пустое обязательное поле → декларация-пробел в отчёте, **не** провал
     (ложно-красный на отсутствующем корпусе недопустим);
   - `problems` заполняется только фактическими противоречиями, требующими
     пути к датасету (объявлен `sha256`/`records`, а файла нет).

   **`trajectory metrics`** — метрики эпизодов, формулы фиксированы:
   - `success_rate` — доля успехов среди эпизодов с известным вердиктом
     (`labeled`), не среди всех;
   - `ci95` — интервал Уилсона по числу **задач** (группировка по `task_id`),
     не по эпизодам;
   - `pass@k` — несмещённая оценка Chen et al. 2021
     (`1 − C(n−c, k)/C(n, k)`), усреднённая по задачам; задачи с `n < k`
     исключаются и учитываются отдельным счётчиком;
   - вердикт эпизода — явное поле `success`; при его отсутствии —
     `final_reward > 0` (для бинарных сред награда 0/1 даёт тот же вердикт);
   - противоречия карточки (`sha256`/`records` при отсутствующем датасете)
     проверяются только при явном пути (`--dataset`): без пути «файла нет»
     не доказать, а выдуманный красный недопустим.

3. Проверки детерминированы, работают без LLM и сети — пригодны как CI-гейт
   и как шаг префлайта перед дорогим прогоном.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Три CLI-команды с фиксированной семантикой (принято)** | детерминированный гейт без LLM; одна точка правды для симлинков, хешей и формул метрик; встраивается в CI/скрипты | расширяет поверхность бинаря; формулы статистики в коде требуют дисциплины версионирования |
| Агентские инструменты (`weights_*`, как `rubric_*`, `model_*`) | модель сама выбирает момент проверки, есть доступ к контексту | проверка недетерминирована по вызову, недоступна в CI без LLM и ключей; дороже |
| Внешние python-скрипты в кейсе (статус-кво, разовые проверки) | ноль изменений в ядре | дублирование правил в каждом кейсе; расходятся версии; нет единого гейта; обходят env-scrub и политику харнесса |
| Снять три подкоманды до дореализации | бинарь не врёт | теряется уже сделанная работа; поверхность придётся открывать заново; проблема «проверок нет» остаётся |

## Consequences

### Positive

- Механический гейт ML-контура: симлинки весов/датасетов и хеши проверяются
  без LLM — воспроизводимость и префлайт перед дорогими прогонами.
- Формулы метрик перестают быть устной договорённостью: `success_rate`,
  Уилсон по задачам, `pass@k` зафиксированы в коде и тестах.
- Карточка датасета получает проверяльность без ложно-красных на пустом диске.

### Negative

- `subprocess sha256sum` — внешняя зависимость (ядроutils); при её отсутствии
  проверка честно деградирует в `Warn`, то есть полный PASS без хешей
  невозможен (принимается осознанно).
- Статистические метрики (Уилсон, `pass@k`) предполагают независимость
  эпизодов задачи; на малых `n` интервалы широкие — числа могут читаться как
  более точные, чем есть (митигация: счётчик исключённых задач и явные
  `labeled`-фильтры в отчёте).
- Дисциплинарный долг: решение зафиксировано ADR **после** появления каркаса
  команд; цена — потеря «решение раньше реализации» на этом участке.
- Расширение CLI-поверхности увеличивает объём документации и тестов; каждое
  изменение семантики — новая ревизия контракта.

## Reversibility

**reversible**: три подкоманды изолированы (модули `weights`, `dataset_card`,
`trajectory` + ветки CLI), не затрагивают ядро агента и граф зависимостей.
Откат — удаление подкоманд и модулей одним коммитом; манифест `artifacts.yaml`
и карточки остаются полезными данными. Оценка: обратимо без миграций.
