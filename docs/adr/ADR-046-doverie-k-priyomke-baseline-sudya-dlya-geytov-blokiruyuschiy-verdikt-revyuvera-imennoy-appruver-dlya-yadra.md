# ADR-046. Доверие к приёмке: baseline-судья для гейтов, блокирующий вердикт ревьювера, именной аппрувер для ядра

- Date: 2026-09-13
- Status: Accepted

## Context

Приёмка в харнессе держится на трёх опорах, и в каждой найден обход.

1. **Гейты узлов флота.** Механического контроля того, *кто* исполняет гейт,
   не было: `run_command` запускал команду как записана, поэтому строка вида
   `./target/debug/arch-ml control check .` исполнялась бинарником, который
   собрал сам исполнитель. Дельта, меняющая проверки в `src/`, влияла на
   собственную приёмку — тот же класс дефекта, что зафиксирован в ADR-011
   («страж проверяет наличие надписи, а не поведение»).
   Уточнение по факту (13.09.2026): функция-детектор самооценки в базе
   `arch/integration@14c2107` отсутствует — она существовала только в
   незакоммиченном рабочем дереве параллельного потока. Поэтому решение
   ниже вводит и детектор, и обязательную реакцию; «предупреждение, которое
   уже было» — не аргумент.

2. **Вердикт ревьювера.** `expand_review_pair` достраивает узел-ревьювер с
   гейтом `Review` (разбор `READY`/`NOT-READY`) и предупреждает, если
   `merge_gate != owner`. Но `worktree accept` (`src/worktree.rs`) проверяет
   только чистоту дерева и выполняет merge — вердикты он не читает вовсе.
   Итог: `NOT-READY` красит узел в журнале, но интеграцию не блокирует.

3. **Самоулучшение ядра.** `src/evolve.rs` (H2.2) умеет propose/commit с
   именным аппрувером и append-only журналом, но применяет изменение только
   через managed-блок (`evolve_apply` → `managed::BlockOp::Replace` с
   `upsert`). В файлах `src/` managed-блоков нет — они живут в md-артефактах
   (`AGENTS.md` и родственные). Значит правка кода ядра идёт **мимо**
   протокола evolve: только руками и только по договорённости.

Факт 13.09.2026: ветка `arch/integration` (ядро: CLI-команды артефактов,
MCP-фикс, TUI-слияние) собиралась и принималась вручную; протокол с именным
аппрувером существовал только для доменного слоя.

## Decision

1. **Baseline-судья для гейтов.** `GateContext` получает
   `judge: Option<&Path>` — путь судьи, зафиксированный **до** прогона узла, и
   политику судьи. `fleet run` фиксирует baseline (флаг `--judge`, конфиг
   `[fleet] judge_binary`; если не задан — бинарь, запустивший флот, при
   условии, что он вне ворктри узла) и передаёт его в контекст гейта.
   `run_command`:
   - команда зовёт судью внутри ворктри узла, baseline задан → токен судьи
     подменяется baseline-путём; в отчёт гейта идёт фактический судья (путь +
     `sha256`);
   - baseline не задан, а судья внутри ворктри → **Fail** «самооценка
     запрещена: укажите baseline-судью» (сегодня — только warn);
   - судья вне ворктри → поведение прежнее (`Ok`), но отчёт называет судью.

2. **Блокирующий вердикт ревьювера.** `worktree accept` перед merge читает
   вердикты ревьюверов, относящиеся к этой ветке (журнал флота в `state_dir`:
   узел-ревьювер ↔ ветка ↔ вердикт), и при незакрытом `NOT-READY`
   **отказывает**, называя находки. Обход — только явным именным аппрувером:
   `arch-ml worktree accept <name> --approver <имя>` (запись в журнал
   приёмки). Автоматического мержа нет: `accept` остаётся рукой человека.
   Отсутствие вердиктов вообще — не «ок», а явное «не проверено» в выводе
   (журнал мог быть очищен).

3. **Именной аппрувер для ядра.** `evolve` расширяется на файлы `src/**`:
   кроме managed-блоков — режим замены/вставки файла целиком со сверкой
   базового хеша (`--content-file`), тот же именной аппрувер и тот же журнал.
   Условие commit — **зелёный прогон гейтов baseline-судьёй** (fitness/format/
   test по `CONSTRAINTS.yaml`); красный гейт — отказ, а не «коммит с оговоркой».
   Правка ядра перестаёт быть ручным мержем в обход протокола.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Baseline-судья + блокирующий вердикт + evolve на ядро (принято)** | приёмка не принадлежит оцениваемому дереву; `NOT-READY` блокирует механически; ядро и домен по одному протоколу | требует явного baseline-бинаря; accept читает состояние вне репозитория; грубый file-режим evolve |
| Статус-кво: warn про самооценку, accept без вердиктов, evolve только для домена | ноль работы | исполнитель подменяет судью; `NOT-READY` — украшение; правки ядра в обход протокола |
| Запретить гейтам звать `arch-ml` вообще | простая формулировка | теряем класс детерминированных гейтов (`control check`, `spine_lint`) — основной инструмент приёмки |
| Хранить вердикт ревьювера файлом в worktree | accept читает локально, без журнала | артефакт лежит в дереве, которое контролирует исполнитель: подмена вердикта тривиальна |
| Разрешить evolve менять `src/**` без прогона гейтов | быстрое самоулучшение | самоулучшение без приёмки — то самое «в обход», ради чего ADR и пишется |

## Consequences

### Positive

- Судья приёмки не принадлежит оцениваемому дереву: подмена гейта дельтой
  невозможна молча, в отчёте — фактический путь и хеш судьи.
- `NOT-READY` блокирует интеграцию механически; обход возможен только именным
  аппрувером и оставляет след в журнале.
- Изменения ядра идут по тому же протоколу, что доменный слой: предложение →
  именной аппрувер → зелёные гейты baseline-судьёй → применение.

### Negative

- Флот обязан знать baseline-бинарь: в CI его надо собирать явно, а при
  отсутствии гейт **падает** (Fail), а не проходит тихо — цена в отказах.
- `accept` начинает зависеть от состояния вне репозитория (`state/fleet`):
  очистка журнала снимает блокировку; «вердиктов нет» честно сообщается как
  «не проверено», но это не защита от намеренной чистки.
- File-режим `evolve` грубее managed-блоков (нет патч-семантики, выше риск
  затереть контекст); выравнивается строгим условием зелёных гейтов.
- Поверхность растёт: новый флаг у `fleet run`, новый у `worktree accept`,
  новый режим у `evolve` — каждый требует строки в README и `docs/fleet.md`.

## Reversibility

**reversible**: политика судьи — флаг/конфиг (снятие возвращает warn);
accept-гейт снимается одной правкой; расширение evolve аддитивно. Миграций
нет, обратной несовместимости для уже созданных планов и предложений нет.
