# ADR-035. Звено «INT → контракт»: поле `contract` и trace-проверка

- Date: 2026-09-04
- Status: Accepted
- Expiry review: при подключении содержимого контракта (валидация
  openapi/asyncapi из `src/openapi.rs`/`src/asyncapi.rs` к полю `contract`)
  или `contract_diff` (`src/contract_diff.rs`) к модели — пересмотреть
  границу «существование файла» vs «разбор содержимого» и состав
  error-находок звена.

## Context

Внешнее ревью (задача EA-2): модель архитектуры (ADR-003) и трассировка
(ADR-006) не связаны с межсистемными контрактами. Интеграции (`INT-*`) —
самое хрупкое место банковского ландшафта (каналы, рельсы, процессинги),
но артефакт контракта (openapi/asyncapi-спецификация) живёт отдельно от
модели: разрыв «интеграция есть, контракт потерян/никогда не был» не видит
никто. В репозитории уже есть инструменты уровня содержимого контрактов
(`src/openapi.rs` — lint OpenAPI, `src/contract_diff.rs` — эволюция
контракта), но звена от модели к файлу контракта нет.

Ограничения площадки прежние: схема сущности расширяется только аддитивно
(старые модели валидны), обязательных звеньев кроме `AD → fitness-правило`
не вводим без необходимости.

## Decision

1. **Поле `contract: Option<String>`** в схеме сущности (frontmatter,
   `src/model/parse.rs`): путь к контрактному артефакту
   (openapi/asyncapi/др.) относительно корня кейса. По смыслу — для `INT`,
   схема общая (как остальные необязательные поля; `deny_unknown_fields`
   допускает его как известное, старые модели без поля валидны).
2. **Новое звено trace check «INT → контракт»** (`src/trace.rs`):
   - `INT` с непустым полем `contract`: файл ОБЯЗАН существовать
     (относительно того же корня кейса, из которого читаются `model/` и
     `CONSTRAINTS.yaml`) — битый путь даёт **error**-находку
     `int-contract-missing` (заявленный контракт потерян — это разрыв
     трассировки, exit code 1, как у обязательного звена AD);
   - `INT` без поля `contract` — **warn**-находка `int-without-contract`
     («интеграция без контрактного артефакта»): внешняя система без
     контракта в репозитории легитимна, но должна быть видна в отчёте;
   - пустое/пробельное значение `contract` эквивалентно отсутствию поля;
   - звено включается в таблицу покрытия отчёта
     («звено | покрыто | доля | сироты») — как существующие звенья.
3. **Содержимое контракта не разбирается** (осознанное ограничение
   итерации): проверяется только факт существования файла по заявленному
   пути. Валидация openapi уже есть в `src/openapi.rs`; сочленение
   «`contract` → openapi-lint» и «`contract` → `contract_diff`
   (эволюция контракта, `src/contract_diff.rs`)» — следующие шаги,
   зафиксированы в Expiry review, в этой итерации не кодятся.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Поле `contract` + звено с error на битый путь и warn на отсутствие (выбрано) | разрыв «контракт заявлен и потерян» блокирует, легитимные внешние интеграции не штрафуются error'ом | содержимое контракта пока не проверяется |
| `contract` обязателен у всех `INT` (отсутствие — error) | полное покрытие контрактами | внешние интеграции без артефакта в репо (чужой рельс, SWIFT) легитимны — error лжёт и учит игнорировать отчёт |
| Проверка содержимого контракта (разбор openapi/asyncapi) сразу | сильнее гарантия | дублирует `src/openapi.rs`; сочленение требует решений (какой линт по типу файла, что делать с не-openapi артефактами) — отложено осознанно |
| Связь модели с контрактом через `verified_by`/`implements` на файл | без нового поля | связи модели — про сущности и правила `C-NNN`, не про файлы; путь в списке ID ломает валидацию ссылок |
| Путь относительно `model/` вместо корня кейса | короче пути | контракты не часть модели; корень кейса — единая точка резолва (`model/`, `CONSTRAINTS.yaml`, spine уже резолвятся от него) |

## Consequences

### Positive

- Замкнуто звено «модель ↔ межсистемные контракты»: потерянный контрактный
  артефакт — блокирующая находка CI (`error`, exit 1), интеграция без
  контракта видна поимённо в отчёте (`warn`).
- Схема расширена аддитивно: старые модели без `contract` валидны; поле
  общее (любой тип сущности может сослаться на контракт при нужде).
- Звено — одно определение по образцу существующих (`level_report`),
  отчёт без новых форматов; evidence bundle получает строку покрытия
  «INT → контракт» бесплатно.

### Negative

- Проверка — только существование файла: битый по содержимому контракт
  звеном не ловится (до сочленения с `src/openapi.rs`).
- Путь не нормализуется и не ограничивается периметром кейса: `../` в
  значении `contract` резолвится как есть (контент кейса — доверенный,
  как и пути в `code_roots`).
- Контракты не участвуют в обмене моделью (ADR-009/ADR-032) — экспорт
  форматов поле `contract` не переносит.

## Reversibility

reversible. Поле опционально и ни на что, кроме нового звена, не влияет;
удаление `int_level` и поля возвращает поведение к ADR-006. Существующие
кейсы без `INT` или без `contract` получают максимум warn — поведение
error-гейта не меняется.
