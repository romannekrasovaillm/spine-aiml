# ADR-031. Модель угроз Spine BE: docs/threat-model.md как живой артефакт, реестр GAP, протокол пересмотра

- Date: 2026-09-04
- Status: Accepted

## Context

Внешнее ревью (замечание «модель угроз самого агента»): bash в периметре,
prompt injection из содержимого репозитория, vendored Node, аудит бинаря.
Карточка threat model заявлена волной 2 библиотеки правил (ADR-019,
`wave2-mandated.yaml`) и не была реализована. Самопроверка поверхности
(ADR-016) закрыла egress-дисциплину, но оставила GAP-C1/C2 и не касалась
агента как вектора.

Факты кода на дату ADR: policy R0–R5 и env_scrub есть (`src/tool.rs`,
`src/tools/bash.rs`); маркировки недоверенного контента, sandbox,
пиновки `vendor/archify`, SBOM/подписи поставки — нет.

## Decision

1. **Модель угроз — живой документ** `docs/threat-model.md` (v1.0):
   активы, шесть границ доверия (TB-1…TB-6), восемь угроз T1–T8 с
   действующими митигациями (со ссылками на код/правила) и остаточным
   риском по шкале З/Ч/GAP, реестр GAP с планом закрытия, out of scope,
   протокол пересмотра (новый канал/вендор/транспорт; не реже года; по
   инциденту).
2. **Механические закрытия из реестра GAP выполняются гейдами, а не
   обещаниями**: пиновка вендора — `vendor/archify/SHA256SUMS` +
   fitness-правило BE-22 (`command_succeeds` сверки, dogfood CI) в том же
   изменении, что и этот ADR.
3. **Открытые GAP — запланированные пакеты, а не умолчания**: SBOM и
   подпись поставки (T-3), sandbox bash и injection-гигиена (T-4) — в
   плане доработок по ревью; GAP-C1/C2 — по протоколу ADR-016.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Живой threat-model.md + GAP-реестр + гейты (принято)** | документ для ИБ-ревью ДИТ; дыры видны поимённо со статусом; часть закрывается механически сразу | требует дисциплины пересмотра (закреплена протоколом §7) |
| STRIDE-воркшоп с внешним ИБ-консультантом | независимый взгляд | недоступно сейчас; документ нужен до пилота; v1 не мешает будущему воркшопу |
| Только механические усиления без документа | код важнее прозы | ИБ-ревью ДИТ требует артефакт; без реестра GAP дыры снова станут умолчаниями |
| Отложить до пилота | ноль затрат сейчас | карточка волны 2 уже просрочена; ревью повторит находку |

## Consequences

### Positive

- Замечание ревью закрыто артефактом: у каждой угрозы — текущие митигации
  со ссылками на код и честный остаточный риск; ИБ заказчика получает
  документ вместо устных ответов.
- Пиновка вендора (BE-22) — первая механическая проверка целостности
  поставки в репозитории; регресс целостности ломает dogfood CI.
- Реестр GAP связывает открытые дыры с пакетами плана — следующий пересмотр
  проверяет закрытие по списку, а не по памяти.

### Negative

- Документ поддерживается вручную: новая поверхность без пересмотра делает
  его устаревшим (смягчается протоколом §7 и правилом свежести `max_age`
  при заведении гейта на документ).
- Часть митигаций — процессные (журнал, ревью плагинов), их сила зависит
  от дисциплины пользователя; зафиксировано как остаточный риск, а не как
  «закрыто».

## Reversibility

reversible. Документ и правило BE-22 аддитивны; их удаление не меняет
поведение агента (митигации TB-1 живут в policy/env_scrub независимо).
