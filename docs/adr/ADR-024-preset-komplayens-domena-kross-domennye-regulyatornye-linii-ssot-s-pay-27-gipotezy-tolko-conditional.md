# ADR-024. Пресет комплайенс-домена: кросс-доменные регуляторные линии, SSOT с PAY-27, гипотезы только conditional

- Date: 2026-09-01
- Status: Accepted

## Context

Волна 2 карты дифференциации (ADR-014) — compliance-глубина. Материал
готов и верифицирован: `banking/compliance/` содержит reg-map
(21 строка нормативных гипотез с протоколом верификации), карты
719-П (гл. 1/2/7 + прил. 1, верифицировано 2026-08-31), 851-П
(действующий антифрод-акт, OCR-верифицировано), 683-П (суперседирован,
генеалогия), частично верифицированный 152-ФЗ (ст. 3/6/18/18.1/19/22 +
FAQ РКН).

Два напряжения:

1. **SSOT с PAY-27.** Антифрод-ядро 851-П (пп. 3.1 уровни, 3.2 pentest,
   4.1 ОУД4, п. 13 оценка) и ГОСТ Р 57580.1/.2 уже материализованы в
   mandatory-блоке PAY-27 платежного пресета со стражами PAY-27a..f
   (демо-проверено: FAIL 26/3 — ожидаемый). Прямое дублирование норм в
   комплаенс-пресете создаст два расходящихся источника одной нормы —
   антипаттерн «дублирование одного правила в трёх источниках»
   (блок 15 каталога источников).
2. **Верифицированное vs гипотезы.** Reg-map содержит строки со
   статусом ВЕРИФИЦИРОВАНО и [ТРЕБУЕТ ПРОВЕРКИ] (187-ФЗ/КИИ, 115-ФЗ
   ПОД/ФТ, СКЗИ, модельный риск, 98-ФЗ КТ, 757-П). Продуктовое обещание
   ADR-016/017 — «строго по первоисточнику»: гипотеза не может
   становиться обязательным правилом для проектов ДИТ.

## Decision

Создать пресет `banking/presets/compliance/` (SPINE-COMPLIANCE.md +
профиль evidence-артефактов) с границей:

1. **Кросс-доменные линии, отсутствующие в платежах**: 152-ФЗ (ПДн),
   КИИ 187-ФЗ, ПОД/ФТ 115-ФЗ, СКЗИ, модельный риск, КТ, ИИ-мягкое
   право ЦБ (Кодекс этики п. 6.5/6.9 — верифицировано, R-07).
   Платёжный надзор (719-П + 851-П + ГОСТ 57580.x) остаётся в PAY-27 —
   комплаенс-пресет ссылается на него таблицей кросс-ссылок, не
   дублируя нормы.
2. **Гипотезы — только conditional** с маркером [ТРЕБУЕТ ПРОВЕРКИ]
   в условии блока; повышение до mandatory — только после верификации
   по протоколу reg-map (первоисточник → цитата → маппинг → статус).
3. **CMP-01 (реестр применимых актов со статусами верификации) —
   mandatory-вход** любого комплаенс-проекта: протокол reg-map
   спускается в проект ДИТ.
4. **Профиль — evidence-артефакты** (`profiles/evidence-docs.yaml`,
   стек-агностичный: file_exists/must_contain по docs/compliance/**),
   в отличие от стекового go-kafka-pg платежей.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Перенести 719-П/851-П в комплаенс-пресет («единый регуляторный дом») | один дом для всей нормативки | churn PAY-27 ([ADOPTED], демо волны 1 проверено), ломает ADR-017, платежи — домен волны 1 со своим надзором; отклонено |
| Мега-пресет «банк целиком» | один файл на всё | нарушает доменную дифференциацию ADR-014; раздувает спайн проекта (лимит 3–7 инвариантов, Fundamentals of SA); отклонено |
| Статус-кво: reg-map без пресета | ноль работы | reg-map — позиция продукта, не стартовый пакет проекта; у проекта ДИТ нет Binds/Prevents/Rule и стражей; отклонено |
| **Принято: кросс-доменные линии + SSOT-ссылки** | честность гипотез, PAY-27 не задет, реестр актов как обязательный вход | две точки входа для платёжно-комплаенс-проектов (см. Consequences) |

## Consequences

### Positive

- Комплаенс-проекты ДИТ стартуют с реестра актов и верификационного
  протокола, а не с чистого листа; статус каждой нормы виден машине
  (стражи) и человеку (маркеры).
- Гипотезы честно видны как conditional — исключён риск продать
  неверифицированную норму как обязательную (ядро доверия продукта).
- PAY-27 не тронут: демо волны 1 и ADR-017 стабильны.

### Negative

- **Две точки входа** для проектов на стыке платежей и комплайенса:
  нужно включать оба пресета; митигировано таблицей кросс-ссылок в
  SPINE-COMPLIANCE (PAY-27, PAY-01, PAY-12, PAY-15) и инструкцией
  применения в README.
- Гипотетические блоки (CMP-08…CMP-12) до верификации — бумажные
  обязательства без норм: требуют верификационной работы; владелец —
  продукт, протокол reg-map, срок — первый проект соответствующего
  контура.
- 12 блоков в каталоге против лимита 3–7 на систему (Fundamentals):
  допустимо, т.к. пресет — каталог выбора, а не спайн одного решения;
  проект включает подмножество (обязательный минимум — CMP-01…05).

## Reversibility

reversible — пресет целиком декларативные артефакты (md/yaml) без кода;
смена границы SSOT (например, перенос 851-П-ядра в компляенс-дом)
оформляется supersede-ADR + миграцией кросс-ссылок PAY-27 ↔ CMP.
