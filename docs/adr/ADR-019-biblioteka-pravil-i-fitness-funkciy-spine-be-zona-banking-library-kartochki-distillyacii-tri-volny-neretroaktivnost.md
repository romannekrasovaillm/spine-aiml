# ADR-019. Библиотека правил и fitness-функций Spine BE: зона banking/library, карточки дистилляции, три волны, неретроактивность

- Date: 2026-09-01
- Status: Accepted

## Context

Владелец предоставил расширенное издание «Источники solution-архитектуры»
(64 888 байт, docx; 168 источников: блок 0 — 12 уже встроенных, блоки
1–15 — 156 кандидатов) с требованием имплементировать идеи «в полном
объёме, особенно улучшив fitness-функции». Документ несёт четыре
механизма: фильтр включения (паттерн обязан принять одну из пяти форм:
spine-инвариант / поле ADR / fitness-функция / пункт NFR-бюджета /
элемент гейта), шаблон карточки дистилляции (7 полей: Trigger, Rule,
Rationale, Check, Evidence, Reversibility, Owner/Expiry — карточка без
Check или Owner не попадает в библиотеку), порядок трёх волн
(1 — механизируемое; 2 — обязательное извне; 3 — смысловое) и
восемь антипаттернов расширения (прил. Б).

Противоречия, которые обязан снять ADR:

- **Полнота vs собственный фильтр документа**: «реалистичный шаг —
  25–40 правил из первой волны, а не все блоки сразу»; антипаттерн
  «рост библиотеки как показатель успеха». Слепое импортирование 156
  источников правилами нарушило бы сам документ.
- **Дублирование**: прил. А (20 функций) частично пересекается с
  пресетом PAY (идемпотентность, outbox) — антипаттерн «дублирование
  одного правила в трёх источниках».
- **Невыразимые проверки**: «дата последних учений не старше
  интервала», «ежегодный pentest» — четыре типа движка
  (must_contain / must_not_contain / file_exists / command_succeeds)
  не выражают свежесть файла нативно.
- **Зона**: `assets/plugins/` — MIT (AD-BE1), библиотека банковских
  правил — proprietary ценность.

Significance: 3 → Standard (new_component, cross_domain_integration,
api_contract_change — расширение схемы FitnessRule движка).

## Decision

**1. Зона `banking/library/`** (proprietary, страж BE-01) — библиотека
правил Spine BE:

- `README.md` — методология: фильтр пяти форм, шаблон карточки
  дистилляции (7 полей), порядок волн, антипаттерны прил. Б как
  правила governance, происхождение источника.
- `fitness/wave1-mechanizable.yaml` — волна 1 (механизируемое):
  правила из прил. А + блоков 5/6/7/11/12, с карточками в
  комментариях; генеральные правила — в кросс-ссылке с доменными
  инстанциациями пресета PAY (одно правило — одна формулировка:
  генеральная здесь, доменная в PAY, дубли запрещены).
- `fitness/wave2-mandated.yaml` — волна 2 (обязательное извне):
  threat model, ПДн-регионы; регуляторные строки — только через
  reg-map (верификация по cbr.ru на дату применения — требование
  источника совпадает с нашей дисциплиной).
- `sources.md` — каталог всех 15+1 блоков источника (пространство
  выбора): источник → паттерн → точка встраивания → статус
  (встроено / в PAY / волна N / отложено фильтром). Каталог
  фиксирует «полный объём» без раздувания исполняемых правил.

**2. Движковое улучшение fitness (код, через handoff)**: новый тип
правила `max_age` в `src/control.rs` — file_exists + свежесть файла
не старше N дней (`path`, `max_age_days`). Механизирует
невыразимое: свежесть DR-учений (прил. А № 19), ежегодность pentest
(PAY-27b), пересмотр ADR по инцидентам. Обратная совместимость:
старые CONSTRAINTS парсятся без изменений.

**3. Неретроактивность и жизненный цикл** (в методологию и AD-BE6):
правило вводится датой и не краснит существующие системы задним
числом (Zalando); новое правило стартует в режиме аудита, потом
принуждение (Kyverno); Expiry обязателен в карточке; правило,
реализуемое платформой, не становится правилом команды (CNCF).

**4. Улучшение пресета PAY от источника**: PAY-07 (ретраи) дополняется
требованием бюджета ретраев на цепочку, а не на вызов (AWS Builders'
Library — «три уровня ретраев дают многократный рост нагрузки»).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Зона library + 3 волны + карточки + max_age (принято)** | полный объём при живом governance; каталог 168 источников как пространство выбора; невыразимые проверки становятся нативными | волны 2–3 стартуют позже волны 1 (осознанно — порядок источника); max_age — правка ядра через handoff |
| Импорт всех 156 источников правилами сразу | формальная полнота | нарушает собственный фильтр документа; антипаттерн «рост библиотеки»; правило без проверки живёт до первого дедлайна |
| Только прил. А (20 функций), без каталога и governance | быстро | теряна методология (фильтр/карточки/антипаттерны) — источник обеднён до списка; следующие добавления без фильтра |
| Библиотека в assets/plugins (MIT) | попадает в существующую механику плагинов | proprietary-ценность утекает (AD-BE1); отвергнуто; плагины ru-* (ADR-018) подключат library через скиллы позже |
| Без max_age (обходиться command_succeeds со shell-скриптами) | ноль правок ядра | свежесть — частая проверка (учения, pentest, ADR-пересмотр); shell-гимнастика в каждом правиле нечитаема и хрупка |

## Consequences

### Positive

- 20 функций прил. А материализованы с карточками и кросс-ссылками;
  PAY-пресет обогащён (бюджет ретраев); дубли устранены по построению.
- Каталог источников делает следующую дистилляцию дешёвой: каждое
  новое правило выбирается из каталога с готовой точкой встраивания.
- max_age закрывает класс «свежесть evidence» — надзорные артефакты
  (719-П: ежегодный pentest, DR-учения) проверяются машиной.
- Неретроактивность — прямой ответ на страх ДИТ «вендор правилами
  сломает нам существующие системы в день обновления».

### Negative

- Правила волны 1 написаны под типовые структуры путей (deploy/,
  docs/, tests/) — при применении в проекте ДИТ глобы адаптируются
  (оговорено в комментариях каждого правила).
- max_age — расширение схемы FitnessRule: чужие CONSTRAINTS с
  неизвестными полями, если были, станут строже парситься; в нашем
  контуре таких нет (проверить при реализации).
- Каталог sources.md — снимок источника на 2026-08-31; обновление
  источника не отслеживается автоматически (Expiry каталога — год,
  пересмотр по заявке владельца).
- Волна 3 (смысловое: границы доменов, данные, миграции, ИИ) —
  карточки без Check не попадают в исполняемую библиотеку; их место —
  скиллы плагинов ru-* (ADR-018), не CONSTRAINTS.

## Reversibility

**reversible** (данные) для зоны library и каталога; **costly** для
max_age после того, как правила начнут использовать тип в CI заказчиков
(обратная совместимость декларацией старых типов сохраняется).
