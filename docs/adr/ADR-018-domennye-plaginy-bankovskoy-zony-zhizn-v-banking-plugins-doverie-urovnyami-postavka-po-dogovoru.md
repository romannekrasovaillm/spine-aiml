# ADR-018. Доменные плагины банковской зоны: жизнь в banking/plugins, доверие уровнями, поставка по договору

- Date: 2026-09-01
- Status: Accepted

## Context

Транш T3 (ADR-015) — доменная библиотека: плагины ru-payments
(СБП/НСПК, ISO 20022), ru-integration (СМЭВ, ЕБС, АБС), ru-compliance
(методики по картам 719-П/851-П). Плагин — единица распространения
знаний ядра (AD-10 ядра: plugin.json + skills/ + mcp.json + agents/ +
hooks/), каталоги подключения — `[plugins].dirs`.

Живое противоречие (обнаружено при сверке ADR-013/016/банк-профиля):

1. **Лицензионная граница** (AD-BE1): `assets/plugins/` — MIT-зона;
   банковские доменные знания — proprietary ценность продукта
   (LICENSE.banking). Класть их в MIT-зону нельзя.
2. **Оборонительный банк-профиль** (ADR-016): `include_mcp = false`,
   `include_hooks = false` — недоверенные библиотеки не исполняют код
   в контуре. Но T3-плагины — наша собственная ценность, и их нужно
   доставлять в тот же контур.
3. **Механизм ядра один** (AD-4/AD-10): отдельная «банковская»
   подсистема плагинов в коде = дублирование механики и ветвления —
   против принципов тонкого ядра.

Дополнительное ограничение: плагин несёт разнородный контент — скиллы
(данные, безопасно), MCP-серверы и хуки (исполняемые пути, риск).
Банку нужен раздельный контроль.

## Decision

**Банковские доменные плагины живут в `banking/plugins/<name>/`**
(proprietary-зона, заголовок лицензии — страж BE-01 расширяется на
`banking/plugins/**`), **загружаются тем же механизмом ядра** через
отдельную запись в `[plugins].dirs` банк-профиля. Никакого второго
плагин-механизма в коде не появляется: ядро (MIT) умеет читать плагины
из любого каталога, различие — только в том, где они лежат и как
поставляются.

**Доверие уровнями** (профиль банка):

- **Скиллы (`skills/`)** банковских плагинов подгружаются всегда —
  это данные (методики), попадают в поиск/подгрузку как обычные скиллы.
- **MCP-серверы (`mcp.json`) и хуки (`hooks/`)** банковских плагинов —
  только после явного включения банком (в банк-профиле заводится
  список доверенных плагинов, для которых `include_mcp/include_hooks`
  переопределяются в true; по умолчанию — false, как сегодня).

**Совместимость версий**: plugin.json банковского плагина обязан
нести `min_core_version` (версия ядра, с которой проверен); поставка
банка валидирует совместимость при установке, несовместимость —
ошибка установки, не молчаливая работа.

**Поставка**: банковские плагины входят в поставку по лицензионному
договору (закрытый канал, вместе с banking/); обновления — тем же
каналом. В git-репозитории форка банковские плагины разрабатываются
открыто для нас (banking/plugins/), для заказчика упаковываются
поставкой.

**Первый плагин волны T3 — ru-compliance** (решение владельца
подтверждается при старте волны): скиллы-методики по верифицированным
картам 719-П/851-П/152-ФЗ (reg-map → скилл-навык «спроектировать
надзорный контур»), без MCP и хуков — только данные, что снимает
вопрос доверия для первого плагина полностью.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **banking/plugins + механизм ядра + доверие уровнями (принято)** | лицензионная граница цела (AD-BE1); один механизм плагинов (AD-10); банку — раздельный контроль скиллы/MCP/хуки; первый плагин (ru-compliance) — чистые данные | в банк-профиле появляется явный список доверия (эксплуатационная ответственность ДИТ); нужна валидация min_core_version |
| Доменные плагины в assets/plugins (MIT) | ноль новой механики | proprietary-знания утекают в MIT-зону — прямое нарушение ADR-013; отвергнуто |
| Отдельная подсистема «банковских плагинов» в коде | можно зашить спец-логику | дублирование механики AD-10, ветвления в ядре против AD-4; отвергнуто |
| Не плагины, а скиллы-каталог в banking/skills с ручной установкой | проще | теряются поиск скиллов, plugin.json-версионирование, агент-линзы; скилл-библиотека ядра не видит их; отвергнуто |
| Плагины только в поставке заказчика (не в нашем git) | закрытость максимальна | теряем dogfooding и CI-стражи на банковских плагинах; разработка вслепую; отвергнуто |

## Consequences

### Positive

- T3 стартует без нарушения лицензионной границы: банковские плагины
  — в banking/ (proprietary), механика — в ядре (MIT).
- Банк-контур получает управляемое доверие: методики доступны сразу,
  исполняемые пути — только явным решением ДИТ.
- Стражи BE-01 (заголовок лицензии) автоматически распространяются
  на banking/plugins — граница машино-проверяема.
- Dogfooding: наши же скиллы ru-compliance живут в тех же механиках,
  что и MIT-плагины — качество механики проверяется на себе.

### Negative

- Валидация `min_core_version` — новая механика в ядре (небольшая:
  чтение поля + сравнение семвера при загрузке плагина), потребует
  кодовой правки через handoff и тестов.
- Список доверия в банк-профиле — точка человеческой ошибки (доверил
  плагин с хуком без ревью); митигируется комментарием в профиле и
  ревью изменений профиля при поставке.
- Двойной каталог плагинов (assets/plugins + banking/plugins) —
  небольшая сложность онбординга; митигируется документацией
  banking/README.md.

## Reversibility

**reversible**: расположение и правила доверия — данные и конфиги;
переезд каталога или смена политики доверия не ломает механику ядра.
