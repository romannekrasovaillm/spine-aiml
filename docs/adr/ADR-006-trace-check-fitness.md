# ADR-006. Трассируемость как fitness-функция (`arch trace check`)

- Date: 2026-08-17
- Status: Accepted
- Expiry review: при появлении P1-1 (количественные NFR) и P2-2 (кейсы как
  регрессионный набор) — пересмотреть состав обязательных звеньев и пороги
  покрытия (сейчас обязательно одно: `AD → fitness-правило`).

## Context

Ревью `SPINE-REVIEW.md` (находка F-1, задача P0-2): P0-1 дал типизированную
модель (`model/`, связи `depends_on`/`implements`/`affects`/`verified_by`),
но цепочка `REQ → NFR → AD/ADR → CMP → fitness-правило → evidence` целиком
не проверяется. Рубрика `solution_architecture` требует двусторонней
трассировки «без сирот»; сироту (требование без реализации, инвариант без
проверки) сейчас не видит никто.

Жёсткий минимум DoD: каждый `AD-*` из ARCHITECTURE-SPINE.md либо связан хотя
бы с одним правилом CONSTRAINTS.yaml, либо помечен `unverifiable:` с
обоснованием — иначе `error` и exit code 1 (годится для CI флота).

## Decision

1. **Новый модуль `src/trace.rs`**: `trace_check(case_dir)` читает
   `<case>/model/` (модель P0-1), `<case>/CONSTRAINTS.yaml` (ID правил,
   разделяемый загрузчик из `model::validate`) и `<case>/ARCHITECTURE-SPINE.md`
   (перечень инвариантов; файл опционален).
2. **Звенья и правила покрытия** (одно определение на звено, без транзитивной
   магии — транзитивность обеспечивается тем, что каждое звено покрыто):
   - `REQ → дизайн`: есть входящая ссылка любой сущности. Сирота — `warn`.
   - `NFR → дизайн`: есть способ проверки (`verification`/`verified_by`)
     **и** связь с `AD`/`ADR`/`CMP` (любое направление). Сирота — `warn`.
   - `AD → fitness`: `verified_by` содержит существующее правило `C-NNN`
     **или** непустое `unverifiable` с обоснованием. Нарушение — **`error`**
     (единственное обязательное звено этой итерации).
   - `ADR → CMP`: `affects` содержит существующий `CMP-*`. Сирота — `warn`.
   - `CMP → fitness`: `implements` содержит хотя бы один `AD-*`
     (компонент привязан к проверяемому инварианту). Сирота — `warn`.
3. **Сверка со spine**: если `ARCHITECTURE-SPINE.md` есть, каждый его `AD-<n>`
   обязан существовать в модели (`error`); сущность `AD-*` в модели вне
   spine — `warn`. Извлечение ID — общий хелпер `control::spine_ad_ids`
   (та же семантика определения AD-блока, что у `lint_spine`).
4. **Поле `unverifiable`** добавлено в схему сущности (`Option<String>`):
   непустое обоснование снимает требование fitness-правила. В `model::validate`:
   `unverifiable` без обоснования (пустая строка) — `error`; одновременные
   `verified_by`-правило и `unverifiable` у `AD` — `warn` в trace
   (противоречивая пометка, правило выигрывает).
5. **Отчёт**: markdown-таблица «звено | покрыто | доля | сироты (поимённо)» +
   список находок — формат пригоден для вставки в evidence bundle.
   Exit code 1 при любой находке `error` (как `control check`).
6. **Интерфейсы**: CLI `arch trace check <dir>` (где `<dir>` — корень кейса);
   инструмент агента `trace_check` (регистрация в `tools::domain_tools`,
   строка в `docs/tools.md`).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Позвенное покрытие + одно обязательное звено (выбрано) | отчёт читаем, сироты видны поимённо, CI ломается только на обязательном | проценты по звеньям, а не по полным сквозным цепочкам |
| Полная транзитивная проверка REQ→…→evidence на каждое требование | строгая сквозная трассировка | хрупко: один разрыв обнуляет цепочку; графа кейса пока мало для такой строгости |
| Все звенья обязательные (error) | максимум дисциплины | невозможно поэтапное наращивание модели; существующие кейсы ломаются |
| Трассировка текстовая (grep ссылок по markdown, как lint_spine) | не нужна модель | это и есть F-1: проза без графа не даёт ни сирот, ни покрытия |

## Consequences

### Positive

- Спайн больше не может молча потерять проверку: `AD` без правила и без
  `unverifiable` ломает CI (exit 1). Кейс 002 показывает 100% покрытия.
- `unverifiable` делает честным отказ от механической проверки: обоснование
  ревьюится как часть модели, а не живёт в головах.
- Отчёт в markdown вставляется в evidence bundle без переработки.
- Сверка модели со spine ловит расхождение «проза обновилась, модель нет».

### Negative

- Покрытие позвенное, не сквозное: теоретически возможен «луковый» граф,
  где каждое звено формально покрыто, а полной цепочки REQ→…→правило нет.
  Смягчается малым размером моделей кейсов; сквозной режим — кандидат на
  P1 при первом реальном запросе.
- `unverifiable` — точка злоупотребления («не смог придумать правило»);
  сдерживается ревью модели в git и обязательным обоснованием.
- Правила-покрытия в кейсах forward-looking (regex по будущему коду) —
  проверяют намерение, а не факт; это свойство самих fitness-правил,
  а не trace-слоя.

## Reversibility

reversible. `trace.rs` — чистый читатель модели; его удаление не трогает
ни формат `model/`, ни CONSTRAINTS.yaml. Поле `unverifiable` опционально,
старые модели без него валидны.
