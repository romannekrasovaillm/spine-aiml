# ADR-036. Глобальный реестр ADR: агрегация docs/adr и model/ADR по набору проектов

- Date: 2026-09-04
- Status: Accepted

## Context

Внешнее ревью зафиксировало разрыв «процессная обвязка: нет глобального
реестра ADR»: решения живут по проектам (прозаические `docs/adr/*.md`,
типизированные `model/ADR-*.md` — ADR-003), а единого среза «какие решения
приняты по набору репозиториев» у архитектора нет. При работе с флотом
проектов (кейсы, сервисы, worktree-флот) это боль: дубли решений и
коллизии номеров между проектами видны только вручную.

ADR-033 (single-user by design) уже ответил на класс таких замечаний
рамкой: RBAC, серверный режим и многопользовательские сервисы в продукте
не строятся; процессная обвязка — снаружи, в контуре заказчика. Глобальный
реестр ADR при этом — НЕ сервис: это чтение файлов, которые и так лежат в
git-репозиториях пользователя. Значит, задача сводится к детерминированной
агрегации — механике, а не платформе (AD-1, AD-2).

Два формата ADR сосуществуют осознанно: проза (шаблон AI-DLC, `control adr`)
и типизированные сущности модели (ADR-003, frontmatter). Реестр обязан
покрывать оба, не заставляя мигрировать.

## Decision

**1. Команда `arch-be adr registry <ROOT> [--json] [--strict]`** (модуль
`src/adr_registry.rs`). Сканируется сам `ROOT` и его НЕПОСРЕДСТВЕННЫЕ
подкаталоги (каждый — проект/репозиторий); `.git`, `target`,
`node_modules` не считаются проектами. Рекурсии глубже одного уровня нет:
набор проектов задаётся кладкой каталогов, а не обходом всего дерева.

**2. Два источника записей:**

- `docs/adr/*.md` — прозаические ADR: номер из первого заголовка
  `# ADR-NNN.` / `# ADR-NNN:` (валидация токена — общий regex
  идентификатора `crate::model::id_re`), заголовок — остаток заголовка,
  `- Date:` / `- Status:` — из шапки; файл без такого заголовка не
  считается ADR;
- `model/ADR-*.md` — типизированные сущности (разбор —
  `crate::model::parse_entity`): берутся только сущности с префиксом
  `ADR-` (остальные типы модели игнорируются); неразбираемый файл
  пропускается — его проблемы остаются зоной `arch-be model validate`.

**3. Индекс и находки.** Таблица «проект | ADR | заголовок | статус |
дата | источник» с детерминированной сортировкой (проект, номер,
источник, файл). Находки: коллизия номеров (один `ADR-NNN` в разных
проектах с РАЗНЫМИ заголовками — глобального пространства номеров
нет), дубль заголовка (одинаковый заголовок у разных номеров), запись
без даты/статуса. Проект без ADR — не находка (молча не попадает в
индекс); пустой набор — понятная ошибка «нечего регистрировать».

**4. Реестр — отчёт, гейт — опция.** По умолчанию exit 0 (агрегация не
блокирует); `--strict` даёт exit 1 при любой находке — для CI контура
заказчика, где и живёт процессная обвязка (ADR-033). `--json` — единый
объект `{root, entries, findings}` для скриптов и SDK-стиля потребления.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Файловая агрегация `adr registry` (принято)** | ноль инфраструктуры; оба формата ADR; детерминизм (AD-2); находки (коллизии/дубли) — бесплатный аудит флота проектов | снимок по запросу, а не живой индекс; эвристика проза-парсера (шапка `- Date:`/`- Status:`) |
| Серверный реестр ADR (сервис + БД) | живой индекс, поиск, права | против ADR-033 (single-user by design) и AD-1; новый компонент сопровождения |
| Реестр вручную в Confluence | привычно архкомитету | расходится с файлами уже на первом форке; ноль механических находок |
| Только model/ADR как источник | один строгий формат | ломает существующие прозаические библиотеки ADR; миграция ради реестра |
| Рекурсивный обход всего дерева ROOT | находит вложенные монорепо | непредсказуемое время и шум (vendor, чужие чекауты); граница «один уровень» явна и конфигурируется кладкой |

## Consequences

### Positive

- Разрыв «нет глобального реестра» закрыт механикой: один вызов — срез
  решений по всему набору проектов, пригодный для evidence bundle и
  архкомитета (markdown) и для скриптов (JSON).
- Коллизии номеров и дубли решений между проектами видны механически —
  то, что раньше ловилось только памятью архитектора.
- Оба формата ADR равноправны: типизация модели (ADR-003) не становится
  обязательной для попадания в реестр.
- Граница продукта сохранена: реестр — read-only агрегация файлов, ни
  сервиса, ни состояния, ни сети (ADR-033, AD-2).

### Negative

- Проза-парсер — эвристика: нестандартная шапка ADR (без `- Date:`/
  `- Status:`) даёт находку «без даты/статуса», а не молчаливый пропуск —
  шум в строгом режиме лечится приведением шапки к шаблону.
- Снимок по запросу: «живость» реестра — дисциплина перезапуска команды
  (CI с `--strict` закрывает это для контура).
- Один уровень вложенности: экзотические кладки (проекты глубже первого
  уровня) требуют запуска на конкретном подкаталоге.

## Reversibility

**reversible.** Команда read-only: ничего не пишет в сканируемые проекты;
удаление модуля не затрагивает форматы ADR и существующие команды
(`control adr`, `model *`). Решение не меняет ни один существующий
контракт.
