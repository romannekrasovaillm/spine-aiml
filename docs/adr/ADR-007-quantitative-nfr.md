# ADR-007. Количественные NFR поверх типизированной модели (`arch nfr`)

- Date: 2026-08-17
- Status: Accepted
- Expiry review: при появлении P1-3 (нотация и обмен) — пересмотреть,
  не переехали ли количественные поля во внешний формат (Structurizr DSL);
  при появлении P2-2 (кейсы как регрессионный набор) — зафиксировать
  ожидаемые выводы `arch nfr` кейса 002 как золотые.

## Context

Ревью `SPINE-REVIEW.md` (задача P1-1): количественные NFR — главный
дифференциатор Spine от кодовых харнессов. P0-1 дал типизированную модель
(`model/`, ADR-003), но числа в NFR/INT-сущностях живут в свободной прозе:
«Цель: p99 < 2s» не сверяется с бюджетами hop'ов, доступность не считается,
TCO и цена выхода не оцениваются (критерий `portability` рубрики сегодня без
инструмента), а сценарии атрибутов качества (QAS) в критерии приёмки
handoff-пакета попадают ручным копированием.

Требования DoD: расхождение суммы бюджетов hop'ов с целевым p99 — `error` с
указанием виновных hop'ов; QAS из модели попадают в `TASK.md` handoff-пакета
автоматически; проверки полностью детерминированы, LLM не нужен; тарифы —
данными в сущностях, не в коде.

## Decision

1. **Структурированные поля во frontmatter** (все опциональны — старые
   модели валидны без изменений; `deny_unknown_fields` продолжает ловить
   опечатки):
   - `INT-*`: `latency_budget_ms` — заявленный бюджет hop'а, мс.
   - `NFR-*`: `p99_target_ms`, `availability_target` (доля, 0..1),
     `rto_minutes`, `rpo_seconds`, `rps_target`, `currency` (отображаемая
     валюта стоимостного отчёта).
   - `CMP-*`/`INT-*`: `availability` (доля), `replicas` (параллельная
     избыточность, дефолт 1), `rps_per_instance`, `instances`,
     `cost_per_instance_month`, `exit_cost` (разовая цена выхода:
     миграция данных, лицензии, переинтеграция).
2. **Новый тип сущности `QAS-`** (quality attribute scenario): поля
   `source` / `stimulus` / `artifact` / `response` / `measure` (строки).
   Префикс добавлен в `ID_PATTERN` и `EntityKind`; незаполненное поле —
   `warn` `qas-incomplete` в `model validate` (по аналогии с
   `nfr-without-verification`). Рекомендуемая связь — `implements: [NFR-…]`.
3. **Новый модуль `src/nfr.rs`** — чистый читатель модели (через публичное
   API `model::*`), четыре проверки, каждая возвращает отчёт с находками
   `NfrIssue { severity, rule, message }`; `error` → exit code 1 (как
   `control check` / `trace check`):
   - `arch nfr budget <case>` — для каждого `NFR` с `p99_target_ms`
     складывает `latency_budget_ms` hop'ов `INT-*` из `affects` (порядок —
     порядок модели): сумма > цели → `error` `budget-exceeded` с перечнем
     hop'ов и их бюджетов (виновные видны поимённо); hop без бюджета →
     `error` `budget-hop-missing`; цель без цепочки INT → `error`
     `budget-no-chain`; INT с бюджетом вне проверяемых цепочек → `warn`.
   - `arch nfr availability <case>` — цепочка участков из `affects`
     (`CMP`/`INT`): последовательно `A = ∏Aᵢ`; участок с `replicas = n`
     считается параллельным `1 − (1−A)ⁿ`. Итог < `availability_target` →
     `error`; участок без данных → `warn` (исключается, отчёт помечает
     неполноту); цели RTO/RPO из `NFR` выводятся рядом, их отсутствие при
     заявленном SLA → `warn`.
   - `arch nfr capacity <case>` — для `NFR` с `rps_target`: каждый `CMP`
     цепочки обязан держать цель (`instances × rps_per_instance ≥ target`),
     требуемое число инстансов `⌈target / rps_per_instance⌉`; дефицит →
     `error` `capacity-insufficient`, нет данных → `warn`.
   - `arch nfr cost <case>` — TCO = Σ `instances × cost_per_instance_month`
     (месяц/год), цена выхода = Σ `exit_cost` + доля от годового TCO;
     валюта — из поля `currency` ёмкостного NFR. Неполные тарифные данные →
     `warn`, компонент исключается из суммы.
   - Числа вне диапазона (отрицательные, `availability` вне 0..1) — `error`
     `bad-value`: мусорные данные не должны давать уверенный PASS.
4. **QAS → критерии приёмки handoff-пакета**: `generate_handoff` при
   наличии `<repo>/model/` с сущностями `QAS-*` вставляет в `TASK.md`
   секцию «Критерии приёмки (QAS из модели)» — по строке на сценарий
   (stimulus/source/artifact/response/measure). Модель без QAS — секции
   нет; битая модель — ошибка генерации с контекстом (молчаливый пропуск
   превратил бы «автоматически» в «иногда»).
5. **Кейс 002** (`кейсы/payment-processing-platform/model/`): бюджеты на
   `INT-001…005`, структурные цели в `NFR-001…007`, новый `NFR-017`
   (cross-border: SWIFT + core banking — много-hop'овая цепочка), данные
   ёмкости/тарифов на шести `CMP` платёжного контура, `QAS-001…003`.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Поля во frontmatter сущностей (выбрано) | один источник истины, git-diff, валидация опечаток через `deny_unknown_fields`, trace/validate работают поверх тех же данных | frontmatter растёт; схема — конвенция, не XSD |
| Отдельный `NFR.yaml` в корне кейса | не трогает схему сущностей | второй источник истины, рассинхрон с прозой; новый формат файла |
| Цепочка hop'ов из графа `depends_on` | «настоящая» топология | граф компонентный, а не сценарный: одна цепочка на NFR не восстанавливается; циклы ломают сумму |
| Цена выхода через egress-тарифы провайдеров | точнее экономика | хардкод чужих прайсов в репо; устаревает; `exit_cost` данными честнее |
| QAS как проза в NFR, без нового префикса | не расширять схему | нечему ссылаться (`implements`), нечего разворачивать в TASK.md детерминированно |

## Consequences

### Positive

- Latency-бюджет перестаёт быть пожеланием: превышение суммы hop'ов над
  целью p99 ломает CI с поимённым списком виновных.
- Доступность/ёмкость/стоимость считаются из тех же данных, что читают
  люди, — расхождение «проза vs расчёт» невозможно по построению.
- Критерий `portability` получает инструмент: TCO и цена выхода — числа,
  а не раздел «на потом».
- QAS — первоклассная сущность: ссылка `implements → NFR-*` трассируется,
  критерии приёмки в `TASK.md` появляются без ручного копирования.

### Negative

- Модель доступности — композиционная оценка (независимые отказы, реплики
  идентичны): общезависимые отказы (ЦОД, общая БД) она не видит. Смягчается
  тем, что это инструмент сравнения «заявлено vs посчитано», а не симулятор.
- Поля-конвенции не защищают от бессмысленных, но валидных чисел — только
  диапазоны проверяются; смысл — на ревью модели в git.
- `replicas` как единственный вид параллелизма не покрывает active/active
  кластеры с разнородными нодами; при первом таком кейсе поле придётся
  расширять (обратимо: поля опциональны).

## Reversibility

reversible. Все поля опциональны; удаление `src/nfr.rs` и секции QAS из
`generate_handoff` не трогает формат `model/` и существующие проверки.
Кейс 002 без новых полей остаётся валидной моделью.
