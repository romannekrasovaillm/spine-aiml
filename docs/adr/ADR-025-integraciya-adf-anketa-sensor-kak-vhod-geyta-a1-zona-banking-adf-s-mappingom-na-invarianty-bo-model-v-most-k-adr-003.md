# ADR-025. Интеграция ADF: анкета-сенсор как вход гейта A1, зона banking/adf с маппингом на инварианты, BO-модель в мост к ADR-003

- Date: 2026-09-01
- Status: Accepted

## Context

Внутрибанковский фреймворк ADF (снимок `parsed_questions_all_v2.json`,
github.com/antonpropp/rules_adf @f016cf5) — каталог ветвящейся
архитектурной анкеты: 223 вопроса / 567 ответов / 349 триггеров /
38 доменов (compliance 21, cybersecurity 11, corp_architecture 11,
aiagents 7, каналы ~40, финансы ~30…). По README источника: это НЕ
тексты правил — анкета строит BO-модель продукта (команды
`set`/`bo`/`link` в `answer_command`) и связывает карточки правил
банка с парами `questions_id + questions_answers_id`; ветвление
`вопрос → ответ → следующий вопрос` определяет применимость.

Живые пересечения со Spine BE:

- вопросы ADF = условия включения conditional-блоков наших пресетов
  (16201516707 «Обрабатываются данные платёжных карт?» → PAY-12;
  списания/переводы → PAY-домен; критичность → CMP-09/PAY-10;
  GigaChat/AI-HUB → ADR-012, CMP-06/07);
- corp_architecture (АС/ФП, выделение бизнес-логики) = решения
  architectural-quantum / modular-monolith + объекты нашей
  типизированной модели (ADR-003: sys/cmp);
- ЕК-заявка (4943) = EA-мост (ea-repository-bridge).

Significance: Standard (2 триггера — new_component,
cross_domain_integration). Проблема данных: снимок содержит
задокументированную битую ссылку (16201516826-2), ID строковые,
`answer_command` нельзя исполнять как код (README прямо запрещает).

## Decision

1. **Форма инжекции — декларативная**: `banking/adf/` — зона данных
   с тремя артефактами: (а) снапшот каталога байт-в-байт
   (`catalog/`, SSOT снапшота не модифицируется); (б) таблица
   маппинга `adf-mapping.md`: домен/вопрос ADF → инвариант
   PAY/CMP/GEN → страж → открываемый conditional-блок; (в) README
   зоны: происхождение, статистика, протокол обновления снапшота.
2. **Роль анкеты — сенсор гейта A1** (guided discovery): скилл
   `adf-questionnaire` (плагин ru-architecture) описывает методику
   прогона: стартовые вопросы → ветвление по триггерам → ответы
   фиксируются в проекте → маппинг открывает conditional-блоки
   пресетов и создаёт строки CMP-01-реестра. Анкета НЕ заменяет
   significance_score и не порождает инварианты сама.
3. **BO-команды → мост в ADR-003**: `bo`/`link` из ответов
   маппятся на сущности типизированной модели (product → карточка
   системы, АС/ФП → sys/cmp, сегменты/каналы → атрибуты), команды
   НЕ исполняются (только парсинг в модель, не в eval/shell).
4. **Карточки правил банка не копируются**: у нас их нет в снимке;
   наша ценность — связка «ответ анкеты → наши инварианты и
   стражи». Тексты правил банка живут в его системе.
5. Обновление снапшота — замена файла + пересчёт статистики +
   перегенерация маппинга (ID вопросов стабильны — строки
   маппинга переживают обновление).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|-------|
| Сенсор в ядре (arch control sensors adf-режим: анкета из JSON, ответы в adf-answers.yaml, автоприменимость блоков) | машинная точность, битые ссылки ловятся автоматически | кодовый транш (handoff → harness) до доказательства ценности маппинга на пилоте; отложено — кандидат следующего транша |
| Дистилляция 223 вопросов в спайн-блоки ADF-n | «единый пресет» | вопросы — Да/Нет-классификация (сенсор), не инварианты; дублирование CMP-02; ~100 блоков против лимита 3–7 (Fundamentals of SA); отклонено |
| Статус-кво: ADF остаётся внешним инструментом банка | ноль работы | решения проекта ДИТ проходят мимо Spine BE — анкета определяет применимость наших же блоков, разрыв трассируемости; отклонено |
| **Принято: зона + маппинг + скилл (декларативно)** | сессия, не транш; ID стабильны — маппинг живёт при обновлениях; скилл даёт методику уже сейчас | ручной прогон анкеты (агентом по скиллу), без автоматики ядра |

## Consequences

### Positive

- Ответы ADF-анкеты напрямую открывают conditional-блоки PAY/CMP:
  применимость инвариантов определяется анкетой банка, а не мнением
  архитектора — готовая рамка guided discovery для A1.
- ЕК-заявка и АС/ФП-решения анкеты стыкуются с ea-repository-bridge:
  проект Spine BE говорит на языке корп-ландшафта банка.
- aiagents-домен анкеты (GigaChat, AI-HUB) подтверждает модельную
  матрицу ADR-012 и даёт ей вход из процесса банка.

### Negative

- Маппинг покрывает не все 223 вопроса: организационные домены
  (provision, operations, law, strategy, marketing, doc_flow,
  loyality) — вне фокуса Spine BE; фиксируются в маппинге строкой
  «вне фокуса», чтобы честность покрытия была видимой.
- Ручной прогон анкеты по скиллу медленнее кодового сенсора и
  зависит от дисциплины агента; митигировано: ответы сохраняются
  в проект (adf-answers.yaml) и машиночитаемы для будущего сенсора.
- Снапшот стареет: обновление — ручной протокол (README зоны);
  наша валидация (2026-09-01) нашла 3 битых триггера (1 задокументирован
  источником, 2 — новые находки) при 100% достижимости вопросов —
  список живёт в README зоны и переносится в `data_errors` прогона.
- Происхождение данных — внешний репозиторий GitHub (antonpropp/
  rules_adf): включение в поставку banking/ — по договорной рамке
  ADR-018/013, provenance зафиксирован в README зоны; перед
  поставкой клиенту сверить право на распространение снапшота.

## Reversibility

reversible — зона целиком декларативные артефакты (json/md); смена
формы (сенсор в ядре) не ломает данные и маппинг (ID стабильны),
оформляется supersede-ADR без миграций.
