# ADR-050. Политика кодовых харнессов: канон claude-code@DeepSeek-Flash[1m], контракт-обязательство результата и гигиена агентного периметра

- Date: 2026-09-23
- Status: Accepted (решение владельца получено 23.09.2026 через `propose_options`; significance = 5 → Critical, триггер `security_boundary_change`)

## Context

Замер фактического употребления кодовых харнессов на стенде (23.09.2026) по трём независимым источникам следов: логи прогонов `reports/harness/*.log` (189 файлов с результатом), журналы сессий `sessions/*.jsonl`, события флотов `state/fleet/*.jsonl`.

1. **Рабочий исполнитель — один.** 178 из 204 вызовов `harness_run` — `claude-code` (Claude Code 2.1.278). По логам с результатом: 147 прогонов и **77,1 ч из 79,7 ч суммарного времени прогонов (97 %)**; медиана 26 мин, максимум 6 541 с при потолке адаптера 7 200 с (`config.toml [harnesses.claude-code]`). Вторичные харнессы — единичная обкатка: codewhale 5 прогонов (4 × exit 0, медиана 6 мин), kimi-code 3 (один exit 143 = SIGTERM на 1 800 с), qwen-code 2, theseus 1 (exit 3, обрыв по лимиту ходов), hermes 1, kimi-acp/hermes-acp 2/0.
2. **Модель за каноном — не Anthropic.** `~/.bashrc:171-177` подменяет эндпойнт: `ANTHROPIC_BASE_URL=http://localhost:8765`, `ANTHROPIC_MODEL=deepseek-flash[1m]`; на 8765 слушает локальный прокси владельца `~/.local/bin/claude-deepseek-proxy.py --port 8765 --mode cache-preserve` (таблица алиасов — строки 71-75: только `flash`/`pro`). То есть канонический харнесс = эргономика Claude Code поверх дешёвой длинноконтекстной модели, с сохранением KV-кэша на прокси.
3. **Контракт результата провален на трети работы.** 61 из 189 логов (у `claude-code` — 61 из 147, 41 %) содержат «JSON-контракт результата в stdout не найден»; ещё 7 контрактов невалидны по схеме (`status='done'`, `status='measured'`, прозовый текст в поле `status`). Медиана длительности таких прогонов — 1 356 с, то есть это полноценные прогоны, а не убитые: машинная приёмка (A4) на них невозможна, интеграция уходит в ручную.
4. **Вторичные адаптеры неработоспособны по конкретным причинам** (события флотов): openclaw — невалидный `~/.openclaw/openclaw.json` и SQLite-схема 17 против поддерживаемой 1 (падение 4-5 с, exit 1); qwen-code — апстрим отвечает `400 … supported API model names are deepseek-flash, deepseek-v4-pro, but you passed coder-model`; hermes — лог 1 байт; theseus — обрыв по лимиту ходов; `contract_status=missing` у всех вторичных и у claude-code в тех же прогонах.
5. **Долг гигиены агентного периметра.** 172 из 189 логов несут одну и ту же пару stderr-жалоб Claude Code: (а) предупреждение о permission-правиле `Bash(grep -o '"type":"message"…[^"]*' ~/.openclaw/agents/main/sessions/…)` — `~/.claude/settings.json:86` и `~/.claude/settings.local.json:49`; wildcard в середине правила означает, что команда авто-одобряется с любыми вставленными в эту позицию опциями без запроса; (б) `[claude-code:unrecognized_model] {"model":"deepseek-v4-flash"}` — имя модели отсутствует в таблице алиасов прокси, часть запросов (генерация заголовков сессий, `query_source=sdk`) уходит в деградацию/отказ.

Ограничение по силам: контур работает в однопользовательском режиме, второй исполнитель не обкатан, а оба узла канона (прокси и permission-конфиг) лежат вне версионируемых репозиториев.

## Decision

1. **Канон исполнителя.** Рабочим исполнителем контура объявляется `claude-code` (Claude Code CLI) поверх DeepSeek-Flash[1m] через локальный прокси `localhost:8765`. Вторичные харнессы (`codewhale`, `kimi-code`, `qwen-code`, `theseus`, `hermes`, `openclaw`, ACP-варианты) переводятся в статус «не обкатаны»: в рабочие прогоны не ставятся, адаптеры остаются в конфиге как заготовки. Выход из этого состояния — только через доказанный паритет, а не по желанию: 3 подряд прогона одного и того же пакета с `exit 0` и `status=complete`.
2. **Контракт-обязательство результата.** Прогон считается принятым только при валидном JSON-контракте (`status ∈ complete|partial|blocked`). «Контракт не найден» → автоматический повтор прогона один раз с явным напоминанием о контракте в задании; повторный провал → прогон помечается `rejected`, ручная приёмка допускается только именным решением архитектора. Правило действует для всех харнессов без исключений для канона.
3. **Гигиена агентного периметра.** Permission-правила с wildcard в середине запрещены: `*` допустим только как завершающий префиксный wildcard (`Bash(python3 *)`). Таблица алиасов прокси обязана покрывать все имена моделей, которые отправляет Claude Code (включая `deepseek-v4-flash`, `deepseek-v4-pro[1m]`), чтобы `unrecognized_model` не возникал. Канон конфигурации — `~/.config/arch-ml/config.toml` (адаптеры), `~/.claude/settings.json` (периметр), прокси; все три — под fitness-стражем (C-37, C-38).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. Канон claude-code + гигиена (принят)** | Опирается на 97 % фактического времени прогонов; нулевая миграция; закрывает контрактный долг и security-дефект permission-правила; дешевле всех по внедрению | Единая точка отказа сохраняется: один прокси-процесс, один ключ API, одна модель; второй исполнитель не появляется; 41 % прогонов без контракта требуют правок кода харнесса, а не политики |
| **B. claude-code основным + обкатка codewhale как дублёра (A/B)** | Даёт проверенный fallback (codewhale: 4/5 exit 0, 3 complete, медиана 6 мин — лучший из вторичных); цена 2-3 прогона; не меняет контур | Полный паритет не гарантирован (выборка 5 прогонов); дублёр требует сопровождения двух адаптеров и двух наборов разрешений; отвлекает 2-3 прогона от кейсов |
| **C. Диспетчер по классу задачи (роутинг-ADR)** | Формализует, что дорогое идёт на канон, дешёвая механика — на второй харнесс; даёт fitness на контракт | Преждевременен: роутер, отправляющий работу на непаритетный харнесс, врёт молча; требует ADR + правок роутера флота до доказательства паритета |
| **D. Смена основы на kimi-code/k3 без самописного прокси** | Убирает самописный прокси и зависимость от API DeepSeek; 1M контекст у k3 есть | Наибольшая необратимость: переписать Stop-хук (`arch-be gate`), 62 permission-правила, плагины claude-контура; у kimi-code уже был обрыв по 1 800 с; приёмка наработанных кейсов деградирует |

## Consequences

### Positive

- Рабочий контур зафиксирован документом, а не привычкой: у «почему всё идёт через claude-code» появляется проверяемое обоснование и цена.
- Машинная приёмка (A4) перестаёт быть лотереей: контракт результата становится обязательным условием приёмки, а не пожеланием в шаблоне задания.
- Закрывается дефект периметра: mid-wildcard permission-правило удалено, авто-одобрение произвольных опций без запроса перестаёт действовать в интерактивных сессиях Claude Code.
- Появляются механические стражи (C-37, C-38), которые ловят рецидив обоих дефектов без участия человека.

### Negative

- **Единая точка отказа принимается осознанно.** Остановка прокси `localhost:8765` или исчерпание ключа DeepSeek останавливает все агентные работы; вторичные харнессы в статусе «не обкатаны» как аварийный путь не годятся. Митигация — не техническая, а процедурная: ручной перевод в `theseus`/`codewhale` по решению владельца (условие возврата — два простоя контура дольше 30 мин в течение месяца).
- Зависимость от модели одного вендора: `deepseek-flash[1m]` определяет и цену, и поведение 97 % прогонов; деградация модели на стороне API не компенсируется.
- Контракт-обязательство добавляет повторный прогон в 41 % случаев — прямые потери времени (медиана 22 мин × 1), пока повтор не научен отдавать контракт с первого раза.
- Вторичные адаптеры остаются гниющими: openclaw/qwen/hermes/theseus в конфиге, но неработоспособны; при первом же обращении к ним это обнаружится снова.
- Прокси и permission-конфиг живут вне версионируемых репозиториев (у прокси четыре ротационных `.bak`-копии, свежая правка — 23.09 08:24): правки не ревьюятся, откат — руками по бэкапу. Это долг, а не свойство решения.

## Reversibility

**costly.** Обратимо по существу, дорого по факту:

- отмена политики (возврат вторичных харнессов в ротацию) — правка `config.toml` и статусов, часы;
- повторное включение mid-wildcard правил — тривиально, но возвращает дефект, поэтому запрет дублируется fitness-правилом;
- переход на другую основу (вариант D) — дни: 62 permission-правила, Stop-хук `arch-be gate`, плагины, привычки интерактивных сессий привязаны к Claude Code CLI;
- данные (следы прогонов, сессии, события флотов) не разрушаются и служат доказательной базой при пересмотре.

Необратимости нет: ни один узел решения не уничтожает данные и не меняет форматы контрактов.
