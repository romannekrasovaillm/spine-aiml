# ADR-015. Инструментальная поверхность Spine BE: четыре транша, первый — контрактный контур

- Date: 2026-08-31
- Status: Accepted

## Context

Владелец продукта требует «максимум инструментов, тулов и MCP полезных
для solution-архитекторов» банка. Инвентаризация (2026-08-31): ~30
инструментов ядра, 6 плагинов / 51 скилл, 8 субагентов, MCP-клиент
(stdio) + `arch mcp serve` наружу (6 контрольных инструментов).
Пробелы сгруппированы в четыре транша (см. Decision).

Significance Score: 5 → Critical (new_component, new_vendor,
cross_domain_integration, api_contract_change, security_boundary_change).

## Decision

Четыре транша расширения инструментальной поверхности; порядок
исполнения:

- **T1 — Контрактный контур (выбран первым)**: `openapi_lint`
  (OpenAPI 3.x: версионирование, идемпотентность mutating-endpoint'ов,
  ошибки RFC 7807), `asyncapi_lint` (контракты событий), `contract_diff`
  (breaking changes между версиями). Rust-код — только через handoff
  кодовому харнессу, walking skeleton (один инструмент) до массовой
  генерации.
- **T2 — Security/compliance**: threat_model (STRIDE по DFD),
  compliance-рубрики (152-ФЗ, КИИ, ЦБ), регуляторная трассируемость
  REG→REQ. Переприоритизирован владельцем на сессии 2026-08-31:
  регуляторное усиление самого продукта выполняется ДО T1 (ADR-016);
  полная T2-волна — после T1.
- **T3 — Доменная библиотека**: плагины ru-payments (СБП/НСПК,
  ISO 20022), ru-integration (СМЭВ, ЕБС, АБС), ru-compliance —
  скиллы-данные, выверка по первоисточникам.
- **T4 — MCP-экспансия**: расширение `arch mcp serve` (kb_search,
  skill_search, mermaid_render, banking-пресеты кодовым агентам),
  HTTP/SSE-транспорт, банковский MCP-пресет с правилом периметра
  (никаких npx/uvx из публичных регистров в контуре ДИТ).

Правила всех траншей: код — через handoff; данные — руками архитектора;
walking skeleton прежде массы; каждый новый инструмент получает строку в
`docs/tools.md` и страж в CONSTRAINTS, если заявляет инвариант.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Транши T1→T4, T1 первый (принято; T2-усиление продукта — внеочередное, ADR-016)** | контрактный контур ценен в каждом проекте; на T1 доказываем кодовую дисциплину форка | до появления в бинаре — цикл прогона кодового харнесса |
| Один мегапрун всех траншей сразу | максимум поверхности быстро | нарушение walking-skeleton-дисциплины; немеханизируемое ревью |
| Только данные (T3), без кода | дёшево | запрос владельца — про инструменты; методики без тулов не закрывают |
| Только MCP (T4) | центр контура инструментов | главный потребитель — кодовые агенты, не архитектор |

## Consequences

### Positive

- Роадмап поверхности зафиксирован; каждый транш независимо
  поставляем и проверяем.
- T1 прокладывает конвейер «Rust-инструмент форка через handoff» —
  далее T2/T4 переиспользуют его.

### Negative

- Транши конкурируют за время владельца; срыв порядка волн ломает
  демо-наратив (митигируется: смена порядка — только решением владельца,
  как с ADR-016).
- Рост поверхности инструментов удорожает `docs/tools.md` и реестр —
  новые инструменты без строки в справочнике — defect.

## Reversibility

**reversible**: транши — план; порядок меняется решением владельца
(пример — ADR-016), без архитектурных потерь.
