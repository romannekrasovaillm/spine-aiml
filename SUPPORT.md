# SUPPORT — поддержка Spine Banking Edition

Снимок: 2026-09-04.

## Канал

- Вопросы и дефекты — через внутренний трекер проекта заказчика с меткой
  `spine-be`, либо напрямую владельцу продукта (контакт — в лицензионном
  договоре). Публичного трекера у проприетарной зоны нет.
- Уязвимости — по процедуре `SECURITY.md` (не в общий трекер).

## Сроки реакции (целевые, для договоров с поддержкой)

| Severity | Определение | Реакция | Целевое решение |
|---|---|---|---|
| S1 | потеря данных, утечка секретов, исполнение чужого кода | 1 рабочий день | hotfix или workaround в 3 рабочих дня |
| S2 | гейт/инструмент не работает по заявленному контракту | 2 рабочих дня | фикс в следующем релизе |
| S3 | косметика, документация, feature-request | 5 рабочих дней | по ROADMAP |

Без договора поддержки — best effort, без обязательств по срокам.

## Политика версий

- Версионирование артефактов — датой поставки (YYYY-MM-DD) + git-тег;
  SemVer вводится с первым стабильным API SDK (ADR-028, v1).
- Окно поддержки: текущая поставка и предыдущая (две линии); фиксы ИБ —
  на обе, функциональные — только на текущую.
- Обратная совместимость: схемы CONSTRAINTS/model/headless-JSON — только
  аддитивные изменения (SDK-контракт, `sdk/CONTRACT.md`); ломающие — через
  ADR с миграционной инструкцией.

## Что приложить к дефекту

Вывод `arch-ml doctor`, версию поставки (git-тег/дата), команду запуска,
фрагмент журнала сессии (`sessions/*.jsonl` — предварительно проверить на
секреты; redactor покрывает типовые форматы, не все).
