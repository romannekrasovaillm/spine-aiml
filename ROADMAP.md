# ROADMAP — Spine AI/ML Edition

Снимок: 2026-09-22. Документ пересматривается владельцем не реже раза в
квартал и по завершении каждого пункта (статус обновляется в том же
коммите). История и обоснования — в ADR (`docs/adr/`), не здесь.

> Продуктовая идентичность: доменный метахарнесс AI/ML-исследователя
> (форк банковской линии Spine — `NOTICE.md`; доменная зона — `aiml/`,
> пресет `aiml/presets/ml-researcher/`, инварианты ML-01…ML-14).

## Принципы планирования

- Каждое изменение ядра — через ADR + handoff-конвейер (ADR-015);
  fitness-гейты обновляются в том же коммите (AD-9).
- Приоритет: сначала доказуемость и воспроизводимость для
  ML-исследователя (офлайн-гейты, evidence-дисциплина, пины версий
  стека), потом новые функции.
- Внешнее ревью репозитория 2026-09-22 (13 пунктов: идентичность,
  быстрый старт, CI-покрытие SDK, вес репозитория) обработано волной
  коммитов `improve/aiml-edition-review` — статусы ниже.

## Горизонт 2 — глубина AI/ML-инструментария (Q4 2026 – Q1 2027)

- Реестр артефактов ML (веса, датасеты, eval-траектории) как
  CLI-поверхность — ADR-044: карточки, пины, связь с evidence.
- Лесенка обучения маленьких моделей (кейс `laguna-compact`): ось
  лесенки и пороги различимости объявлены до прогона (ADR-052, ADR-055),
  носители стадий, RL-стадия с наградой по состоянию среды (AD-13).
- Состязание длинноконтекстных архитектур (кейс `kimi-killer`): гейт A5
  по единому контракту прогона, механический вердикт.
- Роутинг гипотез по фактам проекта (ADR-047, плагин hypothesis-router):
  расширение доменных хуков, покрытие кейсами.
- JSON Schema манифестов плагинов + `arch-ml plugin validate` в CI
  (манифесты приведены к единому формату 2026-09-22; схема — следующий
  шаг).
- Декомпозиция крупнейших модулей (`control.rs`, `tui/app.rs`,
  `tui/render.rs`, `main.rs`) — задача P2-3; благодаря полному покрытию
  тестами рефакторинг относительно безопасен.
- Калибровка значимости по данным живых прогонов: пороги
  `[significance]` — рабочая гипотеза (ADR-034), пересмотр по
  `significance-cases.yaml`.

## Чего в планах нет (осознанно)

- Серверный/многопользовательский режим, RBAC — ADR-033 (single-user
  by design; процессная обвязка — снаружи, файловая поверхность).
- Обучение моделей внутри харнесса: `arch-ml` — метахарнесс
  (контроль, evidence, handoff), обучение живёт в контуре кейсов
  (GB10/DGX Spark) и запускается своими раннерами.
