# Инструкция для агента: развёртывание arch-ml с нуля

Контракт для ИИ-агента, которому передали бинарь `arch-ml` (из этого
каталога) и задачу «поднять харнесс и подключить LLM». Выполняй шаги
по порядку; после каждого — проверка. Не пересобирай бинарь. Не пиши
значения ключей в конфиг, логи, ответы и файлы — только имена
env-переменных / пути файлов ключей.

## Термины

- `CONFIG` = `~/.config/arch-ml/config.toml` (создаётся на шаге 2).
- Порядок поиска конфига: `--config <path>` → `./arch-ml.toml` → `CONFIG` → встроенные дефолты.
- Встроено в бинарь (не искать и не качать): промпты, рубрики, бенчмарки,
  7 плагинов / 52 скилла (деплоятся `init` в `~/.arch-ml/plugins/`),
  дефолтные секции моделей deepseek/deepseek-pro/glm*/kimi/gigachat*.

## Шаг 1. Установка

Бинарь собран только под Linux x86-64. Определи платформу машины
пользователя и действуй по ветке:

- **Linux** — основной путь, шаги ниже дословно.
- **Windows** — развёртывание ТОЛЬКО внутри WSL2 (Ubuntu): все шаги
  инструкции выполняются в терминале WSL без поправок; ключи — в
  `~/.bashrc` WSL-окружения (не в Windows); файлы из Windows видны по
  `\\wsl$\Ubuntu\home\<user>`; GPU-инференс в WSL2 работает (CUDA), проще —
  Ollama для Windows как сервер, arch-ml из WSL ходит на него по сети.
- **macOS** — arch-ml нативно не запустится. Варианты: отдельная
  Linux-машина/VM в контуре (сервер локальной модели при этом может жить
  на Маке: Ollama, `brew install llama.cpp`, LM Studio — Metal из коробки;
  vLLM на Маке нет; шелл zsh → export'ы в `~/.zshrc`) либо Linux-VM на
  самом Маке (UTM/Parallels; на Apple Silicon — с эмуляцией x86-64
  Rosetta). Если недоступно ни то ни другое — СТОП, эскалация к
  пользователю: нужен Linux-хост, darwin-сборки не существует.

```bash
mkdir -p ~/.local/bin && cp arch-ml ~/.local/bin/ && chmod +x ~/.local/bin/arch-ml
```

Файл из релиза GitHub называется `arch-ml-linux-x86_64` (без exec-бита):
`cp arch-ml-linux-x86_64 ~/.local/bin/arch-ml && chmod +x ~/.local/bin/arch-ml`.
Если пользователь скачивал релиз — сверь `sha256sum` с заметками релиза.

Проверка: `arch-ml -V` — версия обязана совпадать с версией релиза.
Если `command not found` — добавь `~/.local/bin` в PATH пользователя.

## Шаг 2. Инициализация

```bash
arch-ml init
```

Проверка: существуют `CONFIG`, `~/.arch-ml/plugins/`,
`~/.arch-ml/mcp.json`. `init` идемпотентен по ассетам, но спроси
пользователя перед повторным запуском поверх настроенного конфига.

## Шаг 3. Ключи — СНАЧАЛА СПРОСИ ПОЛЬЗОВАТЕЛЯ

Секреты — только с ведома пользователя. Спроси, какие провайдеры нужны
и где лежат ключи (env уже выставлен? файл? выдать сейчас?). Затем:

- env уже выставлен → ничего не делать, иди на шаг 4;
- ключ передан → `export <ИМЯ>=...` в `~/.bashrc` пользователя
  (`DEEPSEEK_API_KEY` / `ZHIPU_API_KEY` / `KIMI_API_KEY`), значение
  не печатать и не повторять в выводе;
- ключ в файле → прописать `api_key_file = "~/.<name>_key"` в секции модели.

Проверка: `[ -n "$DEEPSEEK_API_KEY" ] && echo ok` (по каждому нужному
провайдеру; значение не выводить).

Если DeepSeek среди провайдеров нет — поставь в `CONFIG`
`default_model = "glm"` (или `"kimi"`): дефолт — deepseek, и запуск
без `--model` упрётся в отсутствующий ключ.

Если у пользователя НЕТ ни одного ключа и он хочет начать бесплатно:
предложи z.ai — регистрация по email, банковская карта не нужна, пока
используются бесплатные flash-модели (glm-4.7-flash = $0 по прайсингу
z.ai на 2026-09-02; оплата привязывается только для платных моделей).
Тогда: `ZHIPU_API_KEY` + `default_model = "glm-flash"`. Сценарий проверен
живьём 2026-09-08 (чистое окружение, только ключ GLM, прямой доступ из
РФ): doctor «0 проблем», `run -q` без `--model` → корректный ответ.

## Шаг 4. Диагностика

```bash
arch-ml doctor
```

Приёмка: строка `Итог: 0 проблем`. Предупреждения о ключах неиспользуемых
моделей и о placeholder-каталогах knowledge — допустимы.

## Шаг 5. Приёмочный прогон (облачные LLM)

Для каждого затребованного провайдера:

```bash
arch-ml run -q --timeout 90  --model deepseek "Ответь ровно одним словом: столица Франции?"
arch-ml run -q --timeout 120 --model glm      "Ответь ровно одним словом: столица Японии?"
arch-ml run -q --timeout 90  --model kimi     "Ответь ровно одним словом: столица Китая?"
```

Приёмка: exit 0, stdout — одно осмысленное слово. Известные факты
(сверено прямыми вызовами без прокси 2026-09-07): api.deepseek.com,
api.z.ai и api.kimi.com из РФ доступны напрямую; api.moonshot.ai
душится DPI — у kimi должен оставаться
`base_url = "https://api.kimi.com/coding/v1"`. Если endpoint недоступен
из сети пользователя (DPI) — поле `proxy` в секции модели.

## Шаг 6. Локальная модель (если затребована)

0. Если сервера ещё нет — поставь один (спроси пользователя, какой):
   Ollama (Linux: `curl -fsSL https://ollama.com/install.sh | sh`;
   macOS/Windows — приложение с ollama.com; свежие версии берут контекст
   из метаданных модели — qwen3:8b → 40960, на старых дефолт 4096 →
   `OLLAMA_CONTEXT_LENGTH=32768`), llama.cpp (готовый zip из релизов
   ggml-org/llama.cpp под ОС пользователя или сборка cmake; на Маке —
   `brew install llama.cpp`), vLLM (`pip install vllm`, Linux + NVIDIA;
   tool-флаги и матрица версий — в блоке про HF ниже).
1. Получи у пользователя URL сервера и проверь:
   `curl -s <base_url>/models | head -c 400` (OpenAI-совместимый
   endpoint: llama.cpp, vLLM, Ollama `/v1`, LM Studio, шлюз).
2. Допиши в `CONFIG`:

```toml
[models.local]
base_url = "http://<host>:<port>/v1"
model = "<точный id из /v1/models>"
api_key_env = "LOCAL_LLM_API_KEY"
max_tokens = 4096
timeout_secs = 600
context_limit = <реальный ctx сервера>
```

3. `export LOCAL_LLM_API_KEY=local` в `~/.bashrc` (сервер без auth;
   значение произвольное, но переменная обязана быть непустой).
4. Приёмка: `arch-ml run -q --timeout 240 --model local "…"` → exit 0.
5. Ошибка `HTTP 400 … does not support tools` = модель без tool calls;
   харнесс агентный и шлёт tools всегда → сообщи пользователю, что нужна
   модель с поддержкой инструментов (проверено: Qwen3.x на llama.cpp/vLLM).

Веса с HuggingFace (если пользователь просит «модель с HF»): HF — склад
весов, не сервер. Форматы: safetensors → vLLM, GGUF (репо с суффиксом
`-GGUF`) → llama.cpp/Ollama (`hf download <репо> <файл.gguf> --local-dir
~/models`, затем `llama-server -m <файл> --port 8080 -c 32768 --jinja` —
`--jinja` обязателен для tools, контекст от 32768: промпт харнесса ~14K
токенов, иначе `exceed_context_size_error`). ВАЖНО: CLI называется `hf` —
старый `huggingface-cli` в huggingface_hub 1.x отключён («deprecated and
no longer works», скачивает ничего; проверено 2026-09-08). vLLM запускать
ТОЛЬКО с tool-флагами, иначе arch-ml получит HTTP 400 "auto tool choice
requires...": `vllm serve <репо> --enable-auto-tool-choice
--tool-call-parser hermes --guided-decoding-backend lm-format-enforcer`;
матрица версий (проверено на драйвере NVIDIA 560): свежий vllm требует
свежий драйвер (torch cu128+); под драйвер 560 — `vllm==0.6.3` +
`transformers==4.45.2` (>=4.46 ломает: assert "factor" in rope_scaling),
бэкенд lm-format-enforcer (у outlines зависимость pyairports на PyPI —
пустышка). huggingface.co из РФ нестабилен (DPI): зеркало
`HF_ENDPOINT=https://hf-mirror.com`, http-прокси через `HTTPS_PROXY`
(socks не поддерживается — при «Unknown scheme … socks://» убрать
ALL_PROXY), ModelScope, `ollama pull` (реестр Ollama из РФ доступен
напрямую — самый беспроблемный канал, проверено 2026-09-08). Приёмка та же:
`curl <base_url>/models` → точный id → прогон `run -q --model local`.

## Шаг 7. Контекстные папки (если затребованы)

ПРАВИЛО: секции `[knowledge]` и `[plugins]` уже есть в сгенерированном
конфиге — правь их `dirs` по месту. Вторая секция с тем же именем роняет
харнесс: `TOML parse error ... duplicate key` (проверено 2026-09-08).

- База знаний: реальные каталоги пользователя (НЕ симлинки) в
  `[knowledge].dirs`; placeholder-строки из init удалить. Приёмка:
  `arch-ml kb "<доменный запрос>"` → ненулевые хиты.
- Плагины: каталог библиотеки пользователя в `[plugins].dirs` (плагин =
  `plugin.json` + `skills/<name>/SKILL.md`). Приёмка: `arch-ml plugins
  list` показывает плагины пользователя.
- Глобальная память: `~/.arch-ml/MEMORY.md` (в системный промпт
  каждой сессии).

## Стоп-условия (эскалация к пользователю)

- Провайдер отвечает 401/403 после корректной установки ключа → ключ
  невалиден/отозван — сообщить, не подбирать.
- Региональная блокировка endpoint'а → сообщить, предложить поле `proxy`
  в секции модели; VPN/egress-шлюз поднимать только с разрешения.
- Нужна правка firewall, системных сервисов, ротация ключей → только
  по прямому указанию пользователя.
- Любое значение ключа оказалось напечатано → сообщить пользователю
  о необходимости ротации.
