# Инструкция для человека: arch-ml с нуля до рабочего состояния

Проверена живьём 2026-09-07 на чистом окружении и перепроверена 2026-09-08
(протокол — `ПРОВЕРКА.md`).
Всё делается за ~5 минут; пересборка бинаря не требуется ни на одном шаге.

## Шаг 0. Требования

- **Linux x86-64** (бинарь статический, зависимостей нет) — основная и
  единственная платформа самого arch-ml. Для Windows и macOS — см. блоки ниже.
- Доступ в интернет к API провайдеров (для облачных LLM) или запущенный
  локальный inference-сервер (для локальной модели).
- Ключи провайдеров — получаете в личных кабинетах (ссылки ниже).

### Если у вас Windows

Развёртывание — только в **WSL2** (подсистема Linux в Windows): это
полноценный Linux, и вся инструкция выполняется внутри него дословно.

1. `wsl --install` в PowerShell от администратора (или Ubuntu из
   Microsoft Store), перезагрузка, создание пользователя Ubuntu.
2. Откройте терминал Ubuntu — дальше по этой инструкции с шага 1,
   без каких-либо поправок.
3. Нюансы: ключи прописывайте в `~/.bashrc` внутри WSL (не в Windows);
   файлы дистрибутива удобно забирать из Windows по пути
   `\\wsl$\Ubuntu\home\<пользователь>`; локальный инференс с NVIDIA GPU
   в WSL2 работает (CUDA пробрасывается), но проще поставить Ollama для
   Windows как сервер — arch-ml из WSL ходит на него по сети
   (`base_url = "http://<IP-Windows>:11434/v1"`).

### Если у вас macOS

Нативной сборки arch-ml под macOS **нет** — харнесс запускается только на
Linux. Варианты по предпочтительности:

1. **Отдельная Linux-машина или VM в контуре (рекомендуется).** arch-ml
   ставится туда по этой инструкции. Мак при этом не пропадает: на нём
   можно держать сервер локальной модели (Ollama, llama.cpp, LM Studio —
   все с ускорением Metal), arch-ml ходит на него по сети — подробности в
   разделе «Если inference-сервер — на Маке» ниже.
2. **Мак — единственная машина.** Поставьте Linux-VM: бесплатный UTM или
   Parallels, гостевая Ubuntu. На Apple Silicon (M1–M4) при создании VM
   включите эмуляцию x86-64 (в UTM — галочка Rosetta): бинарь x86-64
   работает через неё. На Intel-Маках VM x86-64 идёт нативно.
3. **Чисто на Маке, без Linux — никак**: inference-сервер поднять можно,
   сам arch-ml — нет (сборки под macOS не существует).

## Шаг 1. Получение и установка бинаря

Есть два способа получить файлы — выберите свой.

**А. Из релиза на GitHub** (рекомендуется):

```bash
# Скачайте со страницы последнего релиза
# (github.com/romannekrasovaillm/spine-aiml/releases) бинарь
# arch-ml-linux-x86_64; инструкции и конфиг — каталог deploy-kit/ в репозитории
```

**Б. Из репозитория** (сборка из исходников):

```bash
git clone https://github.com/romannekrasovaillm/spine-aiml.git
cd spine-aiml
cargo build --release        # бинарь: target/release/arch-ml
cd deploy-kit                # здесь все инструкции и starter-конфиг
```

Бинаря в клоне нет — он сознательно не хранится в git (релиз-артефакт):
скачайте `arch-ml-linux-x86_64` со страницы релиза, как в пути А, или
соберите из исходников, как в пути Б.

Далее общий путь. ВНИМАНИЕ: скачанный с GitHub файл называется
`arch-ml-linux-x86_64` и не имеет бита исполнения — переименуйте и
разрешите запуск:

```bash
sha256sum arch-ml*                        # сверьте с SHA-256 из заметок релиза!
mkdir -p ~/.local/bin
cp arch-ml-linux-x86_64 ~/.local/bin/arch-ml
chmod +x ~/.local/bin/arch-ml
arch-ml -V                                # версия релиза
```

Если `arch-ml: command not found` — у вас `~/.local/bin` не в PATH:
`export PATH="$HOME/.local/bin:$PATH"` (и допишите в `~/.bashrc`).

## Шаг 2. Инициализация

```bash
arch-ml init
```

Создаёт:
- `~/.config/arch-ml/config.toml` — конфиг (все личные настройки живут здесь);
- `~/.arch-ml/` — ассеты из бинаря: `assets/` (промпты, рубрики, бенчмарки),
  `plugins/` (7 плагинов, 52 скилла), `mcp.json`, `cron.toml`, `CONSTRAINTS.example.yaml`;
- рабочие каталоги `sessions/`, `reports/`, `state/` — по мере использования.

Не пропускайте этот шаг: бинарь технически запустится и без `init`, но
без плагинов и скиллов (doctor покажет «0 плагинов, 0 скиллов», 1 проблему).

## Шаг 3. Ключи (секреты — только через окружение, никогда в конфиг)

Достаточно ОДНОГО ключа — того провайдера, которым будете пользоваться.
Добавьте в `~/.bashrc` (или `~/.profile`) и перелогиньтесь / `source ~/.bashrc`:

```bash
export DEEPSEEK_API_KEY="sk-..."     # platform.deepseek.com → API Keys
export ZHIPU_API_KEY="..."           # z.ai (docs.z.ai) → API Keys; тот же аккаунт работает на open.bigmodel.cn
export KIMI_API_KEY="..."            # kimi.com → платформа Kimi Code (kimi.com/code)
```

Альтернатива env — файл ключа (права 600), путь прописывается в конфиге
модели как `api_key_file = "~/.deepseek_api_key"`. Значение ключа в конфиг
не пишется никогда.

ВАЖНО: модель по умолчанию — DeepSeek (`default_model = "deepseek"`).
Если ваш единственный ключ — GLM или Kimi, первый прогон упрётся в
отсутствие `DEEPSEEK_API_KEY`. Лечение одной строкой в
`~/.config/arch-ml/config.toml`:

```toml
default_model = "glm"     # или "kimi", "glm-flash" (бесплатный тариф)
```

## Шаг 4. Проверка окружения

```bash
arch-ml doctor
```

Эталон: `✓ default_model «deepseek»`, `✓ plugins 7 плагинов, 52 скиллов`,
`Итог: 0 проблем`. Предупреждения про ключи моделей, которыми не пользуетесь
(gigachat и т.п.), — нормально: ключ нужен только при выборе модели.

## Шаг 5. Первый прогон

```bash
arch-ml run -q "Ответь одним словом: столица Франции?"   # headless, ответ в stdout
arch-ml                                                   # интерактивный TUI
```

## Китайские LLM: что уже настроено и как пользоваться

Все перечисленные модели **уже встроены в бинарь** — после `export` ключа
работают без правки конфига. Проверено из РФ 2026-09-07.

### DeepSeek (дефолтная модель)

- Ключ: https://platform.deepseek.com → API Keys (пополняемый баланс).
- Модели: `deepseek` = deepseek-flash (повседневная, дефолт),
  `deepseek-pro` = deepseek-v4-pro (тяжёлый ризонинг: состязательное ревью, гейты).
- Доступ из РФ прямой, без VPN (проверено 2026-09-07 с полностью снятыми
  прокси). Если в вашей сети DPI всё же режет — поле `proxy` в секции
  модели (см. «Типичные грабли»). Контекст 1M.
- Ризонинг: `/think on|off` в TUI, `--think on|off` в `run`.

### Z.AI GLM (Zhipu)

- Ключ: https://z.ai → регистрация (email) → API Keys.
- **Бесплатный старт без банковской карты.** Карта не требуется, пока вы
  пользуетесь бесплатными flash-моделями: glm-4.7-flash стоит $0 за
  токены (прайсинг z.ai на 2026-09-02); привязка способа оплаты нужна,
  только если захотите платные модели (glm-5.2, glm-5.3 и т.п.).
  Бесплатный тариф — с урезанными квотами и скоростью: годится для
  знакомства с харнессом, черновиков, крона и дайджестов; для тяжёлого
  ризонинга (состязательное ревью, гейты) берите платную модель.
  Сценарий «только бесплатный ключ GLM» проверен живьём 2026-09-08 в
  чистом окружении: `default_model = "glm-flash"` → ответы корректные,
  доступ из РФ прямой, без VPN.
- Модели: `glm` = glm-5.2 (флагман, 1M), `glm-4.7`, `glm-air` (дёшево),
  `glm-flash` = glm-4.7-flash (бесплатный тариф),
  `glm-5.3-flash` (окно 1.3M, платная, но самая дешёвая в своём поколении).
- Доступ из РФ: `api.z.ai` работает напрямую, без VPN (проверено
  2026-09-07 с полностью снятыми прокси; DPI у провайдеров флапает —
  запасной вариант поле `proxy`, см. «Типичные грабли»).
  Если ваш аккаунт заведён на китайской площадке — замените в конфиге
  `base_url` на `https://open.bigmodel.cn/api/paas/v4` (ключ тот же).
- Нюанс семейства glm-5.3*: thinking не отключается протоколом (HTTP 1210);
  «выключение» эмулируется `reasoning_effort=low` — карты уже прописаны
  в дефолтах, ничего делать не нужно.

### Kimi (Moonshot AI)

- Ключ: https://kimi.com (coding-поверхность Kimi Code).
- Модель: `kimi` = k3 (флагман Kimi Code; у поверхности есть и вариант
  k3-256k, в дефолте — k3 с лимитом контекста 1M). Прямой доступ из РФ
  проверен 2026-09-07 (с полностью снятыми прокси).
- ВАЖНО: `api.moonshot.ai` из РФ задушен DPI и флапает — в дефолте уже
  стоит рабочий `https://api.kimi.com/coding/v1`, не меняйте.
- Запасной путь ключа: файл `~/.kimi_api_key` (уже прописан как `api_key_file`).

### Выбор модели

```bash
arch-ml run --model glm -q "..."        # разово
arch-ml run --model deepseek-pro -q "..."
```

- В TUI: команда `/model` — пикер.
- Постоянно: в `config.toml` строка `default_model = "glm"`.
- Список настроенных моделей: `arch-ml models`.

## Локальная / self-hosted модель (контур банка)

Подходит любой OpenAI-совместимый сервер: llama.cpp (`llama-server`),
vLLM, Ollama (`/v1`), LM Studio, корпоративный шлюз. Добавьте секцию в
`~/.config/arch-ml/config.toml`:

```toml
[models.local]
base_url = "http://10.0.0.5:8000/v1"        # ваш сервер
model = "qwen3.8-27b"                       # ТОЧНЫЙ id из GET /v1/models вашего сервера
api_key_env = "LOCAL_LLM_API_KEY"           # имя ЛЮБОЙ установленной переменной (см. ниже)
max_tokens = 4096
timeout_secs = 600                          # локальные модели медленнее — бюджет больше
context_limit = 131072                      # реальный --ctx-size сервера, не больше
```

И в `~/.bashrc`:

```bash
export LOCAL_LLM_API_KEY="local"   # значение произвольное: сервер без auth,
                                   # но харнесс требует непустой ключ (Bearer шлётся, сервер его игнорирует)
```

**Обязательные условия (проверено на ошибках):**

1. **Модель должна поддерживать tool calls.** Харнесс — агентный и всегда
   шлёт `tools` в запросе. Модель без поддержки tools →
   `HTTP 400 ... does not support tools` (воспроизведено на Ollama с
   моделью без tool-шаблона). Берите Qwen3.x/Qwen3.5 на llama.cpp/vLLM —
   с ними проверено.
2. **`model` — точный id** из ответа `curl http://<сервер>/v1/models`,
   включая регистр и суффиксы (`:latest`, `@…@llama.cpp` и т.п.).
3. `context_limit` не превышает реальный контекст сервера, иначе HTTP 400/413
   на длинных сессиях.
4. Сервер в приватной сети (RFC1918/loopback) харнесс ходит напрямую,
   мимо env-прокси — VPN/прокси не мешают.

Проверено 2026-09-07: llama.cpp-сервер с Qwen3.8-27B за корпоративным
шлюзом (keyless, приватная сеть) — ответ корректный.

### Модель с HuggingFace: от скачивания до arch-ml

Частый вопрос: «а как взять модель с HuggingFace?» Важно понимать роли:
**HuggingFace — склад весов, а не сервер.** arch-ml ничего не скачивает и
не обслуживает сам: вы забираете веса с HF, поднимаете их любым
OpenAI-совместимым сервером и указываете его адрес в `[models.local]`
(секция выше). Три шага:

**Шаг 1. Выберите модель и формат.** На HF одна и та же модель лежит в
двух форматах:

| Формат | Как выглядит репозиторий | Чем обслуживать | Кому подходит |
|---|---|---|---|
| safetensors (оригинал) | `Qwen/Qwen3-8B` | vLLM (GPU, тяжёлый) | Сервер с GPU, максимум качества |
| GGUF (квантованный) | `Qwen/Qwen3-8B-GGUF` (суффикс `-GGUF`) | llama.cpp, Ollama, LM Studio | Рабочая станция, CPU/GPU пополам |

Правила выбора:
- **Tool calls обязательны** (см. условие 1 выше) — ищите в карточке
  модели «tool use / function calling»; с Qwen3/Qwen3.5/Qwen2.5-Instruct
  проверено. И берите модель от ~7B: крошечные (0.5–1.5B) протокол tools
  принимают, но агентную работу (прочитать файл → использовать результат)
  тянут плохо — проверено на Qwen2.5-0.5B.
- **Контекст сервера — от 32K.** Системный промпт arch-ml с инструментами
  и скиллами занимает ~14K токенов ещё до вашего первого сообщения:
  при `-c 8192` сервер отвечает `exceed_context_size_error` (проверено).
- **Размер под память**: квант Q4_K_M ≈ 0,6–0,7 ГБ на 1 млрд параметров
  (7–8B ≈ 5 ГБ, 27–32B ≈ 17–20 ГБ) плюс KV-кэш контекста.
- Файлов в GGUF-репозитории много (по одному на квант) — качайте один,
  обычно `q4_k_m` (баланс качества и размера).

**Шаг 2. Скачайте веса.**

```bash
# GGUF (точное имя файла смотрите на странице репозитория, вкладка Files):
hf download Qwen/Qwen2.5-0.5B-Instruct-GGUF \
    qwen2.5-0.5b-instruct-q4_k_m.gguf --local-dir ~/models

# safetensors для vLLM качать руками не нужно — vLLM скачает сам на шаге 3
```

ВАЖНО: команда называется `hf` (пакет `pip install huggingface_hub`).
Старый `huggingface-cli` в свежих версиях (1.x) отключён — печатает
«deprecated and no longer works» и ничего не скачивает (проверено
2026-09-08). Если `hf` не находится — обновите пакет; если у вас наоборот
старая версия (<1.0), там работает только `huggingface-cli` с теми же
аргументами.

Доступ к huggingface.co из РФ нестабилен (DPI режет по SNI; проверено
2026-09-07/08: напрямую — сбой соединения, через прокси — скачивается).
Если не качается, по порядку:

```bash
# 1) зеркало HF (тот же интерфейс, другой домен):
HF_ENDPOINT=https://hf-mirror.com hf download <репо> <файл> --local-dir ~/models

# 2) прокси/VPN, если он у вас настроен:
HTTPS_PROXY=http://127.0.0.1:12080 hf download <репо> <файл> --local-dir ~/models
#    (socks-схему hf-клиент не понимает — нужен http-прокси; если видите
#     ошибку "Unknown scheme for proxy URL socks://..." — уберите ALL_PROXY)

# 3) ModelScope (китайское зеркало, у моделей Qwen веса те же):
pip install modelscope && modelscope download --model Qwen/Qwen3-8B

# 4) реестр Ollama (не HF, но те же веса популярных моделей; из РФ
#    работает напрямую, без зеркал и прокси — самый беспроблемный канал,
#    проверено 2026-09-08):
ollama pull qwen3:8b
```

**Шаг 3. Поднимите сервер и подключите к arch-ml.**

Сначала установите сам сервер (один из трёх — на чистой машине его нет):

```bash
# Ollama (проще всего; есть под все ОС):
#   Linux:   curl -fsSL https://ollama.com/install.sh | sh
#   macOS/Windows: приложение с ollama.com

# llama.cpp (нужен бинарь llama-server):
#   готовые сборки без компиляции — релизы GitHub ggml-org/llama.cpp:
#   llama-bXXXX-bin-ubuntu-x64.zip (Linux), -macos-arm64.zip (Мак), -win-x64.zip (Windows);
#   на Маке проще: brew install llama.cpp
#   из исходников: git clone https://github.com/ggml-org/llama.cpp &&
#     cmake -B llama.cpp/build llama.cpp && cmake --build llama.cpp/build --target llama-server -j

# vLLM (Linux + NVIDIA GPU):
#   pip install vllm    # см. замечание о совместимости версий в варианте B
```

```bash
# Вариант A — llama.cpp (GGUF). Флаг --jinja ОБЯЗАТЕЛЕН для tool calls,
# контекст — от 32768 (промпт харнесса ~14K токенов, см. выше):
llama-server -m ~/models/qwen2.5-0.5b-instruct-q4_k_m.gguf \
    --port 8080 -c 32768 --jinja

# Вариант B — vLLM (safetensors, сам скачает с HF).
# Флаги tools ОБЯЗАТЕЛЬНЫ: без них arch-ml получит
# HTTP 400 "auto tool choice requires --enable-auto-tool-choice..." (проверено):
vllm serve Qwen/Qwen3-8B --port 8000 --served-model-name qwen3-8b \
    --enable-auto-tool-choice --tool-call-parser hermes \
    --guided-decoding-backend lm-format-enforcer
# Совместимость версий (проверено 2026-09-08 на драйвере NVIDIA 560):
# свежий vllm требует свежий драйвер (torch cu128+); под драйвер 560/571
# ставьте vllm==0.6.3 (torch 2.4 cu121) + transformers==4.45.2
# (transformers >=4.46 ломает старый vllm: assert "factor" in rope_scaling),
# бэкенд guided-decoding — lm-format-enforcer (у outlines на PyPI
# зависимость pyairports — пакет-пустышка, import падает).

# Вариант C — Ollama (GGUF из файла). Если ollama уже запущен (systemd/
# предыдущий `ollama serve`), повторный `ollama serve` не нужен и упадёт
# с "address in use" — это нормально, просто пропустите его:
printf 'FROM %s/models/qwen2.5-0.5b-instruct-q4_k_m.gguf\n' "$HOME" > Modelfile
ollama create my-qwen -f Modelfile          # endpoint :11434/v1
```

Контекст Ollama: свежие версии (проверено на 0.18) берут контекст из
метаданных модели (qwen3:8b → 40960) — настраивать ничего не нужно,
промпт харнесса (~14K) проходит. На старых версиях дефолт был 4096 —
тогда перед `ollama serve` выставьте `OLLAMA_CONTEXT_LENGTH=32768`
(или `PARAMETER num_ctx 32768` в Modelfile), иначе длинные сессии
упрутся в усечение контекста.

Проверка сервера: `curl http://127.0.0.1:8080/v1/models` — отсюда берёте
точный `model` для конфига. Дальше секция `[models.local]` из основной
инструкции (base_url, model, api_key_env, context_limit) и приёмка:

```bash
arch-ml run -q --model local "Ответь одним словом: столица Италии?"
```

Проверено end-to-end 2026-09-07/08: GGUF `Qwen2.5-0.5B-Instruct` скачан с HF,
поднят `llama-server --jinja`, arch-ml ходит на него как на обычную
локальную модель; отдельно прогнаны Ollama (`qwen3:8b`, включая реальный
вызов инструментов) и vLLM (протокол tools на уровне HTTP)
(протокол — `ПРОВЕРКА.md`).

> Замечание про HF Inference API/Endpoints (serverless): это платная
> облачная услуга HF, а не «локальная модель»; из РФ недоступна. Для
> контура банка путь именно такой: скачать веса → свой сервер → arch-ml.

### Если inference-сервер — на Маке (Apple Silicon)

Сам arch-ml на macOS не запустится (бинарь только Linux x86-64) — ставьте
харнесс на Linux-машину или в Linux-VM на самом Маке (варианты — шаг 0),
а сервер модели держите на Маке: arch-ml ходит на
него по сети (`base_url = "http://<IP-мака>:<порт>/v1"`). Рабочие варианты
на Маке (все с ускорением Metal из коробки):

- **Ollama** — приложение с ollama.com или `brew install ollama`; дальше
  `ollama pull qwen3:8b`, endpoint `http://<IP>:11434/v1` (чтобы слушал
  сеть, а не только localhost: `OLLAMA_HOST=0.0.0.0 ollama serve`).
- **llama.cpp** — `brew install llama.cpp`, дальше тот же
  `llama-server -m <файл.gguf> --port 8080 -c 32768 --jinja --host 0.0.0.0`.
- **LM Studio** — GUI: вкладка Developer → Start Server (OpenAI-compatible).
- **vLLM на Маке нет** (нужен NVIDIA/AMD GPU на Linux) — не ищите.
- Нюанс: дефолтный шелл macOS — zsh, поэтому `export LOCAL_LLM_API_KEY=...`
  пишите в `~/.zshrc`, а не в `~/.bashrc`.

## Свои контекстные папки (развитие «сверху бинаря»)

Бинарь пересобирать не нужно: всё личное подключается через конфиг.
Принцип Context Supply Chain: подключайте узкие релевантные домены,
а не «всю Wiki» — качество контекста важнее объёма.

ВАЖНО: секции `[knowledge]` и `[plugins]` уже есть в сгенерированном
конфиге — правьте их `dirs` по месту. Не дописывайте вторую секцию с тем
же именем в конец файла: TOML не терпит дублей, харнесс упадёт с
`TOML parse error ... duplicate key` (проверено 2026-09-08).

### База знаний (`arch-ml kb` + инструмент `kb_search`)

```toml
[knowledge]
dirs = [
  "~/knowledge/architecture",     # ЗАМЕНИТЕ на свои каталоги
  "~/knowledge/adr",
]
extensions = ["md", "txt", "rst"]
```

- BM25-поиск с живым обходом каталогов — индекс строить не нужно,
  новые файлы подхватываются сразу.
- Тильда `~/` раскрывается; **симлинки не обходятся** — указывайте реальные
  каталоги или копии.
- Файлы >5 МБ участвуют только по имени; кэш корпуса 256 МБ.
- Нюанс: `arch-ml init` пишет в конфиг placeholder-каталоги
  (`~/knowledge/architecture|papers|skills`) — doctor честно покажет
  «0 из 3 каталогов доступны», пока не замените на свои.
- Проверка: `arch-ml kb "saga компенсация транзакции"`.

### Библиотека плагинов/скиллов

```toml
[plugins]
dirs = [
    "~/.arch-ml/plugins",     # локальная библиотека (из init)
    "~/my-skills/plugins",         # ваша библиотека — раскомментируйте и укажите
]
include_mcp = true
include_hooks = true               # false для недоверенных библиотек
```

- Плагин = каталог с `plugin.json` + `skills/<имя>/SKILL.md`
  (+ опционально `mcp.json`, `agents/`, `hooks/`). Плагин — единственная
  единица установки; скиллы отдельно не ставятся.
- Проверка: `arch-ml plugins list`, `arch-ml skills list`.

### Глобальная память

`~/.arch-ml/MEMORY.md` — дописывается в системный промпт каждой
сессии. Путь переопределяется `[paths] memory_file`. Команды: `/memory`
в TUI, `arch-ml memory`.

## Типичные грабли

| Симптом | Причина и лечение |
|---|---|
| `переменная окружения DEEPSEEK_API_KEY не установлена` | Не сделан `export` или не перелогинились после правки `.bashrc` |
| Провайдер недоступен из вашей сети (таймаут/сброс соединения) | DPI провайдера. В секции модели добавьте `proxy = "http://127.0.0.1:12080"` (ваш локальный egress-шлюз; loopback-шлюз харнесс поднимает сам при выборе модели) |
| Kimi: таймауты/флапы | Кто-то поменял base_url на api.moonshot.ai — вернуть `api.kimi.com/coding/v1` |
| Локальная: `HTTP 400 does not support tools` | Модель без поддержки tool calls — сменить модель (Qwen3.x) |
| Локальная (vLLM): `HTTP 400 "auto" tool choice requires ...` | Сервер запущен без tool-флагов — перезапустите с `--enable-auto-tool-choice --tool-call-parser hermes --guided-decoding-backend lm-format-enforcer` |
| Скачивание с HF: `huggingface-cli ... deprecated and no longer works` | CLI переименован — используйте `hf download ...` (те же аргументы) |
| Любая команда: `TOML parse error ... duplicate key` | В конфиге две одинаковые секции (например, дописали вторую `[plugins]` в конец) — правите существующую секцию, дубль удалите |
| Локальная: `model not found` | `model` не совпадает с id из `/v1/models` сервера |
| `0 из N каталогов доступны` (knowledge) | Placeholder-каталоги из init не заменены на свои; либо каталог — симлинк |
| glm-5.3*: `HTTP 1210` при `/think off` | Thinking не отключается — дефолтные карты уже эмулируют off через `reasoning_effort=low`; не правьте `thinking_off` |
| Пустой stdout при `-q` и exit 1 | Причина в stderr — читайте её (строгий headless-контракт) |

## Полезное напоследок

- `arch-ml doctor` — первая команда при любой проблеме.
- `arch-ml run -q "..." > answer.md` — контракт для скриптов и кронов
  (stdout — только ответ, сбой — stderr + exit 1).
- Полный справочник опций конфига — прямо в сгенерированном
  `~/.config/arch-ml/config.toml` (все секции прокомментированы).
- Документация репозитория: `docs/getting_started.md`, `docs/models.md`,
  `docs/web_kb.md`, `docs/plugins_and_skills.md`.
